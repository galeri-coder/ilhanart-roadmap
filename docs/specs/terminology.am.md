# 📚 የቴክኒካዊ ቃላት እና ፅንሰ-ሀሳቦች መዝገበ ቃላት
> **"የዚህን ፕሮቶኮል ቋንቋ መረዳት ራዕዩን መረዳት ማለት ነው።"**

## ⚙️ PoArt ፎረንሲክ ሞተር (PFE) v1.0፡ መሰረታዊ መሠረተ ልማት

**PoArt ፎረንሲክ ሞተር (PFE)** የ[PoArt] ፕሮቶኮል ዋና ሎጂክ እና ቴክኒካዊ አሰራርን የሚወክል ዋና ደረጃ ነው። ይህ ጥሬ የስነ-ጥበብ ምርት መረጃዎችን የሚወስድ እና ወደ **ዲጂታል ማስረጃ** የሚለውጥ "ፎረንሲክ ሞተር" ነው ይህም ሊረጋገጥ የሚችል እና የማይለወጥ ነው።

### 🧩 ለምን "PoArt Forensic"?

- **PoArt (የጥበብ ማስረጃ)፡** የሞተሩ አላማ የዲጂታል ንብረትን እሴት በግምት ሳይሆን **በማረጋገጥ በሚቻል የምርት ሂደት** ላይ መሰረት ማድረግ ነው።
- **Forensic (ሳይንሳዊ ማረጋገጫ)፡**
  - **ቴክኒካዊ ትርጉም፡** የምርት ሂደት መረጃዎች (የብሩሽ ምት፣ የጊዜ ቪዲዮ፣ መዝገቦች) አልተጎዱም ለማረጋገጥ የአልጎሪዝም ዘዴ እና የመዝገብ ቅደም ተከተል።
  - **ፍልስፍናዊ ደረጃ፡** **የሰው ጊዜ፣ ጥረት እና የውሳኔ ወጪዎችን** ወደ ሊለካ እውነታ መለወጥ በአይ.አይ "ቅጽበታዊ ውጤት" ምርት ላይ።

> ማስታወሻ፡ የብሎክቼይን ውህደት (ለምሳሌ፣ Solana) የPFE ዋና አካል አይደለም; በተለየ ሁኔታ **የሰንሰለት መልህቅ ደረጃ** ለማረጋገጫ/መመዝገብ ዓላማዎች ይገለጻል።

### 🛠️ ቴክኒካዊ ወሰን v1.0

**PoArt ፎረንሲክ ሞተር (PFE) v1.0** ከውስብስብ የፋይናንስ ሞዴሎች ይልቅ በሚከተሉት **3 ቁልፍ ምሰሶዎች** ላይ ተገንብቷል፡

1. **Hashing & Sealing (ማሸግ)፡**  
   PFE በማረጋገጥ በሚቻል መንገድ ሁሉንም የማስረጃ ፓኬት ውስጥ ያሉ ነገሮችን (የስራ ፋይል፣ ቪዲዮ፣ JSON/መዝገብ፣ ፊርማ፣ ወዘተ.) ያቀናጃል እና ልዩ **NotarySeal** እሴት ያመነጫል።

   **ቁልፍ ጽንሰ-ሐሳቦች (v1.0)፡**
   - **FileHash (የስራ አሻራ)፡** ከስራ ፋይል ባይቶች የተፈጠረ ሃሽ።
   - **EvidenceRoot (የማስረጃ ፓኬት ሥር)፡** የማስረጃ ፓኬትን ታማኝነት የሚወክል የሥር ማጠቃለያ (Merkle ሥር ወይም የካኖኒካል ውክልና ሃሽ)።
   - **NotarySeal (የመጨረሻ ማኅተም / PFE ውጤት)፡** ከEvidenceRoot + ጊዜ + ፊርማ ጥምረት የተፈጠረ የመጨረሻ ማኅተም።

   **ቀመሮች (ለባለሀብቶች በግልጽ የሚታዩ)፡**
   
   $$\text{FileHash}_{512} = \text{SHA-512}(\text{ArtworkFileBytes})$$
   
   $$\text{NotarySeal} = \text{SHA-512}(\text{EvidenceRoot} \mid \text{SignerSignature} \mid \text{TimeStamp})$$
   
   **የካኖኒካል ፔይሎድ ትርጉሞች (v1.0)፡**
   
   - **EvidenceRootPayload:**
```
   file_sha512:{sha512}\nforensics:{canonicalForensics(forensics)}
```
   
   - **NotarySealPayload:**
```
   evidence_root:{evidence_root}\nsigner_sig:{signer_sig}\ntimestamp:{timestamp}
```
   
   > ማስታወሻ፡ እንደ PFE ውጤት የሚጠቀሰው እሴት **NotarySeal** ነው። **SignerSignature** ሂደት በደረጃ 2 (በSolana Wallet Adapter) ውስጥ ይነቃል; በአሁኑ v1.0 ውስጥ የስርዓቱ የማረጋገጫ ፊርማ ጥቅም ላይ ይውላል። የማረጋገጫ ይፋዊ ቁልፍ በ`issuer.attestation_pubkey` መስክ ስር በመዝገቡ ውስጥ ይታተማል።

2. **Indexing (ማከማቸት)፡**  
   የትኛው የቦርሳ፣ በየትኛው ቀን፣ **የስራ ማስረጃ** ለየትኛው ሥራ ወደ ግልጽ እና ሊጠየቅ የሚችል የመዝገብ ደረጃ እንደላከ ይጽፋል።  
   *(ይህ ደረጃ የውሂብ ጎታ ሊሆን ይችላል; የሰንሰለት ውህደት እንደ "የሰንሰለት መልህቅ ደረጃ" በተለየ ይገለጻል።)*

3. **Verification (ማረጋገጫ)፡**  
   የስራው ትክክለኛነት ሲጠየቅ፣ PFE ጥሬ ማስረጃዎችን እንደገና ያስራል; የተሰላው **EvidenceRoot / NotarySeal** እሴቶች ከተከማቸ መዝገቦች ጋር እንደሚጣጣሙ በሂሳብ ይመረምራል።

### 🧮 PoArt የእሴት ቲዎሪ (The Value Theorem)

[PoArt] ፕሮቶኮል የዲጂታል ንብረትን እሴት ($V$) በማይገባ የገበያ ግንዛቤ ላይ አያሰረውም፣ ነገር ግን **በምርት ሂደት አካላዊ እውነታ** ላይ ያሰረዋል።

አርቲፊሻል ኢንተለጀንስ (AI) ሂደቱን በቅጽበት ውጤቶችን በመስጠት ያጠፋዋል ($t \to 0$)። [PoArt]፣ ነገር ግን፣ እሴትን እንደ **ጊዜ፣ ሥራ እና ተወካይነት** ክፍሎች ስብስብ ይይዛል።

$$V_{\text{PoArt}} = \int_{t_{\text{start}}}^{t_{\text{end}}} \left(P_{\text{labor}}(t) \cdot I_{\text{agency}}(t)\right) dt + U_{\text{irreversible}}$$

#### የተለዋዋጮች ትርጉሞች

- **$\int dt$ (የሂደት ስብስብ)፡**  
  እሴት "ቅጽበታዊ ውጤት" አይደለም; በ$t_{\text{start}}$ እና $t_{\text{end}}$ መካከል የተሰበሰበ **ሂደት** ነው። ርዝመቱ እየቀነሰ ሲሄድ (የአይ.አይ ምርት)፣ የውህደት ውጤቱ ወደ 0 ይቀርባል።

- **$P_{\text{labor}}(t)$ (ቅጽበታዊ የሥራ ኃይል)፡**  
  በምርት ጊዜ የተጠቀሙት የአእምሮ እና የአካል ጥረት ጥንካሬን ይወክላል። ሊረጋገጥ የሚችል ጥረት እያደገ በሄደ መጠን፣ integrand ያድጋል።  
  > ማስታወሻ፡ ይህ ቃል በተግባር "ሊለካ/ሊረጋገጥ የሚችል የሥራ ምልክቶች" በኩል ሊመደብ ይችላል።

- **$I_{\text{agency}}(t)$ (የተወካይነት ፋክተር)፡**  
  የፈጣሪው ስጋት የመውሰድ እና ውሳኔ የመስጠት ችሎታ። በ$0$ እና $1$ መካከል እሴቶችን ይወስዳል።
  - **AI ($I \approx 0$)፡** ትዕዛዞችን ያከናውናል፣ ስጋት አይወስድም፣ ወጪ አይከፍልም።
  - **ሰው ($I \to 1$)፡** ውሳኔዎችን ይለውጣል፣ ያወላውላል፣ ስጋቶችን ይወስዳል።

- **$U_{\text{irreversible}}$ (የማይመለስ ልዩነት)፡**  
  መመለስ (`Ctrl+Z`) በዲጂታል ምርት ውስጥ የሚቻል ቢሆንም፣ በአካላዊ ምርት ውስጥ (በካንቫስ ላይ የተተገበረ ቀለም፣ የተቆረጠ እብነ በረድ፣ በቀጥታ ስርጭት ውስጥ እንቅስቃሴ) ምንም የመመለሻ መንገድ የለም። ይህ **የማይመለስነት** በስራው ውስጥ "ልዩነትን" (የማይተካ ባህሪያት) የሚፈጥር ተጨማሪ ቃል ነው።

### 🔎 የጉዳይ ትንተና፡ AI "ቅጽበታዊ ውጤት" vs. ሰው "የተረጋገጠ ሂደት"

የሚከተለው ሁኔታ **PoArt የእሴት ቲዎሪ** በተግባር እንዴት እንደሚሰራ እና በ[PoArt] መለኪያ ላይ የAI ምርት ለምን ዝቅተኛ ነጥብ እንደሚያገኝ ያሳያል።

#### ሁኔታ A፡ በአይ.አይ የ10 ሰከንድ ምስላዊ ምርት

- **ርዝመት ($\Delta t$)፡** $10$ ሰከንዶች (ትንሽ ሂደት)
- **የሥራ ኃይል ($P_{\text{labor}}$)፡** $1$ ክፍል (ትእዛዝ መጻፍ ብቻ)
- **የተወካይነት ፋክተር ($I_{\text{agency}}$)፡** $0.01$ (ስጋት የለም፣ ወጪ የለም)
- **የማይመለስነት ($U_{\text{irreversible}}$)፡** $0$ (ሊመለስ ይችላል / ሊገለበጥ ይችላል)

**ውጤት፡**

$$V_{\text{AI}} \approx \int_{0}^{10} (1 \cdot 0.01) \, dt + 0 = 0.1$$

> **አስተያየት፡** ውጤቱ ፍጹም ቢሆንም; የ[PoArt] እሴት ወደ $0$ ይቀርባል ምክንያቱም ምንም ሂደት አልተኖረም እና ምንም ተወካይነት/ስጋት አልተካተተም።

#### ሁኔታ B፡ በቀጥታ ስርጭት ውስጥ የ6 ሰዓት አካላዊ ምርት

- **ርዝመት ($\Delta t$)፡** $6$ ሰዓታት ($21{,}600$ ሰከንዶች)
- **የሥራ ኃይል ($P_{\text{labor}}$)፡** $0.5$ ክፍሎች (ቀጣይ የአካል እና የአእምሮ ጥረት)
- **የተወካይነት ፋክተር ($I_{\text{agency}}$)፡** $0.9$ (ውሳኔዎችን መለወጥ፣ ስጋቶችን መውሰድ፣ የማይመለሱ ምርጫዎች)
- **የማይመለስነት ($U_{\text{irreversible}}$)፡** $>0$ (አካላዊ ምልክቶች መመለስ አይችሉም)

**ውጤት፡**

$$V_{\text{Human}} \approx \int_{0}^{21600} (0.5 \cdot 0.9) \, dt + U_{\text{irreversible}} \approx 9720 + U_{\text{irreversible}}$$

### ✅ መደምደሚያ፡ ከማስረጃ ጋር የተያያዘ እሴት (Proof-Bound Value)

ይህ ቲዎሪ የ[PoArt] እሴት ጥያቄን ከ"ምርጫ" ወይም "የገበያ ታሪክ" ሆኖ ከመሆን ያወጣዋል እና **በሚረጋገጥ የምርት እውነታ** ጋር ያያይዛዋል።

1. **ሂደት የለም፣ እሴት የለም፡**  
   AI ሂደቱን በቅጽበት ውጤቶች ያጠፋዋል ($t \to 0$)። የሂደቱ መስኮት እየቀነሰ ሲሄድ፣ የውህደት ውጤቱ መቀነስ አለበት፡
   
   $$\Delta t \downarrow \ \Rightarrow\ \int \left(P(t) \cdot I(t)\right) dt \to 0$$

2. **ተወካይነት እና ስጋት ማባዛቶች ናቸው፡**  
   [PoArt] "የተጠቀመ ጊዜ" ብቻ አይለካም ነገር ግን በዚያ ጊዜ ውስጥ ያለውን እውነተኛ የውሳኔ ደረጃ፣ ስጋት እና ወጪም ይለካል። ስጋት የሌለው ምርት (AI) ዝቅተኛ እሴት አለው፡
   
   $$V_{\text{PoArt}} \propto \int \left(P_{\text{labor}}(t) \cdot I_{\text{agency}}(t)\right) dt$$

3. **ልዩነት አካላዊ ማስረጃ ነው፣ ግብይት አይደለም፡**  
   በአካላዊ ምርት ውስጥ የማይመለሱ ምልክቶች (የካንቫስ ምት፣ የድንጋይ ቁራጭ) ከዲጂታል `Ctrl+Z` አመክንዮ ውጭ ናቸው። ይህ የማይመለስነት ($U_{\text{irreversible}}$) ስራውን በኦንቶሎጂ ልዩ ያደርገዋል።

> **🔐 ማጠቃለያ፡** የእሴት ቲዎሪው እንደ መለኪያ እርግጠኛ አለመሆን ቢመስልም (እውነተኛው ዓለም አቻው ሙሉ በሙሉ ሊለካ ባይችልም)፣ የዚህ ቀመር ዓላማ አቀማመጥ እና የተለዋዋጮች አቅጣጫ ማሳየት ነው። በአይ.አይ ዘመን፣ እጥረት ያለው "ምስል" ሳይሆን **ሊረጋገጥ የሚችል ሥራ፣ ጊዜ እና ተወካይነት** ነው። [PoArt] ይህን እጥረት ይለካል እና በ**ማስረጃ ፓኬት** ይጽፋል።

### 6.1 የሕዝብ መዝገብ

- **የሕዝብ መዝገብ፡** ሁሉም የተፈቀዱ መረጃዎች በ`ilhanart.org/registry` (ወይም GitHub Registry) ይጻፋሉ።

**የመዝገብ አመክንዮ (የታቀደ ደረጃ - በJSON መንገድ ቅርጸት)፡**

መዝገቡን የሚገባ እያንዳንዱ ምዝገባ እነዚህን ዝቅተኛ ሊረጋገጡ የሚችሉ ዋና መስኮች ይይዛል፡

- **ማንነት እና ሁኔታ፡**
  - `certificate_id` (ሊነበብ የሚችል ማጣቀሻ)
  - `status` (active / void)
  - `void_reason` (የሚተገበር ከሆነ)
  - `visibility` (private / masked / public)
  - `created_at` (የጊዜ ማህተም)

- **አሳታሚ ባለሥልጣን፡**
  - `issuer.name`
  - `issuer.location`
  - `issuer.attestation_pubkey`

- **የሥራ መረጃ፡**
  - `asset.title`
  - `asset.creator`
  - `asset.creator_wallet` (ከተቻለ; ለማንነት ከቶከን በር ጋር)
  - `asset.fingerprints.sha256`
  - `asset.fingerprints.sha512`

- **የፎረንሲክ መረጃ፡**
  - `forensics.ip_masked`
  - `forensics.location`
  - `forensics.device`
  - `forensics.timestamp`

- **ክሪፕቶግራፊያዊ ማስረጃዎች፡**
  - `proof.evidence_root`
  - `proof.signer_sig`
  - `proof.notary_seal`

- **አስተዳደር፡**
  - `governance.decision`
  - `governance.veto_threshold`

መዝገቡ ሁለት ደረጃዎች ሊኖሩት ይችላሉ፡
- **1)** በሰው የሚነበብ መረጃ ጠቋሚ (የድህረ ገጽ ዝርዝር / ፍለጋ / ማጣሪያ)
- **2)** በማሽን የሚነበብ ውክልና (JSON መዝገቦች; ለPFE ማረጋገጫ)

**ይህ "ምዝገባ" በማስረጃ ፓኬት → EvidenceRoot → NotarySeal የPFE ሰንሰለት ሊረጋገጥ ይችላል። መዝገቡ የማረጋገጫ ዓላማዎችን ያቀርባል፣ "ክሶች" አይደለም።**

### 6.2 40% የማህበረሰብ ቬቶ (የተዘጋ-ቶከን አስተዳደር)

- **40% የማህበረሰብ ቬቶ፡** ድምጽ ከማሕተም መስጠት አንድ ወር በፊት ይጀምራል; 40% የማህበረሰብ **የተዘጋ-ቶከን (በSolana የተረጋገጠ)** ቬቶ ጥያቄውን ያስወግዳል።

**የድምጽ ፍሰት (የታቀደ ግልጽ ሂደት)፡**
- **የማመልከቻ መስኮት፡** የእጩ ፕሮጀክት "የPoArt እጩ ምዝገባ" ይከፍታል (የእጩ መዝገቦች በ"በመጠባበቅ ላይ" ሁኔታ ውስጥ ይታያሉ)።
- **የግምገማ ጊዜ፡** ማህበረሰቡ ለ30 ቀናት ማስረጃዎችን ይመረምራል (የማስረጃ ፓኬት + የቀጥታ ስርጭት መዝገቦች + ሜታዳታ)።
- **የተዘጋ-ቶከን ማረጋገጫ፡** ድምጽ በተረጋገጡ የSolana ቦርሳዎች ይደረጋል (ለምሳሌ የተወሰነ ቶከን/NFT ባለቤትነት + የቦርሳ ፊርማ)።
- **የቬቶ ደንብ፡** 40% ድምጾች **ተቃውሞ (አይ / ቬቶ)** ከሆኑ፣ ጥያቄው ይውድቃል።
- **ግልጽነት፡** የድምጽ ውጤቶች በመዝገቡ ውስጥ እንደ "የውሳኔ መዝገብ" (ቀን፣ ጥምርታ፣ የምስል መለያ) ይቀመጣሉ።

---

### 6.3 የሜታዳታ ማመሳሰል (ከአካላዊ ዓለም ጋር መጣጣም)

- **የሜታዳታ ማመሳሰል፡** በመዝገቡ ውስጥ ያለው ቴክኒካዊ መረጃ 100% ከአካላዊ አካል ጋር መጣጣም አለበት።

**ቴክኒካዊ ትርጉም "100% መጣጣም" (የታቀደ ግልጽነት)፡**
- **ዝቅተኛ መጣጣም (አስገዳጅ)፡**
  - በመዝገቡ ውስጥ ያለው `asset.fingerprints.sha256/sha512` ከሚናገሩት ፋይል ሃሽ ጋር **ተመሳሳይ** መሆን አለበት።
  - በመዝገቡ ውስጥ `proof.notary_seal` እንደገና ሲመነጨር (የማስረጃ ፓኬት ካለ)፣ **ተመሳሳይ** መሆን አለበት።
- **የአካላዊ ማጣቀሻ መጣጣም (የማስረጃ ዓይነት)፡**
  - አካላዊ ሥራ + በቀጥታ ስርጭት ውስጥ የታየ ቀን/ብሎክ ማጣቀሻ እና ተመሳሳይ ማስረጃ ከማስረጃ ፓኬት ጋር መጣጣም አለበት።
- **የግላዊነት ማክበር፡**
  - በ`masked` ታይታዎች ውስጥ እንደ IP/አካባቢ ያሉ መስኮች **በመሸፈኛ ደረጃዎች መሠረት** ይታተማሉ።

---

### 6.4 ክርክር እና መሻር

መዝገቡ የ"ፍቃድ" ሂደት ብቻ አይደለም; በማጭበርበር ላይ **የህይወት ግምገማ ሂደት** ነው።

- ክርክር ሲጀመር፣ ምዝገባው ወደ **"review" (ግምገማ)** ሁኔታ ሊቀመጥ ይችላል።
- ማጭበርበር ሲገኝ፣ እንደ `status: void` ምልክት ተደርጎ ምክንያት ይጨመራል፡
  - `void_reason` (የአይ.አይ አጠቃቀም / ስርቆት / መቀየር፣ ወዘተ.)
  - `revoked_at` (የመሻር ጊዜ)
- የመሻር ውሳኔ ምንጭ በመዝገቡ ውስጥ ግልጽ ነው፡
  - የማህበረሰብ ድምጽ / የተፈቀደ ኮሚቴ / የሳይንሳዊ ምርመራ ማስታወሻ (የሚተገበር)

> **ይህ ክፍል በ"ቀይ ባንዲራ ፕሮቶኮል" ክፍል ውስጥ ያለው የVOID ጽንሰ-ሐሳብ መዝገብ መንታ ነው።**

## 7) 🔐 ቴክኒካዊ ማኅተም (NOTARY SEAL)

በ**PoArt ፎረንሲክ ሞተር (PFE) v1.0** የተፈጠረ የማይለወጥ ማኅተም አልጎሪዝም፡

$$\text{NotarySeal} = \text{SHA-512}\left(\text{EvidenceRoot} \mid \text{SignerSignature} \mid \text{TimeStamp}\right)$$

# [PoArt] ዲጂታል ኖተሪ እና ሳይንሳዊ ማስረጃ ፕሮቶኮል (Beta v1.0)

> **"ባህል ከካፒታል ይበልጣል። ሥራዎችህን ዛሬ ጠብቅ፣ ነገ ውሰድ።"**

---

## ለምን ሕዝባዊ?

እውነተኛ ደህንነት ከግልጽነት ይመጣል። በ**የሕዝብ መዝገብ** ስርዓታችን ምስጋና፣ በዓለም ላይ ያለ ማንኛውም ሰው ፋይል ትክክል መሆኑን በሰከንዶች ውስጥ ማረጋገጥ ይችላል፣ ምንም ባለሥልጣን ሳያስፈልግ።

---

## 🧩 ለምን በርካታ "የታይታ ሞጁሎች"?

ይህ የኮዱ በጣም አስፈላጊ ክፍል ነው (የታይታ ምርጫ ዝርዝር)። እነዚህ ምርጫዎች ተጠቃሚዎች **"ግላዊነት vs. ግልጽነት"** ማመጣጠን እንዲችሉ ያስችላቸዋል፡

### 🔒 የግል

- **ሁኔታ፡** አርቲስቱ ሥራውን ገና ማተም አይፈልግም፣ ግን "ይህንን በዚህ ቀን አድርጌዋለሁ" ለማረጋገጥ ጊዜ ማህተም ማድረግ ይፈልጋል።
- **ኮዱ ምን ያደርጋል፡** በውሂብ ጎታ ውስጥ መረጃ ይጽፋል ግን ማህተሙን `visibility: "private"` ያስቀምጣል። በኋላ "የሕዝብ ንባብ" ፖሊሲ ሲጽፉ፣ እነዚህን መዝገቦች ከሕዝብ በ`WHERE visibility = 'public'` መደበቅ ይችላሉ።

### 🕶️ የተሸፈነ

- **ሁኔታ፡** አርቲስቱ ግልጽነት ይፈልጋል ግን የቤት አድራሻው (የአይፒ አካባቢ) እንዳይገኝ ይፈራል።
- **ኮዱ ምን ያደርጋል፡** `maskIP` እና `maskLoc` ተግባራት በJavaScript ጎን ላይ ይሰራሉ። የአይፒ አድራሻውን ወደ `88.241.***.***` ቅርፀት፣ አካባቢውን ወደ `***/TR` ቅርፀት ይለውጣል፣ እና የተቀነሰውን ስሪት ወደ ውሂብ ጎታ ይልካል።

## 💡 ቴክኖሎጂያዊ ፈጠራ

PoArt የፋይል ስቀላ ስርዓት ብቻ አይደለም። በአንድ ድስት ውስጥ ሦስት የተለያዩ የቴክኖሎጂ ደረጃዎችን በማጣመር አዲስ ደረጃ የሚያመጣ **"የሳይንሳዊ እንክብካቤ ሰንሰለት"** ሞተር ነው።

**በዚህ ክፍል ውስጥ እንደ "ሞተር" የተገለጸው ደረጃ ከቀደሙት ውል ጋር በPoArt ፎረንሲክ ሞተር (PFE) ዋና ክፍል ጋር ይዛመዳል።**

### 1) የደንበኛ-ጎን ሃሽንግ (ከፍተኛው ግላዊነት)

የእርስዎ የጥበብ ሥራ ፋይሎች ወደ አገልጋይ አይጫኑም። የእኛ በአሳሽ-ላይ የተመሰረተ (የደንበኛ-ጎን) ሞተር የፋይሉን ሃሽ (ዲጂታል ማጠቃለያ) በራስዎ ኮምፒውተር ላይ ያስላል። ይህ አሻራ እና ሜታዳታ ብቻ ወደ አገልጋይ ይላካሉ።

> **የግላዊነት እውነታ፡** የሥራ ፋይሉ ወደ አገልጋይ አይጫንም እና በዚህ መንገድ ይጠበቃል። ሆኖም፣ የፎረንሲክ መረጃ (IP/አካባቢ) በተመረጠው የታይታ ሁኔታ (የግል/የተሸፈነ/ሕዝባዊ) መሠረት ይጋራል።

### 2) የፎረንሲክ መረጃ ውህደት (የሳይንስ ኃይል)

ከተለመደ የጊዜ ማህተም በላይ። ስርዓቱ እነዚህን መረጃዎች በአንድ "መነሻ ማኅተም" ውስጥ ያዋህዳል፡

- **ዲጂታል ማጠቃለያ (SHA-512)፡** የሥራው አንድ ፒክሰል ቢቀየር የሚሰበር የሚስጠራዊ ማጠቃለያ ደረጃ (SHA-512) በመጠቀም አሻራ።
- **አካባቢ እና ጊዜ፡** በሚሊሰከንድ ትክክለኛነት ቀን፣ ሀገር፣ ከተማ እና የወረዳ መረጃ የግብይት።
- **የመሣሪያ ማንነት፡** ኦፐሬቲንግ ሲስተም፣ አሳሽ እና የመሣሪያ ዓይነት (User-Agent ትንተና)።

## 🔬 ቴክኒካዊ ጥልቀት፡ የማኅተም አልጎሪዝም

### መወሰን የሚቻል የሃሽ ተግባራት
```javascript
// የእገዛ ተግባራት፡ ማጠቃለያን ወደ ሄክሳዴሲማል ገመድ መቀየር
async function digestToHex(algorithm, dataBytes) {
  const hashBuffer = await crypto.subtle.digest(algorithm, dataBytes);
  const hashArray = Array.from(new Uint8Array(hashBuffer));
  return hashArray.map(b => b.toString(16).padStart(2, '0')).join('');
}

// ገመድን ወደ ባይት ድርድር መቀየር
function stringToBytes(text) {
  return new TextEncoder().encode(text);
}

// የካኖኒካል ፎረንሲክስ ገመድ ማመንጨት (v1.0፡ ቋሚ የመስክ ቅደም ተከተል + UTF-8 + አንጓዳቢ \n)
// የደረጃ 2 እውነታ፡ ወደ ካኖኒካል JSON ከRFC 8785 (JCS) ጋር መሸጋገር
function canonicalForensics(forensicsData) {
  return JSON.stringify({
    ip_masked: forensicsData.ip_masked,
    location: forensicsData.location,
    device: forensicsData.device,
    timestamp: forensicsData.timestamp
  });
}
```

### NotarySeal ማመንጨት ሂደት (ሙሉ በሙሉ መወሰን የሚቻል)
```javascript
// 1. FileHash ስሌት (የደንበኛ-ጎን)
async function computeFileHash(file) {
  const fileBuffer = await file.arrayBuffer();
  const fileBytes = new Uint8Array(fileBuffer);
  
  const sha256 = await digestToHex('SHA-256', fileBytes);
  const sha512 = await digestToHex('SHA-512', fileBytes);
  
  return { sha256, sha512 };
}

// 2. የፎረንሲክስ መረጃ ስብስብ (ነጠላ የጊዜ ማህተም አጠቃቀም)
async function collectForensics(visibilityMode) {
  const timestamp = new Date().toISOString(); // ነጠላ የጊዜ ማህተም ማመንጨት
  const ipData = await fetch('https://ipapi.co/json/').then(r => r.json());
  
  let forensics = {
    ip_masked: visibilityMode === 'masked' ? maskIP(ipData.ip) : ipData.ip,
    location: visibilityMode === 'masked' 
      ? `***/${ipData.country}` 
      : `${ipData.city}, ${ipData.country_name || ipData.country}`,
    device: navigator.userAgent,
    timestamp: timestamp // ተመሳሳይ የጊዜ ማህተም
  };
  
  return { forensics, timestamp };
}

// 3. EvidenceRoot ግንባታ (ከካኖኒካል ምስጠራ ጋር)
async function computeEvidenceRoot(fileHash512, forensicsData) {
  const canonicalPayload = `file_sha512:${fileHash512}\nforensics:${canonicalForensics(forensicsData)}`;
  return await digestToHex('SHA-512', stringToBytes(canonicalPayload));
}

// 4. NotarySeal ማመንጨት (ተመሳሳይ የጊዜ ማህተም አጠቃቀም)
async function computeNotarySeal(evidenceRoot, signerSignature, timestamp) {
  const sealPayload = `evidence_root:${evidenceRoot}\nsigner_sig:${signerSignature}\ntimestamp:${timestamp}`;
  return await digestToHex('SHA-512', stringToBytes(sealPayload));
}

// የመሸፈኛ እገዛ ተግባራት (IPv4 እና IPv6 ድጋፍ)
function maskIP(ip) {
  if (!ip) return "***";
  
  // IPv4 ምርመራ
  if (ip.includes(".")) {
    const parts = ip.split(".");
    if (parts.length === 4) {
      return `${parts[0]}.${parts[1]}.***.***`;
    }
  }
  
  // IPv6 ወይም ያልታወቀ ቅርጸት
  return "***";
}
```

### የማረጋገጫ ፍሰት (ሁለት ደረጃዎች)

#### Quick Verify (ፈጣን ማረጋገጫ)
```javascript
// የፋይል ሃሽን ብቻ አረጋግጥ (ፈጣን ቀይ ባንዲራ)
async function verifyQuick(file, certificateId) {
  const { sha512: userFileHash } = await computeFileHash(file);
  
  // ከመዝገብ ያግኙ
  const cert = await fetchFromRegistry(certificateId);
  const { sha512: originalHash } = cert.asset.fingerprints;
  
  // የሃሽ ንጽጽር
  if (userFileHash === originalHash) {
    return {
      valid: true,
      message: "✅ ትክክለኛ - የፋይል ሃሽ ይዛመዳል"
    };
  } else {
    return {
      valid: false,
      message: "❌ ሐሰተኛ - ፋይሉ ተለውጧል"
    };
  }
}
```

#### Full Verify (ሙሉ ማረጋገጫ)
```javascript
// EvidenceRoot እና NotarySeal እንደገና ያመነጩ እና ያረጋግጡ
async function verifyFull(file, certificateId) {
  const { sha512: userFileHash } = await computeFileHash(file);

  // ከመዝገብ ያግኙ
  const cert = await fetchFromRegistry(certificateId);

  // 1) FileHash ማረጋገጫ (ፈጣን ቀይ ባንዲራ)
  const originalHash = cert.asset.fingerprints.sha512;
  if (userFileHash !== originalHash) {
    return { valid: false, message: "❌ ሐሰተኛ - የፋይል ሃሽ አይዛመድም" };
  }

  // 2) EvidenceRoot እንደገና አመንጭ (በመዝገቡ ውስጥ ከተከማቸው የፎረንሲክ መረጃ ጋር)
  const evidenceRoot = await computeEvidenceRoot(userFileHash, cert.forensics);
  if (evidenceRoot !== cert.proof.evidence_root) {
    return { valid: false, message: "❌ አይዛመድም - EvidenceRoot አይቆምም" };
  }

  // 3) NotarySeal እንደገና አመንጭ (ከተመሳሳይ የጊዜ ማህተም + signer_sig ጋር)
  const seal = await computeNotarySeal(
    evidenceRoot,
    cert.proof.signer_sig,
    cert.forensics.timestamp
  );

  if (seal !== cert.proof.notary_seal) {
    return { valid: false, message: "❌ አይዛመድም - NotarySeal አይቆምም" };
  }

  // አማራጭ፡ በደረጃ 2 ውስጥ፣ signer_sig ን በattestation_pubkey ጋር ያረጋግጡ
  // const sigValid = await verifySig(cert.issuer.attestation_pubkey, cert.proof.signer_sig, evidenceRoot);
  // if (!sigValid) return { valid: false, message: "❌ ልክ ያልሆነ ፊርማ" };

  return { valid: true, message: "✅ ትክክለኛ - ሙሉ ማረጋገጫ ተሳክቷል" };
}
```

> **ወሳኝ እውነቶች፡**
> - **Quick Verify፡** ለፈጣን አጠቃቀም የፋይል ሃሽን ብቻ ያረጋግጣል።
> - **Full Verify፡** ሁሉንም የፕሮቶኮል ደረጃዎችን ያረጋግጣል (EvidenceRoot + NotarySeal)።
> - ሁሉም የሃሽ ስራዎች በመወሰን በሚቻል መንገድ ከቋሚ ምስጠራ እና ቋሚ አንጓዳቢዎች ጋር ይከናወናሉ።
> - **የአሁኑ መደበኛ v1.0፡** ቋሚ የመስክ ቅደም ተከተል + UTF-8 ምስጠራ + አንጓዳቢ `\n`።
> - **የደረጃ 2 እቅድ፡** ወደ ካኖኒካል JSON ከRFC 8785 (JCS - JSON Canonicalization Scheme) ጋር መሸጋገር።
> - በመሸፈኛ ሁኔታ ውስጥ፣ የEvidenceRoot እና NotarySeal ስሌት በተሸፈነ የፎረንሲክ መረጃ ይከናወናል; ስለዚህ ማረጋገጫ መወሰን ይቀራል።
> - ተመሳሳይ የጊዜ ማህተም በሂደቱ ውስጥ (ፎረንሲክስ + NotarySeal) ጥቅም ላይ ይውላል; መወሰን የተረጋገጠ ነው።
> - **የፎረንሲክ የመስክ ስሞች፡** `ip_masked`, `location`, `device`, `timestamp` (ኮድ እና መዝገብ በትክክል ይዛመዳሉ)።
> - **የመዝገብ መንገድ፡** `certificate.asset.fingerprints` (ከማረጋገጫ ኮድ ጋር በትክክል ይዛመዳል)።
> - **በመዝገቡ ውስጥ signer_sig፡** የ`proof.signer_sig` መስክ ለሙሉ ማረጋገጫ ያስፈልጋል።
> - SignerSignature ሂደት በደረጃ 2 በSolana Wallet Adapter ውስጥ ይነቃል; በv1.0 ውስጥ፣ ማረጋገጫ በ`attestation_pubkey` ሊከናወን ይችላል።
