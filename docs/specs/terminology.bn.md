# 📚 প্রযুক্তিগত শব্দ এবং ধারণার শব্দকোষ
> **"এই প্রোটোকলের ভাষা বোঝা মানে এর দৃষ্টিভঙ্গি বোঝা।"**

## ⚙️ PoArt ফরেনসিক ইঞ্জিন (PFE) v1.0: মৌলিক অবকাঠামো

**PoArt ফরেনসিক ইঞ্জিন (PFE)** হল সেই মূল স্তর যা [PoArt] প্রোটোকলের পেছনে কেন্দ্রীয় যুক্তি এবং প্রযুক্তিগত পরিচালনার প্রতিনিধিত্ব করে। এটি একটি "ফরেনসিক ইঞ্জিন" যা শিল্প উৎপাদনের কাঁচা ডেটা নিয়ে এবং এটিকে **ডিজিটাল প্রমাণে** রূপান্তরিত করে যা যাচাইযোগ্য এবং অপরিবর্তনীয়।

### 🧩 "PoArt Forensic" কেন?

- **PoArt (শিল্পের প্রমাণ):** ইঞ্জিনের উদ্দেশ্য হল ডিজিটাল সম্পদের মূল্যকে অনুমানের সাথে নয় বরং **যাচাইযোগ্য উৎপাদন প্রক্রিয়ার** সাথে যুক্ত করা।
- **Forensic (বৈজ্ঞানিক যাচাইকরণ):**
  - **প্রযুক্তিগত সংজ্ঞা:** উৎপাদন প্রক্রিয়া ডেটায় (ব্রাশ স্ট্রোক, টাইম ভিডিও, রেকর্ড) হস্তক্ষেপ না করা হয়েছে তা যাচাই করার জন্য অ্যালগরিদমিক পদ্ধতি এবং রেকর্ড ক্রম।
  - **দার্শনিক স্তর:** **মানুষের সময়, শ্রম এবং সিদ্ধান্তের খরচ** পরিমাপযোগ্য সত্যে রূপান্তরিত করার দাবি, AI-র "তাৎক্ষণিক ফলাফল" উৎপাদনের বিপরীতে।

> নোট: ব্লকচেইন একীকরণ (যেমন, Solana) PFE-র মূল অংশ নয়; এটি যাচাইকরণ/নিবন্ধন উদ্দেশ্যে **চেইন অ্যাঙ্কর লেয়ার** হিসাবে আলাদাভাবে বর্ণনা করা হবে।

### 🛠️ প্রযুক্তিগত পরিধি v1.0

**PoArt ফরেনসিক ইঞ্জিন (PFE) v1.0** জটিল আর্থিক মডেলের পরিবর্তে নিম্নলিখিত **3টি মূল স্তম্ভের** উপর নির্মিত:

1. **Hashing & Sealing (সিল করা):**  
   PFE প্রমাণ প্যাকেজে সমস্ত উপাদান (কাজের ফাইল, ভিডিও, JSON/রেকর্ড, স্বাক্ষর, ইত্যাদি) নির্ধারিত পদ্ধতিতে প্রক্রিয়া করে এবং একটি অনন্য **NotarySeal** মান তৈরি করে।

   **মূল ধারণা (v1.0):**
   - **FileHash (কাজের ফিঙ্গারপ্রিন্ট):** কাজের ফাইল বাইট থেকে তৈরি হ্যাশ।
   - **EvidenceRoot (প্রমাণ প্যাকেজের মূল):** প্রমাণ প্যাকের অখণ্ডতার প্রতিনিধিত্বকারী রুট সারাংশ (Merkle রুট অথবা ক্যানোনিকাল প্রতিনিধিত্বের হ্যাশ)।
   - **NotarySeal (চূড়ান্ত সিল / PFE আউটপুট):** EvidenceRoot + সময় + স্বাক্ষরের সমন্বয় থেকে তৈরি চূড়ান্ত সিল।

   **সূত্র (বিনিয়োগকারীদের স্পষ্টভাবে দেখানো):**
   
   $$\text{FileHash}_{512} = \text{SHA-512}(\text{ArtworkFileBytes})$$
   
   $$\text{NotarySeal} = \text{SHA-512}(\text{EvidenceRoot} \mid \text{SignerSignature} \mid \text{TimeStamp})$$
   
   **ক্যানোনিকাল পেলোড সংজ্ঞা (v1.0):**
   
   - **EvidenceRootPayload:**
```
   file_sha512:{sha512}\nforensics:{canonicalForensics(forensics)}
```
   
   - **NotarySealPayload:**
```
   evidence_root:{evidence_root}\nsigner_sig:{signer_sig}\ntimestamp:{timestamp}
```
   
   > নোট: PFE আউটপুট হিসাবে উল্লেখিত মান হল **NotarySeal**। **SignerSignature** প্রক্রিয়া পর্যায় 2-তে (Solana Wallet Adapter-এর সাথে) সক্রিয় করা হবে; বর্তমান v1.0-এ, সিস্টেমের প্রমাণীকরণ স্বাক্ষর ব্যবহার করা হয়। প্রমাণীকরণ পাবলিক কী রেজিস্ট্রিতে `issuer.attestation_pubkey` ফিল্ডের অধীনে প্রকাশিত হয়।

2. **Indexing (সংরক্ষণ):**  
   কোন ওয়ালেট, কোন তারিখে, **কাজের প্রমাণ** কোন কাজের জন্য স্পষ্ট এবং প্রশ্নযোগ্য রেজিস্টার স্তরে পাঠিয়েছে তা লিখে।  
   *(এই স্তর ডাটাবেস হতে পারে; চেইন একীকরণ আলাদাভাবে "চেইন অ্যাঙ্কর লেয়ার" হিসাবে বর্ণনা করা হয়েছে।)*

3. **Verification (যাচাইকরণ):**  
   কাজের বৈধতা নিয়ে প্রশ্ন উত্থাপিত হলে, PFE কাঁচা প্রমাণগুলি পুনরায় প্রক্রিয়া করে; গণনাকৃত **EvidenceRoot / NotarySeal** মান সংরক্ষিত রেকর্ডের সাথে মিলছে কিনা গাণিতিকভাবে পরীক্ষা করে।

### 🧮 PoArt মূল্য তত্ত্ব (The Value Theorem)

[PoArt] প্রোটোকল ডিজিটাল সম্পদের মূল্য ($V$) অস্পষ্ট বাজার ধারণার সাথে যুক্ত করে না, বরং **উৎপাদন প্রক্রিয়ার ভৌত বাস্তবতার** সাথে যুক্ত করে।

কৃত্রিম বুদ্ধিমত্তা (AI) তাৎক্ষণিক ফলাফল প্রদান করে প্রক্রিয়াকে ধ্বংস করে ($t \to 0$)। [PoArt], তবে, মূল্যকে **সময়, শ্রম এবং এজেন্সি** উপাদানের সঞ্চয় হিসাবে সংরক্ষণ করে।

$$V_{\text{PoArt}} = \int_{t_{\text{start}}}^{t_{\text{end}}} \left(P_{\text{labor}}(t) \cdot I_{\text{agency}}(t)\right) dt + U_{\text{irreversible}}$$

#### ভেরিয়েবলের সংজ্ঞা

- **$\int dt$ (প্রক্রিয়া সঞ্চয়):**  
  মূল্য "তাৎক্ষণিক ফলাফল" নয়; এটি $t_{\text{start}}$ এবং $t_{\text{end}}$-র মধ্যে সংগৃহীত **প্রক্রিয়া**। মেয়াদ হ্রাসের সময় (AI উৎপাদন), একীকরণ ফলাফল 0-র কাছাকাছি পৌঁছায়।

- **$P_{\text{labor}}(t)$ (তাৎক্ষণিক শ্রম শক্তি):**  
  উৎপাদন সময় ব্যয় করা মানসিক এবং শারীরিক শ্রমের তীব্রতার প্রতিনিধিত্ব করে। যাচাইযোগ্য শ্রম বাড়ার সময়, ইন্টিগ্র্যান্ড বৃদ্ধি পায়।  
  > নোট: এই শব্দটি ব্যবহারিকভাবে "পরিমাপযোগ্য/যাচাইযোগ্য শ্রম সংকেত" দ্বারা সাধারণীকরণ করা যেতে পারে।

- **$I_{\text{agency}}(t)$ (এজেন্সি ফ্যাক্টর):**  
  সৃষ্টিকর্তার ঝুঁকি নেওয়া এবং সিদ্ধান্ত নেওয়ার ক্ষমতা। এটি $0$ এবং $1$-র মধ্যে মান নেয়।
  - **AI ($I \approx 0$):** আদেশ বাস্তবায়ন করে, কোন ঝুঁকি নেয় না, কোন খরচ দেয় না।
  - **মানুষ ($I \to 1$):** সিদ্ধান্ত পরিবর্তন করে, দ্বিধা করে, ঝুঁকি নেয়।

- **$U_{\text{irreversible}}$ (অপরিবর্তনীয় অনন্যতা):**  
  ডিজিটাল উৎপাদনে পূর্বাবস্থায় ফেরানো (`Ctrl+Z`) সম্ভব হওয়া সত্ত্বেও, ভৌত উৎপাদনে (ক্যানভাসে প্রয়োগ করা রঙ, খোদাই করা পাথর, সরাসরি সম্প্রচারে ক্রিয়া) ফেরত যাওয়ার কোন পথ নেই। এই **অপরিবর্তনীয় প্রকৃতি** কাজে "অনন্যতা" (পরিবর্তনহীন বৈশিষ্ট্য) তৈরি করা অতিরিক্ত পদ।

### 🔎 কেস বিশ্লেষণ: AI "তাৎক্ষণিক ফলাফল" বনাম মানুষ "যাচাইকৃত প্রক্রিয়া"

নিচের দৃশ্য **PoArt মূল্য তত্ত্ব** ব্যবহারিকভাবে কিভাবে কাজ করে এবং [PoArt] স্কেলে AI উৎপাদন কম স্কোর পায় কেন তা দেখায়।

#### দৃশ্য A: AI-এর সাথে 10-সেকেন্ড দৃশ্য উৎপাদন

- **মেয়াদ ($\Delta t$):** $10$ সেকেন্ড (ছোট প্রক্রিয়া)
- **শ্রম শক্তি ($P_{\text{labor}}$):** $1$ ইউনিট (শুধুমাত্র আদেশ লেখা)
- **এজেন্সি ফ্যাক্টর ($I_{\text{agency}}$):** $0.01$ (কোন ঝুঁকি নেই, কোন খরচ নেই)
- **অপরিবর্তনীয় প্রকৃতি ($U_{\text{irreversible}}$):** $0$ (বিপরীত করা যায় / কপি করা যায়)

**ফলাফল:**

$$V_{\text{AI}} \approx \int_{0}^{10} (1 \cdot 0.01) \, dt + 0 = 0.1$$

> **মন্তব্য:** ফলাফল নিখুঁত হওয়া সত্ত্বেও; [PoArt] মূল্য $0$-র কাছাকাছি পৌঁছায় কারণ কোন প্রক্রিয়া বাস করেনি এবং কোন এজেন্সি/ঝুঁকি জড়িত ছিল না।

#### দৃশ্য B: সরাসরি সম্প্রচারে 6-ঘন্টার ভৌত উৎপাদন

- **মেয়াদ ($\Delta t$):** $6$ ঘন্টা ($21{,}600$ সেকেন্ড)
- **শ্রম শক্তি ($P_{\text{labor}}$):** $0.5$ ইউনিট (ক্রমাগত শারীরিক এবং মানসিক শ্রম)
- **এজেন্সি ফ্যাক্টর ($I_{\text{agency}}$):** $0.9$ (সিদ্ধান্ত পরিবর্তন, ঝুঁকি নেওয়া, অপরিবর্তনীয় পছন্দ)
- **অপরিবর্তনীয় প্রকৃতি ($U_{\text{irreversible}}$):** $>0$ (ভৌত সংকেত ফেরত করা যায় না)

**ফলাফল:**

$$V_{\text{Human}} \approx \int_{0}^{21600} (0.5 \cdot 0.9) \, dt + U_{\text{irreversible}} \approx 9720 + U_{\text{irreversible}}$$

> **মন্তব্য:** প্রক্রিয়ার সম্প্রসারণ এবং এজেন্সি (ঝুঁকি) বৃদ্ধির সাথে, মূল্য সঞ্চিত রূপে জমা হয়। $U_{\text{irreversible}}$ পদ কাজে "অনন্যতা" (পরিবর্তনহীন বৈশিষ্ট্য) তৈরি করা অতিরিক্ত অবদান।

### ✅ উপসংহার: প্রমাণ-বাউন্ড মূল্য (Proof-Bound Value)

এই তত্ত্ব [PoArt]-এর মূল্য দাবিকে "পছন্দ" বা "বাজারের গল্প" থেকে টেনে এবং এটিকে **যাচাইযোগ্য উৎপাদন বাস্তবতার** সাথে যুক্ত করে।

1. **প্রক্রিয়া না থাকলে, মূল্য নেই:**  
   AI তাৎক্ষণিক ফলাফল দিয়ে প্রক্রিয়াকে ধ্বংস করে ($t \to 0$)। প্রক্রিয়া উইন্ডো সংকুচিত হওয়ার সময়, একীকরণ ফলাফল হ্রাস পাওয়া উচিত:
   
   $$\Delta t \downarrow \ \Rightarrow\ \int \left(P(t) \cdot I(t)\right) dt \to 0$$

2. **এজেন্সি এবং ঝুঁকি গুণক:**  
   [PoArt] শুধু "ব্যয় করা সময়" পরিমাপ করে না বরং সেই সময়ের মধ্যে সিদ্ধান্ত, ঝুঁকি এবং খরচের প্রকৃত স্তরও পরিমাপ করে। ঝুঁকি ছাড়া উৎপাদন (AI) কম মূল্যবান:
   
   $$V_{\text{PoArt}} \propto \int \left(P_{\text{labor}}(t) \cdot I_{\text{agency}}(t)\right) dt$$

3. **অনন্যতা হল ভৌত প্রমাণ, মার্কেটিং নয়:**  
   ভৌত উৎপাদনে অপরিবর্তনীয় সংকেত (ক্যানভাস স্ট্রোক, পাথরের টুকরা) ডিজিটালের `Ctrl+Z` যুক্তির বাইরে। এই অপরিবর্তনীয় প্রকৃতি ($U_{\text{irreversible}}$) কাজকে অস্তিত্ব দ্বারা অনন্য করে তোলে।

> **🔐 সারাংশ:** মূল্য তত্ত্ব পরিমাপ হিসাবে অনিশ্চয়তার মতো দেখাতে পারে (বাস্তব বিশ্বের সমতুল্য সম্পূর্ণভাবে পরিমাপ করা না যাওয়া সত্ত্বেও), এই সূত্রের উদ্দেশ্য হল ভেরিয়েবল স্থাপনা এবং দিকনির্দেশনা দেখানো। AI যুগে, দুর্লভ জিনিস "ছবি" নয় বরং **যাচাইযোগ্য কাজ, সময় এবং এজেন্সি**। [PoArt] এই দুর্লভতা পরিমাপ করে এবং এটিকে **প্রমাণ প্যাকেজের সাথে** লিখে।

### 🏛️ "ইঞ্জিন" ধারণার গুরুত্ব

Pump.fun বা অনুরূপ প্ল্যাটফর্মগুলি থেকে আসা টোকেন প্রায়শই শুধু **"প্রবেশ টিকিট"** হয়। **PoArt ফরেনসিক ইঞ্জিন (PFE)**, তবে, **সাংবিধানিক যুক্তি স্তর** যা সিদ্ধান্ত নেয় এই টিকিট কোন অধিকার সুরক্ষিত করে, কাজ কিভাবে লেখা হবে এবং শিল্প/বিজ্ঞান/প্রযুক্তি কিভাবে সংরক্ষণ করা হবে।

## a) [PoArt] কি? (দার্শনিক এবং প্রযুক্তিগত সংজ্ঞা)

Bitcoin *"বিদ্যুৎ এবং প্রসেসর শক্তি দিয়ে"* **(কাজের প্রমাণ)** মূল্য তৈরি করে, তেমনি [PoArt]-এর সাথে যুক্ত প্রকল্প *"শিল্প দক্ষতা এবং মানব সময় দিয়ে"* মূল্য তৈরি করে।

এটি Pump.fun এবং DEX প্ল্যাটফর্মে *"ডেভেলপার বিক্রয় করেছে, প্রকল্প শেষ"* ঝুঁকি দূর করে; কারণ এখানে মূল্য কোডে নয় বরং **উৎপাদনের ধারাবাহিকতায়**।

> **[PoArt] অংশগ্রহণকারীদের "আমাদের বিশ্বাস করুন" বলে না; "এটি প্রমাণ, নিজের চোখে দেখুন, নিজের গণিতে যাচাই করুন" বলে।**

## b) [PoArt]-এর 5-স্তম্ভ মান (সত্যের 5 স্তম্ভ)

এই 5টি আইটেম অপরিবর্তনীয় ফিল্টার যার মধ্য দিয়ে একটি প্রকল্পকে [PoArt] সিল পেতে পাস করতে হবে।

### 1) সরাসরি পরিচয়ের প্রমাণ

- **সমস্যা:** ক্রিপ্টো জগত অস্পষ্ট পরিচয়ের অজানা প্রতিষ্ঠাতাদের (Devs) দিয়ে পূর্ণ যারা অর্থ সংগ্রহ করে এবং প্রকল্প ছেড়ে দেয়।
- **[PoArt] সমাধান:** সৃষ্টিকর্তা শুধু পরিচয়ই যাচাই করে না বরং **উৎপাদন সময় উপস্থিতিও** যাচাই করে। এতে সরাসরি সম্প্রচারের সেশন অন্তর্ভুক্ত যেখানে সম্প্রদায়ের কথোপকথন হয় এবং বিশেষ অনুরোধ তাৎক্ষণিকভাবে বাস্তবায়িত হয়, পূর্বরেকর্ড করা ভিডিও নয়।  
  (উদাহরণস্বরূপ, *"আজকের তারিখ এবং বর্তমান ব্লক নম্বর ক্যানভাসের ডান কোণে লিখুন"*)
- **স্লোগান:** *"বট পেইন্ট করতে পারে কিন্তু বট ঘামায় না এবং ইম্প্রোভাইজ করতে পারে না।"*

### 2) কাজ এবং প্রক্রিয়ার প্রমাণ

- **সমস্যা:** 2 সেকেন্ডে তৈরি AI (কৃত্রিম বুদ্ধিমত্তা) ছবি ডিজিটাল জগতে 2 মাসে করা তেল চিত্রকে সমান "jpeg" চিকিত্সা পায়।
- **[PoArt] সমাধান:** কাজের "গর্ভধারণ এবং জন্ম" প্রক্রিয়া লেখা হয়। স্কেচ পর্যায়, পেইন্টিং পর্যায়, সঞ্চিত ব্যয়িত ঘন্টা এবং শিল্পী কাজ তৈরির সময় কাটানো ভৌত প্রক্রিয়া লেখা হয়। এটি টোকেনে **"সময়ের খরচ"** যোগ করে। সম্পদ উৎপাদন কঠিন, এর মূল্য শক্তিশালী।

### 3) সৌন্দর্য মূল্যের প্রমাণ

- **সমস্যা:** "মেমে" সংস্কৃতি যা শুধুমাত্র তাৎক্ষণিক হাসিতে মনোনিবেশ করে যখন সৌন্দর্য এবং শৈল্পিক গভীরতা উপেক্ষা করা হয়, যা স্বল্পমেয়াদী "Hype" প্রকল্পের কারণ হয়।
- **[PoArt] সমাধান:** প্রকল্পে একাডেমিক শিল্প মান, রঙ তত্ত্ব, রচনা নিয়ম এবং উপাদান জ্ঞান (Impasto, Texture, ইত্যাদি) থাকতে হবে। বিষয়বস্তু শুধু আপনাকে হাসাতে হবে না; এটি দর্শকদের মধ্যে বিস্ময় তৈরি করা উচিত এবং **সংগ্রহ মূল্য** থাকা উচিত।

### 4) ধারণা নতুনত্ব

- **সমস্যা:** সৃজনশীলতা ছাড়া হাজার হাজার কুকুর/বিড়াল টোকেনের অনুলিপি।
- **[PoArt] সমাধান:** প্রকল্পকে শিল্প, বিজ্ঞান, দর্শন বা প্রযুক্তিকে অর্থবহ কাঠামোতে সংযোগকারী নতুন সেতু তৈরি করতে হবে।  
  (উদাহরণস্বরূপ, প্রাচীন ডেভিড মূর্তিকে ক্রিপ্টো বাজার ডেটার সাথে সংযুক্ত করা; মানব ধারণা "পাথরে পরিণত হচ্ছে" ধারণাটি এর মাধ্যমে প্রক্রিয়া করা এবং বৈজ্ঞানিক সূত্র দিয়ে ভিত্তি দেওয়া।)  
  কাজ শুধু দৃশ্য আমন্ত্রণ হওয়া উচিত নয় বরং **বিজ্ঞান, দর্শন বা প্রযুক্তি** সম্পর্কে চিন্তা উদ্দীপনাকারী বৌদ্ধিক চ্যালেঞ্জও হওয়া উচিত।

> [!IMPORTANT]
> **স্মরণীয় উদাহরণ (লাস পালমিটাস প্রভাব):** মেক্সিকোর লাস পালমিটাস এলাকায়, অপরাধে পীড়িত, 200-এর বেশি বাড়ি একটি বিশাল রংধনু প্রদর্শনীতে রূপান্তরিত করা হয়েছিল। এই সৌন্দর্য হস্তক্ষেপের ফলে, এলাকায় অপরাধের মাত্রায় উল্লেখযোগ্য হ্রাস পেয়েছে, এবং যুবকরা অপরাধী গ্যাংয়ের পরিবর্তে শিল্পে অংশগ্রহণ শুরু করেছে। সৌন্দর্য রূপান্তর মানুষের তাদের পরিবেশ এবং একে অপরের প্রতি সম্মান পুনঃলিখন করেছে (সামাজিক একীকরণ)।
>
> **প্রত্যাশা:** [PoArt] তালিকায় প্রবেশকারী প্রকল্পকে, উপরোক্ত উদাহরণের মতো, দৃশ্য সৌন্দর্যের বাইরে সামাজিক, বৈজ্ঞানিক বা দার্শনিক কারণ এবং ফলাফল সম্পর্ক থাকতে হবে। সময় একমাত্র সম্পদ যা অর্থ দিয়ে কেনা যায় না তাই, এই প্রোটোকলে সময়কে নিরাপত্তা হিসাবে রেখে যাচাই করা উচিত। প্রকল্পের ধারণা ভিত্তি এত শক্তিশালী এবং সর্বব্যাপী হওয়া উচিত যে, বছরের পর বছর সম্ভাব্য CTO (কমিউনিটি টেকওভার) পরিস্থিতিতেও, সম্প্রদায় এই উত্তরাধিকার উত্তরাধিকারসূত্রে পেয়ে প্রকল্পের সৃজনশীল ক্ষমতা স্বাধীনভাবে চালিয়ে যেতে পারে।

### 5) অ্যালগরিদমিক নয় এজেন্সি

- **সমস্যা:** নিখুঁত কিন্তু আত্মা ছাড়া পুনরাবৃত্ত ডিজিটাল উৎপাদন।
- **[PoArt] সমাধান:** ভুল করতে পারে, ঝুঁকি নিতে পারে এবং আবেগজনিত পরিবর্তন অনুভব করতে পারে এমন মানুষের অনন্য এজেন্সি কাজে অনুভূত হওয়া উচিত। ব্রাশ স্ট্রোকে অনিশ্চয়তা, উপাদানের আকস্মিক প্রতিক্রিয়া এবং শিল্পীর তাৎক্ষণিক সিদ্ধান্ত **জৈবিক স্বাক্ষর** যা কাজকে "যান্ত্রিক উৎপাদন" থেকে আলাদা করে।

> *সম্মতি নোট:* "প্রমাণ প্যাকেজ" শব্দ পূর্ববর্তী অংশে চেইন **প্রমাণ প্যাকেজ → EvidenceRoot → NotarySeal**-এর সাথে সংযুক্ত; অর্থাৎ, প্যাকেজের অখণ্ডতা যাচাইযোগ্য সিল দ্বারা উপস্থাপিত হয়।

### 🔄 365-দিনের পুনর্নবীকরণ (স্থায়িত্ব প্রোটোকল)

- **বিপ্লবী বৈশিষ্ট্য:** ক্রিপ্টো প্রকল্পে "Dev" (ডেভেলপার) সাধারণত টোকেন প্রকাশ করে এবং সাধারণত 1-2 মাস পরে অদৃশ্য হয়ে যায় (নরম রাগ)। [PoArt] এটি অসম্ভব করে তোলে।
- **নিয়ম:** "যাচাইকৃত শিল্পী" অবস্থা সারাজীবন নয়। শুধুমাত্র **1 বছর** বৈধ।
- **অপারেশন:** শিল্পী/ডেভেলপারকে প্রতি 365 দিনে সম্প্রদায়কে **নতুন গুরুত্বপূর্ণ এবং যাচাইযোগ্য কাজ** উপস্থাপন করতে হবে।
- **দৃশ্য উদাহরণ:** আপনি 2026 সালে প্রকল্প শুরু করেছেন। জানুয়ারী 2027-এ, সিস্টেম "প্রমাণ মেয়াদ শেষ" সতর্কতা দেয়। যদি শিল্পী নতুন প্রদর্শনী, নতুন ভৌত কাজ বা নতুন প্রযুক্তিগত একীকরণ উপস্থাপন না করে তবে প্রকল্পের "বিশ্বাস ব্যাজ" পড়ে যায়।
- **ফলাফল:** এই সিস্টেম নিশ্চিত করে যে **বিষয়বস্তু কখনও প্রাসঙ্গিকতা হারায় না** এবং বিনিয়োগকারী কখনো *"ডেভেলপার এখনও আছে?"* ভয় পায় না। প্রকল্প জীবন্ত স্টুডিও হয়ে যায়।

## 🗳️ 6) গভর্নেন্স এবং পাবলিক রেজিস্ট্রি

**এই অংশের উদ্দেশ্য: [PoArt] মানকে "ব্যক্তিদের উপর বিশ্বাস" স্তর থেকে রেজিস্টার + যাচাইকরণ + সম্প্রদায় তত্ত্বাবধানের সাথে টেকসই পাবলিক অবকাঠামোতে রূপান্তর করা।**

### 6.1 পাবলিক রেজিস্ট্রি

- **পাবলিক রেজিস্ট্রি:** সমস্ত অনুমোদিত ডেটা `ilhanart.org/registry` (বা GitHub Registry) এ লেখা হয়।

**রেজিস্টার যুক্তি (প্রস্তাবিত মান - JSON পথ ফর্ম্যাটে):**

রেজিস্ট্রিতে প্রবেশকারী প্রতিটি এন্ট্রিতে এই ন্যূনতম যাচাইযোগ্য মূল ফিল্ড রয়েছে:

- **পরিচয় এবং অবস্থা:**
  - `certificate_id` (পাঠযোগ্য রেফারেন্স)
  - `status` (active / void)
  - `void_reason` (যদি প্রযোজ্য হয়)
  - `visibility` (private / masked / public)
  - `created_at` (টাইম স্ট্যাম্প)

- **জারিকারী কর্তৃপক্ষ:**
  - `issuer.name`
  - `issuer.location`
  - `issuer.attestation_pubkey`

- **কাজের তথ্য:**
  - `asset.title`
  - `asset.creator`
  - `asset.creator_wallet` (যদি সম্ভব হয়; টোকেন গেটের সাথে পরিচয়ের জন্য)
  - `asset.fingerprints.sha256`
  - `asset.fingerprints.sha512`

- **ফরেনসিক ডেটা:**
  - `forensics.ip_masked`
  - `forensics.location`
  - `forensics.device`
  - `forensics.timestamp`

- **ক্রিপ্টোগ্রাফিক প্রমাণ:**
  - `proof.evidence_root`
  - `proof.signer_sig`
  - `proof.notary_seal`

- **গভর্নেন্স:**
  - `governance.decision`
  - `governance.veto_threshold`

রেজিস্ট্রির দুটি স্তর হতে পারে:
- **1)** মানব-পাঠযোগ্য সূচক (ওয়েব তালিকা / অনুসন্ধান / ফিল্টার)
- **2)** মেশিন-পাঠযোগ্য প্রতিনিধিত্ব (JSON রেকর্ড; PFE যাচাইকরণের জন্য)

**এই "রেজিস্ট্রেশন" প্রমাণ প্যাকেজ → EvidenceRoot → NotarySeal-এর PFE চেইন দ্বারা যাচাইযোগ্য হয়ে ওঠে। রেজিস্টার যাচাইকরণ লক্ষ্য প্রদান করে, "দাবি" নয়।**

### 6.2 40% কমিউনিটি ভেটো (টোকেন-গেটেড গভর্নেন্স)

- **40% কমিউনিটি ভেটো:** অবস্থা দেওয়ার এক মাস আগে ভোট শুরু হয়; **টোকেন-গেটেড (Solana দিয়ে যাচাইকৃত)** সম্প্রদায়ের 40% ভেটো আবেদন বাতিল করে দেয়।

**ভোটিং প্রবাহ (প্রস্তাবিত স্পষ্ট প্রক্রিয়া):**
- **আবেদন উইন্ডো:** প্রার্থী প্রকল্প "PoArt প্রার্থী নিবন্ধন" খোলে (প্রার্থী রেকর্ড "মুলতুবি অবস্থা" তে দেখায়)।
- **পর্যালোচনা সময়কাল:** সম্প্রদায় 30 দিন পর্যন্ত প্রমাণ পরীক্ষা করে (প্রমাণ প্যাকেজ + সরাসরি সম্প্রচার রেকর্ড + মেটাডেটা)।
- **টোকেন-গেটেড যাচাইকরণ:** ভোটিং যাচাইকৃত Solana ওয়ালেটের সাথে করা হয় (উদাহরণস্বরূপ বিশেষ টোকেন/NFT মালিকানা + ওয়ালেট স্বাক্ষর)।
- **ভেটো নিয়ম:** যদি 40% ভোট **বিরোধিতা (না / ভেটো)** হয় তবে আবেদন বাতিল হয়।
- **স্বচ্ছতা:** ভোটিং ফলাফল রেজিস্ট্রিতে "সিদ্ধান্ত রেকর্ড" (তারিখ, অনুপাত, ছবি ID) হিসাবে সংরক্ষণ করা হয়।

### 6.3 মেটাডেটা সমন্বয় (ভৌত জগতের সাথে সারিবদ্ধকরণ)

- **মেটাডেটা সমন্বয়:** রেজিস্ট্রিতে প্রযুক্তিগত ডেটা ভৌত সত্তার সাথে 100% মিলতে হবে।

**"100% সারিবদ্ধতা"-এর প্রযুক্তিগত সংজ্ঞা (প্রস্তাবিত স্বচ্ছতা):**
- **ন্যূনতম সারিবদ্ধতা (বাধ্যতামূলক):**
  - রেজিস্ট্রিতে `asset.fingerprints.sha256/sha512` আলোচিত ফাইলের হ্যাশের সাথে **অভিন্ন** হতে হবে।
  - রেজিস্ট্রিতে `proof.notary_seal` পুনরায় তৈরি করার সময় (যদি প্রমাণ প্যাকেজ উপস্থিত থাকে), এটি **অভিন্ন** হতে হবে।
- **ভৌত রেফারেন্স সারিবদ্ধতা (প্রমাণ প্রকার):**
  - ভৌত কাজ + সরাসরি সম্প্রচারে দেখানো তারিখ/ব্লক রেফারেন্স এবং একই প্রমাণ প্রমাণ প্যাকেজের সাথে মিলতে হবে।
- **গোপনীয়তা সম্মতি:**
  - `masked` দৃশ্যমানতায় IP/অবস্থানের মতো ফিল্ড **মাস্কিং মানদণ্ড অনুযায়ী** প্রকাশিত হয়।

### 6.4 বিবাদ এবং বাতিলকরণ

রেজিস্টার শুধু "অনুমোদন" প্রক্রিয়া নয়; এটি জালিয়াতির বিরুদ্ধে **জীবন্ত পর্যালোচনা প্রক্রিয়া**।

- বিবাদ শুরু হলে, এন্ট্রিকে **"review" (পর্যালোচনা)** অবস্থায় রাখা যেতে পারে।
- জালিয়াতি আবিষ্কারে, এটিকে `status: void` হিসাবে চিহ্নিত করা হয় এবং কারণ যোগ করা হয়:
  - `void_reason` (AI ব্যবহার / চুরি / হেরফের, ইত্যাদি)
  - `revoked_at` (বাতিল সময়)
- বাতিলকরণ সিদ্ধান্তের উৎস রেজিস্ট্রিতে স্পষ্ট:
  - সম্প্রদায় ভোট / অফিসিয়াল কমিটি / বৈজ্ঞানিক অনুসন্ধান নোট (প্রযোজ্য)

> **এই অংশটি "লাল পতাকা প্রোটোকল" অংশে VOID ধারণার রেজিস্টার যমজ।**

> **"সংস্কৃতি মূলধনের চেয়ে বড়। আজ আপনার কাজ রক্ষা করুন, আগামীকাল নিয়ে যান।"**

---

## পাবলিক কেন?

প্রকৃত নিরাপত্তা স্বচ্ছতা থেকে আসে। আমাদের **পাবলিক রেজিস্ট্রি** সিস্টেমের জন্য ধন্যবাদ, বিশ্বের যেকোনো জায়গায় যে কেউ সেকেন্ডে একটি ফাইল প্রকৃত কিনা যাচাই করতে পারে, কোন কর্তৃপক্ষের প্রয়োজন ছাড়াই।

---

## 🧩 একাধিক "দৃশ্যমানতা মডিউল" কেন?

এটি কোডের সবচেয়ে গুরুত্বপূর্ণ অংশ (দৃশ্যমানতা বিকল্প মেনু)। এই বিকল্পগুলি ব্যবহারকারীদের **"গোপনীয়তা বনাম স্বচ্ছতা"**-তে ভারসাম্য তৈরি করার অনুমতি দেয়:

### 🔒 ব্যক্তিগত

- **দৃশ্য:** শিল্পী এখনও কাজ প্রকাশ করতে চায় না, কিন্তু "আমি এটি এই তারিখে করেছি" প্রমাণ করতে টাইম স্ট্যাম্প করতে চায়।
- **কোড কি করে:** এটি ডাটাবেসে ডেটা লেখে কিন্তু সিলকে `visibility: "private"` হিসাবে চিহ্নিত করে। পরে আপনি "পাবলিক রিড" নীতি লেখার সময়, আপনি এই রেকর্ডগুলি `WHERE visibility = 'public'` দিয়ে মানুষের থেকে লুকাতে পারেন।

### 🕶️ মাস্ক করা

- **দৃশ্য:** শিল্পী স্বচ্ছতা চায় কিন্তু ভয় পায় যে তার বাড়ির ঠিকানা (IP অবস্থান) পাওয়া যাবে।
- **কোড কি করে:** `maskIP` এবং `maskLoc` ফাংশন JavaScript পাশে কাজ করে। এটি IP ঠিকানা `88.241.***.***` ফর্ম্যাটে, অবস্থান `***/TR` ফর্ম্যাটে পরিবর্তন করে, এবং সেন্সর করা সংস্করণ ডাটাবেসে পাঠায়।
- **গোপনীয়তা সত্য:** মাস্কিং ব্রাউজারে করা হয়, Supabase প্রকৃত অবস্থান দেখে না। **কিন্তু:** যদি অবস্থান ডেটার জন্য ipapi.co-র মতো তৃতীয়-পক্ষ APIs ব্যবহার করা হয় তবে, এই প্রদানকারীরা অনুরোধের সময় IP ঠিকানা দেখে।
- **মাস্ক মোডে সিলিং:** EvidenceRoot এবং NotarySeal গণনা মাস্ক করা ফরেনসিক ডেটার সাথে করা হয়; তাই যাচাইকরণ নির্ধারিত থাকে।

### 🌍 পাবলিক

- **দৃশ্য:** সম্পূর্ণ স্বচ্ছতা। [PoArt] মানদণ্ড অনুযায়ী, কোথায়, কখন, কোন নেটওয়ার্ক থেকে কাজ তৈরি করা হয়েছিল তা প্রকাশ্যে ঘোষণা করা হয়।

## 💡 প্রযুক্তিগত নতুনত্ব

PoArt শুধু ফাইল আপলোড সিস্টেম নয়। এটি একটি পাত্রে তিনটি ভিন্ন প্রযুক্তিগত স্তর মিশিয়ে নতুন মান আনা **"বৈজ্ঞানিক যত্ন চেইন"** ইঞ্জিন।

**এই অংশে "ইঞ্জিন" হিসাবে বর্ণিত স্তর পূর্ববর্তী শর্তে PoArt ফরেনসিক ইঞ্জিন (PFE)-এর মূলের সাথে মিলে যায়।**

### 1) ক্লায়েন্ট-সাইড হ্যাশিং (সর্বোচ্চ গোপনীয়তা)

আপনার শিল্পের টুকরোগুলির ফাইল সার্ভারে আপলোড করা হয় না। আমাদের ব্রাউজার-ভিত্তিক (ক্লায়েন্ট-সাইড) ইঞ্জিন আপনার নিজের কম্পিউটারে ফাইলের হ্যাশ (ডিজিটাল সারাংশ) গণনা করে। শুধুমাত্র এই ফিঙ্গারপ্রিন্ট এবং মেটাডেটা সার্ভারে পাঠানো হয়।

> **গোপনীয়তা সত্য:** কাজের ফাইল সার্ভারে আপলোড হয় না এবং এইভাবে নিরাপদ। তবে, ফরেনসিক ডেটা (IP/অবস্থান) নির্বাচিত দৃশ্যমানতা মোড (ব্যক্তিগত/মাস্ক/পাবলিক) অনুযায়ী শেয়ার করা হয়।

### 2) ফরেনসিক ডেটা ফিউশন (বৈজ্ঞানিক শক্তি)

সাধারণ টাইম স্ট্যাম্পের চেয়ে বেশি। সিস্টেম এই ডেটাকে একটি "রুট সিল" এ যুক্ত করে:

- **ডিজিটাল সারাংশ (SHA-512):** ক্রিপ্টোগ্রাফিক সারাংশ মান (SHA-512) ব্যবহার করে ফিঙ্গারপ্রিন্ট যা কাজের একটি পিক্সেল পরিবর্তনেও ভাঙবে।
- **অবস্থান এবং সময়:** মিলিসেকেন্ড নির্ভুলতার সাথে তারিখ, দেশ, শহর এবং জেলা ডেটা এনকোডিং।
- **যন্ত্র পরিচয়:** অপারেটিং সিস্টেম, ব্রাউজার এবং যন্ত্রের ধরন (User-Agent বিশ্লেষণ)।

## 🛡️ ব্যবহারের ক্ষেত্রে এবং সুবিধা

যদি আপনি শিল্পী, লেখক বা ডিজাইনার হন, "আমি এটি প্রথম করেছি" বলা যথেষ্ট নয়; আপনাকে প্রমাণ করতে হবে।

**আপনি PoArt দিয়ে সিল করা কাজ:**

- **গাণিতিক প্রমাণ:** আপনার ফাইলের একটি পিক্সেলও পরিবর্তিত হলে, সিস্টেম জানে। হেরফের অসম্ভব।
- **আইনি ভিত্তি:** কোন তারিখ, কোন শহর, কোন যন্ত্র থেকে কাজ সিল করা হয়েছিল তা লেখা আছে।
- **তাৎক্ষণিক সার্টিফিকেট:** এটি সেকেন্ডে আপনার জন্য বিশেষ **"সম্পদ পরিচয় সার্টিফিকেট"** তৈরি করে, QR কোড এবং সিল করা।

## 🗺️ রোডম্যাপ: ভবিষ্যত "বিশ্বাসহীন"

বর্তমান সংস্করণ **(Beta v1.0)** শেষ ব্যবহারকারীদের সর্বাধিক গতি, সহজ ইন্টারফেস এবং বিনামূল্যে অ্যাক্সেস দেওয়ার জন্য ডিজাইন করা হয়েছে। আমাদের চূড়ান্ত দৃষ্টিভঙ্গি, তবে, এমন একটি কাঠামোতে রূপান্তর যেখানে ডাটাবেস ম্যানেজার (আমরা) এমনকি হস্তক্ষেপ করতে পারি না।

### পর্যায় 1: বিটা (এখন সরাসরি)

- **অবকাঠামো:** ক্লাউড ডাটাবেস (Supabase)।
- **উদ্দেশ্য:** গতি, UX (ব্যবহারকারী অভিজ্ঞতা) বাধা অপসারণ এবং সম্মতি। "ঘর্ষণ-মুক্ত" নিরাপত্তা প্রদান করা।

## 🔬 প্রযুক্তিগত গভীরতা: সিল অ্যালগরিদম

### নির্ধারিত হ্যাশ ফাংশন
```javascript
// সহায়ক ফাংশন: সারাংশকে হেক্সাডেসিমাল স্ট্রিংয়ে রূপান্তর করুন
async function digestToHex(algorithm, dataBytes) {
  const hashBuffer = await crypto.subtle.digest(algorithm, dataBytes);
  const hashArray = Array.from(new Uint8Array(hashBuffer));
  return hashArray.map(b => b.toString(16).padStart(2, '0')).join('');
}

// স্ট্রিংকে বাইট অ্যারেতে রূপান্তর করুন
function stringToBytes(text) {
  return new TextEncoder().encode(text);
}

// ক্যানোনিকাল ফরেনসিক্স স্ট্রিং সৃষ্টি (v1.0: স্থির ফিল্ড ক্রম + UTF-8 + ডিলিমিটার \n)
// পর্যায় 2 সত্য: RFC 8785 (JCS) দিয়ে ক্যানোনিকাল JSON-এ রূপান্তর
function canonicalForensics(forensicsData) {
  return JSON.stringify({
    ip_masked: forensicsData.ip_masked,
    location: forensicsData.location,
    device: forensicsData.device,
    timestamp: forensicsData.timestamp
  });
}
```

### NotarySeal সৃষ্টি প্রক্রিয়া (সম্পূর্ণভাবে নির্ধারিত)
```javascript
// 1. FileHash গণনা (ক্লায়েন্ট-সাইড)
async function computeFileHash(file) {
  const fileBuffer = await file.arrayBuffer();
  const fileBytes = new Uint8Array(fileBuffer);
  
  const sha256 = await digestToHex('SHA-256', fileBytes);
  const sha512 = await digestToHex('SHA-512', fileBytes);
  
  return { sha256, sha512 };
}

// 2. ফরেনসিক ডেটা সংগ্রহ (একক টাইম স্ট্যাম্পের ব্যবহার)
async function collectForensics(visibilityMode) {
  const timestamp = new Date().toISOString(); // একক টাইম স্ট্যাম্প সৃষ্টি
  const ipData = await fetch('https://ipapi.co/json/').then(r => r.json());
  
  let forensics = {
    ip_masked: visibilityMode === 'masked' ? maskIP(ipData.ip) : ipData.ip,
    location: visibilityMode === 'masked' 
      ? `***/${ipData.country}` 
      : `${ipData.city}, ${ipData.country_name || ipData.country}`,
    device: navigator.userAgent,
    timestamp: timestamp // একই টাইম স্ট্যাম্প
  };
  
  return { forensics, timestamp };
}

// 3. EvidenceRoot নির্মাণ (ক্যানোনিকাল এনক্রিপশনের সাথে)
async function computeEvidenceRoot(fileHash512, forensicsData) {
  const canonicalPayload = `file_sha512:${fileHash512}\nforensics:${canonicalForensics(forensicsData)}`;
  return await digestToHex('SHA-512', stringToBytes(canonicalPayload));
}

// 4. NotarySeal সৃষ্টি (একই টাইম স্ট্যাম্পের ব্যবহার)
async function computeNotarySeal(evidenceRoot, signerSignature, timestamp) {
  const sealPayload = `evidence_root:${evidenceRoot}\nsigner_sig:${signerSignature}\ntimestamp:${timestamp}`;
  return await digestToHex('SHA-512', stringToBytes(sealPayload));
}

// মাস্কিং সহায়ক ফাংশন (IPv4 এবং IPv6 সমর্থন)
function maskIP(ip) {
  if (!ip) return "***";
  
  // IPv4 পরীক্ষা
  if (ip.includes(".")) {
    const parts = ip.split(".");
    if (parts.length === 4) {
      return `${parts[0]}.${parts[1]}.***.***`;
    }
  }
  
  // IPv6 বা অজানা ফর্ম্যাট
  return "***";
}
```

### যাচাইকরণ প্রবাহ (দুই স্তর)

#### Quick Verify (দ্রুত যাচাইকরণ)
```javascript
// শুধু ফাইল হ্যাশ যাচাই করুন (দ্রুত লাল পতাকা)
async function verifyQuick(file, certificateId) {
  const { sha512: userFileHash } = await computeFileHash(file);
  
  // রেজিস্ট্রি থেকে পুনরুদ্ধার করুন
  const cert = await fetchFromRegistry(certificateId);
  const { sha512: originalHash } = cert.asset.fingerprints;
  
  // হ্যাশ তুলনা
  if (userFileHash === originalHash) {
    return {
      valid: true,
      message: "✅ প্রকৃত - ফাইল হ্যাশ মিলছে"
    };
  } else {
    return {
      valid: false,
      message: "❌ মিথ্যা - ফাইলে হেরফের করা হয়েছে"
    };
  }
}
```

#### Full Verify (সম্পূর্ণ যাচাইকরণ)
```javascript
// EvidenceRoot এবং NotarySeal পুনরায় তৈরি করুন এবং যাচাই করুন
async function verifyFull(file, certificateId) {
  const { sha512: userFileHash } = await computeFileHash(file);

  // রেজিস্ট্রি থেকে পুনরুদ্ধার করুন
  const cert = await fetchFromRegistry(certificateId);

  // 1) FileHash যাচাই (দ্রুত লাল পতাকা)
  const originalHash = cert.asset.fingerprints.sha512;
  if (userFileHash !== originalHash) {
    return { valid: false, message: "❌ মিথ্যা - ফাইল হ্যাশ মিলছে না" };
  }

  // 2) EvidenceRoot পুনরায় তৈরি করুন (রেজিস্ট্রিতে সংরক্ষিত ফরেনসিক ডেটার সাথে)
  const evidenceRoot = await computeEvidenceRoot(userFileHash, cert.forensics);
  if (evidenceRoot !== cert.proof.evidence_root) {
    return { valid: false, message: "❌ মিল নেই - EvidenceRoot দাঁড়ায় না" };
  }

  // 3) NotarySeal পুনরায় তৈরি করুন (একই টাইম স্ট্যাম্প + signer_sig দিয়ে)
  const seal = await computeNotarySeal(
    evidenceRoot,
    cert.proof.signer_sig,
    cert.forensics.timestamp
  );

  if (seal !== cert.proof.notary_seal) {
    return { valid: false, message: "❌ মিল নেই - NotarySeal দাঁড়ায় না" };
  }

  // ঐচ্ছিক: পর্যায় 2-এ, signer_sig ও attestation_pubkey দিয়ে যাচাই করুন
  // const sigValid = await verifySig(cert.issuer.attestation_pubkey, cert.proof.signer_sig, evidenceRoot);
  // if (!sigValid) return { valid: false, message: "❌ ভুল স্বাক্ষর" };

  return { valid: true, message: "✅ প্রকৃত - সম্পূর্ণ যাচাইকরণ সফল" };
}
```

> **গুরুত্বপূর্ণ সত্য:**
> - **Quick Verify:** দ্রুত ব্যবহারের জন্য শুধু ফাইল হ্যাশ যাচাই করে।
> - **Full Verify:** সমস্ত প্রোটোকল স্তর যাচাই করে (EvidenceRoot + NotarySeal)।
> - সমস্ত হ্যাশ ক্রিয়া স্থির এনক্রিপশন এবং স্থির ডিলিমিটার দিয়ে নির্ধারিত পদ্ধতিতে করা হয়।
> - **বর্তমান মান v1.0:** স্থির ফিল্ড ক্রম + UTF-8 এনক্রিপশন + ডিলিমিটার `\n`।
> - **পর্যায় 2 পরিকল্পনা:** RFC 8785 (JCS - JSON Canonicalization Scheme) দিয়ে ক্যানোনিকাল JSON-এ রূপান্তর।
> - মাস্ক মোডে, EvidenceRoot এবং NotarySeal গণনা মাস্ক করা ফরেনসিক ডেটার সাথে করা হয়; তাই যাচাইকরণ নির্ধারিত থাকে।
> - সম্পূর্ণ প্রক্রিয়ায় একক টাইম স্ট্যাম্প ব্যবহার করা হয় (ফরেনসিক্স + NotarySeal); নির্ধারণ গ্যারান্টিযুক্ত।
> - **ফরেনসিক ফিল্ড নাম:** `ip_masked`, `location`, `device`, `timestamp` (কোড এবং রেজিস্ট্রি ঠিক মিলে)।
> - **রেজিস্টার পথ:** `certificate.asset.fingerprints` (যাচাইকরণ কোডের সাথে ঠিক মিলে)।
> - **রেজিস্ট্রিতে signer_sig:** সম্পূর্ণ যাচাইকরণের জন্য `proof.signer_sig` ফিল্ড প্রয়োজন।
> - SignerSignature প্রক্রিয়া পর্যায় 2-এ Solana Wallet Adapter দিয়ে সক্রিয় করা হবে; v1.0-এ, যাচাইকরণ `attestation_pubkey` দিয়ে করা যেতে পারে।
