## ⚙️ PoArt Forensic Engine (PFE) v1.0: Βασική Υποδομή

Το **PoArt Forensic Engine (PFE)** είναι το θεμελιώδες στρώμα που αντιπροσωπεύει τη βασική λογική και την τεχνική λειτουργία πίσω από το πρωτόκολλο [PoArt]. Είναι η "εγκληματολογική μηχανή" που μετατρέπει τα ακατέργαστα δεδομένα παραγωγής ενός έργου τέχνης σε επαληθεύσιμη και αμετάβλητη **ψηφιακή απόδειξη**.

### 🧩 Γιατί "PoArt Forensic";

- **PoArt (Proof of Art):** Η εστίαση της μηχανής είναι η σύνδεση της αξίας ενός ψηφιακού περιουσιακού στοιχείου όχι με κερδοσκοπία, αλλά με την **επαληθευμένη διαδικασία παραγωγής**.
- **Forensic (Εγκληματολογική Επαλήθευση):**
  - **Τεχνικός Ορισμός:** Αλγοριθμική προσέγγιση και αλυσίδα αποδείξεων για την επαλήθευση ότι τα δεδομένα της διαδικασίας παραγωγής (πινελιές, timelapse, αρχεία καταγραφής) δεν έχουν χειραγωγηθεί.
  - **Φιλοσοφικό Επίπεδο:** Ενάντια στην "στιγμιαία παραγωγή" της τεχνητής νοημοσύνης· ισχυρισμός μετατροπής της ανθρώπινης παραγωγής που περιέχει **χρόνο, προσπάθεια και κόστος αποφάσεων** σε μετρήσιμη πραγματικότητα.

> Σημείωση: Η ενσωμάτωση blockchain (π.χ. Solana) δεν είναι ο πυρήνας του PFE· θα οριστεί ξεχωριστά ως **Chain Anchor Layer** για επαλήθευση/μητρώο.

### 🛠️ Τεχνικό Πεδίο v1.0

Το **PoArt Forensic Engine (PFE) v1.0** είναι χτισμένο σε **3 βασικούς πυλώνες** αντί για πολύπλοκα χρηματοοικονομικά μοντέλα:

1. **Hashing & Sealing (Σφράγιση):**  
   Το PFE επεξεργάζεται ντετερμινιστικά όλα τα στοιχεία μέσα στο Evidence Pack (αρχείο έργου, βίντεο, JSON/log, υπογραφή κ.λπ.) και δημιουργεί μια μοναδική τιμή **NotarySeal**.

   **Βασικές έννοιες (v1.0):**
   - **FileHash (αποτύπωμα έργου):** Το hash που δημιουργείται από τα bytes του αρχείου του έργου.
   - **EvidenceRoot (ρίζα πακέτου αποδείξεων):** Η ριζική περίληψη που αντιπροσωπεύει την ακεραιότητα του Evidence Pack (ρίζα Merkle ή hash του κανονικού μανιφέστου).
   - **NotarySeal (τελική σφραγίδα / έξοδος PFE):** Η τελική σφραγίδα που δημιουργείται από τον συνδυασμό EvidenceRoot + χρόνος + υπογραφή.

   **Τύποι (σε μορφή κατανοητή για επενδυτές):**
   
   $$\text{FileHash}_{512} = \text{SHA-512}(\text{ArtworkFileBytes})$$
   
   $$\text{NotarySeal} = \text{SHA-512}(\text{EvidenceRoot} \mid \text{SignerSignature} \mid \text{TimeStamp})$$
   
   **Ορισμοί Canonical Payload (v1.0):**
   
   - **EvidenceRootPayload:**
```
   file_sha512:{sha512}\nforensics:{canonicalForensics(forensics)}
```
   
   - **NotarySealPayload:**
```
   evidence_root:{evidence_root}\nsigner_sig:{signer_sig}\ntimestamp:{timestamp}
```
   
   > Σημείωση: Η τιμή που θεωρείται ως έξοδος PFE είναι το **NotarySeal**. Ο μηχανισμός **SignerSignature** θα ενεργοποιηθεί στη Φάση 2 (με Solana Wallet Adapter)· στην τρέχουσα v1.0 χρησιμοποιείται η δική του υπογραφή πιστοποίησης του συστήματος. Το δημόσιο κλειδί πιστοποίησης δημοσιεύεται στο μητρώο στο πεδίο `issuer.attestation_pubkey`.

2. **Indexing (Αρχειοθέτηση):**  
   Καταγράφει ποιο πορτοφόλι, σε ποια ημερομηνία, παρουσίασε **Labor Proof (Απόδειξη Εργασίας)** για ποιο έργο· σε ένα διαφανές και αναζητήσιμο στρώμα μητρώου.  
   *(Αυτό το στρώμα μπορεί να είναι βάση δεδομένων· η ενσωμάτωση blockchain ορίζεται ξεχωριστά ως "Chain Anchor Layer".)*

3. **Verification (Επαλήθευση):**  
   Όταν η αυθεντικότητα ενός έργου αμφισβητείται, το PFE επεξεργάζεται ξανά τις ακατέργαστες αποδείξεις· ελέγχει με μαθηματική βεβαιότητα εάν οι υπολογισμένες τιμές **EvidenceRoot / NotarySeal** αντιστοιχούν στις καταγραφές στο αρχείο.

### 🧮 Θεώρημα Αξίας PoArt (The Value Theorem)

Το πρωτόκολλο [PoArt] συνδέει την αξία ($V$) ενός ψηφιακού περιουσιακού στοιχείου όχι με την υποκειμενική αντίληψη της αγοράς, αλλά με τη **φυσική πραγματικότητα της διαδικασίας παραγωγής**.

Η Τεχνητή Νοημοσύνη (AI) ακυρώνει τη διαδικασία παρέχοντας στιγμιαία αποτελέσματα ($t \to 0$). Το [PoArt] θεωρεί αντίθετα την αξία ως συσσώρευση των συστατικών **χρόνου, εργασίας και θέλησης**.

$$V_{\text{PoArt}} = \int_{t_{\text{start}}}^{t_{\text{end}}} \left(P_{\text{labor}}(t) \cdot I_{\text{agency}}(t)\right) dt + U_{\text{irreversible}}$$

#### Ορισμός Μεταβλητών

- **$\int dt$ (Συσσώρευση Διαδικασίας):**  
  Η αξία δεν είναι μια στιγμιαία "έξοδος"· είναι μια **διαδικασία** που συσσωρεύεται μεταξύ $t_{\text{start}}$ και $t_{\text{end}}$. Καθώς ο χρόνος μειώνεται (παραγωγή AI), το αποτέλεσμα του ολοκληρώματος προσεγγίζει το 0.

- **$P_{\text{labor}}(t)$ (Στιγμιαία Ένταση Εργασίας):**  
  Αντιπροσωπεύει την ένταση της νοητικής και φυσικής προσπάθειας που δαπανήθηκε τη στιγμή της παραγωγής. Καθώς η επαληθευμένη προσπάθεια αυξάνεται, το ολοκληρωτέο μεγαλώνει.  
  > Σημείωση: Αυτός ο όρος μπορεί να κανονικοποιηθεί στην πράξη σε "μετρήσιμα/επαληθεύσιμα σήματα εργασίας".

- **$I_{\text{agency}}(t)$ (Συντελεστής Θέλησης):**  
  Αυτή είναι η ικανότητα του παραγωγού να αναλαμβάνει ρίσκα και να παίρνει αποφάσεις. Παίρνει τιμές μεταξύ $0$ και $1$.
  - **AI ($I \approx 0$):** Εκτελεί εντολές, δεν αναλαμβάνει ρίσκα, δεν πληρώνει κόστη.
  - **Άνθρωπος ($I \to 1$):** Αλλάζει αποφάσεις, διστάζει, αναλαμβάνει ρίσκα.

- **$U_{\text{irreversible}}$ (Μη Αναστρέψιμη Μοναδικότητα):**  
  Ενώ στην ψηφιακή παραγωγή μπορείς να αναιρέσεις (`Ctrl+Z`)· στη φυσική παραγωγή (μπογιά εφαρμοσμένη σε καμβά, σκαλισμένο μάρμαρο, χειρονομία κατά τη διάρκεια ενός live) δεν υπάρχει επιστροφή. Αυτή η **μη αναστρεψιμότητα** είναι ένας πρόσθετος όρος που δημιουργεί "μοναδικότητα" (μη ανταλλάξιμο χαρακτήρα) στο έργο.

### 🔎 Ανάλυση Περίπτωσης: AI "Στιγμιαία Έξοδος" εναντίον Άνθρωπος "Αποδεδειγμένη Διαδικασία"

Το ακόλουθο σενάριο δείχνει πώς λειτουργεί το **Θεώρημα Αξίας PoArt** στην πράξη και γιατί οι παραγωγές AI λαμβάνουν χαμηλές βαθμολογίες στο πρότυπο [PoArt].

#### Σενάριο A: Οπτική Παραγωγή με AI σε 10 Δευτερόλεπτα

- **Διάρκεια ($\Delta t$):** $10$ δευτερόλεπτα (διαδικασία ουσιαστικά ανύπαρκτη)
- **Ένταση Εργασίας ($P_{\text{labor}}$):** $1$ μονάδα (μόνο γράψιμο εντολής)
- **Συντελεστής Θέλησης ($I_{\text{agency}}$):** $0.01$ (χωρίς ρίσκο, χωρίς κόστος)
- **Μη Αναστρεψιμότητα ($U_{\text{irreversible}}$):** $0$ (αναστρέψιμο / αντιγράψιμο)

**Αποτέλεσμα:**

$$V_{\text{AI}} \approx \int_{0}^{10} (1 \cdot 0.01) \, dt + 0 = 0.1$$

> **Σχόλιο:** Ακόμα κι αν η έξοδος είναι τέλεια· επειδή η διαδικασία δεν έχει βιωθεί και δεν περιέχει θέληση/ρίσκο, η αξία [PoArt] προσεγγίζει το $0$.

#### Σενάριο B: Φυσική Παραγωγή σε Ζωντανή Μετάδοση για 6 Ώρες

- **Διάρκεια ($\Delta t$):** $6$ ώρες ($21{,}600$ δευτερόλεπτα)
- **Ένταση Εργασίας ($P_{\text{labor}}$):** $0.5$ μονάδες (συνέχεια φυσικής και νοητικής προσπάθειας)
- **Συντελεστής Θέλησης ($I_{\text{agency}}$):** $0.9$ (αλλαγή αποφάσεων, ανάληψη ρίσκων, μη αναστρέψιμες επιλογές)
- **Μη Αναστρεψιμότητα ($U_{\text{irreversible}}$):** $>0$ (τα φυσικά ίχνη δεν μπορούν να ακυρωθούν)

**Αποτέλεσμα:**

$$V_{\text{Human}} \approx \int_{0}^{21600} (0.5 \cdot 0.9) \, dt + U_{\text{irreversible}} \approx 9720 + U_{\text{irreversible}}$$

> **Σχόλιο:** Καθώς η διαδικασία επιμηκύνεται και η θέληση (ρίσκο) αυξάνεται, η αξία συσσωρεύεται σωρευτικά. Ο όρος $U_{\text{irreversible}}$ είναι μια πρόσθετη συμβολή που δημιουργεί "μοναδικότητα" (μη ανταλλάξιμο χαρακτήρα) στο έργο.

### ✅ Συμπέρασμα: Αξία Συνδεδεμένη με Απόδειξη (Proof-Bound Value)

Αυτό το θεώρημα αφαιρεί τον ισχυρισμό αξίας [PoArt] από το να είναι ένα "like" ή μια "αφήγηση αγοράς" και τον συνδέει με την **επαληθευμένη πραγματικότητα της παραγωγής**.

1. **Χωρίς Διαδικασία Δεν Δημιουργείται Αξία:**  
   Η AI ακυρώνει τη διαδικασία στη στιγμιαία έξοδο ($t \to 0$). Καθώς το παράθυρο διαδικασίας στενεύει, το αποτέλεσμα του ολοκληρώματος μειώνεται από μαθηματική αναγκαιότητα:
   
   $$\Delta t \downarrow \ \Rightarrow\ \int \left(P(t) \cdot I(t)\right) dt \to 0$$

2. **Η Θέληση και το Ρίσκο είναι Πολλαπλασιαστές:**  
   Το [PoArt] μετρά όχι μόνο τον "χρόνο που δαπανήθηκε", αλλά και το πραγματικό επίπεδο απόφασης, ρίσκου και κόστους σε αυτόν τον χρόνο. Η αξία μιας παραγωγής χωρίς ανάληψη ρίσκων (AI) είναι χαμηλή:
   
   $$V_{\text{PoArt}} \propto \int \left(P_{\text{labor}}(t) \cdot I_{\text{agency}}(t)\right) dt$$

3. **Η Μοναδικότητα είναι Φυσική Απόδειξη, Όχι Μάρκετινγκ:**  
   Στη φυσική παραγωγή, τα μη αναστρέψιμα ίχνη (πινελιά σε καμβά, σπασμένο μάρμαρο) είναι εκτός της ψηφιακής λογικής `Ctrl+Z`. Αυτή η μη αναστρεψιμότητα ($U_{\text{irreversible}}$) καθιστά το έργο οντολογικά μοναδικό.

> **🔐 ΠΕΡΙΛΗΨΗ:** Αν και το θεώρημα αξίας μπορεί να φαίνεται απροσδιόριστο ως μέτρηση (ακόμα κι αν δεν μπορεί να μετρηθεί 100% στην πραγματική ζωή), ο σκοπός αυτού του τύπου είναι να δείξει τη δομή και την κατεύθυνση των μεταβλητών. Αυτό που είναι σπάνιο στην εποχή της AI δεν είναι η "εικόνα", αλλά η **επαληθευμένη εργασία, ο χρόνος και η θέληση.** Το [PoArt] μετρά αυτή τη σπανιότητα και την καταγράφει μέσω του **Evidence Pack**.

### 🏛️ Σημασία της Έννοιας "Engine" (Μηχανή)

Τα tokens που εμφανίζονται σε πλατφόρμες όπως το Pump.fun είναι συχνά μόνο **"εισιτήρια πρόσβασης"**. Το **PoArt Forensic Engine (PFE)** είναι αντίθετα ένα **συνταγματικό λογικό στρώμα** που ορίζει ποια δικαιώματα προστατεύει αυτό το εισιτήριο, πώς καταγράφεται η εργασία και πώς η τέχνη/επιστήμη/τεχνολογία γίνονται μόνιμες.

> **Σημείωση:** Ο λόγος που ξεκινήσαμε αυτό το έργο στο Pumpfun είναι ότι δεν είχαμε αρκετή ρευστότητα και ακόλουθους. Η χρήση υπαρχόντων δεδομένων ήταν ένα στρατηγικά σωστό βήμα, αν και όχι το πιο ποιοτικό. Ο ορισμός της λογικής αυτής της μηχανής στο GitHub, ανεξάρτητα από προϋπολογισμό και πόρους, αποδεικνύει ότι το έργο δεν είναι απλώς χρηματοοικονομική κερδοσκοπία, αλλά ένα μακροπρόθεσμο όραμα **υποδομής λογισμικού** και **ψηφιακής εθνικής βιβλιοθήκης**.

## a) Τι Είναι το [PoArt]; (Φιλοσοφικός και Τεχνικός Ορισμός)

**Proof of Art [PoArt];** είναι ένα θεσμικό πρότυπο επαλήθευσης που εγγυάται ότι η αξία πίσω από ένα περιουσιακό στοιχείο στο blockchain βασίζεται όχι σε κερδοσκοπία, αλλά σε επαληθευμένη **ανθρώπινη εργασία**, **χρόνο** και **φυσική ενέργεια**.

Όπως το Bitcoin παράγει αξία μέσω *"Ηλεκτρικής Ενέργειας και Υπολογιστικής Ισχύος"* **(Proof of Work)**· τα συμβατά έργα με το [PoArt] παράγουν αξία μέσω *"Καλλιτεχνικής Ικανότητας και Ανθρώπινου Χρόνου"*.

Εξαλείφει τον κίνδυνο *"Ο Dev πούλησε, το έργο τελείωσε"*, παρόντα στο Pump.fun και τις πλατφόρμες DEX· γιατί εδώ η αξία δεν είναι στον κώδικα, αλλά στη **συνέχεια της παραγωγής**.

> **Το [PoArt] δεν λέει στον συμμετέχοντα "Εμπιστευτείτε μας"· λέει "Ορίστε οι αποδείξεις, δείτε με τα μάτια σας, επαληθεύστε με τα μαθηματικά σας".**

## b) Το Πρότυπο [PoArt] με 5 Πυλώνες (The 5 Pillars of Truth)

Αυτά τα 5 σημεία είναι μη χειραγωγήσιμα φίλτρα που ένα έργο πρέπει να περάσει για να πάρει τη σφραγίδα [PoArt].

### 1) Απόδειξη Ταυτότητας Live (Live Identity Proof)

- **Πρόβλημα:** Ο κόσμος των κρυπτονομισμάτων είναι γεμάτος ανώνυμους ιδρυτές (Dev) με απροσδιόριστη ταυτότητα που συλλέγουν χρήματα και εγκαταλείπουν το έργο.
- **Λύση [PoArt]:** Ο παραγωγός αποδεικνύει όχι μόνο την ταυτότητα, αλλά **την παρουσία του κατά τη διάρκεια της παραγωγής**. Αυτό περιλαμβάνει συνεδρίες ζωντανής μετάδοσης όπου αλληλεπιδρούν με την κοινότητα και εκπληρώνουν συγκεκριμένες στιγμιαίες απαιτήσεις, όχι με προηγουμένως εγγεγραμμένα βίντεο.  
  (Για παράδειγμα: *"Γράψε τη σημερινή ημερομηνία και τον τρέχοντα αριθμό μπλοκ στη δεξιά γωνία του καμβά"*)
- **Σύνθημα:** *"Τα ρομπότ μπορούν να ζωγραφίσουν, αλλά τα ρομπότ δεν ιδρώνουν και δεν αυτοσχεδιάζουν."*

### 2) Απόδειξη Εργασίας και Διαδικασίας (Labor & Process Proof)

- **Πρόβλημα:** Οι εικόνες AI που παράγονται σε 2 δευτερόλεπτα και οι πίνακες ζωγραφικής σε λάδι που γίνονται σε 2 μήνες θεωρούνται το ίδιο "jpeg" στον ψηφιακό κόσμο.
- **Λύση [PoArt]:** Η διαδικασία "εγκυμοσύνης και γέννησης" του έργου καταγράφεται. Τα στάδια του σκίτσου, τα στρώματα μπογιάς, οι συσσωρευμένες ώρες που δαπανήθηκαν και η φυσική διαδικασία που βίωσε ο καλλιτέχνης κατά τη δημιουργία του έργου τεκμηριώνονται. Αυτό προσθέτει **"Κόστος Χρόνου" (Time Cost)** στο token. Όσο πιο δύσκολο είναι να παραχθεί το περιουσιακό στοιχείο, τόσο πιο στέρεη είναι η αξία του.

### 3) Απόδειξη Αισθητικής Αξίας (Aesthetic Value Proof)

- **Πρόβλημα:** Η αισθητική και το καλλιτεχνικό βάθος της κουλτούρας "Meme" που αγνοεί τα πάντα και επικεντρώνεται μόνο στη στιγμιαία κωμωδία, και τα βραχυπρόθεσμα έργα "Hype" που προκύπτουν από αυτό.
- **Λύση [PoArt]:** Το έργο πρέπει να έχει ακαδημαϊκά καλλιτεχνικά πρότυπα, θεωρία χρώματος, κανόνες σύνθεσης και γνώση υλικών (Impasto, Υφή κ.λπ.). Το περιεχόμενο δεν πρέπει απλώς να κάνει γέλιο· πρέπει να ξυπνήσει θαυμασμό στον θεατή και να έχει **συλλεκτική αξία**.

### 4) Εννοιολογική Καινοτομία (Conceptual Novelty)

- **Πρόβλημα:** Χιλιάδες πανομοιότυπα dog/cat coin, μακριά από τη δημιουργικότητα.
- **Λύση [PoArt]:** Το έργο πρέπει να χτίσει μια νέα γέφυρα που συνδυάζει σημαντικά την τέχνη, την επιστήμη, τη φιλοσοφία ή την τεχνολογία.  
  (Για παράδειγμα: Συνδυασμός του κλασικού αγάλματος του Δαυίδ με δεδομένα της αγοράς κρυπτονομισμάτων· επεξεργασία μέσω αυτού της ιδέας της "πετρωμένης" ανθρώπινης αντίληψης και δυνατότητα αιτιολόγησης με επιστημονικές πηγές.)  
  Το έργο πρέπει να είναι όχι μόνο μια οπτική γιορτή, αλλά και μια διανοητική πρόκληση που παρακινεί σκέψη για **Επιστήμη, Φιλοσοφία ή Τεχνολογία**.

> [!IMPORTANT]
> **Παράδειγμα Αναφοράς (Εφέ Las Palmitas):** Στην περιοχή Las Palmitas του Μεξικού, που αγωνίζεται με την εγκληματικότητα, πάνω από 200 σπίτια >μετατράπηκαν σε μια γιγάντια γιορτή ουράνιου τόξου. Ως αποτέλεσμα αυτής της αισθητικής παρέμβασης, τα ποσοστά εγκληματικότητας στην περιοχή μειώθηκαν σε >κάποιο βαθμό, οι νέοι άρχισαν να ενδιαφέρονται για την τέχνη αντί για συμμορίες. Η αισθητική αλλαγή επανακωδικοποίησε τον σεβασμό των ανθρώπων για το >περιβάλλον και ο ένας για τον άλλον (Κοινωνική Συνοχή).
>
> **Προσδοκία:** Ένα έργο που μπαίνει στη λίστα [PoArt]· όπως στο παραπάνω παράδειγμα, πρέπει να περιέχει μια κοινωνιολογική, επιστημονική ή φιλοσοφική αιτιώδη >σύνδεση πέρα από την οπτική αισθητική. Επειδή το μόνο πράγμα που δεν μπορεί να αγοραστεί με χρήματα είναι ο "Χρόνος", σε αυτό το πρωτόκολλο ο χρόνος πρέπει να >αποδειχθεί ως εγγύηση μέσω staking. Η εννοιολογική βάση του έργου πρέπει να είναι τόσο ισχυρή και καθολική· ώστε ακόμη και σε ένα πιθανό σενάριο CTO (Community >Take Over) χρόνια αργότερα, η κοινότητα να μπορεί να διατηρήσει αυτόνομα τη δυναμική καινοτομίας του έργου, κληρονομώντας αυτή την κληρονομιά.

- **Λύση [PoArt]:** Η αυθεντική θέληση μιας ανθρώπινης ύπαρξης που μπορεί να κάνει λάθη, να αναλαμβάνει ρίσκα και να αισθάνεται συναισθηματικές διακυμάνσεις πρέπει να αισθάνεται στο έργο. Η αβεβαιότητα στις πινελιές, οι απρόβλεπτες αντιδράσεις του υλικού και οι στιγμιαίες αποφάσεις του καλλιτέχνη είναι η **Βιολογική Υπογραφή** που διαφοροποιεί το έργο από τη "Μηχανική Παραγωγή".

### 📦 Πακέτο Αποδείξεων (Evidence Pack - The Digital Twin)

Πίσω από κάθε έργο πιστοποιημένο [PoArt] υπάρχει ένα κρυπτογραφημένο και σημασμένο με χρονοσήμανση πακέτο δεδομένων που οι επενδυτές μπορούν να κατεβάσουν:

- **Φυσικές Αναφορές:** Αποδείξεις ότι το έργο υπάρχει στον φυσικό κόσμο

> *Σημείωση για συνέπεια:* Η έκφραση "πακέτο αποδείξεων" συνδέεται με τη γραμμή **Evidence Pack → EvidenceRoot → NotarySeal** από προηγούμενες ενότητες· δηλαδή η ακεραιότητα του πακέτου αντιπροσωπεύεται από την επαληθευμένη σφραγίδα.

### 🔄 Ενημέρωση στις 365 Ημέρες (The Sustainability Protocol)

- **Επαναστατικό Χαρακτηριστικό:** Σε έργα κρυπτονομισμάτων ο "Dev" (Προγραμματιστής) λανσάρει το token στην αγορά και συνήθως εξαφανίζεται μετά από 1-2 μήνες (Soft Rug). Το [PoArt] καθιστά αυτό αδύνατο.
- **Κανόνας:** Η κατάσταση "Verified Artist" (Επαληθευμένος Καλλιτέχνης) δεν είναι δια βίου. Είναι έγκυρη μόνο για **1 χρόνο**.
- **Λειτουργία:** Ο καλλιτέχνης/προγραμματιστής πρέπει να παρουσιάσει στην κοινότητα κάθε 365 ημέρες **ένα νέο, μεγάλο και επαληθευμένο έργο**.
- **Παράδειγμα Σεναρίου:** Ξεκίνησες το έργο το 2026. Τον Ιανουάριο του 2027, το σύστημα εκδίδει την προειδοποίηση "Η Περίοδος Απόδειξης Έληξε". Αν ο καλλιτέχνης δεν παρουσιάσει νέα έκθεση, νέο φυσικό έργο ή νέα τεχνολογική ενσωμάτωση, το "Σήμα Εμπιστοσύνης" του έργου πέφτει.
- **Αποτέλεσμα:** Αυτό το σύστημα διασφαλίζει ότι **το περιεχόμενο δεν χάνει ποτέ τη συνάφειά του** και ότι ο επενδυτής δεν ζει στον φόβο *"Είναι ο προγραμματιστής ακόμα εδώ;"*. Το έργο γίνεται ζωντανό στούντιο.

### 🚩 Κόκκινη Σημαία (Red Flag Protocol)

**Σε περίπτωση ανίχνευσης οποιασδήποτε πλαστογράφησης από την κοινότητα ή αλγορίθμους (χρήση AI, κλεμμένη εργασία, χειραγωγημένο βίντεο):**

## 🗳️ 6) ΔΙΑΚΥΒΕΡΝΗΣΗ ΚΑΙ ΔΗΜΟΣΙΟ ΜΗΤΡΩΟ (Governance & Public Registry)

### 6.1 Δημόσιο Μητρώο (Public Registry)

- **Public Registry:** Όλα τα εγκεκριμένα δεδομένα καταγράφονται στη διεύθυνση `ilhanart.org/registry` (ή GitHub Registry).

**Λογική καταγραφής (συνιστώμενο πρότυπο - μορφή διαδρομής JSON):**

Κάθε καταχώρηση που εισέρχεται στο μητρώο περιέχει τουλάχιστον αυτά τα επαληθευμένα βασικά πεδία:

- **Ταυτότητα και Κατάσταση:**
  - `certificate_id` (αναγνώσιμη αναφορά)
  - `status` (active / void)
  - `void_reason` (αν υπάρχει)
  - `visibility` (private / masked / public)
  - `created_at` (χρονοσήμανση)

- **Εκδότρια Οργάνωση:**
  - `issuer.name`
  - `issuer.location`

  - `asset.title`

- **Διακυβέρνηση:**
  - `governance.decision`
  - `governance.veto_threshold`

Το μητρώο μπορεί να έχει δύο επίπεδα:
- **1)** Ευρετήριο αναγνώσιμο από ανθρώπους (λίστα ιστού / αναζήτηση / φίλτρο)
- **2)** Μανιφέστο αναγνώσιμο από μηχανές (καταχωρήσεις JSON· για επαλήθευση PFE)

**Εδώ η "καταγραφή" γίνεται επαληθευμένη από την αλυσίδα Evidence Pack → EvidenceRoot → NotarySeal του PFE. Το μητρώο παρέχει τον σκοπό της επαλήθευσης, όχι την "ισχυρισμό".**

### 6.2 Βέτο Κοινότητας 40% (Token-Gated Governance)

- **Βέτο Κοινότητας 40%:** Η ψηφοφορία ξεκινά ένα μήνα πριν λάβει την κατάσταση· η αντίρρηση του 40% της κοινότητας **Token-Gated (Solana-Verified)** ακυρώνει την αίτηση.

**Ροή ψηφοφορίας (συνιστώμενη καθαρή διαδικασία):**
- **Παράθυρο υποψηφιότητας:** Το έργο υποψηφιότητας ανοίγει "καταχώρηση υποψηφίου PoArt" (οι καταχωρήσεις υποψηφίων εμφανίζονται με κατάσταση "pending").
- **Περίοδος αναθεώρησης:** Για 30 ημέρες η κοινότητα εξετάζει τις αποδείξεις (Evidence Pack + εγγραφές ζωντανών μεταδόσεων + metadata).
- **Επαλήθευση token-gated:** Η ψηφοφορία γίνεται μέσω πορτοφολιών επαληθευμένων στο Solana (π.χ. κατοχή συγκεκριμένου token/NFT + υπογραφή πορτοφολιού).
- **Κανόνας βέτο:** Αν το 40% των ψήφων είναι **αντίρρηση (NO / VETO)**, η αίτηση απορρίπτεται.
- **Διαφάνεια:** Το αποτέλεσμα της ψηφοφορίας αποθηκεύεται στο μητρώο ως "decision record" (ημερομηνία, αναλογία, ID snapshot).

### 6.3 Συγχρονισμός Metadata (Συμμόρφωση με τον Φυσικό Κόσμο)

- **Metadata Sync:** Τα τεχνικά δεδομένα στο μητρώο πρέπει να αντιστοιχούν 100% στο φυσικό περιουσιακό στοιχείο.

**Τεχνικός ορισμός "100% συμμόρφωσης" (συνιστώμενη σαφήνεια):**
- **Ελάχιστη συμμόρφωση (υποχρεωτική):**
  - Το `asset.fingerprints.sha256/sha512` στο μητρώο πρέπει να είναι **ακριβώς ίδιο** με το hash του αρχείου στο χέρι.
  - Το `proof.notary_seal` στο μητρώο, όταν αναπαραχθεί (αν υπάρχει Evidence Pack), πρέπει να είναι **ακριβώς ίδιο**.
- **Συμμόρφωση φυσικής αναφοράς (τύπος απόδειξης):**
  - Αποδείξεις όπως το φυσικό έργο που εμφανίζεται σε ζωντανή μετάδοση + αναφορά ημερομηνίας/μπλοκ πρέπει να είναι συνεπείς με το Evidence Pack.
- **Συμμόρφωση απορρήτου:**
  - Πεδία όπως IP/τοποθεσία σε ορατότητα `masked` δημοσιεύονται **σύμφωνα με το πρότυπο μασκαρέματος**.

Το μητρώο δεν είναι απλώς μηχανισμός "έγκρισης"· είναι **ζωντανός μηχανισμός εποπτείας κατά της πλαστογράφησης**.

- Όταν ξεκινά διαφωνία, η καταχώρηση μπορεί να τεθεί σε λειτουργία **"review"**.

- Η πηγή της απόφασης ανάκλησης είναι σαφώς ορατή στο μητρώο:

## 💡 Τεχνολογική Καινοτομία

Το PoArt δεν είναι απλώς ένα σύστημα μεταφόρτωσης αρχείων. Είναι μια μηχανή **"Forensic Chain of Custody"** που λιώνει τρία διαφορετικά τεχνολογικά στρώματα σε ένα χωνευτήρι και φέρνει ένα νέο πρότυπο.

**Το στρώμα που περιγράφεται σε αυτήν την ενότητα ως "μηχανή" αντιστοιχεί στον πυρήνα PoArt Forensic Engine (PFE) στην προηγούμενη ορολογία.**

### 1) Client-Side Hashing (Μέγιστο Απόρρητο)

Τα αρχεία των έργων σας δεν μεταφορτώνονται ποτέ στον διακομιστή. Η μηχανή μας που βασίζεται σε browser (Client-side) υπολογίζει το hash (ψηφιακή περίληψη) του αρχείου στον υπολογιστή σας. Μόνο αυτό το αποτύπωμα και τα metadata αποστέλλονται στον διακομιστή.

> **Σημείωση για Απόρρητο:** Το αρχείο του έργου δεν μεταφορτώνεται στον διακομιστή και έτσι προστατεύεται. Ωστόσο, τα δεδομένα forensics (IP/τοποθεσία) κοινοποιούνται σύμφωνα με την επιλεγμένη λειτουργία ορατότητας (private/masked/public).

### 2) Forensic Data Fusion (Εγκληματολογική Δύναμη)

Είναι πολύ περισσότερο από μια απλή χρονοσήμανση. Το σύστημα συνδυάζει τα ακόλουθα δεδομένα σε ένα μόνο "Genesis Seal":

- **Ψηφιακή Περίληψη (SHA-512):** Χρησιμοποιώντας το πρότυπο κρυπτογραφικής περίληψης (SHA-512), το ψηφιακό αποτύπωμα που θα σπάσει ακόμα κι αν αλλάξει ένα pixel του έργου.
- **Τοποθεσία και Χρόνος:** Η ημερομηνία με ακρίβεια χιλιοστών του δευτερολέπτου, η χώρα, η πόλη και η περιοχή όπου πραγματοποιήθηκε η συναλλαγή.
- **Ταυτότητα Συσκευής:** Λειτουργικό σύστημα, browser και τύπος συσκευής (ανάλυση User-Agent).

## 🔬 Τεχνικό Βάθος: Αλγόριθμος Σφράγισης

### Ντετερμινιστικές Συναρτήσεις Hash
```javascript
// Βοηθητικές Συναρτήσεις: Μετατροπή περίληψης σε hex συμβολοσειρά
async function digestToHex(algorithm, dataBytes) {
  const hashBuffer = await crypto.subtle.digest(algorithm, dataBytes);
  const hashArray = Array.from(new Uint8Array(hashBuffer));
  return hashArray.map(b => b.toString(16).padStart(2, '0')).join('');
}

// Μετατροπή συμβολοσειράς σε πίνακα bytes
function stringToBytes(text) {
  return new TextEncoder().encode(text);
}

// Δημιουργία κανονικής συμβολοσειράς forensics (v1.0: σταθερή σειρά πεδίων + UTF-8 + διαχωριστής \n)
// Σημείωση Φάσης 2: Μετάβαση σε κανονικό JSON με RFC 8785 (JCS)
function canonicalForensics(forensicsData) {
  return JSON.stringify({
    ip_masked: forensicsData.ip_masked,
    location: forensicsData.location,
    device: forensicsData.device,
    timestamp: forensicsData.timestamp
  });
}
```

### Διαδικασία Παραγωγής NotarySeal (Πλήρως Ντετερμινιστική)
```javascript
// 1. Υπολογισμός FileHash (client-side)
async function computeFileHash(file) {
  const fileBuffer = await file.arrayBuffer();
  const fileBytes = new Uint8Array(fileBuffer);
  
  const sha256 = await digestToHex('SHA-256', fileBytes);
  const sha512 = await digestToHex('SHA-512', fileBytes);
  
  return { sha256, sha512 };
}

// 2. Συλλογή εγκληματολογικών δεδομένων (χρήση ενός χρονοσήματος)
async function collectForensics(visibilityMode) {
  const timestamp = new Date().toISOString(); // Δημιουργία ενός χρονοσήματος
  const ipData = await fetch('https://ipapi.co/json/').then(r => r.json());
  
  let forensics = {
    ip_masked: visibilityMode === 'masked' ? maskIP(ipData.ip) : ipData.ip,
    location: visibilityMode === 'masked' 
      ? `***/${ipData.country}` 
      : `${ipData.city}, ${ipData.country_name || ipData.country}`,
    device: navigator.userAgent,
    timestamp: timestamp // Το ίδιο χρονόσημα
  };
  
  return { forensics, timestamp };
}

// 3. Δημιουργία EvidenceRoot (με κανονική κωδικοποίηση)
async function computeEvidenceRoot(fileHash512, forensicsData) {
  const canonicalPayload = `file_sha512:${fileHash512}\nforensics:${canonicalForensics(forensicsData)}`;
  return await digestToHex('SHA-512', stringToBytes(canonicalPayload));
}

// 4. Παραγωγή NotarySeal (χρήση του ίδιου χρονοσήματος)
async function computeNotarySeal(evidenceRoot, signerSignature, timestamp) {
  const sealPayload = `evidence_root:${evidenceRoot}\nsigner_sig:${signerSignature}\ntimestamp:${timestamp}`;
  return await digestToHex('SHA-512', stringToBytes(sealPayload));
}

// Βοηθητικές συναρτήσεις μασκαρέματος (υποστήριξη IPv4 και IPv6)
function maskIP(ip) {
  if (!ip) return "***";
  
  // Έλεγχος IPv4
  if (ip.includes(".")) {
    const parts = ip.split(".");
    if (parts.length === 4) {
      return `${parts[0]}.${parts[1]}.***.***`;
    }
  }
  
  // IPv6 ή άγνωστη μορφή
  return "***";
}
```

### Ροή Επαλήθευσης (Δύο Επίπεδα)

#### Quick Verify (Γρήγορη Επαλήθευση)
```javascript
// Ελέγχει μόνο το hash του αρχείου (γρήγορη κόκκινη σημαία)
async function verifyQuick(file, certificateId) {
  const { sha512: userFileHash } = await computeFileHash(file);
  
  // Λήψη από Μητρώο
  const cert = await fetchFromRegistry(certificateId);
  const { sha512: originalHash } = cert.asset.fingerprints;
  
  // Σύγκριση hash
  if (userFileHash === originalHash) {
    return {
      valid: true,
      message: "✅ Γνήσιο - Το hash του αρχείου ταιριάζει"
    };
  } else {
    return {
      valid: false,
      message: "❌ Ψεύτικο - Το αρχείο έχει χειραγωγηθεί"
    };
  }
}
```

#### Full Verify (Πλήρης Επαλήθευση)
```javascript
// Αναπαράγει και επαληθεύει EvidenceRoot και NotarySeal
async function verifyFull(file, certificateId) {
  const { sha512: userFileHash } = await computeFileHash(file);

  // Λήψη από Μητρώο
  const cert = await fetchFromRegistry(certificateId);

  // 1) Έλεγχος FileHash (γρήγορη κόκκινη σημαία)
  const originalHash = cert.asset.fingerprints.sha512;
  if (userFileHash !== originalHash) {
    return { valid: false, message: "❌ Ψεύτικο - Το hash του αρχείου δεν ταιριάζει" };
  }

  // 2) Αναπαραγωγή EvidenceRoot (με δεδομένα forensics αποθηκευμένα στο μητρώο)
  const evidenceRoot = await computeEvidenceRoot(userFileHash, cert.forensics);
  if (evidenceRoot !== cert.proof.evidence_root) {
    return { valid: false, message: "❌ Δεν ταιριάζει - EvidenceRoot μη έγκυρο" };
  }

  // 3) Αναπαραγωγή NotarySeal (με το ίδιο χρονόσημα + signer_sig)
  const seal = await computeNotarySeal(
    evidenceRoot,
    cert.proof.signer_sig,
    cert.forensics.timestamp
  );

  if (seal !== cert.proof.notary_seal) {
    return { valid: false, message: "❌ Δεν ταιριάζει - NotarySeal μη έγκυρο" };
  }

  // Προαιρετικά: Στη Φάση 2 επαληθεύστε επίσης το signer_sig με attestation_pubkey
  // const sigValid = await verifySig(cert.issuer.attestation_pubkey, cert.proof.signer_sig, evidenceRoot);
  // if (!sigValid) return { valid: false, message: "❌ Υπογραφή μη έγκυρη" };

  return { valid: true, message: "✅ Γνήσιο - Full Verify πέρασε" };
}
```

> **Σημαντικές Σημειώσεις:**
> - **Quick Verify:** Ελέγχει μόνο το hash του αρχείου για γρήγορη χρήση.
> - **Full Verify:** Επαληθεύει όλα τα στρώματα του πρωτοκόλλου (EvidenceRoot + NotarySeal).
> - Όλες οι λειτουργίες hashing εκτελούνται ντετερμινιστικά, με σταθερή κωδικοποίηση και διαχωριστές.
> - **Πρότυπο κανονικοποίησης v1.0:** Σταθερή σειρά πεδίων + κωδικοποίηση UTF-8 + διαχωριστής `\n`.
> - **Σχέδιο Φάσης 2:** Μετάβαση σε κανονικό JSON με RFC 8785 (JCS - JSON Canonicalization Scheme).
> - Σε λειτουργία Masked ο υπολογισμός του EvidenceRoot και NotarySeal γίνεται με μασκαρεμένα forensics.
> - Χρησιμοποιείται ένα χρονόσημα σε όλη τη διαδικασία (forensics + NotarySeal)· ο ντετερμινισμός είναι εγγυημένος.
> - **Ονόματα πεδίων Forensics:** `ip_masked`, `location`, `device`, `timestamp` (κώδικας και μητρώο πλήρως συμβατά).
> - **Διαδρομή Μητρώου:** `certificate.asset.fingerprints` (πλήρως συμβατό με τον κώδικα επαλήθευσης).
> - **signer_sig στο Μητρώο:** Το πεδίο `proof.signer_sig` είναι απαραίτητο για Full Verify.
> - Ο μηχανισμός SignerSignature θα ενεργοποιηθεί στη Φάση 2 με Solana Wallet Adapter· στο v1.0 μπορεί να γίνει επαλήθευση με `attestation_pubkey`.
