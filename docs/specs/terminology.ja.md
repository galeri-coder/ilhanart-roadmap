## ⚙️ PoArt フォレンジックエンジン (PFE) v1.0：コアインフラストラクチャ

**PoArt フォレンジックエンジン (PFE)** は、[PoArt] プロトコルの背後にあるコアロジックと技術的動作を表すメインレイヤーです。芸術作品の生の制作データを取得し、検証可能で不変の**デジタル証拠**に変換する「フォレンジックエンジン」がここにあります。

### 🧩 なぜ「PoArt フォレンジック」なのか？

- **PoArt（芸術の証明）：** エンジンの焦点は、デジタル資産の価値を投機ではなく、**証明可能な制作プロセス**に結び付けることです。
- **フォレンジック（法的検証）：**
  - **技術的定義：** 制作プロセスに関するデータ（筆のストローク、タイムラプス、ログ）が改ざんされていないことを検証するためのアルゴリズムと記録チェーンアプローチ。
  - **哲学的レイヤー：** AIの「即時出力」生産に対して、**人間の時間、努力、意思決定コスト**を含む制作を測定可能な現実に変換するという主張。

> 注：ブロックチェーン（例：Solana）統合はPFEのコアではなく、検証/レジストリのために別途定義される**チェーンアンカーレイヤー**として扱われます。

### 🛠️ v1.0 技術範囲

**PoArt フォレンジックエンジン (PFE) v1.0** は、複雑な金融モデルではなく、次の**3つの主要な柱**の上に構築されています：

1. **ハッシュとシーリング（封印）：**  
   PFEは、エビデンスパック内のすべての要素（作品ファイル、ビデオ、JSON/ログ、署名など）を決定論的に処理し、一意の**NotarySeal**値を生成します。

   **コア概念（v1.0）：**
   - **FileHash（作品フィンガープリント）：** 作品ファイルのバイトから生成されたハッシュ。
   - **EvidenceRoot（証拠パッケージルート）：** エビデンスパックの完全性を表すルートダイジェスト（Merkle rootまたはカノニカルマニフェストハッシュ）。
   - **NotarySeal（最終シール / PFE出力）：** EvidenceRoot + 時間 + 署名の組み合わせから生成される最終シール。

   **公式（投資家に明確に表示）：**
   
   $$\text{FileHash}_{512} = \text{SHA-512}(\text{ArtworkFileBytes})$$
   
   $$\text{NotarySeal} = \text{SHA-512}(\text{EvidenceRoot} \mid \text{SignerSignature} \mid \text{TimeStamp})$$
   
   **カノニカルペイロード定義（v1.0）：**
   
   - **EvidenceRootPayload：**
```
   file_sha512:{sha512}\nforensics:{canonicalForensics(forensics)}
```
   
   - **NotarySealPayload：**
```
   evidence_root:{evidence_root}\nsigner_sig:{signer_sig}\ntimestamp:{timestamp}
```
   
   > 注：PFE出力として意図される値は**NotarySeal**です。**SignerSignature**メカニズムはフェーズ2（Solana Wallet Adapterを使用）で有効化されます。現在のv1.0では、システム自体のアテステーション署名が使用されます。アテステーション公開鍵はレジストリの`issuer.attestation_pubkey`フィールドで公開されます。

2. **インデックス作成（アーカイブ）：**  
   どのウォレットが、いつ、どの作品のために**労働証明（Labor Proof）**を提出したかを、透明で照会可能な記録レイヤーに処理します。  
   *（このレイヤーはデータベースである可能性があります。チェーン統合は別途「チェーンアンカーレイヤー」として定義されます。）*

3. **検証（Verification）：**  
   作品の真正性が問われたとき、PFEは生の証拠を再処理し、計算された**EvidenceRoot / NotarySeal**値がアーカイブの記録と一致するかどうかを数学的確実性でテストします。

### 🧮 PoArt 価値定理（The Value Theorem）

[PoArt]プロトコルは、デジタル資産の価値（$V$）を主観的市場認識ではなく、**制作プロセスの物理的現実**に関連付けます。

人工知能（AI）は、結果を即座に提供する（$t \to 0$）ことでプロセスを消滅させます。[PoArt]は、価値を**時間、労働、意志**の構成要素の蓄積として扱います。

$$V_{\text{PoArt}} = \int_{t_{\text{start}}}^{t_{\text{end}}} \left(P_{\text{labor}}(t) \cdot I_{\text{agency}}(t)\right) dt + U_{\text{irreversible}}$$

#### 変数の定義

- **$\int dt$（プロセス蓄積）：**  
  価値は即時の「出力」（output）ではなく、$t_{\text{start}}$と$t_{\text{end}}$の間に蓄積される**プロセス**です。期間が減少すると（AI生産）、積分の結果は0に近づきます。

- **$P_{\text{labor}}(t)$（瞬時労働強度）：**  
  制作時に消費される精神的および身体的努力の強度を表します。証明可能な努力が増加すると、被積分関数が大きくなります。  
  > 注：この項は、実際には「測定可能/証明可能な労働シグナル」を通じて正規化できます。

- **$I_{\text{agency}}(t)$（意志係数）：**  
  生産者のリスクテイクと意思決定能力です。$0$と$1$の間の値を取ります。
  - **AI（$I \approx 0$）：** コマンドを実行し、リスクを取らず、代償を払いません。
  - **人間（$I \to 1$）：** 決定を変更し、躊躇し、リスクを取ります。

- **$U_{\text{irreversible}}$（不可逆的独自性）：**  
  デジタル制作では取り消し（`Ctrl+Z`）が可能ですが、物理的制作（キャンバスに塗られた絵の具、彫刻された大理石、ライブ配信中のジェスチャー）では戻ることができません。この**不可逆性**は、作品に「独自性」（非代替性の特徴）を生み出す追加の項です。

### 🔎 ケース分析：AI「即時出力」vs. 人間「証明されたプロセス」

次のシナリオは、**PoArt価値定理**が実際にどのように機能するか、そしてなぜAI生産が[PoArt]標準で低スコアを獲得するかを示しています。

#### シナリオA：AIによる10秒での視覚コンテンツ生成

- **期間（$\Delta t$）：** $10$秒（プロセスがほとんど存在しない）
- **労働強度（$P_{\text{labor}}$）：** $1$単位（コマンド記述のみ）
- **意志係数（$I_{\text{agency}}$）：** $0.01$（リスクなし、代償なし）
- **不可逆性（$U_{\text{irreversible}}$）：** $0$（取り消し可能/複製可能）

**結果：**

$$V_{\text{AI}} \approx \int_{0}^{10} (1 \cdot 0.01) \, dt + 0 = 0.1$$

> **コメント：** 出力が完璧であっても、プロセスが経験されず、意志/リスクを含まないため、[PoArt]価値は$0$に近づきます。

#### シナリオB：ライブ配信での6時間の物理的制作

- **期間（$\Delta t$）：** $6$時間（$21{,}600$秒）
- **労働強度（$P_{\text{labor}}$）：** $0.5$単位（身体的および精神的努力の継続性）
- **意志係数（$I_{\text{agency}}$）：** $0.9$（決定の変更、リスクテイク、不可逆的選択）
- **不可逆性（$U_{\text{irreversible}}$）：** $>0$（物理的痕跡は取り消せない）

**結果：**

$$V_{\text{Human}} \approx \int_{0}^{21600} (0.5 \cdot 0.9) \, dt + U_{\text{irreversible}} \approx 9720 + U_{\text{irreversible}}$$

> **コメント：** プロセスが長くなり、意志（リスク）が増加するにつれて、価値は累積的に増加します。$U_{\text{irreversible}}$項は、作品に「独自性」（非代替性の特徴）を生み出す追加の貢献です。

### ✅ 結論：証明に縛られた価値（Proof-Bound Value）

この定理は、[PoArt]の価値主張を「好み」や「市場の物語」から、**証明可能な制作現実**に変換します。

1. **プロセスなしでは価値は生まれない：**  
   AIは即時出力（$t \to 0$）でプロセスを消滅させます。プロセスウィンドウが狭まると、積分の結果は数学的必然性により減少します：
   
   $$\Delta t \downarrow \ \Rightarrow\ \int \left(P(t) \cdot I(t)\right) dt \to 0$$

2. **意志とリスクは乗数である：**  
   [PoArt]は「費やされた時間」だけでなく、その時間における実際の決定、リスク、代償のレイヤーも測定します。リスクを取らない（AI）生産の価値は低いです：
   
   $$V_{\text{PoArt}} \propto \int \left(P_{\text{labor}}(t) \cdot I_{\text{agency}}(t)\right) dt$$

3. **独自性はマーケティングではなく物理的証明である：**  
   物理的制作における取り消せない痕跡（キャンバスのストローク、大理石の亀裂）は、デジタルの`Ctrl+Z`ロジックの外にあります。この不可逆性（$U_{\text{irreversible}}$）は、作品を存在論的に独自化します。

> **🔐 要約：** 価値定理は測定として不確実に見えるかもしれませんが（現実生活で100%正確に測定できなくても）、この公式の目的は変数の構造と方向を示すことです。AI時代に希少なのは「画像」ではなく、**証明可能な労働、時間、意志**です。[PoArt]はこの希少性を測定し、**エビデンスパック**で証明します。

Pump.funや類似プラットフォームから出るトークンは、多くの場合単なる**「入場券」**の性質を持っています。**PoArt フォレンジックエンジン (PFE)** は、そのチケットがどのような権利を保護するか、労働がどのように記録されるか、そして芸術/科学/技術がどのように永続化されるかを決定する**憲法的論理レイヤー**です。

## b) [PoArt] 5つの基準（The 5 Pillars of Truth）

これらの5項目は、プロジェクトが[PoArt]シールを取得するために合格しなければならない、操作不可能なフィルターです。

### 1) ライブアイデンティティ証明（Live Identity Proof）

- **問題：** 暗号世界は、身元不明の匿名創設者（Dev）がお金を集めてプロジェクトを放棄することで満ちています。
- **[PoArt]解決策：** 生産者は身分証明書だけでなく、**制作時の存在**を証明します。これには、事前録画されたビデオではなく、コミュニティと交流し、即時の特定の要求を満たすライブ配信セッションが含まれます。  
  （例：*「キャンバスの右隅に今日の日付と現在のブロック番号を書いてください」*）
- **モットー：** *「ボットは絵を描けますが、ボットは汗をかかず、即興もできません。」*

### 2) 労働とプロセスの証明（Labor & Process Proof）

- **問題：** 2秒で生成されたAI（人工知能）画像と2ヶ月かけて作られた油絵がデジタル世界で同じ「jpeg」として扱われること。
- **[PoArt]解決策：** 作品の「妊娠と出産」プロセスが記録されます。スケッチ段階、絵の具の層、費やされた累積時間、および芸術家がその作品を作成する際に経験した物理的プロセスが文書化されます。これによりトークンに**「時間コスト」（Time Cost）**が追加されます。資産の制作が困難であるほど、その価値は堅固です。

### 3) 美的価値証明（Aesthetic Value Proof）

- **問題：** 「ミーム」文化が美学と芸術的深さを無視し、即座のコメディだけに焦点を当て、その結果として短命な「ハイプ」プロジェクトが生まれること。
- **[PoArt]解決策：** プロジェクトは学術的芸術基準、色彩理論、構図規則、材料知識（インパスト、テクスチャなど）を持つべきです。内容は笑わせるだけでなく、観客に賞賛を呼び起こし、**コレクション価値**を持つべきです。

### 4) 概念的革新（Conceptual Novelty）

- **問題：** お互いのコピーである、創造性に欠ける何千もの犬/猫コイン。
- **[PoArt]解決策：** プロジェクトは芸術、科学、哲学、技術を意味のある構造で結合する新しい橋を架けるべきです。  
  （例：古典的なダビデ像と暗号市場データを組み合わせ、そこから人間の認識が「石化」するという考えを処理し、これを科学的情報源で裏付けることができること。）  
  作品は視覚的な饗宴だけでなく、**科学、哲学、技術**について考えさせる知的挑戦であるべきです。

> [!IMPORTANT]
> **参考例（ラス・パルミタス効果）：**  
> メキシコの犯罪と闘うラス・パルミタス地区で、200以上の家が巨大な虹の饗宴に変わりました。この美的介入の結果、地区の犯罪率がある程度低下し、若者はギャングの代わりに芸術に関心を持つようになりました。美的変化は人々の環境と互いへの尊重（社会的結束）を再コード化しました。
>
> **期待：** [PoArt]リストに入るプロジェクトは、上記の例のように、純粋な視覚美学を超えた社会学的、科学的、または哲学的な因果関係を含むべきです。お金で買えない唯一の資産は「時間」であるため、このプロトコルでは時間を担保としてステークして証明する必要があります。プロジェクトの概念的基盤は非常に強力で普遍的であるべきで、何年も後に可能なCTO（コミュニティテイクオーバー）シナリオでも、コミュニティがこの遺産を引き継ぎ、プロジェクトの革新的可能性を自律的に継続できるようにすべきです。

### 5) 非アルゴリズム的意志（Non-Algorithmic Agency）

- **問題：** 完璧だが魂のない、互いを繰り返すデジタル制作。
- **[PoArt]解決策：** 間違いを犯し、リスクを取り、感情的な波を経験する人間の独自の意志が作品で感じられるべきです。筆のストロークの不確実性、材料の予期しない反応、芸術家の即座の決定が、作品を「機械生産」から区別する**生物学的署名**です。

## c) 検証と偽造防止メカニズム

このシステムは、プロジェクトが「最初だけ」でなく「永遠に」信頼できて生き続けることを保証します。

### 📦 証拠パッケージ（Evidence Pack - The Digital Twin）

各[PoArt]認証作品の背後には、投資家がダウンロードできる暗号化されたタイムスタンプ付きのデータパッケージがあります：

- **RAWビデオ記録：** 制作時の中断のない生の映像。
- **メタデータ分析：** ファイル作成日、使用されたデバイス情報、位置データ。
- **物理的参照：** 作品が物理世界に存在することを示す証拠  
  （例：作品の横にある現在の新聞またはその時点のブロックチェーンデータ）。

> *整合性注記：* 「証拠パッケージ」という表現は、前のセクションの**Evidence Pack → EvidenceRoot → NotarySeal**ラインに接続されます。つまり、パッケージの完全性は検証可能なシールで表されます。

### 🔄 365日更新（The Sustainability Protocol）

- **革命的機能：** 暗号プロジェクトでは「Dev」（開発者）がトークンを市場に出し、通常1〜2ヶ月後に消えます（ソフトラグ）。[PoArt]はこれを不可能にします。
- **ルール：** 「Verified Artist」（認証アーティスト）ステータスは生涯有効ではありません。**1年間**のみ有効です。
- **動作：** アーティスト/開発者は365日ごとにコミュニティに**新しい、大きな、証明可能な作品**を提示する必要があります。
- **例シナリオ：** 2026年にプロジェクトを開始しました。2027年1月、システムは「証明期限切れ」警告を出します。アーティストが新しい展覧会、新しい物理作品、または新しい技術統合を提示しない場合、プロジェクトの「信頼バッジ」が低下します。
- **結果：** このシステムは**コンテンツが決して古くならない**ことを保証し、投資家が*「開発者はまだここにいるのか？」*という恐怖を経験しないようにします。プロジェクトは生きたスタジオになります。

### 🚩 レッドフラグ（Red Flag Protocol）

**コミュニティまたはアルゴリズムによって検出された詐欺（AI使用、盗作、操作されたビデオ）の場合：**

1. 証明書は直ちに**「無効」（VOID）**としてマークされます。
2. 証拠パッケージは公開的に**「偽物」**としてラベル付けされます。
3. プロジェクトは[PoArt]ブラックリストに追加されます。これは、分散型世界で**評判が唯一の通貨**であるという事実を強化します。

- **公開レジストリ：** すべての承認されたデータは`ilhanart.org/registry`（またはGitHub Registry）アドレスに記録されます。

**記録ロジック（推奨標準 - JSONパス形式）：**

### 6.4 メタデータ同期（Metadata Sync）

- **メタデータ同期：** レジストリの技術データは物理的実体と100%一致しなければなりません。

**「100%一致」を技術的に定義する（推奨明確性）：**

- **最小一致（必須）：**
  - レジストリの`asset.fingerprints.sha256/sha512`と手元のファイルのハッシュは**完全に同一**でなければなりません。
  - レジストリの`proof.notary_seal`を再生成した場合（エビデンスパックがある場合）**完全に同一**でなければなりません。

- **物理的参照一致（証明タイプ）：**
  - ライブ配信で示された物理作品+日付/ブロック参照などの証拠は、エビデンスパックと一致する必要があります。

- **プライバシー遵守：**
  - `masked`可視性下では、IP/位置などのフィールドは**マスキング基準に準拠**して公開されます。

### 6.5 異議、審査、取り消し（Dispute & Revocation）

レジストリは単なる「承認」メカニズムではありません。**詐欺に対する生きた監視**メカニズムです。

- 詐欺が検出された場合、`status: void`としてマークされ、理由が追加されます：

  - `revoked_at`（取り消し時間）
- 取り消し決定の出所はレジストリで明確に表示されます：

## なぜ公開なのか？

## 🧩 なぜ複数の「可視性モジュール」があるのか？

これがコードの最も重要な部分です（可視性選択メニュー）。これらのオプションにより、ユーザーは**「プライバシー vs. 透明性」**のバランスを取ることができます：

### 🔒 プライベート（Private）

- **シナリオ：** アーティストはまだ作品を公開したくないが、タイムスタンプを押して「私はこれをこの日に作った」と証明したい。
- **コードが行うこと：** データをデータベースに書き込みますが、`visibility: "private"`タグを付けます。将来「Public Read」ポリシーを書く際に`WHERE visibility = 'public'`と言うことで、これらの記録を一般から隠すことができます。

### 🕶️ マスク（Masked）

- **シナリオ：** アーティストは透明性を望むが、自宅住所（IP位置）が見つかることを恐れている。
- **コードが行うこと：** JavaScript側で`maskIP`と`maskLoc`関数が動作します。IPアドレスを`88.241.***.***`形式に、位置を`***/TR`形式に変換し、検閲されたバージョンをデータベースに送信します。
- **プライバシーノート：** マスキングはブラウザで行われ、Supabaseは実際の位置を見ません。**しかし：** 位置データにipapi.coなどのサードパーティAPIを使用している場合、これらのプロバイダーはリクエスト時にIPアドレスを見ます。
- **マスクモードでのシーリング：** EvidenceRootとNotarySeal計算はマスクされたフォレンジックデータで行われます。したがって検証は決定論的なままです。

### 🌍 公開（Public）

- **シナリオ：** 完全な透明性。[PoArt]基準に従って、作品がどこで、いつ、どのネットワークから制作されたかが明確に宣言されます。

## 💡 技術革新

PoArtは単なるファイルアップロードシステムではありません。3つの異なる技術レイヤーを1つのポットで融合し、新しい基準をもたらす**「フォレンジック証拠チェーン」（Forensic Chain of Custody）**エンジンです。

**このセクションで「エンジン」として説明されるレイヤーは、以前の用語でのPoArt フォレンジックエンジン（PFE）コアに対応します。**

### 1) クライアントサイドハッシング（Client-Side Hashing）（最大プライバシー）

作品ファイルは決してサーバーにアップロードされません。ブラウザベース（クライアントサイド）で動作するエンジンが、自分のコンピューター上でファイルのハッシュ（デジタルダイジェスト）を計算します。サーバーにはこのフィンガープリントとメタデータのみが送信されます。

> **プライバシーノート：** 作品ファイルはサーバーにアップロードされず、この方法で保護されます。ただし、フォレンジックデータ（IP/位置）は選択された可視性モード（private/masked/public）に応じて共有されます。

### 2) フォレンジックデータ融合（Forensic Data Fusion）（フォレンジック能力）

単なるタイムスタンプ（Timestamp）をはるかに超えています。システムは次のデータを単一の「創世記シール」に統合します：

- **デジタルダイジェスト（SHA-512）：** 暗号ダイジェスト（SHA-512）標準を使用して、作品の1ピクセルが変更されても壊れるデジタルフィンガープリント。
- **位置と時間：** 操作が行われたミリ秒精度の日付、国、都市、地区データ。
- **デバイス識別：** オペレーティングシステム、ブラウザ、デバイスタイプ（User-Agent分析）。

### 決定論的ハッシュ関数
```javascript
// ヘルパー関数：ダイジェストをhex文字列に変換
async function digestToHex(algorithm, dataBytes) {
  const hashBuffer = await crypto.subtle.digest(algorithm, dataBytes);
  const hashArray = Array.from(new Uint8Array(hashBuffer));
  return hashArray.map(b => b.toString(16).padStart(2, '0')).join('');
}

// 文字列をバイト配列に変換
function stringToBytes(text) {
  return new TextEncoder().encode(text);
}

// カノニカルフォレンジック文字列生成（v1.0：固定フィールド順序 + UTF-8 + \n区切り文字）
// フェーズ2注記：RFC 8785（JCS）によるカノニカルJSONへの移行予定
function canonicalForensics(forensicsData) {
  return JSON.stringify({
    ip_masked: forensicsData.ip_masked,
    location: forensicsData.location,
    device: forensicsData.device,
    timestamp: forensicsData.timestamp
  });
}
```

### NotarySeal生成プロセス（完全決定論的）
```javascript
// 1. FileHash計算（クライアントサイド）
async function computeFileHash(file) {
  const fileBuffer = await file.arrayBuffer();
  const fileBytes = new Uint8Array(fileBuffer);
  
  const sha256 = await digestToHex('SHA-256', fileBytes);
  const sha512 = await digestToHex('SHA-512', fileBytes);
  
  return { sha256, sha512 };
}

// 2. フォレンジックデータ収集（単一タイムスタンプ使用）
async function collectForensics(visibilityMode) {
  const timestamp = new Date().toISOString(); // 単一タイムスタンプ生成
  const ipData = await fetch('https://ipapi.co/json/').then(r => r.json());
  
  let forensics = {
    ip_masked: visibilityMode === 'masked' ? maskIP(ipData.ip) : ipData.ip,
    location: visibilityMode === 'masked' 
      ? `***/${ipData.country}` 
      : `${ipData.city}, ${ipData.country_name || ipData.country}`,
    device: navigator.userAgent,
    timestamp: timestamp // 同じタイムスタンプ
  };
  
  return { forensics, timestamp };
}

// 3. EvidenceRoot作成（カノニカルエンコーディング使用）
async function computeEvidenceRoot(fileHash512, forensicsData) {
  const canonicalPayload = `file_sha512:${fileHash512}\nforensics:${canonicalForensics(forensicsData)}`;
  return await digestToHex('SHA-512', stringToBytes(canonicalPayload));
}

// 4. NotarySeal生成（同じタイムスタンプ使用）
async function computeNotarySeal(evidenceRoot, signerSignature, timestamp) {
  const sealPayload = `evidence_root:${evidenceRoot}\nsigner_sig:${signerSignature}\ntimestamp:${timestamp}`;
  return await digestToHex('SHA-512', stringToBytes(sealPayload));
}

// マスキングヘルパー関数（IPv4およびIPv6サポート）
function maskIP(ip) {
  if (!ip) return "***";
  
  // IPv4チェック
  if (ip.includes(".")) {
    const parts = ip.split(".");
    if (parts.length === 4) {
      return `${parts[0]}.${parts[1]}.***.***`;
    }
  }
  
  // IPv6または不明な形式
  return "***";
}
```

### 検証フロー（2レベル）

#### クイック検証（Quick Verify）
```javascript
// ファイルハッシュのみをチェック（高速レッドフラグ）
async function verifyQuick(file, certificateId) {
  const { sha512: userFileHash } = await computeFileHash(file);
  
  // レジストリから取得
  const cert = await fetchFromRegistry(certificateId);
  const { sha512: originalHash } = cert.asset.fingerprints;
  
  // ハッシュ比較
  if (userFileHash === originalHash) {
    return {
      valid: true,
      message: "✅ オリジナル - ファイルハッシュ一致"
    };
  } else {
    return {
      valid: false,
      message: "❌ 偽物 - ファイル改ざん"
    };
  }
}
```

#### 完全検証（Full Verify）
```javascript
// EvidenceRootとNotarySealを再生成して検証
async function verifyFull(file, certificateId) {
  const { sha512: userFileHash } = await computeFileHash(file);

  // レジストリから取得
  const cert = await fetchFromRegistry(certificateId);

  // 1) FileHashチェック（高速レッドフラグ）
  const originalHash = cert.asset.fingerprints.sha512;
  if (userFileHash !== originalHash) {
    return { valid: false, message: "❌ 偽物 - ファイルハッシュ不一致" };
  }

  // 2) EvidenceRoot再生成（レジストリに保存されたフォレンジック使用）
  const evidenceRoot = await computeEvidenceRoot(userFileHash, cert.forensics);
  if (evidenceRoot !== cert.proof.evidence_root) {
    return { valid: false, message: "❌ 不一致 - EvidenceRoot不合格" };
  }

  // 3) NotarySeal再生成（同じtimestamp + signer_sig使用）
  const seal = await computeNotarySeal(
    evidenceRoot,
    cert.proof.signer_sig,
    cert.forensics.timestamp
  );

  if (seal !== cert.proof.notary_seal) {
    return { valid: false, message: "❌ 不一致 - NotarySeal不合格" };
  }

  // オプション：フェーズ2でsigner_sigをattestation_pubkeyでも検証
  // const sigValid = await verifySig(cert.issuer.attestation_pubkey, cert.proof.signer_sig, evidenceRoot);
  // if (!sigValid) return { valid: false, message: "❌ 署名無効" };

  return { valid: true, message: "✅ オリジナル - Full Verify合格" };
}
```

> **重要な注記：**
> - **クイック検証：** 迅速使用のためファイルハッシュのみをチェック。
> - **完全検証：** プロトコルのすべてのレイヤー（EvidenceRoot + NotarySeal）を検証。
> - すべてのハッシュ操作は決定論的に、固定エンコーディングと区切り文字で実行。
> - **v1.0正規化標準：** 固定フィールド順序 + UTF-8エンコーディング + `\n`区切り文字。
> - **フェーズ2計画：** RFC 8785（JCS - JSON正規化スキーム）によるカノニカルJSONへの移行。
> - マスクモードでは、EvidenceRootとNotarySeal計算はマスクされたフォレンジックで実行。
> - 単一タイムスタンプが全プロセス（forensics + NotarySeal）で使用され、決定論性が保証される。
> - **フォレンジックフィールド名：** `ip_masked`、`location`、`device`、`timestamp`（コードとレジストリ完全一致）。
> - **レジストリパス：** `certificate.asset.fingerprints`（検証コードと完全一致）。
> - **レジストリのsigner_sig：** `proof.signer_sig`フィールドは完全検証に必要。
> - SignerSignatureメカニズムはフェーズ2でSolana Wallet Adapterにより有効化；v1.0では`attestation_pubkey`で検証可能。
