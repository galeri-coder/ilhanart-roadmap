## ⚙️ PoArt Forensic Engine (PFE) v1.0: Негізгі Инфрақұрылым

**PoArt Forensic Engine (PFE)** [PoArt] хаттамасының артындағы негізгі логикасы мен техникалық жұмыс істеуін көрсететін негізгі қабат болып табылады. Бұл өнер туындысының шикі өндіріс деректерін тексерілетін және өзгермейтін **цифрлық дәлелге** айналдыратын "сот-криминалистикалық қозғалтқыш".

### 🧩 Неліктен "PoArt Forensic"?

- **PoArt (Proof of Art):** Қозғалтқыштың фокусы цифрлық активтің құндылығын спекуляцияға емес, **дәлелденген өндіріс процесіне** байланыстыру болып табылады.
- **Forensic (Сот-Криминалистикалық Тексеру):**
  - **Техникалық Анықтама:** Өндіріс процесіне қатысты деректердің (қылқалам соққылары, timelapse, логтар) манипуляцияланбағанын тексеруге бағытталған алгоритмдік және дәлел тізбегі тәсілі.
  - **Философиялық Қабат:** Жасанды интеллекттің "лездік шығысына" қарсы; **уақыт, күш-жігер және шешім құнын** қамтитын адам өндірісін өлшенетін шындыққа айналдыру мәлімдемесі.

> Ескерту: Блокчейн (мысалы, Solana) интеграциясы PFE ядросы емес; тексеру/тізілім үшін **Chain Anchor Layer** ретінде бөлек анықталады.

### 🛠️ Техникалық Көлем v1.0

**PoArt Forensic Engine (PFE) v1.0** күрделі қаржылық модельдердің орнына **3 негізгі бағанға** салынған:

1. **Hashing & Sealing (Мөрлеу):**  
   PFE Evidence Pack ішіндегі барлық элементтерді (туынды файлы, бейне, JSON/log, қол қою т.б.) детерминистикалық түрде өңдейді және бірегей **NotarySeal** мәнін жасайды.

   **Негізгі тұжырымдамалар (v1.0):**
   - **FileHash (туынды іздері):** Туынды файлының байттарынан жасалған хэш.
   - **EvidenceRoot (дәлел пакетінің түбірі):** Evidence Pack тұтастығын көрсететін түбірлік дайджест (Merkle түбірі немесе канондық манифест хэші).
   - **NotarySeal (соңғы мөр / PFE шығысы):** EvidenceRoot + уақыт + қол қою комбинациясынан жасалған соңғы мөр.

   **Формулалар (инвесторларға түсінікті форматта):**
   
   $$\text{FileHash}_{512} = \text{SHA-512}(\text{ArtworkFileBytes})$$
   
   $$\text{NotarySeal} = \text{SHA-512}(\text{EvidenceRoot} \mid \text{SignerSignature} \mid \text{TimeStamp})$$
   
   **Canonical Payload Анықтамалары (v1.0):**
   
   - **EvidenceRootPayload:**
```
   file_sha512:{sha512}\nforensics:{canonicalForensics(forensics)}
```
   
   - **NotarySealPayload:**
```
   evidence_root:{evidence_root}\nsigner_sig:{signer_sig}\ntimestamp:{timestamp}
```
   
   > Ескерту: PFE шығысы ретінде қарастырылған мән **NotarySeal** болып табылады. **SignerSignature** механизмі 2-фазада (Solana Wallet Adapter арқылы) іске қосылады; ағымдағы v1.0-де жүйенің өзінің аттестациялық қолтаңбасы қолданылады. Аттестация ашық кілті тізілімде `issuer.attestation_pubkey` өрісінде жарияланады.

2. **Indexing (Архивтеу):**  
   Қай әмиян, қай күні, қандай туынды үшін **Labor Proof (Еңбек Дәлелін)** ұсынғанын; мөлдір және сұрау жасауға болатын тізілім қабатында тіркейді.  
   *(Бұл қабат дерекқор болуы мүмкін; блокчейн интеграциясы орнына "Chain Anchor Layer" ретінде анықталады.)*

3. **Verification (Тексеру):**  
   Туындының түпнұсқалығы күмән келтірілгенде, PFE шикі дәлелдерді қайта өңдейді; есептелген **EvidenceRoot / NotarySeal** мәндерінің мұрағаттағы жазбаларға сәйкес келетінін математикалық сенімділікпен тексереді.

### 🧮 PoArt Құндылық Теоремасы (The Value Theorem)

[PoArt] хаттамасы цифрлық активтің құндылығын ($V$) субъективті нарық қабылдауымен емес, **өндіріс процесінің физикалық шындығымен** байланыстырады.

Жасанды Интеллект (AI) лездік нәтижелер беру арқылы ($t \to 0$) процесті жояды. [PoArt] керісінше құндылықты **уақыт, еңбек және ерік** компоненттерінің жинақталуы ретінде қарастырады.

$$V_{\text{PoArt}} = \int_{t_{\text{start}}}^{t_{\text{end}}} \left(P_{\text{labor}}(t) \cdot I_{\text{agency}}(t)\right) dt + U_{\text{irreversible}}$$

#### Айнымалылардың Анықтамасы

- **$\int dt$ (Процестің Жинақталуы):**  
  Құндылық лездік "шығыс" емес; бұл $t_{\text{start}}$ пен $t_{\text{end}}$ арасында жинақталатын **процесс**. Уақыт азайған сайын (AI өндірісі), интегралдың нәтижесі 0-ге жақындайды.

- **$P_{\text{labor}}(t)$ (Лездік Еңбек Қарқындылығы):**  
  Өндіріс сәтінде жұмсалған ақыл-ой және физикалық күш-жігер қарқындылығын көрсетеді. Дәлелденген күш-жігер өскен сайын, интегранд үлкейеді.  
  > Ескерту: Бұл термин практикада "өлшенетін/дәлелденетін еңбек сигналдары" бойынша қалыпқа келтірілуі мүмкін.

- **$I_{\text{agency}}(t)$ (Ерік Коэффициенті):**  
  Бұл өндірушінің тәуекелге баруы және шешім қабылдау қабілеті. $0$ мен $1$ арасында мән қабылдайды.
  - **AI ($I \approx 0$):** Командаларды орындайды, тәуекелге бармайды, құнын төлемейді.
  - **Адам ($I \to 1$):** Шешімдерді өзгертеді, күмәнданады, тәуекелге барады.

- **$U_{\text{irreversible}}$ (Қайтарымсыз Бірегейлік):**  
  Цифрлық өндірісте кері қайтаруға болады (`Ctrl+Z`); физикалық өндірісте (кенепке жағылған бояу, ойылған мәрмәр, тікелей эфирдегі қимыл) кері қайту жоқ. Бұл **қайтарымсыздық** туындыда "бірегейлік" (non-fungible сипат) жасайтын қосымша термин.

### 🔎 Жағдай Талдауы: AI "Лездік Шығыс" қарсы Адам "Дәлелденген Процесс"

Келесі сценарий **PoArt Құндылық Теоремасының** практикада қалай жұмыс істейтінін және AI өндірістері неліктен [PoArt] стандартында төмен ұпай алатынын көрсетеді.

#### Сценарий A: AI-мен 10 Секундта Көрнекі Өндіріс

- **Ұзақтығы ($\Delta t$):** $10$ секунд (процесс іс жүзінде жоқ)
- **Еңбек Қарқындылығы ($P_{\text{labor}}$):** $1$ бірлік (тек команда жазу)
- **Ерік Коэффициенті ($I_{\text{agency}}$):** $0.01$ (тәуекел жоқ, құн жоқ)
- **Қайтарымсыздық ($U_{\text{irreversible}}$):** $0$ (қайтарымды / көшірмелі)

**Нәтиже:**

$$V_{\text{AI}} \approx \int_{0}^{10} (1 \cdot 0.01) \, dt + 0 = 0.1$$

> **Түсініктеме:** Шығыс мінсіз болса да; процесс өтпегендіктен және ерік/тәуекелді қамтымағандықтан, [PoArt] құндылығы $0$-ге жақындайды.

#### Сценарий B: 6 Сағаттық Тікелей Эфирдегі Физикалық Өндіріс

- **Ұзақтығы ($\Delta t$):** $6$ сағат ($21{,}600$ секунд)
- **Еңбек Қарқындылығы ($P_{\text{labor}}$):** $0.5$ бірлік (физикалық және ақыл-ой күш-жігерінің үздіксіздігі)
- **Ерік Коэффициенті ($I_{\text{agency}}$):** $0.9$ (шешімдерді өзгерту, тәуекелге бару, қайтарымсыз таңдаулар)
- **Қайтарымсыздық ($U_{\text{irreversible}}$):** $>0$ (физикалық іздерді кері қайтаруға болмайды)

**Нәтиже:**

$$V_{\text{Human}} \approx \int_{0}^{21600} (0.5 \cdot 0.9) \, dt + U_{\text{irreversible}} \approx 9720 + U_{\text{irreversible}}$$

> **Түсініктеме:** Процесс ұзарған сайын және ерік (тәуекел) өскен сайын, құндылық жинақталып жинақталады. $U_{\text{irreversible}}$ термині туындыда "бірегейлік" (non-fungible сипат) жасайтын қосымша үлес.

### ✅ Қорытынды: Дәлелге Байланысты Құндылық (Proof-Bound Value)

Бұл теорема [PoArt] құндылық мәлімдемесін "ұнатудан" немесе "нарық баяндауынан" алып тастайды және оны **дәлелденген өндіріс шындығына** байланыстырады.

1. **Процессіз Құндылық Жасалмайды:**  
   AI лездік шығыста ($t \to 0$) процесті жояды. Процесс терезесі тарылған сайын, интегралдың нәтижесі математикалық қажеттіліктен кішірейеді:
   
   $$\Delta t \downarrow \ \Rightarrow\ \int \left(P(t) \cdot I(t)\right) dt \to 0$$

2. **Ерік пен Тәуекел Көбейткіштер:**  
   [PoArt] тек "жұмсалған уақытты" емес, сол уақыттағы нақты шешім, тәуекел және құн деңгейін де өлшейді. Тәуекелге бармайтын (AI) өндірістің құндылығы төмен:
   
   $$V_{\text{PoArt}} \propto \int \left(P_{\text{labor}}(t) \cdot I_{\text{agency}}(t)\right) dt$$

3. **Бірегейлік Физикалық Дәлел, Маркетинг Емес:**  
   Физикалық өндірісте қайтарымсыз іздер (кенептегі қылқалам соққысы, сынған мәрмәр) цифрлық `Ctrl+Z` логикасының сыртында. Бұл қайтарымсыздық ($U_{\text{irreversible}}$) туындыны онтологиялық тұрғыдан бірегей етеді.

> **🔐 ҚЫСҚАША:** Құндылық теоремасы өлшем ретінде белгісіз көрінсе де (нақты өмірде 100% өлшеуге болмаса да), бұл формуланың мақсаты айнымалылардың құрылымы мен бағытын көрсету. AI дәуірінде сирек болатын нәрсе "сурет" емес, **дәлелденген еңбек, уақыт және ерік.** [PoArt] осы тапшылықты өлшейді және **Evidence Pack** арқылы тіркейді.

## a) [PoArt] Дегеніміз Не? (Философиялық және Техникалық Анықтама)

Bitcoin *"Электр энергиясы мен Есептеу Қуаты"* **(Proof of Work)** арқылы құндылық өндіретіні сияқты; [PoArt]-ке сәйкес жобалар *"Көркем Дағды мен Адам Уақыты"* арқылы құндылық өндіреді.

Pump.fun және DEX платформаларында бар *"Әзірлеуші (Dev) сатты, жоба аяқталды"* тәуекелін жояды; өйткені мұнда құндылық кодта емес, **өндірістің үздіксіздігінде**.

> **[PoArt] қатысушыға "Бізге сеніңіз" демейді; "Міне дәлелдер, өз көзіңізбен көріңіз, өз математикаңызбен тексеріңіз" дейді.**

## b) [PoArt] 5 Бағандық Стандарт (The 5 Pillars of Truth)

Бұл 5 тармақ [PoArt] мөрін алу үшін жобаның өтуі керек манипуляцияланбайтын сүзгілер.

### 1) Тікелей Эфирде Жеке Басты Дәлелдеу (Live Identity Proof)

- **Мәселе:** Криптовалюта әлемі анықталмаған жеке басы бар анонимді негізгі қалаушылармен (Dev) толы, олар ақша жинап жобаны тастап кетеді.
- **[PoArt] Шешімі:** Өндіруші тек жеке куәлікті емес, **өндіріс кезіндегі болуын** дәлелдейді. Бұл қауымдастықпен өзара әрекеттесетін және алдын ала жазылған бейнелермен емес, нақты лездік талаптарды орындайтын тікелей эфир сеанстарын қамтиды.  
  (Мысалы: *"Кенептің оң бұрышына бүгінгі күн мен ағымдағы блок нөмірін жаз"*)
- **Ұран:** *"Боттар сурет сала алады, бірақ боттар терлемейді және импровизация жасамайды."*

### 2) Еңбек пен Процесс Дәлелі (Labor & Process Proof)

- **Мәселе:** 2 секундта жасалған AI суреттері мен 2 айда жасалған майлы бояу кескіндері цифрлық әлемде бірдей "jpeg" ретінде қарастырылады.
- **[PoArt] Шешімі:** Туындының "жүктілік және туу" процесі тіркеледі. Эскиз кезеңдері, бояу қабаттары, жинақталған жұмсалған сағаттар және суретші туындыны жасау кезінде өткен физикалық процесс құжатталады. Бұл токенге **"Уақыт Құны" (Time Cost)** қосады. Активті өндіру қаншалықты қиын болса, оның құндылығы соншалықты берік.

### 3) Эстетикалық Құндылық Дәлелі (Aesthetic Value Proof)

- **Мәселе:** Бәрін елемейтін және тек лездік комедияға назар аударатын "Meme" мәдениетінің эстетикасы мен көркемдік тереңдігі және одан туындайтын қысқа мерзімді "Hype" жобалары.
- **[PoArt] Шешімі:** Жоба академиялық өнер стандарттарына, түс теориясына, композиция ережелеріне және материалдар туралы білімге (Impasto, Текстура т.б.) ие болуы керек. Мазмұн тек күлдірмеуі керек; көрермендерде сүйсіністі оятуы және **жинақтау құндылығына** ие болуы керек.

### 4) Тұжырымдамалық Инновация (Conceptual Novelty)

- **Мәселе:** Шығармашылықтан алыс мыңдаған бірдей dog/cat coin.
- **[PoArt] Шешімі:** Жоба өнер, ғылым, философия немесе технологияны мағыналы түрде біріктіретін жаңа көпір салуы керек.  
  (Мысалы: Классикалық Давид мүсінін криптовалюта нарығының деректерімен біріктіру; осы арқылы адам қабылдауының "тасқа айналу" идеясын өңдеу және мұны ғылыми дереккөздермен негіздей алу.)  
  Туынды тек визуалды мерекелік емес, сонымен қатар **Ғылым, Философия немесе Технология** туралы ойлануға түрткі болатын зияткерлік сынақ болуы керек.

> [!IMPORTANT]
> **Анықтама Мысалы (Las Palmitas Әсері):** Мексиканың қылмыспен күресетін Las Palmitas ауданында 200-ден астам үй алып кемпірқосақ мерекесіне айналдырылды. Бұл >эстетикалық араласу нәтижесінде аудандағы қылмыс көрсеткіштері белгілі бір дәрежеде төмендеді, жастар бандалардың орнына өнермен айналысуға бастады. Эстетикалық >өзгеріс адамдардың қоршаған ортаға және бір-біріне деген құрметін (Әлеуметтік Біртұтастық) қайта кодтады.
>
> **Күтілім:** [PoArt] тізіміне кіретін жоба; жоғарыдағы мысалдағыдай, визуалды эстетикадан тыс социологиялық, ғылыми немесе философиялық себеп-салдарлық байланысты >қамтуы керек. Ақшамен сатып алуға болмайтын жалғыз нәрсе "Уақыт" болғандықтан, бұл хаттамада уақыт стейкинг арқылы кепіл ретінде дәлелденуі керек. Жобаның >тұжырымдамалық негізі соншалықты күшті және әмбебап болуы керек; жылдар өткен соң мүмкін CTO (Community Take Over) сценарийінде де, қауымдастық осы мұраны >мұраға қалдыру арқылы жобаның инновациялық әлеуетін автономды түрде жалғастыра алады.

### 5) Алгоритмдік Емес Ерік (Non-Algorithmic Agency)

- **Мәселе:** Мінсіз бірақ жансыз, қайталанатын цифрлық өндірістер.
- **[PoArt] Шешімі:** Қателік жасай алатын, тәуекелге барып, эмоционалдық ауытқуларды сезінетін адам болмысының түпнұсқа ерігі туындыда сезілуі керек. Қылқалам соққыларындағы белгісіздік, материалдың күтпеген реакциялары және суретшінің лездік шешімдері туындыны "Механикалық Өндіріс"тен ажырататын **Биологиялық Қолтаңба**.

## c) Тексеру және Жалған Өнімге Қарсы Механизм

Бұл жүйе жобаның тек "басында" емес, "мәңгілік" сенімді және тірі болуын қамтамасыз етеді.

### 📦 Дәлелдер Пакеті (Evidence Pack - The Digital Twin)

Әрбір [PoArt] сертификатталған туындының артында инвесторлар жүктей алатын шифрланған және уақыт белгісімен белгіленген деректер пакеті бар:

- **RAW Бейне Жазбалар:** Өндіріс сәтінің үздіксіз шикі жазбалары.
- **Метадеректер Талдауы:** Файлдың жасалу күні, қолданылған құрылғы туралы ақпарат және орналасу деректері.
- **Физикалық Анықтамалар:** Туындының физикалық әлемде бар екендігінің дәлелдері  
  (Мысалы: Туынды жанында ағымдағы газет немесе ағымдағы блокчейн деректері).

> *Сәйкестік туралы ескерту:* "Дәлелдер пакеті" өрнегі алдыңғы бөлімдердегі **Evidence Pack → EvidenceRoot → NotarySeal** желісімен байланысты; яғни, пакеттің тұтастығы тексерілетін мөрмен көрсетіледі.

### 🔄 365 Күндік Жаңарту (The Sustainability Protocol)

- **Революциялық Мүмкіндік:** Криптовалюта жобаларында "Dev" (Әзірлеуші) токенді нарыққа шығарады және әдетте 1-2 айдан кейін жоғалады (Soft Rug). [PoArt] мұны мүмкін емес етеді.
- **Ереже:** "Verified Artist" (Тексерілген Суретші) мәртебесі өмір бойы емес. Ол тек **1 жыл** бойы жарамды.
- **Жұмыс Істеу:** Суретші/әзірлеуші әр 365 күн сайын қауымдастыққа **жаңа, үлкен және тексерілетін туындыны** ұсынуы керек.
- **Мысал Сценарий:** Сіз жобаны 2026 жылы бастадыңыз. 2027 жылдың қаңтарында жүйе "Дәлел Мерзімі Аяқталды" ескертуін береді. Егер суретші жаңа көрме, жаңа физикалық туынды немесе жаңа технологиялық интеграция ұсынбаса, жобаның "Сенім Белгісі" төмендейді.
- **Нәтиже:** Бұл жүйе **мазмұннің ешқашан өзектілігін жоғалтпауын** және инвестордың *"Әзірлеуші әлі де осында ма?"* қорқынышын сезінбеуін қамтамасыз етеді. Жоба тірі студияға айналады.

### 🚩 Қызыл Жалау (Red Flag Protocol)

**Қауымдастық немесе алгоритмдер арқылы кез келген жалғандық анықталған жағдайда (AI пайдалану, ұрланған жұмыс, манипуляцияланған бейне):**

1. Сертификат дереу **"ЖАРАМСЫЗ" (VOID)** ретінде белгіленеді.
2. Дәлелдер пакеттері ашық түрде **"Жалған"** ретінде белгіленеді.
3. Жоба [PoArt] қара тізіміне енгізіледі. Бұл орталықсыздандырылған әлемде **беделдің жалғыз валюта** екендігі фактісін нығайтады.

## 🗳️ 6) БАСҚАРУ ЖӘНЕ ҚОҒАМДЫҚ ТІЗІЛІМ (Governance & Public Registry)

**Бұл бөлімнің мақсаты: [PoArt] стандартын "адамдарға сену" саласынан алып тастау және оны тізілім + тексеру + қауымдастық қадағалауымен тұрақты қоғамдық инфрақұрылымға айналдыру.**

### 6.1 Қоғамдық Тізілім (Public Registry)

- **Public Registry:** Барлық мақұлданған деректер `ilhanart.org/registry` (немесе GitHub Registry) мекенжайында тіркеледі.

**Тіркеу логикасы (ұсынылған стандарт - JSON жолының форматы):**

Тізілімге кіретін әрбір жазба кемінде осы тексерілетін негізгі өрістерді қамтиды:

- **Жеке Бас пен Мәртебе:**
  - `certificate_id` (оқылатын анықтама)
  - `status` (active / void)
  - `void_reason` (бар болса)
  - `visibility` (private / masked / public)
  - `created_at` (уақыт белгісі)

- **Шығарушы Мекеме:**
  - `issuer.name`
  - `issuer.location`
  - `issuer.attestation_pubkey`

- **Туынды Туралы Ақпарат:**
  - `asset.title`
  - `asset.creator`
  - `asset.creator_wallet` (мүмкін болса; token-gated жеке бас үшін)
  - `asset.fingerprints.sha256`
  - `asset.fingerprints.sha512`

- **Сот-Криминалистикалық Деректер:**
  - `forensics.ip_masked`
  - `forensics.location`
  - `forensics.device`
  - `forensics.timestamp`

- **Криптографиялық Дәлелдер:**
  - `proof.evidence_root`
  - `proof.signer_sig`
  - `proof.notary_seal`

- **Басқару:**
  - `governance.decision`
  - `governance.veto_threshold`

Тізілімнің екі деңгейі болуы мүмкін:
- **1)** Адам оқитын индекс (веб-тізім / іздеу / сүзгі)
- **2)** Машина оқитын манифест (JSON жазбалары; PFE тексеруі үшін)

**Мұнда "тіркеу" PFE-нің Evidence Pack → EvidenceRoot → NotarySeal тізбегімен тексерілетін болады. Тізілім тексеру мақсатын қамтамасыз етеді, "мәлімдемені" емес.**

---

### 6.2 40% Қауымдастық Вето (Token-Gated Governance)

- **40% Қауымдастық Вето:** Мәртебені алуға бір ай қалғанда дауыс беру басталады; **Token-Gated (Solana-Verified)** қауымдастықтың 40% қарсылығы өтінішті жарамсыз етеді.

**Дауыс беру ағыны (ұсынылған таза процесс):**
- **Кандидаттық терезесі:** Кандидат жоба "PoArt кандидат тіркеуін" ашады (кандидат тіркеулері "pending" мәртебесімен көрінеді).
- **Қарау кезеңі:** 30 күн бойы қауымдастық дәлелдерді (Evidence Pack + тікелей эфир жазбалары + метадеректер) зерттейді.
- **Token-gated тексеру:** Дауыс беру Solana-да тексерілген әмияндар арқылы жүзеге асырылады (мысалы, белгілі бір токен/NFT иемдену + әмиян қолтаңбасы).
- **Вето ережесі:** Егер дауыстардың 40%-ы **қарсылық (NO / VETO)** болса, өтініш қабылданбайды.
- **Мөлдірлік:** Дауыс беру нәтижесі тізілімде "decision record" ретінде сақталады (күн, қатынас, snapshot ID).

---

### 6.3 Метадеректерді Синхрондау (Физикалық Әлеммен Сәйкестік)

- **Metadata Sync:** Тізілімдегі техникалық деректер физикалық активпен 100% сәйкес келуі керек.

**"100% сәйкестікті" техникалық түрде анықтау (ұсынылған айқындық):**
- **Минималды сәйкестік (міндетті):**
  - Тізілімдегі `asset.fingerprints.sha256/sha512` қолдағы файлдың хэшімен **дәл бірдей** болуы керек.
  - Тізілімдегі `proof.notary_seal` қайта жасалғанда (Evidence Pack бар болса) **дәл бірдей** болуы керек.
- **Физикалық анықтама сәйкестігі (дәлел түрі):**
  - Тікелей эфирде көрсетілген физикалық туынды + күн/блок анықтамасы сияқты дәлелдер Evidence Pack-пен үйлесімді болуы керек.
- **Құпиялылық сәйкестігі:**
  - `masked` көрінуде IP/орналасу сияқты өрістер **маскалау стандартына сәйкес** жарияланады.

### 6.4 Қарсылық, Қарау және Жою (Dispute & Revocation)

Тізілім тек "мақұлдау" механизмі емес; **жалғандыққа қарсы тірі қадағалау** механизмі.

- Қарсылық бастағанда, жазба **"review"** режиміне қойылуы мүмкін.
- Жалғандық анықталса, ол `status: void` ретінде белгіленеді және себеп қосылады:
  - `void_reason` (AI пайдалану / плагиат / манипуляция т.б.)
  - `revoked_at` (жою сәті)
- Жою шешімінің көзі тізілімде анық көрінеді:
  - қауымдастық дауысы / рұқсат етілген кеңес / сот-криминалистикалық тергеу жазбасы (қолданылатынына байланысты)

> **Бұл бөлім "Red Flag Protocol" бөліміндегі VOID тұжырымдамасының тізілімдегі баламасы.**

## 🧩 Неліктен Бірнеше "Көрінулік Модулі" Бар?

Ең маңызды код бөлігі осында (көрінулікті таңдау мәзірі). Бұл опциялар пайдаланушыларға **"Құпиялылық қарсы Мөлдірлік"** тепе-теңдігін орнатуға мүмкіндік береді:

### 🔒 Жеке (Private)

- **Сценарий:** Суретші әлі туындыны жариялағысы келмейді, бірақ уақыт белгісін қойып "мен мұны осы күні жасадым" деп дәлелдегісі келеді.
- **Код Не Істейді:** Деректерді дерекқорға жазады, бірақ `visibility: "private"` тегін қолданады. Болашақта "Public Read" саясатын жазғанда, `WHERE visibility = 'public'` деп айту арқылы осы жазбаларды көпшіліктен жасыруға болады.

### 🕶️ Маскаланған (Masked)

- **Сценарий:** Суретші мөлдірлікті қалайды, бірақ үй мекенжайының (IP орналасуы) табылуынан қорқады.
- **Код Не Істейді:** JavaScript жағында `maskIP` және `maskLoc` функциялары жұмыс істейді. IP мекенжайын `88.241.***.***` форматына және орналасуды `***/TR` форматына түрлендіріп, цензураланған нұсқасын дерекқорға жібереді.
- **Құпиялылық Туралы Ескерту:** Маскалау браузерде жүзеге асырылады, Supabase нақты орналасуды көрмейді. **Дегенмен:** Егер орналасу деректері үшін ipapi.co сияқты үшінші тарап API-лері қолданылса, бұл жеткізушілер сұрау сәтінде IP мекенжайын көреді.
- **Masked Режимінде Мөрлеу:** EvidenceRoot және NotarySeal есептеуі маскаланған forensics деректерімен жүзеге асырылады; осылайша тексеру детерминистикалық болып қалады.

### 🌍 Қоғамдық (Public)

- **Сценарий:** Толық мөлдірлік. [PoArt] стандартына сәйкес, туынды қайда, қашан және қандай желіден өндірілгені ашық жарияланады.

## 💡 Технологиялық Инновация

PoArt тек файл жүктеу жүйесі емес. Бұл үш түрлі технологиялық қабатты бір құйма қазанда біріктіретін және жаңа стандарт әкелетін **"Forensic Chain of Custody"** қозғалтқышы.

**Бұл бөлімде "қозғалтқыш" ретінде сипатталған қабат алдыңғы терминологиядағы PoArt Forensic Engine (PFE) ядросына сәйкес келеді.**

### 1) Client-Side Hashing (Максималды Құпиялылық)

Туындыларыңыздың файлдары серверге ешқашан жүктелмейді. Біздің браузерге негізделген (Client-side) қозғалтқышымыз файлдың хэшін (цифрлық дайджестін) компьютеріңізде есептейді. Серверге тек осы ізі мен метадеректер жіберіледі.

> **Құпиялылық Туралы Ескерту:** Туынды файлы серверге жүктелмейді және осылайша қорғалады. Дегенмен, forensics деректері (IP/орналасу) таңдалған көрінулік режиміне сәйкес (private/masked/public) бөліседі.

### 2) Forensic Data Fusion (Сот-Криминалистикалық Қуат)

Бұл жай уақыт белгісінен әлдеқайда көп. Жүйе келесі деректерді бір "Genesis Seal"-да біріктіреді:

- **Цифрлық Дайджест (SHA-512):** Криптографиялық дайджест (SHA-512) стандартын қолдана отырып, туындының бір пиксель өзгерсе де бұзылатын цифрлық ізі.
- **Орналасу және Уақыт:** Транзакция жасалған миллисекунд дәлдігіндегі күн, ел, қала және аудан.
- **Құрылғы Жеке Басы:** Операциялық жүйе, браузер және құрылғы түрі (User-Agent талдауы).

## 🔬 Техникалық Тереңдік: Мөрлеу Алгоритмі

### Детерминистикалық Хэш Функциялары
```javascript
// Көмекші Функциялар: Дайджестті hex жолға түрлендіру
async function digestToHex(algorithm, dataBytes) {
  const hashBuffer = await crypto.subtle.digest(algorithm, dataBytes);
  const hashArray = Array.from(new Uint8Array(hashBuffer));
  return hashArray.map(b => b.toString(16).padStart(2, '0')).join('');
}

// Жолды байт массивіне түрлендіру
function stringToBytes(text) {
  return new TextEncoder().encode(text);
}

// Канондық forensics жолын жасау (v1.0: тұрақты өріс реті + UTF-8 + \n бөлгіші)
// 2-фаза ескертуі: RFC 8785 (JCS) арқылы канондық JSON-ға өту
function canonicalForensics(forensicsData) {
  return JSON.stringify({
    ip_masked: forensicsData.ip_masked,
    location: forensicsData.location,
    device: forensicsData.device,
    timestamp: forensicsData.timestamp
  });
}
```

### NotarySeal Өндіру Процесі (Толықтай Детерминистикалық)
```javascript
// 1. FileHash есептеу (client-side)
async function computeFileHash(file) {
  const fileBuffer = await file.arrayBuffer();
  const fileBytes = new Uint8Array(fileBuffer);
  
  const sha256 = await digestToHex('SHA-256', fileBytes);
  const sha512 = await digestToHex('SHA-512', fileBytes);
  
  return { sha256, sha512 };
}

// 2. Сот-криминалистикалық деректерді жинау (бір уақыт белгісін пайдалану)
async function collectForensics(visibilityMode) {
  const timestamp = new Date().toISOString(); // Бір уақыт белгісін жасау
  const ipData = await fetch('https://ipapi.co/json/').then(r => r.json());
  
  let forensics = {
    ip_masked: visibilityMode === 'masked' ? maskIP(ipData.ip) : ipData.ip,
    location: visibilityMode === 'masked' 
      ? `***/${ipData.country}` 
      : `${ipData.city}, ${ipData.country_name || ipData.country}`,
    device: navigator.userAgent,
    timestamp: timestamp // Сол уақыт белгісі
  };
  
  return { forensics, timestamp };
}

// 3. EvidenceRoot жасау (канондық кодтаумен)
async function computeEvidenceRoot(fileHash512, forensicsData) {
  const canonicalPayload = `file_sha512:${fileHash512}\nforensics:${canonicalForensics(forensicsData)}`;
  return await digestToHex('SHA-512', stringToBytes(canonicalPayload));
}

// 4. NotarySeal өндіру (сол уақыт белгісін пайдалану)
async function computeNotarySeal(evidenceRoot, signerSignature, timestamp) {
  const sealPayload = `evidence_root:${evidenceRoot}\nsigner_sig:${signerSignature}\ntimestamp:${timestamp}`;
  return await digestToHex('SHA-512', stringToBytes(sealPayload));
}

// Маскалау көмекші функциялары (IPv4 және IPv6 қолдауы)
function maskIP(ip) {
  if (!ip) return "***";
  
  // IPv4 бақылауы
  if (ip.includes(".")) {
    const parts = ip.split(".");
    if (parts.length === 4) {
      return `${parts[0]}.${parts[1]}.***.***`;
    }
  }
  
  // IPv6 немесе белгісіз формат
  return "***";
}
```

```javascript
    return {
      valid: false,
      message: "❌ Жалған - Файл манипуляцияланған"
    };
  }
}
```

#### Full Verify (Толық Тексеру)
```javascript
// EvidenceRoot және NotarySeal-ды қайта жасайды және тексереді
async function verifyFull(file, certificateId) {
  const { sha512: userFileHash } = await computeFileHash(file);

  // Тізілімнен алу
  const cert = await fetchFromRegistry(certificateId);

  // 1) FileHash бақылауы (жылдам қызыл жалау)
  const originalHash = cert.asset.fingerprints.sha512;
  if (userFileHash !== originalHash) {
    return { valid: false, message: "❌ Жалған - Файл хэші сәйкес емес" };
  }

  // 2) EvidenceRoot қайта жасау (тізілімде сақталған forensics арқылы)
  const evidenceRoot = await computeEvidenceRoot(userFileHash, cert.forensics);
  if (evidenceRoot !== cert.proof.evidence_root) {
    return { valid: false, message: "❌ Сәйкес келмейді - EvidenceRoot жарамсыз" };
  }

  // 3) NotarySeal қайта жасау (сол уақыт белгісі + signer_sig арқылы)
  const seal = await computeNotarySeal(
    evidenceRoot,
    cert.proof.signer_sig,
    cert.forensics.timestamp
  );

  if (seal !== cert.proof.notary_seal) {
    return { valid: false, message: "❌ Сәйкес келмейді - NotarySeal жарамсыз" };
  }

  // Қосымша: 2-фазада signer_sig-ті attestation_pubkey арқылы да тексеру
  // const sigValid = await verifySig(cert.issuer.attestation_pubkey, cert.proof.signer_sig, evidenceRoot);
  // if (!sigValid) return { valid: false, message: "❌ Қолтаңба жарамсыз" };

  return { valid: true, message: "✅ Түпнұсқа - Full Verify өтті" };
}
```

> **Маңызды Ескертулер:**
> - **Quick Verify:** Жылдам пайдалану үшін тек файл хэшін тексереді.
> - **Full Verify:** Хаттаманың барлық қабаттарын (EvidenceRoot + NotarySeal) тексереді.
> - Барлық хэш операциялары детерминистикалық түрде, тұрақты кодтау және бөлгіштермен жүзеге асырылады.
> - **v1.0 канонизация стандарты:** Тұрақты өріс реті + UTF-8 кодтау + `\n` бөлгіші.
> - **2-фаза жоспары:** RFC 8785 (JCS - JSON Canonicalization Scheme) арқылы канондық JSON-ға өту.
> - Masked режимінде EvidenceRoot және NotarySeal есептеуі маскаланған forensics арқылы жүзеге асырылады.
> - Бір уақыт белгісі бүкіл процесте (forensics + NotarySeal) қолданылады; детерминизм кепілдендірілген.
> - **Forensics өріс атаулары:** `ip_masked`, `location`, `device`, `timestamp` (код пен тізілім толықтай сәйкес).
> - **Тізілім жолы:** `certificate.asset.fingerprints` (тексеру кодымен толықтай сәйкес).
> - **Тізілімдегі signer_sig:** `proof.signer_sig` өрісі Full Verify үшін қажет.
> - SignerSignature механизмі 2-фазада Solana Wallet Adapter арқылы іске қосылады; v1.0-де `attestation_pubkey` арқылы тексеру жүргізуге болады.
