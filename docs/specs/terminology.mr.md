# 📚 तांत्रिक शब्द आणि संकल्पनांचा शब्दकोश
> **"या प्रोटोकॉलची भाषा समजून घेणे म्हणजे तिची दृष्टी समजून घेणे."**

## ⚙️ PoArt फॉरेन्सिक इंजिन (PFE) v1.0: मूलभूत पायाभूत सुविधा

**PoArt फॉरेन्सिक इंजिन (PFE)** हे [PoArt] प्रोटोकॉलच्या मागे असलेले मध्यवर्ती तर्क आणि तांत्रिक ऑपरेशनचे प्रतिनिधित्व करणारे मुख्य स्तर आहे. हे एक "फॉरेन्सिक इंजिन" आहे जे कला उत्पादनाचा कच्चा डेटा घेते आणि त्याचे **डिजिटल पुरावा** मध्ये रूपांतर करते जे सत्यापन करण्यायोग्य आणि अपरिवर्तनीय आहे.

### 🧩 "PoArt Forensic" का?

- **PoArt (कलेचा पुरावा):** इंजिनचे उद्दिष्ट डिजिटल मालमत्तेचे मूल्य अटकळांशी जोडण्याऐवजी **सत्यापन करण्यायोग्य उत्पादन प्रक्रियेशी** जोडणे आहे.
- **Forensic (वैज्ञानिक सत्यापन):**
  - **तांत्रिक व्याख्या:** उत्पादन प्रक्रिया डेटा (ब्रश स्ट्रोक, वेळ व्हिडिओ, रेकॉर्ड) हाताळले गेले नाही हे सत्यापित करण्यासाठी अल्गोरिदम पद्धत आणि रेकॉर्ड क्रम.
  - **तात्विक स्तर:** **मानवी वेळ, मेहनत आणि निर्णय खर्च** मोजता येण्याजोग्या सत्यात रूपांतरित करण्याचा दावा, AI च्या "त्वरित परिणाम" उत्पादनाच्या विरुद्ध.

> टीप: ब्लॉकचेन एकत्रीकरण (उदा., Solana) PFE चे मूळ नाही; हे सत्यापन/नोंदणी उद्देशांसाठी **चेन अँकर लेयर** म्हणून स्वतंत्रपणे वर्णन केले जाईल.

### 🛠️ तांत्रिक व्याप्ती v1.0

**PoArt फॉरेन्सिक इंजिन (PFE) v1.0** जटिल आर्थिक मॉडेल्सपेक्षा खालील **3 मुख्य स्तंभांवर** तयार केले आहे:

1. **Hashing & Sealing (सील करणे):**  
   PFE पुराव्याच्या पॅकेजमधील सर्व घटक (कामाची फाइल, व्हिडिओ, JSON/रेकॉर्ड, स्वाक्षरी, इ.) निर्धारक पद्धतीने प्रक्रिया करते आणि एक अद्वितीय **NotarySeal** मूल्य तयार करते.

   **मुख्य संकल्पना (v1.0):**
   - **FileHash (कामाचे फिंगरप्रिंट):** कामाच्या फाइल बाइट्सपासून तयार केलेला हॅश.
   - **EvidenceRoot (पुराव्याच्या पॅकेजचे मूळ):** पुराव्याच्या पॅकच्या अखंडतेचे प्रतिनिधित्व करणारे मूळ सारांश (Merkle मूळ किंवा कॅनॉनिकल प्रतिनिधित्वाचा हॅश).
   - **NotarySeal (अंतिम सील / PFE आउटपुट):** EvidenceRoot + वेळ + स्वाक्षरी संयोजनापासून तयार केलेली अंतिम सील.

   **सूत्रे (गुंतवणूकदारांना स्पष्टपणे दिसतात):**
   
   $$\text{FileHash}_{512} = \text{SHA-512}(\text{ArtworkFileBytes})$$
   
   $$\text{NotarySeal} = \text{SHA-512}(\text{EvidenceRoot} \mid \text{SignerSignature} \mid \text{TimeStamp})$$
   
   **कॅनॉनिकल पेलोड व्याख्या (v1.0):**
   
   - **EvidenceRootPayload:**
```
   file_sha512:{sha512}\nforensics:{canonicalForensics(forensics)}
```
   
   - **NotarySealPayload:**
```
   evidence_root:{evidence_root}\nsigner_sig:{signer_sig}\ntimestamp:{timestamp}
```
   
   > टीप: PFE आउटपुट म्हणून संदर्भित मूल्य **NotarySeal** आहे. **SignerSignature** प्रक्रिया टप्पा 2 मध्ये (Solana Wallet Adapter सह) सक्रिय केली जाईल; सध्याच्या v1.0 मध्ये, सिस्टमची प्रमाणीकरण स्वाक्षरी वापरली जाते. प्रमाणीकरण सार्वजनिक की रजिस्टरमध्ये `issuer.attestation_pubkey` फील्डच्या अंतर्गत प्रकाशित केली जाते.

2. **Indexing (संचयन):**  
   कोणत्या वॉलेटने, कोणत्या तारखेला, **कामाचा पुरावा** कोणत्या कामासाठी स्पष्ट आणि चौकशी करण्यायोग्य रजिस्टर स्तरावर पाठवला हे लिहिते.  
   *(हा स्तर डेटाबेस असू शकतो; चेन एकत्रीकरण स्वतंत्रपणे "चेन अँकर लेयर" म्हणून वर्णन केले आहे.)*

3. **Verification (सत्यापन):**  
   कामाच्या वैधतेवर प्रश्न उपस्थित केल्यावर, PFE कच्चे पुरावे पुन्हा प्रक्रिया करते; गणना केलेली **EvidenceRoot / NotarySeal** मूल्ये साठवलेल्या रेकॉर्डशी जुळतात की नाही हे गणितीयपणे तपासते.

### 🧮 PoArt मूल्य सिद्धांत (The Value Theorem)

[PoArt] प्रोटोकॉल डिजिटल मालमत्तेचे मूल्य ($V$) अमूर्त बाजार धारणेशी जोडत नाही, तर **उत्पादन प्रक्रियेच्या भौतिक वास्तवाशी** जोडते.

आर्टिफिशियल इंटेलिजन्स (AI) त्वरित परिणाम देऊन प्रक्रिया नष्ट करते ($t \to 0$). [PoArt], तथापि, मूल्याला **वेळ, मेहनत आणि एजन्सी** घटकांच्या संचयन म्हणून हाताळते.

$$V_{\text{PoArt}} = \int_{t_{\text{start}}}^{t_{\text{end}}} \left(P_{\text{labor}}(t) \cdot I_{\text{agency}}(t)\right) dt + U_{\text{irreversible}}$$

#### व्हेरिएबल्सच्या व्याख्या

- **$\int dt$ (प्रक्रिया संचयन):**  
  मूल्य "त्वरित परिणाम" नाही; हे $t_{\text{start}}$ आणि $t_{\text{end}}$ दरम्यान संचित **प्रक्रिया** आहे. कालावधी कमी होत असताना (AI उत्पादन), समाकलन परिणाम 0 च्या जवळ येतो.

- **$P_{\text{labor}}(t)$ (त्वरित मेहनत शक्ती):**  
  उत्पादन दरम्यान खर्च केलेल्या मानसिक आणि शारीरिक मेहनतीच्या तीव्रतेचे प्रतिनिधित्व करते. सत्यापन करण्यायोग्य मेहनत वाढत असताना, इंटिग्रँड वाढते.  
  > टीप: हा शब्द व्यवहारात "मोजता येण्याजोग्य/सत्यापन करण्यायोग्य मेहनत संकेत" द्वारे सामान्यीकृत केला जाऊ शकतो.

- **$I_{\text{agency}}(t)$ (एजन्सी घटक):**  
  निर्मात्याची जोखीम घेण्याची आणि निर्णय घेण्याची क्षमता. हे $0$ आणि $1$ दरम्यान मूल्ये घेते.
  - **AI ($I \approx 0$):** आदेश कार्यान्वित करते, कोणतीही जोखीम घेत नाही, कोणताही खर्च भरत नाही.
  - **मानव ($I \to 1$):** निर्णय बदलतो, संकोच करतो, जोखीम घेतो.

- **$U_{\text{irreversible}}$ (अपरिवर्तनीय विशिष्टता):**  
  डिजिटल उत्पादनात पूर्ववत करणे (`Ctrl+Z`) शक्य असले तरी, भौतिक उत्पादनात (कॅनव्हासवर लावलेला रंग, कोरलेला दगड, थेट प्रसारणातील क्रिया) परत येण्याचा मार्ग नाही. हे **अपरिवर्तनीय स्वरूप** कामात "विशिष्टता" (बदलता न येणारे गुणधर्म) तयार करणारा अतिरिक्त शब्द आहे.

### 🔎 केस विश्लेषण: AI "त्वरित परिणाम" vs. मानव "सत्यापित प्रक्रिया"

खालील परिस्थिती **PoArt मूल्य सिद्धांत** व्यवहारात कसे कार्य करते आणि [PoArt] स्केलवर AI उत्पादन कमी स्कोअर का मिळवते हे दर्शविते.

#### परिस्थिती A: AI सह 10-सेकंद दृश्य उत्पादन

- **कालावधी ($\Delta t$):** $10$ सेकंद (लहान प्रक्रिया)
- **मेहनत शक्ती ($P_{\text{labor}}$):** $1$ युनिट (फक्त आदेश लिहिणे)
- **एजन्सी घटक ($I_{\text{agency}}$):** $0.01$ (जोखीम नाही, खर्च नाही)
- **अपरिवर्तनीय स्वरूप ($U_{\text{irreversible}}$):** $0$ (उलट करता येण्याजोगे / कॉपी करण्यायोग्य)

**परिणाम:**

$$V_{\text{AI}} \approx \int_{0}^{10} (1 \cdot 0.01) \, dt + 0 = 0.1$$

> **टिप्पणी:** परिणाम परिपूर्ण असला तरी; [PoArt] मूल्य $0$ च्या जवळ येते कारण कोणतीही प्रक्रिया जगली नाही आणि कोणतीही एजन्सी/जोखीम सामील नव्हती.

#### परिस्थिती B: थेट प्रसारणात 6-तास भौतिक उत्पादन

- **कालावधी ($\Delta t$):** $6$ तास ($21{,}600$ सेकंद)
- **मेहनत शक्ती ($P_{\text{labor}}$):** $0.5$ युनिट्स (सतत शारीरिक आणि मानसिक मेहनत)
- **एजन्सी घटक ($I_{\text{agency}}$):** $0.9$ (निर्णय बदलणे, जोखीम घेणे, अपरिवर्तनीय निवडी)
- **अपरिवर्तनीय स्वरूप ($U_{\text{irreversible}}$):** $>0$ (भौतिक संकेत पूर्ववत करू शकत नाही)

**परिणाम:**

$$V_{\text{Human}} \approx \int_{0}^{21600} (0.5 \cdot 0.9) \, dt + U_{\text{irreversible}} \approx 9720 + U_{\text{irreversible}}$$

> **टिप्पणी:** प्रक्रिया विस्तारित होत असताना आणि एजन्सी (जोखीम) वाढत असताना, मूल्य संचित रीतीने जमा होते. $U_{\text{irreversible}}$ शब्द कामात "विशिष्टता" (बदलता न येणारे गुणधर्म) तयार करणारे अतिरिक्त योगदान आहे.

### ✅ निष्कर्ष: पुरावा-बद्ध मूल्य (Proof-Bound Value)

हा सिद्धांत [PoArt] चा मूल्य दावा "प्राधान्य" किंवा "बाजार कथा" असण्यापासून काढून टाकतो आणि त्याला **सत्यापन करण्यायोग्य उत्पादन वास्तवाशी** जोडतो.

1. **प्रक्रिया नाही, मूल्य नाही:**  
   AI त्वरित परिणामांसह प्रक्रिया नष्ट करते ($t \to 0$). प्रक्रिया विंडो संकुचित होत असताना, समाकलन परिणाम कमी व्हायला हवा:
   
   $$\Delta t \downarrow \ \Rightarrow\ \int \left(P(t) \cdot I(t)\right) dt \to 0$$

2. **एजन्सी आणि जोखीम गुणक आहेत:**  
   [PoArt] फक्त "खर्च केलेला वेळ" मोजत नाही तर त्या वेळेतील निर्णय, जोखीम आणि खर्चाची वास्तविक पातळी देखील मोजते. जोखीम नसलेल्या उत्पादनाचे (AI) कमी मूल्य आहे:
   
   $$V_{\text{PoArt}} \propto \int \left(P_{\text{labor}}(t) \cdot I_{\text{agency}}(t)\right) dt$$

3. **विशिष्टता भौतिक पुरावा आहे, विपणन नाही:**  
   भौतिक उत्पादनातील अपरिवर्तनीय संकेत (कॅनव्हास स्ट्रोक, दगडाचा तुकडा) डिजिटलच्या `Ctrl+Z` तर्काच्या बाहेर आहेत. हे अपरिवर्तनीय स्वरूप ($U_{\text{irreversible}}$) कामाला ऑन्टोलॉजीद्वारे अद्वितीय बनवते.

> **🔐 सारांश:** मूल्य सिद्धांत मापन म्हणून अनिश्चितता सारखे दिसू शकते (वास्तविक जगाचे समतुल्य पूर्णपणे मोजले जाऊ शकत नसले तरी), या सूत्राचे उद्दिष्ट व्हेरिएबल्सची स्थापना आणि दिशा दर्शविणे आहे. AI युगात, दुर्मिळ गोष्ट "चित्र" नाही तर **सत्यापन करण्यायोग्य काम, वेळ आणि एजन्सी** आहे. [PoArt] या दुर्मिळतेचे मोजमाप करते आणि ते **पुराव्याच्या पॅकेजसह** लिहिते.

### 🏛️ "इंजिन" संकल्पनेचे महत्त्व

Pump.fun किंवा समान प्लॅटफॉर्मवरून येणारे टोकन्स बहुतेकदा फक्त **"प्रवेश तिकीट"** असतात. **PoArt फॉरेन्सिक इंजिन (PFE)**, तथापि, **संवैधानिक तर्क स्तर** आहे जे हे तिकीट कोणते अधिकार संरक्षित करते, काम कसे लिहिले जाईल आणि कला/विज्ञान/तंत्रज्ञान कसे राखले जाईल हे ठरवते.

> **टीप:** आम्ही Pumpfun वर हा प्रकल्प सुरू करण्याचे कारण आमच्याकडे पुरेसा निधी किंवा पुरेसे अनुयायी नव्हते. अस्तित्वात असलेला डेटा वापरणे हे धोरणात्मकदृष्ट्या योग्य पाऊल होते, जरी ते सर्वोच्च गुणवत्तेचे नसले तरी. बजेट आणि संसाधनांची पर्वा न करता, GitHub वर या इंजिनचे तर्क परिभाषित करणे प्रकल्प फक्त आर्थिक अटकळ नाही, तर **सॉफ्टवेअर पायाभूत सुविधा** आणि **राष्ट्रीय डिजिटल लायब्ररी** ची दीर्घकालीन दृष्टी आहे हे सिद्ध करते.

## a) [PoArt] म्हणजे काय? (तात्विक आणि तांत्रिक व्याख्या)

**कलेचा पुरावा [PoArt];** ही एक संस्थात्मक सत्यापन मानक आहे जी ब्लॉकचेनवरील मालमत्तेमागील मूल्य अटकळांवर आधारित नाही, तर **मानवी मेहनत**, **वेळ** आणि **सत्यापन करण्यायोग्य भौतिक ऊर्जा** यावर आधारित आहे याची खात्री करते.

Bitcoin *"वीज आणि प्रोसेसर शक्तीसह"* **(कामाचा पुरावा)** मूल्य तयार करतो त्याप्रमाणे, [PoArt] शी संरेखित प्रकल्प *"कला कौशल्य आणि मानवी वेळेसह"* मूल्य तयार करतात.

## 🗳️ 6) प्रशासन आणि सार्वजनिक रजिस्टर

**रजिस्टर तर्क (प्रस्तावित मानक - JSON पथ स्वरूपात):**

  - `forensics.ip_masked`
  - `forensics.location`

  - `forensics.timestamp`

  - `proof.evidence_root`

  - `proof.notary_seal`

- **प्रशासन:**
  - `governance.decision`

रजिस्टरचे दोन स्तर असू शकतात:
- **1)** मानव-वाचनीय निर्देशांक (वेब यादी / शोध / फिल्टर)

### 6.2 40% समुदाय व्हेटो (टोकन-गेटेड प्रशासन)

- **40% समुदाय व्हेटो:** स्थिती देण्यापूर्वी एक महिना मतदान सुरू होते; **टोकन-गेटेड (Solana सह सत्यापित)** समुदायाचे 40% व्हेटो अर्ज रद्द करते.

**मतदान प्रवाह (प्रस्तावित स्पष्ट प्रक्रिया):**
- **अर्ज विंडो:** उमेदवार प्रकल्प "PoArt उमेदवार नोंदणी" उघडतो (उमेदवार रेकॉर्ड "प्रलंबित स्थिती" मध्ये दिसतात).
- **पुनरावलोकन कालावधी:** समुदाय 30 दिवस पुरावे तपासतो (पुराव्याचे पॅकेज + थेट प्रसारण रेकॉर्ड + मेटाडेटा).
- **टोकन-गेटेड सत्यापन:** मतदान सत्यापित Solana वॉलेटसह केले जाते (उदा. विशिष्ट टोकन/NFT मालकी + वॉलेट स्वाक्षरी).
- **व्हेटो नियम:** जर 40% मते **विरोध (नाही / व्हेटो)** असतील तर अर्ज नाकारला जातो.
- **पारदर्शकता:** मतदान परिणाम रजिस्टरमध्ये "निर्णय रेकॉर्ड" (तारीख, प्रमाण, प्रतिमा ID) म्हणून संग्रहित केले जातात.

### 6.3 मेटाडेटा समक्रमण (भौतिक जगाशी संरेखन)

- **मेटाडेटा समक्रमण:** रजिस्टरमधील तांत्रिक डेटा भौतिक संस्थेशी 100% जुळले पाहिजे.

**"100% संरेखन" ची तांत्रिक व्याख्या (प्रस्तावित पारदर्शकता):**
- **किमान संरेखन (अनिवार्य):**
  - रजिस्टरमधील `asset.fingerprints.sha256/sha512` चर्चा केलेल्या फाइलच्या हॅशसह **समान** असले पाहिजे.
  - रजिस्टरमधील `proof.notary_seal` पुन्हा तयार केले असता (पुराव्याचे पॅकेज असल्यास), ते **समान** असले पाहिजे.
- **भौतिक संदर्भ संरेखन (पुरावा प्रकार):**
  - भौतिक काम + थेट प्रसारणात दर्शविलेला तारीख/ब्लॉक संदर्भ आणि समान पुरावा पुराव्याच्या पॅकेजशी जुळले पाहिजे.
- **गोपनीयता अनुपालन:**
  - `masked` दृश्यतेमध्ये IP/स्थान सारख्या फील्ड **मास्किंग मानकांनुसार** प्रकाशित केल्या जातात.

### 6.4 विवाद आणि रद्द

रजिस्टर फक्त "मंजूरी" प्रक्रिया नाही; हे फसवणुकीविरुद्ध **जिवंत पुनरावलोकन प्रक्रिया** आहे.

## 🧩 अनेक "दृश्यता मॉड्यूल" का?

हा कोडचा सर्वात महत्त्वाचा भाग आहे (दृश्यता पर्याय मेनू). हे पर्याय वापरकर्त्यांना **"गोपनीयता vs. पारदर्शकता"** संतुलित करण्यास सक्षम करतात:

### 🔒 खाजगी

- **परिस्थिती:** कलाकार अद्याप काम प्रकाशित करू इच्छित नाही, पण "मी हे या तारखेला केले" हे सिद्ध करण्यासाठी टाइम स्टॅम्प करू इच्छितो.
- **कोड काय करतो:** हे डेटाबेसमध्ये डेटा लिहितो परंतु सील `visibility: "private"` म्हणून चिन्हांकित करतो. नंतर तुम्ही "सार्वजनिक वाचन" धोरण लिहिता तेव्हा, तुम्ही या रेकॉर्डना `WHERE visibility = 'public'` सह लोकांपासून लपवू शकता.

### 🕶️ मुखवटा घातलेले

- **परिस्थिती:** कलाकार पारदर्शकता इच्छितो परंतु त्याचा घराचा पत्ता (IP स्थान) सापडेल याची भीती वाटते.
- **कोड काय करतो:** `maskIP` आणि `maskLoc` फंक्शन JavaScript बाजूस काम करतात. हे IP पत्ता `88.241.***.***` स्वरूपात, स्थान `***/TR` स्वरूपात बदलते आणि सेन्सर केलेली आवृत्ती डेटाबेसला पाठवते.
- **गोपनीयता सत्य:** मास्किंग ब्राउझरवर केले जाते, Supabase खरे स्थान पाहत नाही. **परंतु:** जर स्थान डेटासाठी ipapi.co सारख्या तृतीय-पक्ष API चा वापर केला असेल तर, हे प्रदाते विनंती वेळी IP पत्ता पाहतात.
- **मास्क मोडमध्ये सील करणे:** EvidenceRoot आणि NotarySeal गणना मुखवटा घातलेल्या फॉरेन्सिक डेटासह केली जाते; त्यामुळे सत्यापन निर्धारक राहते.

### 🌍 सार्वजनिक

- **परिस्थिती:** पूर्ण पारदर्शकता. [PoArt] मानकांनुसार, कुठे, केव्हा, कोणत्या नेटवर्कवरून काम तयार केले गेले हे उघडपणे घोषित केले जाते.

## 💡 तांत्रिक नवीनता

PoArt फक्त फाइल अपलोड प्रणाली नाही. हे एका भांड्यात तीन वेगवेगळे तांत्रिक स्तर एकत्रित करून नवीन मानक आणणारे **"वैज्ञानिक काळजी साखळी"** इंजिन आहे.

**या विभागात "इंजिन" म्हणून वर्णन केलेला स्तर मागील अटींमधील PoArt फॉरेन्सिक इंजिन (PFE) च्या कोरशी जुळतो.**

### 1) क्लायंट-साइड हॅशिंग (सर्वोच्च गोपनीयता)

तुमच्या कलाकृतीच्या फाइल्स सर्व्हरवर अपलोड केल्या जात नाहीत. आमचे ब्राउझर-आधारित (क्लायंट-साइड) इंजिन तुमच्या स्वतःच्या संगणकावर फाइलचा हॅश (डिजिटल सारांश) गणना करते. फक्त हे फिंगरप्रिंट आणि मेटाडेटा सर्व्हरला पाठवले जाते.

> **गोपनीयता सत्य:** काम फाइल सर्व्हरवर अपलोड केली जात नाही आणि अशा प्रकारे संरक्षित आहे. तथापि, फॉरेन्सिक डेटा (IP/स्थान) निवडलेल्या दृश्यता मोड (खाजगी/मुखवटा/सार्वजनिक) नुसार सामायिक केला जातो.

### 2) फॉरेन्सिक डेटा फ्यूजन (वैज्ञानिक शक्ती)

सामान्य टाइम स्टॅम्पपेक्षा अधिक. प्रणाली या डेटाला एका "मूळ सील" मध्ये एकत्रित करते:

- **डिजिटल सारांश (SHA-512):** क्रिप्टोग्राफिक सारांश मानक (SHA-512) वापरून फिंगरप्रिंट जे कामाचा एक पिक्सेल बदलला तरी तुटेल.
- **स्थान आणि वेळ:** मिलीसेकंद अचूकतेसह तारीख, देश, शहर आणि जिल्हा डेटा व्यवहार.
- **उपकरण ओळख:** ऑपरेटिंग सिस्टम, ब्राउझर आणि उपकरण प्रकार (User-Agent विश्लेषण).

## 🗺️ रोडमॅप: भविष्य "विश्वासरहित"

वर्तमान आवृत्ती **(Beta v1.0)** अंतिम वापरकर्त्यांना जास्तीत जास्त वेग, सोपा इंटरफेस आणि मोफत प्रवेश देण्यासाठी डिझाइन केली आहे. आमची अंतिम दृष्टी, तथापि, एका संरचनेत संक्रमण आहे जिथे डेटाबेस प्रशासक (आम्ही) देखील हस्तक्षेप करू शकत नाही.

- **उद्दिष्ट:** वेग, UX (वापरकर्ता अनुभव) अडथळे काढून टाकणे आणि अनुपालन. "घर्षणरहित" सुरक्षा प्रदान करणे.

## 🔬 तांत्रिक खोली: सील अल्गोरिदम

### निर्धारक हॅश फंक्शन्स
```javascript
// सहाय्यक फंक्शन्स: सारांश हेक्साडेसिमल स्ट्रिंगमध्ये रूपांतरित करा
async function digestToHex(algorithm, dataBytes) {
  const hashBuffer = await crypto.subtle.digest(algorithm, dataBytes);
  const hashArray = Array.from(new Uint8Array(hashBuffer));
  return hashArray.map(b => b.toString(16).padStart(2, '0')).join('');
}

// स्ट्रिंग बाइट अॅरेमध्ये रूपांतरित करा
function stringToBytes(text) {
  return new TextEncoder().encode(text);
}

// कॅनॉनिकल फॉरेन्सिक्स स्ट्रिंग निर्मिती (v1.0: स्थिर फील्ड क्रम + UTF-8 + विभाजक \n)
// टप्पा 2 सत्य: RFC 8785 (JCS) सह कॅनॉनिकल JSON मध्ये संक्रमण
function canonicalForensics(forensicsData) {
  return JSON.stringify({
    ip_masked: forensicsData.ip_masked,
    location: forensicsData.location,
    device: forensicsData.device,
    timestamp: forensicsData.timestamp
  });
}
```

### NotarySeal निर्मिती प्रक्रिया (पूर्णपणे निर्धारक)
```javascript
// 1. FileHash गणना (क्लायंट-साइड)
async function computeFileHash(file) {
  const fileBuffer = await file.arrayBuffer();
  const fileBytes = new Uint8Array(fileBuffer);
  
  const sha256 = await digestToHex('SHA-256', fileBytes);
  const sha512 = await digestToHex('SHA-512', fileBytes);
  
  return { sha256, sha512 };
}

// 2. फॉरेन्सिक डेटा संकलन (एकल टाइम स्टॅम्प वापर)
async function collectForensics(visibilityMode) {
  const timestamp = new Date().toISOString(); // एकल टाइम स्टॅम्प निर्मिती
  const ipData = await fetch('https://ipapi.co/json/').then(r => r.json());
  
  let forensics = {
    ip_masked: visibilityMode === 'masked' ? maskIP(ipData.ip) : ipData.ip,
    location: visibilityMode === 'masked' 
      ? `***/${ipData.country}` 
      : `${ipData.city}, ${ipData.country_name || ipData.country}`,
    device: navigator.userAgent,
    timestamp: timestamp // समान टाइम स्टॅम्प
  };
  
  return { forensics, timestamp };
}

// 3. EvidenceRoot बांधकाम (कॅनॉनिकल एन्क्रिप्शनसह)
async function computeEvidenceRoot(fileHash512, forensicsData) {
  const canonicalPayload = `file_sha512:${fileHash512}\nforensics:${canonicalForensics(forensicsData)}`;
  return await digestToHex('SHA-512', stringToBytes(canonicalPayload));
}

// 4. NotarySeal निर्मिती (समान टाइम स्टॅम्प वापर)
async function computeNotarySeal(evidenceRoot, signerSignature, timestamp) {
  const sealPayload = `evidence_root:${evidenceRoot}\nsigner_sig:${signerSignature}\ntimestamp:${timestamp}`;
  return await digestToHex('SHA-512', stringToBytes(sealPayload));
}

// मास्किंग सहाय्यक फंक्शन्स (IPv4 आणि IPv6 समर्थन)
function maskIP(ip) {
  if (!ip) return "***";
  
  // IPv4 तपासणी
  if (ip.includes(".")) {
    const parts = ip.split(".");
    if (parts.length === 4) {
      return `${parts[0]}.${parts[1]}.***.***`;
    }
  }
  
  // IPv6 किंवा अज्ञात स्वरूप
  return "***";
}
```

### सत्यापन प्रवाह (दोन स्तर)

#### Quick Verify (जलद सत्यापन)
```javascript
// फक्त फाइल हॅश सत्यापित करा (जलद लाल ध्वज)
async function verifyQuick(file, certificateId) {
  const { sha512: userFileHash } = await computeFileHash(file);
  
  // रजिस्टरमधून मिळवा
  const cert = await fetchFromRegistry(certificateId);
  const { sha512: originalHash } = cert.asset.fingerprints;
  
  // हॅश तुलना
  if (userFileHash === originalHash) {
    return {
      valid: true,
      message: "✅ अस्सल - फाइल हॅश जुळते"
    };
  } else {
    return {
      valid: false,
      message: "❌ खोटे - फाइल हाताळली गेली आहे"
    };
  }
}
```

#### Full Verify (पूर्ण सत्यापन)
```javascript
// EvidenceRoot आणि NotarySeal पुन्हा तयार करा आणि सत्यापित करा
async function verifyFull(file, certificateId) {
  const { sha512: userFileHash } = await computeFileHash(file);

  // रजिस्टरमधून मिळवा
  const cert = await fetchFromRegistry(certificateId);

  // 1) FileHash सत्यापन (जलद लाल ध्वज)
  const originalHash = cert.asset.fingerprints.sha512;
  if (userFileHash !== originalHash) {
    return { valid: false, message: "❌ खोटे - फाइल हॅश जुळत नाही" };
  }

  // 2) EvidenceRoot पुन्हा तयार करा (रजिस्टरमध्ये संचयित फॉरेन्सिक डेटासह)
  const evidenceRoot = await computeEvidenceRoot(userFileHash, cert.forensics);
  if (evidenceRoot !== cert.proof.evidence_root) {
    return { valid: false, message: "❌ जुळत नाही - EvidenceRoot टिकत नाही" };
  }

  // 3) NotarySeal पुन्हा तयार करा (समान टाइम स्टॅम्प + signer_sig सह)
  const seal = await computeNotarySeal(
    evidenceRoot,
    cert.proof.signer_sig,
    cert.forensics.timestamp
  );

  if (seal !== cert.proof.notary_seal) {
    return { valid: false, message: "❌ जुळत नाही - NotarySeal टिकत नाही" };
  }

  // पर्यायी: टप्पा 2 मध्ये, signer_sig देखील attestation_pubkey सह सत्यापित करा
  // const sigValid = await verifySig(cert.issuer.attestation_pubkey, cert.proof.signer_sig, evidenceRoot);
  // if (!sigValid) return { valid: false, message: "❌ अवैध स्वाक्षरी" };

  return { valid: true, message: "✅ अस्सल - पूर्ण सत्यापन उत्तीर्ण" };
}
```

> **महत्त्वपूर्ण सत्ये:**
> - **Quick Verify:** जलद वापरासाठी फक्त फाइल हॅश सत्यापित करते.
> - **Full Verify:** सर्व प्रोटोकॉल स्तर सत्यापित करते (EvidenceRoot + NotarySeal).
> - सर्व हॅश ऑपरेशन्स स्थिर एन्क्रिप्शन आणि स्थिर विभाजकांसह निर्धारक पद्धतीने केले जातात.
> - **वर्तमान मानक v1.0:** स्थिर फील्ड क्रम + UTF-8 एन्क्रिप्शन + विभाजक `\n`.
> - **टप्पा 2 योजना:** RFC 8785 (JCS - JSON Canonicalization Scheme) सह कॅनॉनिकल JSON मध्ये संक्रमण.
> - मास्क मोडमध्ये, EvidenceRoot आणि NotarySeal गणना मुखवटा घातलेल्या फॉरेन्सिक डेटासह केली जाते; त्यामुळे सत्यापन निर्धारक राहते.
> - संपूर्ण प्रक्रियेत एकल टाइम स्टॅम्प वापरला जातो (फॉरेन्सिक्स + NotarySeal); निर्धारकता खात्री आहे.
> - **फॉरेन्सिक फील्ड नावे:** `ip_masked`, `location`, `device`, `timestamp` (कोड आणि रजिस्टर अचूकपणे जुळतात).
> - **रजिस्टर पथ:** `certificate.asset.fingerprints` (सत्यापन कोडशी अचूकपणे जुळते).
> - **रजिस्टरमध्ये signer_sig:** पूर्ण सत्यापनासाठी `proof.signer_sig` फील्ड आवश्यक आहे.
> - SignerSignature प्रक्रिया टप्पा 2 मध्ये Solana Wallet Adapter सह सक्रिय केली जाईल; v1.0 मध्ये, सत्यापन `attestation_pubkey` सह केले जाऊ शकते.
