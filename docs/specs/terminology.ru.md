## ⚙️ PoArt Forensic Engine (PFE) v1.0: Базовая инфраструктура

**PoArt Forensic Engine (PFE)** — это основной уровень, представляющий базовую логику и техническую работу протокола [PoArt]. Это "криминалистический движок", который берет сырые производственные данные произведения искусства и превращает их в проверяемое и неизменяемое **цифровое доказательство**.

### 🧩 Почему "PoArt Forensic"?

- **PoArt (Proof of Art):** Фокус движка на привязке стоимости цифрового актива не к спекуляции, а к **доказуемому процессу производства**.
- **Forensic (Криминалистическая проверка):**
  - **Техническое определение:** Алгоритмический подход и цепочка записей для проверки того, что данные производственного процесса (мазки кисти, таймлапс, логи) не были манипулированы.
  - **Философский уровень:** Утверждение о превращении человеческого производства, содержащего **время, усилия и цену решений**, в измеримую реальность, в отличие от "мгновенного вывода" искусственного интеллекта.

> Примечание: Интеграция блокчейна (например, Solana) не является ядром PFE; она рассматривается как отдельный **Chain Anchor Layer**, который будет определен для проверки/реестра.

### 🛠️ Технический охват v1.0

**PoArt Forensic Engine (PFE) v1.0** построен на этих **3 основных столпах**, а не на сложных финансовых моделях:

1. **Hashing & Sealing (Хеширование и опечатывание):**  
   PFE детерминистически обрабатывает все элементы в Evidence Pack (файл произведения, видео, JSON/логи, подпись и т.д.) и создает уникальное значение **NotarySeal**.

   **Основные концепции (v1.0):**
   - **FileHash (отпечаток произведения):** Хеш, созданный из байтов файла произведения.
   - **EvidenceRoot (корень пакета доказательств):** Корневая сводка, представляющая целостность Evidence Pack (корень Меркла или канонический хеш манифеста).
   - **NotarySeal (окончательная печать / вывод PFE):** Окончательная печать, созданная из комбинации EvidenceRoot + время + подпись.

   **Формулы (четко видны инвесторам):**
   
   $$\text{FileHash}_{512} = \text{SHA-512}(\text{ArtworkFileBytes})$$
   
   $$\text{NotarySeal} = \text{SHA-512}(\text{EvidenceRoot} \mid \text{SignerSignature} \mid \text{TimeStamp})$$
   
   **Определения канонической полезной нагрузки (v1.0):**
   
   - **EvidenceRootPayload:**
```
   file_sha512:{sha512}\nforensics:{canonicalForensics(forensics)}
```
   
   - **NotarySealPayload:**
```
   evidence_root:{evidence_root}\nsigner_sig:{signer_sig}\ntimestamp:{timestamp}
```
   
   > Примечание: Значение, подразумеваемое как вывод PFE, — это **NotarySeal**. Механизм **SignerSignature** будет активирован в фазе 2 (с Solana Wallet Adapter); в текущей v1.0 используется собственная аттестационная подпись системы. Открытый ключ аттестации публикуется в реестре в поле `issuer.attestation_pubkey`.

2. **Indexing (Архивирование):**  
   Обрабатывает в прозрачном и запрашиваемом уровне записей, какой кошелек, в какую дату представил **Labor Proof (Доказательство труда)** для какого произведения.  
   *(Этот уровень может быть базой данных; интеграция цепи отдельно определяется как "Chain Anchor Layer".)*

3. **Verification (Проверка):**  
   Когда подлинность произведения ставится под сомнение, PFE повторно обрабатывает сырые доказательства; с математической уверенностью проверяет, соответствуют ли рассчитанные значения **EvidenceRoot / NotarySeal** записи в архиве.

### 🧮 Теорема стоимости PoArt (The Value Theorem)

Протокол [PoArt] связывает стоимость ($V$) цифрового актива не с субъективным восприятием рынка, а с **физической реальностью производственного процесса**.

Искусственный интеллект (ИИ) уничтожает процесс, мгновенно выдавая результат ($t \to 0$). [PoArt] же рассматривает стоимость как накопление компонентов **времени, труда и воли**.

$$V_{\text{PoArt}} = \int_{t_{\text{start}}}^{t_{\text{end}}} \left(P_{\text{labor}}(t) \cdot I_{\text{agency}}(t)\right) dt + U_{\text{irreversible}}$$

#### Определение переменных

- **$\int dt$ (Накопление процесса):**  
  Стоимость — это не мгновенный "вывод" (output); это **процесс**, накапливающийся между $t_{\text{start}}$ и $t_{\text{end}}$. По мере уменьшения продолжительности (производство ИИ) результат интеграла приближается к 0.

- **$P_{\text{labor}}(t)$ (Мгновенная рабочая сила):**  
  Представляет интенсивность умственных и физических усилий, затраченных в момент производства. По мере увеличения доказуемых усилий подынтегральное выражение растет.  
  > Примечание: Этот термин может быть нормализован на практике через "измеримые/доказуемые сигналы труда".

- **$I_{\text{agency}}(t)$ (Коэффициент воли):**  
  Это способность производителя идти на риск и принимать решения. Принимает значение от $0$ до $1$.
  - **ИИ ($I \approx 0$):** Выполняет команды, не идет на риск, не платит цену.
  - **Человек ($I \to 1$):** Меняет решения, колеблется, идет на риск.

- **$U_{\text{irreversible}}$ (Необратимая сингулярность):**  
  В то время как в цифровом производстве возможна отмена (`Ctrl+Z`); в физическом производстве (краска, нанесенная на холст, высеченный мрамор, жест в прямом эфире) нет возврата. Эта **необратимость** — дополнительный термин, создающий "сингулярность" (non-fungible характер) в произведении.

### 🔎 Анализ кейса: ИИ "Мгновенный вывод" против Человек "Доказанный процесс"

Следующий сценарий показывает, как **Теорема стоимости PoArt** работает на практике и почему производства ИИ получают низкие оценки в стандарте [PoArt].

#### Сценарий A: Визуальное производство с ИИ за 10 секунд

- **Продолжительность ($\Delta t$):** $10$ секунд (процесс практически отсутствует)
- **Рабочая сила ($P_{\text{labor}}$):** $1$ единица (только написание команды)
- **Коэффициент воли ($I_{\text{agency}}$):** $0.01$ (нет риска, нет цены)
- **Необратимость ($U_{\text{irreversible}}$):** $0$ (обратимо / копируемо)

**Результат:**

$$V_{\text{AI}} \approx \int_{0}^{10} (1 \cdot 0.01) \, dt + 0 = 0.1$$

> **Комментарий:** Даже если вывод безупречен; поскольку процесс не был пережит и не содержит воли/риска, стоимость [PoArt] приближается к $0$.

#### Сценарий B: 6-часовое физическое производство в прямом эфире

- **Продолжительность ($\Delta t$):** $6$ часов ($21{,}600$ секунд)
- **Рабочая сила ($P_{\text{labor}}$):** $0.5$ единиц (непрерывность физических и умственных усилий)
- **Коэффициент воли ($I_{\text{agency}}$):** $0.9$ (изменения решений, готовность к риску, необратимые выборы)
- **Необратимость ($U_{\text{irreversible}}$):** $>0$ (физические следы необратимы)

**Результат:**

$$V_{\text{Human}} \approx \int_{0}^{21600} (0.5 \cdot 0.9) \, dt + U_{\text{irreversible}} \approx 9720 + U_{\text{irreversible}}$$

> **Комментарий:** По мере удлинения процесса и увеличения воли (риска) стоимость кумулятивно возрастает. Термин $U_{\text{irreversible}}$ — это дополнительный вклад, создающий "сингулярность" (non-fungible характер) в произведении.

### ✅ Заключение: Стоимость, привязанная к доказательству (Proof-Bound Value)

Эта теорема выводит утверждение о стоимости [PoArt] из "вкуса" или "рыночного нарратива" и привязывает к **доказуемой реальности производства**.

1. **Без процесса нет стоимости:**  
   ИИ уничтожает процесс мгновенным выводом ($t \to 0$). По мере сужения окна процесса результат интеграла уменьшается по математической необходимости:
   
   $$\Delta t \downarrow \ \Rightarrow\ \int \left(P(t) \cdot I(t)\right) dt \to 0$$

2. **Воля и риск — множители:**  
   [PoArt] измеряет не только "затраченное время", но и реальный слой решений, риска и цены в это время. Стоимость производства без риска (ИИ) низка:
   
   $$V_{\text{PoArt}} \propto \int \left(P_{\text{labor}}(t) \cdot I_{\text{agency}}(t)\right) dt$$

3. **Сингулярность — физическое доказательство, а не маркетинг:**  
   Необратимые следы в физическом производстве (мазок кисти на холсте, скол мрамора) находятся вне логики цифрового `Ctrl+Z`. Эта необратимость ($U_{\text{irreversible}}$) сингуляризирует произведение онтологически.

> **🔐 РЕЗЮМЕ:** Хотя теорема стоимости может показаться неопределенной как измерение (даже если в реальной жизни невозможно измерить на 100%), цель этой формулы — показать конструкцию и направление переменных. В эпоху ИИ редкостью является не "изображение"; это **доказуемый труд, время и воля**. [PoArt] измеряет эту редкость и регистрирует с помощью **Evidence Pack**.

### 🏛️ Важность концепции "Engine" (Движок)

Токены, выходящие с Pump.fun или подобных платформ, чаще всего являются просто **"билетами доступа"**. **PoArt Forensic Engine (PFE)** же — это **конституционный логический уровень**, определяющий, какие права защищает этот билет, как будет записываться труд и как будет увековечено искусство/наука/технология.

> **Примечание:** Причина, по которой мы запустили этот проект на Pump.fun, заключается в том, что у нас не было достаточной ликвидности и количества подписчиков. Использование существующих данных было стратегически правильным ходом, хотя и не самого высокого качества. Независимо от бюджета и возможностей, определение логики этого движка на GitHub доказывает, что проект — это не просто финансовая спекуляция, а долгосрочная **программная инфраструктура** и видение **цифровой национальной библиотеки**.

## a) Что такое [PoArt]? (Философское и техническое определение)

**Proof of Art [PoArt];** — это институциональный стандарт проверки, гарантирующий, что стоимость, стоящая за активом на блокчейне, основана не на спекуляции, а на проверяемом **человеческом труде**, **времени** и **физической энергии**.

Как биткоин создает стоимость с помощью *"Электричества и процессорной мощности"* **(Proof of Work)**; проекты, совместимые с [PoArt], создают стоимость с помощью *"Художественного таланта и человеческого времени"*.

Устраняет риск *"Разработчик (Dev) продал, проект закончился"* на платформах Pump.fun и DEX; потому что здесь стоимость заключена не в коде, а в **непрерывности производства**.

> **[PoArt] не говорит участнику "Доверьтесь нам"; он говорит "Вот доказательства, смотрите своими глазами, проверяйте своей математикой".**

## b) 5-столпный стандарт [PoArt] (The 5 Pillars of Truth)

Эти 5 пунктов — немодифицируемые фильтры, через которые должен пройти проект, чтобы получить печать [PoArt].

### 1) Доказательство живой личности (Live Identity Proof)

- **Проблема:** Криптомир полон анонимных основателей (Dev'ов) с неясной идентичностью, которые собирают деньги и покидают проект.
- **Решение [PoArt]:** Производитель доказывает не только удостоверение личности, но и **свое присутствие во время производства**. Это включает сеансы прямых трансляций, в которых происходит взаимодействие с сообществом и выполняются конкретные мгновенные запросы, а не предварительно записанные видео.  
  (Например: *"Напиши сегодняшнюю дату и текущий номер блока в правом углу холста"*)
- **Девиз:** *"Боты могут создавать изображения, но боты не потеют и не импровизируют."*

### 2) Доказательство труда и процесса (Labor & Process Proof)

- **Проблема:** То, что изображения ИИ (искусственного интеллекта), созданные за 2 секунды, и масляная картина, сделанная за 2 месяца, получают одинаковую обработку "jpeg" в цифровом мире.
- **Решение [PoArt]:** Процесс "беременности и рождения" произведения записывается. Документируются стадии эскизов, слои краски, затраченные кумулятивные часы и физический процесс, который художник пережил при создании этого произведения. Это добавляет **"Стоимость времени" (Time Cost)** к токену. Чем сложнее производство актива, тем прочнее его стоимость.

### 3) Доказательство эстетической ценности (Aesthetic Value Proof)

- **Проблема:** Культура "мемов" игнорирует эстетику и художественную глубину, фокусируясь только на мгновенной комедии, и в результате возникают короткоживущие "хайповые" проекты.
- **Решение [PoArt]:** Проект должен иметь академические художественные стандарты, теорию цвета, правила композиции и знание материалов (импасто, текстура и т.д.). Содержание не должно только смешить; оно должно вызывать восхищение у зрителя и иметь **коллекционную ценность**.

### 4) Концептуальная инновация (Conceptual Novelty)

- **Проблема:** Тысячи собачьих/кошачьих монет, являющихся копиями друг друга, далеких от творчества.
- **Решение [PoArt]:** Проект должен построить новый мост, объединяющий искусство, науку, философию или технологию в значимой структуре.  
  (Например: Объединить классическую статую Давида с данными крипторынка; проработать идею "окаменения" человеческого восприятия и обосновать это научными источниками.)  
  Произведение должно быть не только визуальным праздником; оно также должно быть интеллектуальным вызовом, заставляющим задуматься о **науке, философии или технологии**.

> [!IMPORTANT]
> **Референсный пример (эффект Лас-Пальмитас):**  
> В мексиканском районе Лас-Пальмитас, борющемся с преступностью, более 200 домов были превращены в гигантский радужный праздник. В результате этого эстетического вмешательства уровень преступности в районе до определенной степени снизился, молодежь начала интересоваться искусством вместо банд. Эстетическое изменение перекодировало уважение людей к окружающей среде и друг к другу (социальная сплоченность).
>
> **Ожидание:** Проект, который войдет в список [PoArt]; должен, как и в приведенном выше примере, содержать социологическую, научную или философскую причинно-следственную связь помимо чисто визуальной эстетики. Поскольку единственным активом, который нельзя купить за деньги, является "время", в этом протоколе время должно быть застейкано и доказано как залог. Концептуальная основа проекта должна быть настолько сильной и универсальной, что даже в возможном сценарии CTO (Community Take Over) спустя годы сообщество сможет перенять это наследие и автономно продолжить инновационный потенциал проекта.

### 5) Неалгоритмическая воля (Non-Algorithmic Agency)

- **Проблема:** Безупречные, но бездушные цифровые производства, повторяющие друг друга.
- **Решение [PoArt]:** Подлинная воля человека, способного ошибаться, идти на риск и испытывать эмоциональные колебания, должна ощущаться в произведении. Неопределенность в мазках кисти, неожиданные реакции материала и мгновенные решения художника — это **биологическая подпись**, отличающая произведение от "машинного производства".

## c) Механизм проверки и защиты от подделки

Эта система обеспечивает, чтобы проект оставался надежным и живым не только "в начале", но и "навсегда".

### 📦 Пакет доказательств (Evidence Pack - The Digital Twin)

За каждым сертифицированным произведением [PoArt] находится зашифрованный и проштампованный временем пакет данных, который могут скачать инвесторы:

- **RAW-видеозаписи:** Непрерывные необработанные изображения момента производства.
- **Анализ метаданных:** Дата создания файла, информация об используемом устройстве и данные о местоположении.
- **Физические ссылки:** Доказательства существования произведения в физическом мире  
  (Например: Текущая газета рядом с произведением или данные блокчейна того момента).

> *Примечание консистентности:* Выражение "пакет доказательств" связывается с линией **Evidence Pack → EvidenceRoot → NotarySeal** из предыдущих разделов; то есть целостность пакета представлена проверяемой печатью.

### 🔄 365-дневное обновление (The Sustainability Protocol)

- **Революционная особенность:** В криптопроектах "Dev" (разработчик) выводит токен на рынок и обычно исчезает через 1-2 месяца (Soft Rug). [PoArt] делает это невозможным.
- **Правило:** Статус "Verified Artist" (проверенный художник) не пожизненный. Он действителен только **1 год**.
- **Работа:** Художник/Разработчик обязан каждые 365 дней представлять сообществу **новое, значительное и доказуемое произведение**.
- **Пример сценария:** Вы запустили проект в 2026 году. В январе 2027 года система выдает предупреждение "Срок доказательства истек". Если художник не представит новую выставку, новое физическое произведение или новую технологическую интеграцию, "Значок доверия" проекта падает.
- **Результат:** Эта система обеспечивает, что **содержание никогда не теряет актуальность** и инвестор не испытывает страха *"Разработчик еще здесь?"*. Проект превращается в живую студию.

### 🚩 Красный флаг (Red Flag Protocol)

2. Пакеты доказательств публично маркируются как **"Поддельные"**.
3. Проект добавляется в черный список [PoArt]. Это подтверждает факт, что в децентрализованном мире **репутация — единственная валюта**.

### 6.4 Синхронизация метаданных (Metadata Sync)

- **Синхронизация метаданных:** Технические данные в реестре должны совпадать на 100% с физической сущностью.

**Техническое определение "100% совпадения" (рекомендуемая ясность):**

- **Минимальное совпадение (обязательно):**

- **Совпадение физической ссылки (тип доказательства):**
  - Доказательства, такие как физическое произведение + дата/блок-ссылка, показанные в прямой трансляции, должны быть согласованы с Evidence Pack.

- **Соответствие конфиденциальности:**
  - В видимости `masked` поля, такие как IP/местоположение, публикуются **в соответствии со стандартом маскировки**.

## Почему публичный?

Настоящая безопасность происходит от прозрачности. Благодаря нашей системе **публичного реестра (Public Registry)**, человек в любой точке мира может за секунды проверить, является ли файл, который у него есть, оригинальным, не нуждаясь в каком-либо авторитете.

## 🧩 Почему несколько "модулей видимости"?

Это самая критическая часть кода (меню выбора видимости). Эти опции позволяют пользователям установить баланс **"Конфиденциальность vs. Прозрачность"**:

### 🔒 Приватный (Private)

- **Сценарий:** Художник еще не хочет публиковать произведение, но хочет поставить временную метку и доказать "я сделал это в эту дату".
- **Что делает код:** Записывает данные в базу данных, но ставит метку `visibility: "private"`. При последующем написании политики "Public Read" можно скрыть эти записи от публики, сказав `WHERE visibility = 'public'`.

### 🕶️ Замаскированный (Masked)

- **Сценарий:** Художник хочет прозрачности, но боится, что будет найден его домашний адрес (местоположение IP).
- **Что делает код:** На стороне JavaScript работают функции `maskIP` и `maskLoc`. Конвертирует IP-адрес в форму `88.241.***.***`, местоположение в форму `***/TR` и отправляет цензурированную версию в базу данных.
- **Примечание о конфиденциальности:** Маскировка выполняется в браузере, Supabase не видит реальное местоположение. **Однако:** Если используются сторонние API, такие как ipapi.co для данных о местоположении, эти провайдеры видят IP-адрес в момент запроса.
- **Опечатывание в замаскированном режиме:** Расчет EvidenceRoot и NotarySeal выполняется с замаскированными криминалистическими данными; таким образом проверка остается детерминированной.

### 🌍 Публичный (Public)

- **Сценарий:** Полная прозрачность. В соответствии со стандартом [PoArt] четко заявляется, где, когда, из какой сети было создано произведение.

## 💡 Технологическая инновация

PoArt — это не просто система загрузки файлов. Это движок **"криминалистической цепи хранения" (Forensic Chain of Custody)**, который плавит три разных технологических уровня в одном котле и вносит новый стандарт.

**Уровень, объясняемый как "движок" в этом разделе, соответствует ядру PoArt Forensic Engine (PFE) в предыдущей терминологии.**

### 1) Хеширование на стороне клиента (Максимальная конфиденциальность)

Файлы ваших произведений никогда не загружаются на сервер. Наш работающий на основе браузера (клиентский) движок вычисляет хеш (цифровую сводку) файла на вашем собственном компьютере. На сервер отправляются только этот отпечаток и метаданные.

> **Примечание о конфиденциальности:** Файл произведения не загружается на сервер и таким образом защищен. Однако криминалистические данные (IP/местоположение) делятся в соответствии с выбранным режимом видимости (private/masked/public).

### 2) Слияние криминалистических данных (Криминалистическая сила)

Это гораздо больше, чем обычная временная метка (Timestamp). Система объединяет эти данные в одной "печати генезиса":

- **Цифровая сводка (SHA-512):** Цифровой отпечаток, который будет поврежден, даже если изменится один пиксель произведения, с использованием стандарта криптографической сводки (SHA-512).
- **Местоположение и время:** Данные о дате, стране, городе и районе с точностью до миллисекунд, когда была выполнена операция.
- **Идентичность устройства:** Операционная система, браузер и тип устройства (анализ User-Agent).

## 🔬 Техническая глубина: Алгоритм печати

### Детерминированные хеш-функции
```javascript
// Вспомогательные функции: Преобразование digest в hex-строку
async function digestToHex(algorithm, dataBytes) {
  const hashBuffer = await crypto.subtle.digest(algorithm, dataBytes);
  const hashArray = Array.from(new Uint8Array(hashBuffer));
  return hashArray.map(b => b.toString(16).padStart(2, '0')).join('');
}

// Преобразование строки в массив байтов
function stringToBytes(text) {
  return new TextEncoder().encode(text);
}

// Генерация канонической строки криминалистики (v1.0: фиксированный порядок полей + UTF-8 + разделитель \n)
// Примечание фазы 2: Переход к каноническому JSON с RFC 8785 (JCS)
function canonicalForensics(forensicsData) {
  return JSON.stringify({
    ip_masked: forensicsData.ip_masked,
    location: forensicsData.location,
    device: forensicsData.device,
    timestamp: forensicsData.timestamp
  });
}
```

### Процесс генерации NotarySeal (Полностью детерминированный)
```javascript
// 1. Вычисление FileHash (на стороне клиента)
async function computeFileHash(file) {
  const fileBuffer = await file.arrayBuffer();
  const fileBytes = new Uint8Array(fileBuffer);
  
  const sha256 = await digestToHex('SHA-256', fileBytes);
  const sha512 = await digestToHex('SHA-512', fileBytes);
  
  return { sha256, sha512 };
}

// 2. Сбор криминалистических данных (использование одной временной метки)
async function collectForensics(visibilityMode) {
  const timestamp = new Date().toISOString(); // Генерация одной временной метки
  const ipData = await fetch('https://ipapi.co/json/').then(r => r.json());
  
  let forensics = {
    ip_masked: visibilityMode === 'masked' ? maskIP(ipData.ip) : ipData.ip,
    location: visibilityMode === 'masked' 
      ? `***/${ipData.country}` 
      : `${ipData.city}, ${ipData.country_name || ipData.country}`,
    device: navigator.userAgent,
    timestamp: timestamp // Та же временная метка
  };
  
  return { forensics, timestamp };
}

// 3. Создание EvidenceRoot (с канонической кодировкой)
async function computeEvidenceRoot(fileHash512, forensicsData) {
  const canonicalPayload = `file_sha512:${fileHash512}\nforensics:${canonicalForensics(forensicsData)}`;
  return await digestToHex('SHA-512', stringToBytes(canonicalPayload));
}

// 4. Генерация NotarySeal (использование той же временной метки)
async function computeNotarySeal(evidenceRoot, signerSignature, timestamp) {
  const sealPayload = `evidence_root:${evidenceRoot}\nsigner_sig:${signerSignature}\ntimestamp:${timestamp}`;
  return await digestToHex('SHA-512', stringToBytes(sealPayload));
}

// Вспомогательные функции маскировки (поддержка IPv4 и IPv6)
function maskIP(ip) {
  if (!ip) return "***";
  
  // Проверка IPv4
  if (ip.includes(".")) {
    const parts = ip.split(".");
    if (parts.length === 4) {
      return `${parts[0]}.${parts[1]}.***.***`;
    }
  }
  
  // IPv6 или неизвестный формат
  return "***";
}
```

### Поток проверки (Два уровня)

#### Быстрая проверка (Quick Verify)
```javascript
// Проверяет только хеш файла (быстрый красный флаг)
async function verifyQuick(file, certificateId) {
  const { sha512: userFileHash } = await computeFileHash(file);
  
  // Получить из реестра
  const cert = await fetchFromRegistry(certificateId);
  const { sha512: originalHash } = cert.asset.fingerprints;
  
  // Сравнение хешей
  if (userFileHash === originalHash) {
    return {
      valid: true,
      message: "✅ Оригинал - Хеш файла совпадает"
    };
  } else {
    return {
      valid: false,
      message: "❌ Поддельный - Файл манипулирован"
    };
  }
}
```

#### Полная проверка (Full Verify)
```javascript
// Регенерирует и проверяет EvidenceRoot и NotarySeal
async function verifyFull(file, certificateId) {
  const { sha512: userFileHash } = await computeFileHash(file);

  // Получить из реестра
  const cert = await fetchFromRegistry(certificateId);

  // 1) Проверка FileHash (быстрый красный флаг)
  const originalHash = cert.asset.fingerprints.sha512;
  if (userFileHash !== originalHash) {
    return { valid: false, message: "❌ Поддельный - Хеш файла не совпадает" };
  }

  // 2) Регенерировать EvidenceRoot (с криминалистикой, хранящейся в реестре)
  const evidenceRoot = await computeEvidenceRoot(userFileHash, cert.forensics);
  if (evidenceRoot !== cert.proof.evidence_root) {
    return { valid: false, message: "❌ Не совпадает - EvidenceRoot не проходит" };
  }

  // 3) Регенерировать NotarySeal (с той же временной меткой + signer_sig)
  const seal = await computeNotarySeal(
    evidenceRoot,
    cert.proof.signer_sig,
    cert.forensics.timestamp
  );

  if (seal !== cert.proof.notary_seal) {
    return { valid: false, message: "❌ Не совпадает - NotarySeal не проходит" };
  }

  // Опционально: В фазе 2 также проверить signer_sig с attestation_pubkey
  // const sigValid = await verifySig(cert.issuer.attestation_pubkey, cert.proof.signer_sig, evidenceRoot);
  // if (!sigValid) return { valid: false, message: "❌ Подпись недействительна" };

  return { valid: true, message: "✅ Оригинал - Full Verify пройдена" };
}
```

> **Важные примечания:**
> - **Quick Verify:** Проверяет только хеш файла для быстрого использования.
> - **Full Verify:** Проверяет все уровни протокола (EvidenceRoot + NotarySeal).
> - Все операции хеширования выполняются детерминированно, с фиксированной кодировкой и разделителями.
> - **Стандарт канонизации v1.0:** Фиксированный порядок полей + кодировка UTF-8 + разделитель `\n`.
> - **План фазы 2:** Переход к каноническому JSON с RFC 8785 (JCS - JSON Canonicalization Scheme).
> - В замаскированном режиме вычисление EvidenceRoot и NotarySeal выполняется с замаскированными криминалистическими данными.
> - Одна временная метка используется во всем процессе (криминалистика + NotarySeal); гарантируется детерминизм.
> - **Имена полей криминалистики:** `ip_masked`, `location`, `device`, `timestamp` (код и реестр полностью совместимы).
> - **Путь реестра:** `certificate.asset.fingerprints` (полностью совместим с кодом проверки).
> - **signer_sig в реестре:** Поле `proof.signer_sig` необходимо для Full Verify.
> - Механизм SignerSignature будет активирован в фазе 2 с Solana Wallet Adapter; в v1.0 можно проверять с `attestation_pubkey`.
