## ⚙️ PoArt Forensic Engine (PFE) v1.0: Основная Инфраструктура

**PoArt Forensic Engine (PFE)** — это основной уровень, представляющий центральную логику и техническую работу протокола [PoArt]. Это "криминалистический движок", который берет необработанные данные производства произведения искусства и превращает их в проверяемые и неизменяемые **цифровые доказательства**.

### 🧩 Почему "PoArt Forensic"?

- **PoArt (Proof of Art):** Фокус движка заключается в привязке ценности цифрового актива не к спекуляции, а к **доказуемому процессу производства**.
- **Forensic (Криминалистическая Проверка):**
  - **Техническое Определение:** Алгоритмический подход и цепочка записей для проверки того, что данные процесса производства (мазки кисти, таймлапс, журналы) не были изменены.
  - **Философский Уровень:** Утверждение о преобразовании **человеческого времени, усилий и стоимости решений** в измеримую реальность против "мгновенного вывода" производства ИИ.

> Примечание: Интеграция блокчейна (например, Solana) не является ядром PFE; она будет определена отдельно как **Chain Anchor Layer** для целей верификации/реестра.

### 🛠️ Технический Охват v1.0

**PoArt Forensic Engine (PFE) v1.0** построен на следующих **3 основных столпах** вместо сложных финансовых моделей:

1. **Hashing & Sealing (Запечатывание):**  
   PFE детерминированно обрабатывает все элементы в Пакете Доказательств (файл произведения, видео, JSON/логи, подпись и т.д.) и генерирует уникальное значение **NotarySeal**.

   **Основные концепции (v1.0):**
   - **FileHash (отпечаток произведения):** Хеш, сгенерированный из байтов файла произведения.
   - **EvidenceRoot (корень пакета доказательств):** Корневой дайджест, представляющий целостность Пакета Доказательств (корень Merkle или канонический хеш манифеста).
   - **NotarySeal (финальная печать / вывод PFE):** Финальная печать, сгенерированная из комбинации EvidenceRoot + время + подпись.

   **Формулы (четко видимые для инвесторов):**
   
   $$\text{FileHash}_{512} = \text{SHA-512}(\text{ArtworkFileBytes})$$
   
   $$\text{NotarySeal} = \text{SHA-512}(\text{EvidenceRoot} \mid \text{SignerSignature} \mid \text{TimeStamp})$$
   
   **Определения Канонической Полезной Нагрузки (v1.0):**
   
   - **EvidenceRootPayload:**
```
   file_sha512:{sha512}\nforensics:{canonicalForensics(forensics)}
```
   
   - **NotarySealPayload:**
```
   evidence_root:{evidence_root}\nsigner_sig:{signer_sig}\ntimestamp:{timestamp}
```
   
   > Примечание: Значение, упомянутое как вывод PFE, — это **NotarySeal**. Механизм **SignerSignature** будет активирован на Фазе 2 (с Solana Wallet Adapter); в текущей v1.0 используется собственная подпись аттестации системы. Публичный ключ аттестации публикуется в реестре в поле `issuer.attestation_pubkey`.

2. **Indexing (Архивирование):**  
   Записывает, какой кошелек, в какую дату, отправил **Proof of Labor (Доказательство Труда)** для какого произведения в прозрачный и запрашиваемый уровень реестра.  
   *(Этот уровень может быть базой данных; интеграция цепи определяется отдельно как "Chain Anchor Layer".)*

3. **Verification (Верификация):**  
   Когда подлинность произведения ставится под сомнение, PFE повторно обрабатывает необработанные доказательства; математически проверяет, соответствуют ли вычисленные значения **EvidenceRoot / NotarySeal** архивным записям.

### 🧮 Теорема Ценности PoArt (The Value Theorem)

Протокол [PoArt] связывает ценность ($V$) цифрового актива не с субъективным восприятием рынка, а с **физической реальностью процесса производства**.

Искусственный Интеллект (ИИ) уничтожает процесс, доставляя результат мгновенно ($t \to 0$). [PoArt], однако, рассматривает ценность как накопление компонентов **времени, труда и воли**.

$$V_{\text{PoArt}} = \int_{t_{\text{start}}}^{t_{\text{end}}} \left(P_{\text{labor}}(t) \cdot I_{\text{agency}}(t)\right) dt + U_{\text{irreversible}}$$

#### Определения Переменных

- **$\int dt$ (Накопление Процесса):**  
  Ценность — это не мгновенный "вывод"; это **процесс**, накопленный между $t_{\text{start}}$ и $t_{\text{end}}$. По мере уменьшения продолжительности (производство ИИ), результат интеграла приближается к 0.

- **$P_{\text{labor}}(t)$ (Мгновенная Рабочая Сила):**  
  Представляет интенсивность умственных и физических усилий, затраченных в момент производства. По мере увеличения доказуемых усилий, подынтегральное выражение растет.  
  > Примечание: Этот термин может быть нормализован на практике через "измеримые/доказуемые сигналы труда".

- **$I_{\text{agency}}(t)$ (Коэффициент Воли):**  
  Способность производителя к принятию рисков и принятию решений. Принимает значение между $0$ и $1$.
  - **ИИ ($I \approx 0$):** Выполняет команды, не принимает рисков, не платит затрат.
  - **Человек ($I \to 1$):** Меняет решения, сомневается, принимает риски.

- **$U_{\text{irreversible}}$ (Необратимая Уникальность):**  
  Хотя отмена (`Ctrl+Z`) возможна в цифровом производстве, в физическом производстве (краска, нанесенная на холст, высеченный мрамор, жест в прямом эфире) обратного пути нет. Эта **необратимость** — дополнительный термин, создающий "уникальность" (невзаимозаменяемый характер) в произведении.

### 🔎 Анализ Случая: ИИ "Мгновенный Вывод" против Человека "Доказанный Процесс"

Следующий сценарий демонстрирует, как работает **Теорема Ценности PoArt** на практике и почему производства ИИ получают низкие баллы в стандарте [PoArt].

#### Сценарий A: Визуальное Производство за 10 Секунд с ИИ

- **Продолжительность ($\Delta t$):** $10$ секунд (незначительный процесс)
- **Рабочая Сила ($P_{\text{labor}}$):** $1$ единица (только написание команд)
- **Коэффициент Воли ($I_{\text{agency}}$):** $0.01$ (без риска, без затрат)
- **Необратимость ($U_{\text{irreversible}}$):** $0$ (обратимо / копируемо)

**Результат:**

$$V_{\text{AI}} \approx \int_{0}^{10} (1 \cdot 0.01) \, dt + 0 = 0.1$$

> **Комментарий:** Даже если вывод безупречен; ценность [PoArt] приближается к $0$, потому что не было прожито никакого процесса и не было задействовано воли/риска.

#### Сценарий B: 6-Часовое Физическое Производство в Прямом Эфире

- **Продолжительность ($\Delta t$):** $6$ часов ($21{,}600$ секунд)
- **Рабочая Сила ($P_{\text{labor}}$):** $0.5$ единиц (непрерывность физических и умственных усилий)
- **Коэффициент Воли ($I_{\text{agency}}$):** $0.9$ (изменение решений, принятие рисков, необратимые выборы)
- **Необратимость ($U_{\text{irreversible}}$):** $>0$ (физические следы не могут быть отменены)

**Результат:**

$$V_{\text{Human}} \approx \int_{0}^{21600} (0.5 \cdot 0.9) \, dt + U_{\text{irreversible}} \approx 9720 + U_{\text{irreversible}}$$

> **Комментарий:** По мере удлинения процесса и увеличения воли (риска), ценность накапливается кумулятивно. Термин $U_{\text{irreversible}}$ — дополнительный вклад, создающий "уникальность" (невзаимозаменяемый характер) в произведении.

### ✅ Заключение: Ценность, Привязанная к Доказательству (Proof-Bound Value)

Эта теорема извлекает утверждение о ценности [PoArt] из "лайка" или "рыночного нарратива" и привязывает его к **доказуемой реальности производства**.

1. **Без Процесса Нет Ценности:**  
   ИИ уничтожает процесс мгновенным выводом ($t \to 0$). По мере сужения окна процесса, результат интеграла неизбежно уменьшается:
   
   $$\Delta t \downarrow \ \Rightarrow\ \int \left(P(t) \cdot I(t)\right) dt \to 0$$

2. **Воля и Риск — Множители:**  
   [PoArt] измеряет не только "затраченное время", но и реальный уровень решений, рисков и затрат в это время. Производство без принятия рисков (ИИ) имеет низкую ценность:
   
   $$V_{\text{PoArt}} \propto \int \left(P_{\text{labor}}(t) \cdot I_{\text{agency}}(t)\right) dt$$

3. **Уникальность — Физическое Доказательство, Не Маркетинг:**  
   Необратимые следы в физическом производстве (мазок холста, осколок мрамора) находятся вне логики `Ctrl+Z` цифрового мира. Эта необратимость ($U_{\text{irreversible}}$) онтологически делает произведение уникальным.

> **🔐 РЕЗЮМЕ:** Хотя теорема ценности может казаться неопределенной как измерение (даже если ее реальный аналог не может быть полностью измерен), цель этой формулы — показать конфигурацию и направление переменных. В эпоху ИИ дефицитны не "изображения", а **доказуемый труд, время и воля.** [PoArt] измеряет этот дефицит и регистрирует его с помощью **Пакета Доказательств**.

### 🏛️ Важность Концепции "Движка"

Токены, появляющиеся с Pump.fun или подобных платформ, часто являются просто **"билетами доступа"**. **PoArt Forensic Engine (PFE)**, однако, — это **конституционный логический уровень**, определяющий, какие права защищает этот билет, как будет записываться труд и как будет увековечиваться искусство/наука/технология.

> **Примечание:** Причина, по которой мы запустили этот проект на Pumpfun, заключается в том, что у нас не было достаточной ликвидности и достаточного количества подписчиков. Использование существующих данных было стратегически правильным шагом, даже если не самого высокого качества. Независимо от бюджета и ресурсов, определение логики этого движка на GitHub доказывает, что проект — это не просто финансовая спекуляция, а долгосрочное видение **программной инфраструктуры** и **цифровой национальной библиотеки**.

## a) Что Такое [PoArt]? (Философское и Техническое Определение)

**Proof of Art [PoArt];** — это институциональный стандарт верификации, гарантирующий, что ценность за активом на блокчейне основана не на спекуляции, а на проверяемом **человеческом труде**, **времени** и **физической энергии**.

Так же, как Bitcoin генерирует ценность с помощью *"Электричества и Процессорной Мощности"* **(Proof of Work)**, проекты, совместимые с [PoArt], генерируют ценность с помощью *"Художественного Мастерства и Человеческого Времени"*.

Он устраняет риск *"Разработчик продал, проект закончен"* на платформах Pump.fun и DEX; потому что здесь ценность не в коде, а в **непрерывности производства**.

> **[PoArt] не говорит участникам "Доверьтесь нам"; он говорит "Вот доказательства, смотрите своими глазами, проверяйте своей математикой."**

## b) 5-Столпный Стандарт [PoArt] (5 Столпов Истины)

Эти 5 элементов — неманипулируемые фильтры, которые должен пройти проект, чтобы получить печать [PoArt].

### 1) Доказательство Личности в Реальном Времени

- **Проблема:** Криптомир полон анонимных основателей (Разработчиков) с неясными личностями, собирающих деньги и бросающих проекты.
- **Решение [PoArt]:** Производитель доказывает не только удостоверение личности, но и **присутствие в момент производства**. Это включает в себя сеансы прямой трансляции, где происходит взаимодействие с сообществом и выполняются конкретные мгновенные запросы, а не предварительно записанные видео.  
  (Например, *"Напиши сегодняшнюю дату и текущий номер блока в правом углу холста"*)
- **Девиз:** *"Боты могут рисовать, но боты не потеют и не могут импровизировать."*

### 2) Доказательство Труда и Процесса

- **Проблема:** Визуалы ИИ (Искусственного Интеллекта), произведенные за 2 секунды, получают такое же отношение "jpeg", как картины маслом, сделанные за 2 месяца, в цифровом мире.
- **Решение [PoArt]:** Процесс "беременности и рождения" произведения записывается. Документируются этапы эскиза, слои краски, накопленные часы, потраченные художником, и физический процесс, который художник пережил при создании произведения. Это добавляет **"Временные Затраты"** к токену. Чем сложнее производство актива, тем прочнее его ценность.

### 3) Доказательство Эстетической Ценности

- **Проблема:** Культура "Мемов", фокусирующаяся только на мгновенной комедии, игнорируя эстетику и художественную глубину, приводящая к краткосрочным "Хайповым" проектам.
- **Решение [PoArt]:** Проект должен иметь академические стандарты искусства, теорию цвета, правила композиции и знание материалов (Импасто, Текстура и т.д.). Контент должен не просто смешить; он должен вдохновлять восхищение у зрителей и иметь **коллекционную ценность**.

### 4) Концептуальная Новизна

- **Проблема:** Тысячи копий собачьих/кошачьих монет, лишенных креативности.
- **Решение [PoArt]:** Проект должен построить новый мост, объединяющий искусство, науку, философию или технологию в значимой структуре.  
  (Например, Объединение классической скульптуры Давида с данными криптовалютного рынка; обработка идеи о том, что человеческое восприятие "превращается в камень" через это и обоснование этого научными источниками.)  
  Произведение должно быть не просто визуальным праздником, но и интеллектуальным вызовом, провоцирующим размышления о **Науке, Философии или Технологии**.

> [!IMPORTANT]
> **Эталонный Пример (Эффект Лас Пальмитас):** В районе Лас Пальмитас в Мексике, охваченном преступностью, более 200 домов были превращены в массовое радужное зрелище. В результате этого эстетического вмешательства уровень преступности в районе снизился в определенной степени, и молодежь стала заниматься искусством вместо банд. Эстетические изменения перекодировали уважение людей к своему окружению и друг к другу (Социальная Сплоченность).
>
> **Ожидание:** Проект, входящий в список [PoArt], должен, как в примере выше, содержать социологическую, научную или философскую причинно-следственную связь за пределами чистой визуальной эстетики. Поскольку время — единственный актив, который нельзя купить за деньги, в этом протоколе время должно быть доказано путем его размещения в качестве залога. Концептуальная основа проекта должна быть настолько сильной и универсальной, что даже в возможном сценарии CTO (Community Take Over) спустя годы сообщество может автономно продолжать инновационный потенциал проекта, унаследовав это наследие.

### 5) Неалгоритмическая Воля

- **Проблема:** Идеальные, но бездушные цифровые производства, повторяющие друг друга.
- **Решение [PoArt]:** Уникальная воля человека, который может ошибаться, рисковать и испытывать эмоциональные колебания, должна ощущаться в произведении. Неопределенность в мазках кисти, неожиданные реакции материалов и мгновенные решения художника — это **Биологическая Подпись**, отделяющая произведение от "Машинного Производства".

## c) Механизм Верификации и Анти-Мошенничества

Эта система гарантирует, что проект остается надежным и живым не только "в начале", но и "навсегда".

### 📦 Пакет Доказательств - Цифровой Двойник

За каждым сертифицированным произведением [PoArt] стоит зашифрованный и временно меченный пакет данных, который инвесторы могут скачать:

- **RAW Видеозаписи:** Непрерывные необработанные кадры момента производства.
- **Анализ Метаданных:** Дата создания файла, информация об используемом устройстве и данные о местоположении.
- **Физические Ссылки:** Доказательства того, что произведение существует в физическом мире  
  (Например, Текущая газета или данные блокчейна того момента рядом с произведением).

> *Примечание о последовательности:* Термин "пакет доказательств" связан с цепочкой **Пакет Доказательств → EvidenceRoot → NotarySeal** в предыдущих разделах; то есть целостность пакета представлена проверяемой печатью.

### 🔄 Обновление на 365 Дней (Протокол Устойчивости)

- **Революционная Особенность:** В криптопроектах "Разработчик" выпускает токен и обычно исчезает через 1-2 месяца (Мягкий Раг). [PoArt] делает это невозможным.
- **Правило:** Статус "Верифицированного Художника" не пожизненный. Действителен только **1 год**.
- **Операция:** Художник/Разработчик должен представлять сообществу **новое, значительное и доказуемое произведение** каждые 365 дней.
- **Пример Сценария:** Вы запустили проект в 2026 году. В январе 2027 года система выдает предупреждение "Срок Доказательства Истек". Если художник не представит новую выставку, новое физическое произведение или новую технологическую интеграцию, "Значок Доверия" проекта падает.
- **Результат:** Эта система гарантирует, что **контент никогда не теряет актуальность**, и инвестор никогда не испытывает страх *"Разработчик все еще здесь?"*. Проект становится живой студией.

### 🚩 Протокол Красного Флага

### 6.1 Публичный Реестр

- **Публичный Реестр:** Все утвержденные данные записываются на `ilhanart.org/registry` (или GitHub Registry).

**Логика реестра (рекомендуемый стандарт - в формате пути JSON):**

Каждая запись, входящая в реестр, несет эти минимальные проверяемые основные поля:

- **Идентичность и Статус:**
  - `certificate_id` (читаемая ссылка)
  - `status` (active / void)
  - `void_reason` (если применимо)
  - `visibility` (private / masked / public)
  - `created_at` (временная метка)

- **Выдающая Организация:**
  - `issuer.name`
  - `issuer.location`
  - `issuer.attestation_pubkey`

- **Информация о Произведении:**
  - `asset.title`
  - `asset.creator`
  - `asset.creator_wallet` (если возможно; для токен-гейтед идентичности)
  - `asset.fingerprints.sha256`
  - `asset.fingerprints.sha512`

- **Криминалистические Данные:**
  - `forensics.ip_masked`
  - `forensics.location`
  - `forensics.device`
  - `forensics.timestamp`

- **Криптографические Доказательства:**
  - `proof.evidence_root`
  - `proof.signer_sig`
  - `proof.notary_seal`

- **Управление:**
  - `governance.decision`
  - `governance.veto_threshold`

Реестр может иметь два уровня:
- **1)** Человекочитаемый индекс (веб-листинг / поиск / фильтр)
- **2)** Машиночитаемый манифест (записи JSON; для верификации PFE)

**Эта "запись" становится проверяемой через цепочку Пакет Доказательств → EvidenceRoot → NotarySeal PFE. Реестр предлагает цели верификации, а не "утверждения".**

### 6.2 40% Вето Сообщества (Управление с Токен-Гейтом)

- **40% Вето Сообщества:** Голосование начинается за месяц до предоставления статуса; 40% возражений сообщества **с Токен-Гейтом (верифицированного Solana)** делает заявку недействительной.

**Процесс голосования (рекомендуемый четкий процесс):**
- **Окно заявки:** Проект-кандидат открывает "регистрацию кандидата PoArt" (записи кандидатов появляются в статусе "ожидание").
- **Период рассмотрения:** Сообщество изучает доказательства в течение 30 дней (Пакет Доказательств + записи прямых трансляций + метаданные).
- **Токен-гейтед верификация:** Голосование осуществляется с верифицированными кошельками Solana (например, владение определенным токеном/NFT + подпись кошелька).
- **Правило вето:** Если 40% голосов — **возражение (НЕТ / ВЕТО)**, заявка отклоняется.
- **Прозрачность:** Результат голосования хранится в реестре как "запись решения" (дата, соотношение, ID снапшота).

---

### 6.3 Синхронизация Метаданных (Выравнивание с Физическим Миром)

- **Синхронизация Метаданных:** Технические данные в реестре должны на 100% совпадать с физической сущностью.

**Техническое определение "100% совпадения" (рекомендуемая ясность):**
- **Минимальное совпадение (обязательное):**
  - `asset.fingerprints.sha256/sha512` в реестре должен быть **идентичен** хешу файла в наличии.
  - Когда `proof.notary_seal` в реестре воспроизводится (если существует Пакет Доказательств), он должен быть **идентичен**.
- **Совпадение физической ссылки (тип доказательства):**
  - Физическое произведение + ссылка на дату/блок, показанная в прямой трансляции, и аналогичные доказательства должны быть согласованы с Пакетом Доказательств.
- **Соответствие конфиденциальности:**
  - Поля, такие как IP/местоположение в видимости `masked`, публикуются **согласно стандартам маскирования**.

### 6.4 Спор и Отзыв

Реестр — это не просто механизм "одобрения"; это **живой механизм аудита против мошенничества**.

- При возникновении спора запись может быть помещена в режим **"review" (рассмотрение)**.
- Если обнаружено мошенничество, она маркируется как `status: void` с добавлением причины:
  - `void_reason` (использование ИИ / кража / манипуляция и т.д.)
  - `revoked_at` (время отзыва)
- Источник решения об отзыве четко виден в реестре:

> **Этот раздел является аналогом в реестре концепции VOID из раздела "Протокол Красного Флага".**

## 🧩 Почему Несколько "Модулей Видимости"?

Это самая критическая часть кода (меню выбора видимости). Эти опции позволяют пользователям балансировать **"Конфиденциальность против Прозрачности"**:

### 🔒 Приватный

- **Сценарий:** Художник еще не хочет публиковать произведение, но хочет поставить на него временную метку, чтобы доказать "я сделал это в эту дату".
- **Что Делает Код:** Записывает данные в базу данных, но ставит штамп `visibility: "private"`. Позже при написании политики "Public Read" вы можете скрыть эти записи от публики с помощью `WHERE visibility = 'public'`.

### 🕶️ Замаскированный

- **Сценарий:** Художник хочет прозрачности, но боится, что будет найден его домашний адрес (местоположение IP).
- **Что Делает Код:** Функции `maskIP` и `maskLoc` работают на стороне JavaScript. Преобразует IP-адрес в формат `88.241.***.***`, местоположение в формат `***/TR`, и отправляет цензурированную версию в базу данных.
- **Примечание о Конфиденциальности:** Маскирование выполняется в браузере, Supabase не видит реальное местоположение. **Однако:** Если используются сторонние API, такие как ipapi.co, для данных о местоположении, эти провайдеры видят IP-адрес во время запроса.
- **Запечатывание в Замаскированном Режиме:** Вычисление EvidenceRoot и NotarySeal выполняется с замаскированными криминалистическими данными; таким образом, верификация остается детерминированной.

### 🌍 Публичный

- **Сценарий:** Полная прозрачность. Согласно стандартам [PoArt], где, когда, из какой сети было произведено произведение, четко заявлено.

## 💡 Технологическая Инновация

PoArt — это не просто система загрузки файлов. Это движок **"Криминалистической Цепочки Хранения"**, который приносит новый стандарт, объединяя три разных технологических уровня в одном горшке.

**Уровень, описанный как "движок" в этом разделе, соответствует ядру PoArt Forensic Engine (PFE) в предыдущей терминологии.**

### 1) Хеширование на Стороне Клиента (Максимальная Конфиденциальность)

Ваши файлы произведений искусства никогда не загружаются на сервер. Наш браузерный (клиентский) движок вычисляет хеш (цифровой дайджест) файла на вашем собственном компьютере. На сервер отправляются только этот отпечаток и метаданные.

> **Примечание о Конфиденциальности:** Файл произведения не загружается на сервер и защищен таким образом. Однако криминалистические данные (IP/местоположение) передаются в соответствии с выбранным режимом видимости (приватный/замаскированный/публичный).

### 2) Слияние Криминалистических Данных (Криминалистическая Мощь)

Гораздо больше, чем обычная временная метка. Система объединяет эти данные в единую "Печать Генезиса":

- **Цифровой Дайджест (SHA-512):** Цифровой отпечаток, использующий стандарт криптографического дайджеста (SHA-512), который сломается, если изменится даже один пиксель произведения.
- **Местоположение и Время:** Дата с точностью до миллисекунды, страна, город и данные района транзакции.
- **Идентичность Устройства:** Операционная система, браузер и тип устройства (анализ User-Agent).

## 🔬 Техническая Глубина: Алгоритм Печати

### Детерминированные Хеш-Функции
```javascript
// Вспомогательные Функции: Преобразовать дайджест в шестнадцатеричную строку
async function digestToHex(algorithm, dataBytes) {
  const hashBuffer = await crypto.subtle.digest(algorithm, dataBytes);
  const hashArray = Array.from(new Uint8Array(hashBuffer));
  return hashArray.map(b => b.toString(16).padStart(2, '0')).join('');
}

// Преобразовать строку в массив байтов
function stringToBytes(text) {
  return new TextEncoder().encode(text);
}

// Генерация канонической криминалистической строки (v1.0: фиксированный порядок полей + UTF-8 + разделитель \n)
// Примечание Фазы 2: Переход к каноническому JSON с RFC 8785 (JCS)
function canonicalForensics(forensicsData) {
  return JSON.stringify({
    ip_masked: forensicsData.ip_masked,
    location: forensicsData.location,
    device: forensicsData.device,
    timestamp: forensicsData.timestamp
  });
}
```

### Процесс Производства NotarySeal (Полностью Детерминированный)
```javascript
// 1. Вычисление FileHash (на стороне клиента)
async function computeFileHash(file) {
  const fileBuffer = await file.arrayBuffer();
  const fileBytes = new Uint8Array(fileBuffer);
  
  const sha256 = await digestToHex('SHA-256', fileBytes);
  const sha512 = await digestToHex('SHA-512', fileBytes);
  
  return { sha256, sha512 };
}

// 2. Сбор криминалистических данных (использование одной временной метки)
async function collectForensics(visibilityMode) {
  const timestamp = new Date().toISOString(); // Генерация одной временной метки
  const ipData = await fetch('https://ipapi.co/json/').then(r => r.json());
  
  let forensics = {
    ip_masked: visibilityMode === 'masked' ? maskIP(ipData.ip) : ipData.ip,
    location: visibilityMode === 'masked' 
      ? `***/${ipData.country}` 
      : `${ipData.city}, ${ipData.country_name || ipData.country}`,
    device: navigator.userAgent,
    timestamp: timestamp // Та же временная метка
  };
  
  return { forensics, timestamp };
}

// 3. Создание EvidenceRoot (с канонической кодировкой)
async function computeEvidenceRoot(fileHash512, forensicsData) {
  const canonicalPayload = `file_sha512:${fileHash512}\nforensics:${canonicalForensics(forensicsData)}`;
  return await digestToHex('SHA-512', stringToBytes(canonicalPayload));
}

// 4. Генерация NotarySeal (использование той же временной метки)
async function computeNotarySeal(evidenceRoot, signerSignature, timestamp) {
  const sealPayload = `evidence_root:${evidenceRoot}\nsigner_sig:${signerSignature}\ntimestamp:${timestamp}`;
  return await digestToHex('SHA-512', stringToBytes(sealPayload));
}

// Вспомогательные функции маскирования (поддержка IPv4 и IPv6)
function maskIP(ip) {
  if (!ip) return "***";
  
  // Проверка IPv4
  if (ip.includes(".")) {
    const parts = ip.split(".");
    if (parts.length === 4) {
      return `${parts[0]}.${parts[1]}.***.***`;
    }
  }
  
  // IPv6 или неизвестный формат
  return "***";
}
```

### Поток Верификации (Два Уровня)

#### Quick Verify (Быстрая Верификация)
```javascript
// Проверяет только хеш файла (быстрый красный флаг)
async function verifyQuick(file, certificateId) {
  const { sha512: userFileHash } = await computeFileHash(file);
  
  // Получить из реестра
  const cert = await fetchFromRegistry(certificateId);
  const { sha512: originalHash } = cert.asset.fingerprints;
  
  // Сравнение хеша
  if (userFileHash === originalHash) {
    return {
      valid: true,
      message: "✅ Оригинал - Хеш файла совпадает"
    };
  } else {
    return {
      valid: false,
      message: "❌ Подделка - Файл был изменен"
    };
  }
}
```

#### Full Verify (Полная Верификация)
```javascript
// Регенерирует и проверяет EvidenceRoot и NotarySeal
async function verifyFull(file, certificateId) {
  const { sha512: userFileHash } = await computeFileHash(file);

  // Получить из реестра
  const cert = await fetchFromRegistry(certificateId);

  // 1) Проверка FileHash (быстрый красный флаг)
  const originalHash = cert.asset.fingerprints.sha512;
  if (userFileHash !== originalHash) {
    return { valid: false, message: "❌ Подделка - Хеш файла не совпадает" };
  }

  // 2) Регенерировать EvidenceRoot (с криминалистическими данными, хранящимися в реестре)
  const evidenceRoot = await computeEvidenceRoot(userFileHash, cert.forensics);
  if (evidenceRoot !== cert.proof.evidence_root) {
    return { valid: false, message: "❌ Не совпадает - EvidenceRoot не держится" };
  }

  // 3) Регенерировать NotarySeal (с той же временной меткой + signer_sig)
  const seal = await computeNotarySeal(
    evidenceRoot,
    cert.proof.signer_sig,
    cert.forensics.timestamp
  );

  if (seal !== cert.proof.notary_seal) {
    return { valid: false, message: "❌ Не совпадает - NotarySeal не держится" };
  }

  // Опционально: На Фазе 2 также проверить signer_sig с attestation_pubkey
  // const sigValid = await verifySig(cert.issuer.attestation_pubkey, cert.proof.signer_sig, evidenceRoot);
  // if (!sigValid) return { valid: false, message: "❌ Недействительная подпись" };

  return { valid: true, message: "✅ Оригинал - Полная верификация пройдена" };
}
```

> **Важные Примечания:**
> - **Quick Verify:** Проверяет только хеш файла для быстрого использования.
> - **Full Verify:** Проверяет все уровни протокола (EvidenceRoot + NotarySeal).
> - Все операции хеширования выполняются детерминированно с фиксированной кодировкой и разделителями.
> - **Стандарт канонизации v1.0:** Фиксированный порядок полей + кодировка UTF-8 + разделитель `\n`.
> - **План Фазы 2:** Переход к каноническому JSON с RFC 8785 (JCS - JSON Canonicalization Scheme).
> - В замаскированном режиме вычисление EvidenceRoot и NotarySeal выполняется с замаскированными криминалистическими данными; таким образом верификация остается детерминированной.
> - Одна временная метка используется на протяжении всего процесса (криминалистика + NotarySeal); детерминизм гарантирован.
> - **Имена полей криминалистики:** `ip_masked`, `location`, `device`, `timestamp` (код и реестр полностью совместимы).
> - **Путь реестра:** `certificate.asset.fingerprints` (полностью совместим с кодом верификации).
> - **signer_sig в реестре:** Поле `proof.signer_sig` необходимо для Full Verify.
> - Механизм SignerSignature будет активирован на Фазе 2 с Solana Wallet Adapter; в v1.0 верификация может быть выполнена с `attestation_pubkey`.
