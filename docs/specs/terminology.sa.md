## ⚙️ محرك PoArt الجنائي (PFE) الإصدار 1.0: البنية التحتية الأساسية

**محرك PoArt الجنائي (PFE)** هو الطبقة الرئيسية التي تمثل المنطق الأساسي والتشغيل التقني الكامن وراء بروتوكول [PoArt]. هذا هو "المحرك الجنائي" الذي يأخذ بيانات الإنتاج الخام للعمل الفني ويحولها إلى **دليل رقمي** قابل للتحقق وغير قابل للتغيير.

### 🧩 لماذا "PoArt Forensic"؟

- **PoArt (إثبات الفن):** تركيز المحرك هو ربط قيمة الأصل الرقمي ليس بالمضاربة؛ بل بـ**عملية إنتاج قابلة للإثبات**.
- **Forensic (التحقق الجنائي):**
  - **التعريف التقني:** نهج الخوارزمية وسلسلة السجلات للتحقق من أن البيانات المتعلقة بعملية الإنتاج (ضربات الفرشاة، الفاصل الزمني، السجلات) لم يتم التلاعب بها.
  - **الطبقة الفلسفية:** في مقابل إنتاج الذكاء الاصطناعي "للمخرجات الفورية"؛ ادعاء تحويل إنتاج **الإنسان الذي يتضمن الوقت والجهد وتكلفة القرار** إلى واقع قابل للقياس.

> ملاحظة: تكامل البلوكتشين (مثل Solana) ليس جوهر PFE؛ بل يُعامل كـ**طبقة ربط السلسلة** التي سيتم تعريفها بشكل منفصل للتحقق/السجل.

### 🛠️ النطاق التقني للإصدار 1.0

**محرك PoArt الجنائي (PFE) الإصدار 1.0** مبني على **3 أعمدة رئيسية** بدلاً من النماذج المالية المعقدة:

1. **التجزئة والختم (Hashing & Sealing):**  
   يقوم PFE بمعالجة جميع العناصر في حزمة الأدلة (ملف العمل، الفيديو، JSON/السجل، التوقيع، إلخ) بشكل حتمي لإنتاج قيمة **NotarySeal** فريدة.

   **المفاهيم الأساسية (الإصدار 1.0):**
   - **FileHash (بصمة العمل):** التجزئة المُنتجة من بايتات ملف العمل.
   - **EvidenceRoot (جذر حزمة الأدلة):** الملخص الجذري الذي يمثل سلامة حزمة الأدلة (جذر Merkle أو تجزئة البيان القانوني).
   - **NotarySeal (الختم النهائي / مخرج PFE):** الختم النهائي المُنتج من مزيج EvidenceRoot + الوقت + التوقيع.

   **الصيغ (مرئية بوضوح للمستثمر):**
   
   $$\text{FileHash}_{512} = \text{SHA-512}(\text{ArtworkFileBytes})$$
   
   $$\text{NotarySeal} = \text{SHA-512}(\text{EvidenceRoot} \mid \text{SignerSignature} \mid \text{TimeStamp})$$
   
   **تعريفات الحمولة القانونية (الإصدار 1.0):**
   
   - **EvidenceRootPayload:**
```
   file_sha512:{sha512}\nforensics:{canonicalForensics(forensics)}
```
   
   - **NotarySealPayload:**
```
   evidence_root:{evidence_root}\nsigner_sig:{signer_sig}\ntimestamp:{timestamp}
```
   
   > ملاحظة: القيمة المقصودة كمخرج PFE هي **NotarySeal**. سيتم تفعيل آلية **SignerSignature** في المرحلة 2 (مع Solana Wallet Adapter)؛ في الإصدار 1.0 الحالي، يُستخدم توقيع التصديق الخاص بالنظام. يتم نشر المفتاح العام للتصديق في السجل في حقل `issuer.attestation_pubkey`.

2. **الفهرسة (Indexing):**  
   يسجل أي محفظة، في أي تاريخ، قدمت **إثبات العمل (Labor Proof)** لأي عمل؛ في طبقة سجل شفافة وقابلة للاستعلام.  
   *(يمكن أن تكون هذه الطبقة قاعدة بيانات؛ بينما يُعرَّف تكامل السلسلة بشكل منفصل كـ"طبقة ربط السلسلة".)*

3. **التحقق (Verification):**  
   عند التشكيك في أصالة عمل ما، يعيد PFE معالجة الأدلة الخام؛ ويختبر بدقة رياضية ما إذا كانت قيم **EvidenceRoot / NotarySeal** المحسوبة تتطابق مع السجل في الأرشيف.

### 🧮 نظرية قيمة PoArt (The Value Theorem)

يربط بروتوكول [PoArt] قيمة الأصل الرقمي ($V$) ليس بالإدراك الذاتي للسوق؛ بل بـ**الواقع المادي لعملية الإنتاج**.

الذكاء الاصطناعي (AI)، بإعطاء النتيجة فوراً ($t \to 0$)، يدمر العملية. بينما [PoArt] يتعامل مع القيمة كتراكم لمكونات **الوقت والعمل والإرادة**.

$$V_{\text{PoArt}} = \int_{t_{\text{start}}}^{t_{\text{end}}} \left(P_{\text{labor}}(t) \cdot I_{\text{agency}}(t)\right) dt + U_{\text{irreversible}}$$

#### تعريف المتغيرات

- **$\int dt$ (تراكم العملية):**  
  القيمة ليست "مخرجاً" فورياً؛ إنها **عملية** متراكمة بين $t_{\text{start}}$ و $t_{\text{end}}$. مع تقلص المدة (إنتاج AI)، تقترب نتيجة التكامل من 0.

- **$P_{\text{labor}}(t)$ (قوة العمل اللحظية):**  
  تمثل كثافة الجهد الذهني والجسدي المبذول في لحظة الإنتاج. كلما زاد الجهد القابل للإثبات، زاد المُكامَل.  
  > ملاحظة: يمكن تطبيع هذا الحد عملياً من خلال "إشارات العمل القابلة للقياس/الإثبات".

- **$I_{\text{agency}}(t)$ (معامل الإرادة):**  
  قدرة المنتج على تحمل المخاطر واتخاذ القرارات. يأخذ قيمة بين $0$ و $1$.
  - **AI ($I \approx 0$):** ينفذ الأوامر، لا يتحمل المخاطر، لا يدفع الثمن.
  - **الإنسان ($I \to 1$):** يغير القرار، يتردد، يتحمل المخاطر.

- **$U_{\text{irreversible}}$ (التفرد غير القابل للعكس):**  
  بينما التراجع (`Ctrl+Z`) ممكن في الإنتاج الرقمي؛ في الإنتاج المادي (الطلاء على القماش، النحت في الرخام، الإيماءة في البث المباشر) لا عودة. هذه **اللارجعية** هي حد إضافي يخلق "التفرد" (الطابع غير القابل للاستبدال) في العمل.

### 🔎 تحليل الحالة: AI "المخرج الفوري" مقابل الإنسان "العملية المُثبتة"

يوضح السيناريو التالي كيف تعمل **نظرية قيمة PoArt** عملياً ولماذا تحصل إنتاجات AI على درجات منخفضة في معيار [PoArt].

#### السيناريو أ: إنتاج صورة بـ AI في 10 ثوانٍ

- **المدة ($\Delta t$):** $10$ ثوانٍ (لا عملية تقريباً)
- **قوة العمل ($P_{\text{labor}}$):** $1$ وحدة (كتابة الأمر فقط)
- **معامل الإرادة ($I_{\text{agency}}$):** $0.01$ (لا مخاطرة، لا ثمن)
- **اللارجعية ($U_{\text{irreversible}}$):** $0$ (قابل للتراجع / النسخ)

**النتيجة:**

$$V_{\text{AI}} \approx \int_{0}^{10} (1 \cdot 0.01) \, dt + 0 = 0.1$$

> **التعليق:** حتى لو كان المخرج مثالياً؛ بسبب عدم وجود عملية وعدم وجود إرادة/مخاطرة، تقترب قيمة [PoArt] من $0$.

#### السيناريو ب: إنتاج مادي لمدة 6 ساعات في بث مباشر

- **المدة ($\Delta t$):** $6$ ساعات ($21{,}600$ ثانية)
- **قوة العمل ($P_{\text{labor}}$):** $0.5$ وحدة (استمرارية الجهد الجسدي والذهني)
- **معامل الإرادة ($I_{\text{agency}}$):** $0.9$ (تغيير القرار، تحمل المخاطر، خيارات لا رجعة فيها)
- **اللارجعية ($U_{\text{irreversible}}$):** $>0$ (الآثار المادية لا يمكن التراجع عنها)

**النتيجة:**

$$V_{\text{Human}} \approx \int_{0}^{21600} (0.5 \cdot 0.9) \, dt + U_{\text{irreversible}} \approx 9720 + U_{\text{irreversible}}$$

> **التعليق:** كلما طالت العملية وزادت الإرادة (المخاطرة)، تزداد القيمة تراكمياً. حد $U_{\text{irreversible}}$ هو مساهمة إضافية تخلق "التفرد" (الطابع غير القابل للاستبدال) في العمل.

### ✅ الخلاصة: قفل القيمة بالإثبات (Proof-Bound Value)

تنقل هذه النظرية ادعاء قيمة [PoArt] من كونه "إعجاباً" أو "سردية سوقية" إلى **حقيقة إنتاج قابلة للإثبات**.

1. **لا قيمة بدون عملية:**  
   AI، في المخرج الفوري ($t \to 0$)، يدمر العملية. مع تضييق نافذة العملية، تصغر نتيجة التكامل كضرورة رياضية:
   
   $$\Delta t \downarrow \ \Rightarrow\ \int \left(P(t) \cdot I(t)\right) dt \to 0$$

2. **الإرادة والمخاطرة مُضاعِفان:**  
   [PoArt] لا يقيس فقط "الوقت المُنفق"؛ بل يقيس أيضاً طبقة القرار الحقيقي والمخاطرة والثمن في ذلك الوقت. قيمة الإنتاج الذي لا يتحمل مخاطر (AI) منخفضة:
   
   $$V_{\text{PoArt}} \propto \int \left(P_{\text{labor}}(t) \cdot I_{\text{agency}}(t)\right) dt$$

3. **التفرد دليل مادي وليس تسويقاً:**  
   الآثار غير القابلة للتراجع في الإنتاج المادي (ضربة القماش، كسر الرخام) خارج منطق `Ctrl+Z` في الرقمي. هذه اللارجعية ($U_{\text{irreversible}}$) تجعل العمل فريداً وجودياً.

> **🔐 ملخص:** على الرغم من أن نظرية القيمة قد تبدو غير محددة كقياس (حتى لو لم يمكن قياسها بنسبة 100% في الحياة الواقعية)، فإن هدف هذه الصيغة هو إظهار بنية واتجاه المتغيرات. ما هو نادر في عصر AI ليس "الصورة"؛ بل **العمل والوقت والإرادة القابلة للإثبات.** [PoArt] يقيس هذه الندرة ويسجلها مع **حزمة الأدلة**.

### 🏛️ أهمية مفهوم "المحرك" (Engine)

الرموز الصادرة من Pump.fun أو المنصات المماثلة غالباً ما تكون مجرد **"تذاكر دخول"**. **محرك PoArt الجنائي (PFE)** هو **طبقة المنطق الدستوري** التي تحدد أي حقوق تحميها تلك التذكرة، وكيف سيتم تسجيل العمل، وكيف سيتم تخليد الفن/العلم/التكنولوجيا.

> **ملاحظة:** سبب إطلاقنا لهذا المشروع على Pump.fun هو عدم امتلاكنا سيولة كافية وعدد متابعين كافٍ. استخدام البيانات الموجودة لم يكن الخطوة الأعلى جودة استراتيجياً لكنها كانت الأصح. بغض النظر عن الميزانية والإمكانيات، تعريف منطق هذا المحرك على GitHub يثبت أن المشروع ليس مجرد مضاربة مالية، بل رؤية طويلة المدى لـ**بنية تحتية برمجية** و**مكتبة وطنية رقمية**.

## أ) ما هو [PoArt]؟ (التعريف الفلسفي والتقني)

**Proof of Art [PoArt]؛** هو معيار تحقق مؤسسي يضمن أن القيمة وراء أصل على البلوكتشين تستند ليس إلى المضاربة؛ بل إلى **العمل البشري** و**الوقت** و**الطاقة المادية** القابلة للتحقق.

كما ينتج Bitcoin القيمة من خلال *"الكهرباء وقوة المعالج"* **(Proof of Work)**؛ فإن المشاريع المتوافقة مع [PoArt] تنتج القيمة من خلال *"الموهبة المُنفقة والوقت البشري"*. تقوم بـ"تخزين" الوقت.

تُزيل مخاطر *"المطور باع، المشروع انتهى"* في Pump.fun ومنصات DEX؛ لأن القيمة هنا ليست في الكود، بل مخبأة في **استمرارية الإنتاج**.

> **[PoArt] لا يقول لمشاركيه "ثقوا بنا"؛ بل يقول "ها هي الأدلة، انظروا بأعينكم، تحققوا بالرياضيات".**

## ب) معيار [PoArt] الخماسي (The 5 Pillars of Truth)

هذه النقاط الخمس هي مرشحات غير قابلة للتلاعب يجب على المشروع اجتيازها للحصول على ختم [PoArt].

### 1) إثبات الهوية المباشر (Live Identity Proof)

- **المشكلة:** عالم الكريبتو مليء بمؤسسين مجهولين (Dev) يجمعون المال ويتركون المشروع.
- **حل [PoArt]:** المنتج يثبت ليس فقط بطاقة هويته، بل **وجوده في لحظة الإنتاج**. هذا يتضمن جلسات بث مباشر يتم فيها التفاعل مع المجتمع وتلبية طلبات محددة فورية، وليس مقاطع فيديو مسجلة مسبقاً.  
  (مثال: *"اكتب تاريخ اليوم ورقم البلوك الحالي في الزاوية اليمنى من القماش"*)
- **الشعار:** *"الروبوتات يمكنها الرسم لكن الروبوتات لا تتعرق ولا تستطيع الارتجال."*

### 2) إثبات العمل والعملية (Labor & Process Proof)

- **المشكلة:** معاملة صور AI المُنتجة في ثانيتين ولوحة زيتية استغرقت شهرين كـ"jpeg" متماثلة في العالم الرقمي.
- **حل [PoArt]:** يتم تسجيل عملية "الحمل والولادة" للعمل. مراحل الرسم التخطيطي، طبقات الطلاء، الساعات التراكمية المُنفقة والعملية المادية التي عاشها الفنان أثناء إنشاء ذلك العمل تُوثَّق. هذا يضيف **"تكلفة الوقت" (Time Cost)** للرمز. كلما كان إنتاج الأصل أصعب، كانت قيمته أقوى.

### 3) إثبات القيمة الجمالية (Aesthetic Value Proof)

- **المشكلة:** تجاهل ثقافة "الميم" للجماليات والعمق الفني والتركيز فقط على الكوميديا الفورية، مما ينتج مشاريع "Hype" قصيرة العمر.
- **حل [PoArt]:** يجب أن يمتلك المشروع معايير فنية أكاديمية، نظرية الألوان، قواعد التكوين ومعرفة المواد (Impasto، الملمس، إلخ). المحتوى لا يجب أن يُضحك فقط؛ بل يجب أن يثير الإعجاب في المشاهد ويحمل **قيمة جمع**.

### 4) الابتكار الفكري (Conceptual Novelty)

- **المشكلة:** آلاف عملات الكلاب/القطط المتشابهة والبعيدة عن الإبداع.
- **حل [PoArt]:** يجب أن يبني المشروع جسراً جديداً يربط الفن أو العلم أو الفلسفة أو التكنولوجيا في بنية ذات معنى.  
  (مثال: دمج تمثال داود الكلاسيكي مع بيانات سوق الكريبتو؛ ومعالجة فكرة "تحول الإدراك البشري إلى حجر" من خلال ذلك وإمكانية إثباتها بمصادر علمية.)  
  العمل يجب أن يكون ليس فقط وليمة بصرية؛ بل أيضاً تحدياً فكرياً يجعل التفكير في **العلم أو الفلسفة أو التكنولوجيا**.

> [!IMPORTANT]
> **مثال مرجعي (تأثير Las Palmitas):**  
> في حي Las Palmitas المكسيكي الذي يعاني من الجريمة، تم تحويل أكثر من 200 منزل إلى احتفال قوس قزح عملاق. نتيجة لهذا التدخل الجمالي، انخفضت معدلات الجريمة في الحي بدرجة معينة، وبدأ الشباب بالاهتمام بالفن بدلاً من العصابات. التغيير الجمالي أعاد برمجة احترام الناس لبيئتهم وبعضهم البعض (التماسك الاجتماعي).
>
> **التوقع:** المشروع الذي سيدخل قائمة [PoArt]؛ مثل المثال أعلاه، يجب أن يحتوي على علاقة سبب ونتيجة اجتماعية أو علمية أو فلسفية تتجاوز الجماليات البصرية المجردة. بما أن الشيء الوحيد الذي لا يمكن شراؤه بالمال هو "الوقت"، يجب في هذا البروتوكول إثبات الوقت بتخزينه كضمان. يجب أن يكون الأساس الفكري للمشروع قوياً وعالمياً لدرجة أنه حتى في سيناريو CTO (استحواذ المجتمع) المحتمل بعد سنوات، يمكن للمجتمع تولي هذا الإرث ومواصلة الإمكانات الابتكارية للمشروع بشكل مستقل.

### 5) الإرادة غير الخوارزمية (Non-Algorithmic Agency)

- **المشكلة:** إنتاجات رقمية مثالية لكن بلا روح، متكررة.
- **حل [PoArt]:** يجب أن تُشعَر الإرادة الأصيلة للإنسان القادر على الخطأ، المتحمل للمخاطر والذي يعيش تقلبات عاطفية في العمل. عدم اليقين في ضربات الفرشاة، ردود فعل المادة غير المتوقعة وقرارات الفنان اللحظية هي **التوقيع البيولوجي** الذي يميز العمل عن "إنتاج الآلة".

## ج) آلية التحقق ومكافحة التزوير

هذا النظام يضمن أن يبقى المشروع موثوقاً وحياً ليس فقط "في البداية"، بل "للأبد".

### 📦 حزمة الأدلة (Evidence Pack - التوأم الرقمي)

خلف كل عمل معتمد من [PoArt]، توجد حزمة بيانات مشفرة ومختومة بالوقت يمكن للمستثمرين تنزيلها:

- **تسجيلات الفيديو الخام:** صور خام متواصلة للحظة الإنتاج.
- **تحليل البيانات الوصفية:** تاريخ إنشاء الملف، معلومات الجهاز المستخدم وبيانات الموقع (المدينة-البلد).
- **المراجع المادية:** أدلة على وجود العمل في العالم المادي  
  (مثال: صحيفة اليوم بجانب العمل أو بيانات البلوكتشين في تلك اللحظة).

> *ملاحظة الاتساق:* تعبير "حزمة الأدلة" يرتبط بخط **Evidence Pack → EvidenceRoot → NotarySeal** في الأقسام السابقة؛ أي أن سلامة الحزمة تُمثَّل بختم قابل للتحقق.

### 🔄 التجديد كل 365 يوماً (بروتوكول الاستدامة)

- **الميزة الثورية:** في مشاريع الكريبتو، "المطور" يطلق الرمز ويختفي عادة بعد 1-2 شهر (Soft Rug). [PoArt] يجعل هذا مستحيلاً.
- **القاعدة:** حالة "الفنان المُتحقق منه" ليست مدى الحياة. صالحة لـ**سنة واحدة** فقط.
- **الآلية:** يجب على الفنان/المطور كل 365 يوماً تقديم **عمل جديد وكبير وقابل للإثبات** للمجتمع.
- **سيناريو مثال:** بدأت المشروع في 2026. في يناير 2027 يعطي النظام تحذير "انتهت فترة الإثبات". إذا لم يقدم الفنان معرضاً جديداً أو عملاً مادياً جديداً أو تكاملاً تقنياً جديداً، تسقط "شارة الثقة" للمشروع.
- **النتيجة:** هذا النظام يضمن **عدم فقدان المحتوى لحداثته أبداً** وعدم خوف المستثمر من *"هل المطور لا يزال هنا؟"*. يتحول المشروع إلى استوديو حي.

### 🚩 العلم الأحمر (Red Flag Protocol)

**في حالة اكتشاف أي تزوير (استخدام AI، عمل مسروق، فيديو تم التلاعب به) من قبل المجتمع أو الخوارزميات:**

1. يُعلَّم الشهادة فوراً كـ**"ملغاة" (VOID)**.
2. تُوسم حزم الأدلة علنياً كـ**"مزورة"**.
3. يُدرج المشروع في القائمة السوداء لـ[PoArt]. هذا يعزز حقيقة أن **السمعة هي العملة الوحيدة** في عالم لامركزي.
4. لا يمكن استخدام تعبيرات [PoArt] في أي منشور، المصدر الوحيد الصالح هو https://www.ilhanart.org/public-registry

## 🧩 لماذا توجد عدة "وحدات رؤية"؟

هذا هو الجزء الأكثر أهمية في الكود (قائمة اختيار الرؤية). هذه الخيارات تسمح للمستخدمين بتحقيق توازن **"الخصوصية مقابل الشفافية"**:

### 🔒 خاص (Private)

- **السيناريو:** الفنان لا يريد نشر العمل بعد لكنه يريد وضع طابع زمني وإثبات "لقد صنعت هذا في هذا التاريخ".
- **ما يفعله الكود:** يكتب البيانات في قاعدة البيانات لكن يضع علامة `visibility: "private"`. في المستقبل عند كتابة سياسة "القراءة العامة" يمكنك إخفاء هذه السجلات عن الجمهور بقول `WHERE visibility = 'public'`.

### 🕶️ مُقنَّع (Masked)

- **السيناريو:** الفنان يريد الشفافية لكنه يخاف من اكتشاف عنوان منزله (موقع IP).
- **ما يفعله الكود:** تعمل دالتا `maskIP` و `maskLoc` في جانب JavaScript. تحول عنوان IP إلى شكل `88.241.***.***`، والموقع إلى شكل `***/TR` وترسل النسخة المحجوبة إلى قاعدة البيانات.
- **ملاحظة الخصوصية:** الإخفاء يتم في المتصفح، Supabase لا يرى الموقع الحقيقي. **لكن:** إذا استُخدمت واجهات برمجة تطبيقات طرف ثالث مثل ipapi.co لبيانات الموقع، يرى هؤلاء المزودون عنوان IP في لحظة الطلب.
- **الختم في وضع Masked:** يتم حساب EvidenceRoot و NotarySeal مع بيانات forensics المُخفاة؛ وبذلك يبقى التحقق حتمياً.

### 🌍 عام (Public)

- **السيناريو:** شفافية كاملة. وفقاً لمعيار [PoArt]، يُعلن بوضوح أين ومتى ومن أي شبكة أُنتج العمل.

## 💡 الابتكار التكنولوجي

PoArt ليس مجرد نظام رفع ملفات. إنه محرك **"سلسلة حفظ الأدلة الجنائية" (Forensic Chain of Custody)** يصهر ثلاث طبقات تكنولوجية مختلفة في بوتقة واحدة ليقدم معياراً جديداً.

**الطبقة الموصوفة كـ"محرك" في هذا القسم تتوافق مع جوهر محرك PoArt الجنائي (PFE) في المصطلحات السابقة.**

### 1) التجزئة من جانب العميل (Client-Side Hashing) - أقصى خصوصية

ملفات أعمالك لا تُرفع أبداً إلى الخادم. محركنا الذي يعمل على أساس المتصفح (Client-side) يحسب تجزئة الملف (الملخص الرقمي) على جهاز الكمبيوتر الخاص بك. يُرسل إلى الخادم فقط هذه البصمة والبيانات الوصفية.

> **ملاحظة الخصوصية:** ملف العمل لا يُرفع إلى الخادم ويُحمى بهذه الطريقة. لكن بيانات forensics (IP/الموقع) تُشارك حسب وضع الرؤية المختار (خاص/مُقنَّع/عام).

### 2) دمج البيانات الجنائية (Forensic Data Fusion) - القوة الجنائية

أكثر بكثير من مجرد طابع زمني عادي. يدمج النظام البيانات التالية في "ختم التكوين" واحد:

- **الملخص الرقمي (SHA-512):** بصمة رقمية ستتلف حتى لو تغير بكسل واحد من العمل باستخدام معيار الملخص المشفر (SHA-512).
- **الموقع والوقت:** بيانات التاريخ والبلد والمدينة والمنطقة بدقة ميلي ثانية عند إجراء العملية.
- **هوية الجهاز:** نظام التشغيل والمتصفح ونوع الجهاز (تحليل User-Agent).

## 🔬 العمق التقني: خوارزمية الختم

### دوال التجزئة الحتمية
```javascript
// الدوال المساعدة: تحويل الملخص إلى سلسلة hex
async function digestToHex(algorithm, dataBytes) {
  const hashBuffer = await crypto.subtle.digest(algorithm, dataBytes);
  const hashArray = Array.from(new Uint8Array(hashBuffer));
  return hashArray.map(b => b.toString(16).padStart(2, '0')).join('');
}

// تحويل السلسلة إلى مصفوفة بايت
function stringToBytes(text) {
  return new TextEncoder().encode(text);
}

// إنتاج سلسلة forensics قانونية (v1.0: ترتيب حقول ثابت + UTF-8 + فاصل \n)
// ملاحظة المرحلة 2: سيتم الانتقال إلى JSON قانوني مع RFC 8785 (JCS)
function canonicalForensics(forensicsData) {
  return JSON.stringify({
    ip_masked: forensicsData.ip_masked,
    location: forensicsData.location,
    device: forensicsData.device,
    timestamp: forensicsData.timestamp
  });
}
```

### عملية إنتاج NotarySeal (حتمية بالكامل)
```javascript
// 1. حساب FileHash (جانب العميل)
async function computeFileHash(file) {
  const fileBuffer = await file.arrayBuffer();
  const fileBytes = new Uint8Array(fileBuffer);
  
  const sha256 = await digestToHex('SHA-256', fileBytes);
  const sha512 = await digestToHex('SHA-512', fileBytes);
  
  return { sha256, sha512 };
}

// 2. جمع البيانات الجنائية (استخدام طابع زمني واحد)
async function collectForensics(visibilityMode) {
  const timestamp = new Date().toISOString(); // إنتاج طابع زمني واحد
  const ipData = await fetch('https://ipapi.co/json/').then(r => r.json());
  
  let forensics = {
    ip_masked: visibilityMode === 'masked' ? maskIP(ipData.ip) : ipData.ip,
    location: visibilityMode === 'masked' 
      ? `***/${ipData.country}` 
      : `${ipData.city}, ${ipData.country_name || ipData.country}`,
    device: navigator.userAgent,
    timestamp: timestamp // نفس الطابع الزمني
  };
  
  return { forensics, timestamp };
}

// 3. إنشاء EvidenceRoot (مع الترميز القانوني)
async function computeEvidenceRoot(fileHash512, forensicsData) {
  const canonicalPayload = `file_sha512:${fileHash512}\nforensics:${canonicalForensics(forensicsData)}`;
  return await digestToHex('SHA-512', stringToBytes(canonicalPayload));
}

// 4. إنتاج NotarySeal (استخدام نفس الطابع الزمني)
async function computeNotarySeal(evidenceRoot, signerSignature, timestamp) {
  const sealPayload = `evidence_root:${evidenceRoot}\nsigner_sig:${signerSignature}\ntimestamp:${timestamp}`;
  return await digestToHex('SHA-512', stringToBytes(sealPayload));
}

// دوال الإخفاء المساعدة (دعم IPv4 و IPv6)
function maskIP(ip) {
  if (!ip) return "***";
  
  // فحص IPv4
  if (ip.includes(".")) {
    const parts = ip.split(".");
    if (parts.length === 4) {
      return `${parts[0]}.${parts[1]}.***.***`;
    }
  }
  
  // IPv6 أو تنسيق غير معروف
  return "***";
}
```

#### التحقق السريع (Quick Verify)
```javascript
// يفحص فقط تجزئة الملف (علم أحمر سريع)
async function verifyQuick(file, certificateId) {
  const { sha512: userFileHash } = await computeFileHash(file);
  
  // جلب من السجل
  const cert = await fetchFromRegistry(certificateId);
  const { sha512: originalHash } = cert.asset.fingerprints;
  
  // مقارنة التجزئة
  if (userFileHash === originalHash) {
    return {
      valid: true,
      message: "✅ أصلي - تجزئة الملف متطابقة"
    };
  } else {
    return {
      valid: false,
      message: "❌ مزور - تم التلاعب بالملف"
    };
  }
}
```

#### التحقق الكامل (Full Verify)
```javascript
// يعيد إنتاج EvidenceRoot و NotarySeal ويتحقق
async function verifyFull(file, certificateId) {
  const { sha512: userFileHash } = await computeFileHash(file);

  // جلب من السجل
  const cert = await fetchFromRegistry(certificateId);

  // 1) فحص FileHash (علم أحمر سريع)
  const originalHash = cert.asset.fingerprints.sha512;
  if (userFileHash !== originalHash) {
    return { valid: false, message: "❌ مزور - تجزئة الملف غير متطابقة" };
  }

  // 2) إعادة إنتاج EvidenceRoot (مع forensics المخزنة في السجل)
  const evidenceRoot = await computeEvidenceRoot(userFileHash, cert.forensics);
  if (evidenceRoot !== cert.proof.evidence_root) {
    return { valid: false, message: "❌ غير متطابق - EvidenceRoot غير متطابق" };
  }

  // 3) إعادة إنتاج NotarySeal (مع نفس timestamp + signer_sig)
  const seal = await computeNotarySeal(
    evidenceRoot,
    cert.proof.signer_sig,
    cert.forensics.timestamp
  );

  if (seal !== cert.proof.notary_seal) {
    return { valid: false, message: "❌ غير متطابق - NotarySeal غير متطابق" };
  }

  // اختياري: في المرحلة 2 تحقق من signer_sig مع attestation_pubkey أيضاً
  // const sigValid = await verifySig(cert.issuer.attestation_pubkey, cert.proof.signer_sig, evidenceRoot);
  // if (!sigValid) return { valid: false, message: "❌ التوقيع غير صالح" };

  return { valid: true, message: "✅ أصلي - نجح التحقق الكامل" };
}
```

> **ملاحظات مهمة:**
> - **التحقق السريع:** يفحص فقط تجزئة الملف للاستخدام السريع.
> - **التحقق الكامل:** يتحقق من جميع طبقات البروتوكول (EvidenceRoot + NotarySeal).
> - جميع عمليات التجزئة تتم بشكل حتمي، مع ترميز وفواصل ثابتة.
> - **معيار التقييس v1.0:** ترتيب حقول ثابت + ترميز UTF-8 + فاصل `\n`.
> - **خطة المرحلة 2:** الانتقال إلى JSON قانوني مع RFC 8785 (JCS - مخطط تقييس JSON).
> - في وضع Masked، يتم حساب EvidenceRoot و NotarySeal مع forensics المُخفاة.
> - طابع زمني واحد يُستخدم في كل العملية (forensics + NotarySeal)؛ الحتمية مضمونة.
> - **أسماء حقول Forensics:** `ip_masked`، `location`، `device`، `timestamp` (الكود والسجل متوافقان تماماً).
> - **مسار السجل:** `certificate.asset.fingerprints` (متوافق تماماً مع كود التحقق).
> - **signer_sig في السجل:** حقل `proof.signer_sig` مطلوب للتحقق الكامل.
> - سيتم تفعيل آلية SignerSignature في المرحلة 2 مع Solana Wallet Adapter؛ في v1.0 يمكن التحقق مع `attestation_pubkey`.
