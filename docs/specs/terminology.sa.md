> **"فهم لغة هذا البروتوكول يعني فهم رؤيته."**

## ⚙️ محرك PoArt الجنائي (PFE) الإصدار 1.0: البنية التحتية الأساسية

**محرك PoArt الجنائي (PFE)** هو الطبقة الرئيسية التي تمثل المنطق المركزي والعملية التقنية وراء بروتوكول [PoArt]. هذا هو "المحرك الجنائي" الذي يأخذ بيانات الإنتاج الخام للعمل الفني ويحولها إلى **أدلة رقمية** قابلة للتحقق وغير قابلة للتغيير.

### 🧩 لماذا "PoArt Forensic"؟

- **PoArt (إثبات الفن):** تركيز المحرك هو ربط قيمة الأصل الرقمي ليس بالمضاربة، بل بـ **عملية الإنتاج القابلة للإثبات**.
- **Forensic (التحقق الجنائي):**
  - **التعريف التقني:** نهج خوارزمي وسلسلة سجلات للتحقق من أن بيانات عملية الإنتاج (ضربات الفرشاة، الفيديو بفواصل زمنية، السجلات) لم يتم التلاعب بها.
  - **الطبقة الفلسفية:** الادعاء بتحويل **الوقت البشري والجهد وتكلفة القرار** إلى واقع قابل للقياس، ضد إنتاج الذكاء الاصطناعي "الناتج الفوري".

> ملاحظة: تكامل البلوكشين (مثل Solana) ليس جوهر PFE؛ سيتم تعريفه بشكل منفصل كـ **طبقة مرساة السلسلة** لأغراض التحقق/التسجيل.

### 🛠️ النطاق التقني الإصدار 1.0

**محرك PoArt الجنائي (PFE) الإصدار 1.0** مبني على **الأعمدة الثلاثة الرئيسية** التالية بدلاً من النماذج المالية المعقدة:

1. **التجزئة والختم:**  
   يعالج PFE بشكل حتمي جميع العناصر في حزمة الأدلة (ملف العمل، الفيديو، JSON/السجلات، التوقيع، إلخ) ويولد قيمة فريدة لـ **NotarySeal**.

   **المفاهيم الأساسية (الإصدار 1.0):**
   - **FileHash (بصمة العمل):** التجزئة المولدة من بايتات ملف العمل.
   - **EvidenceRoot (جذر حزمة الأدلة):** الملخص الجذري الذي يمثل سلامة حزمة الأدلة (جذر Merkle أو تجزئة البيان الكنسي).
   - **NotarySeal (الختم النهائي / مخرج PFE):** الختم النهائي المولد من مزيج EvidenceRoot + الوقت + التوقيع.

   **الصيغ (مرئية بوضوح للمستثمرين):**
   
   $$\text{FileHash}_{512} = \text{SHA-512}(\text{ArtworkFileBytes})$$
   
   $$\text{NotarySeal} = \text{SHA-512}(\text{EvidenceRoot} \mid \text{SignerSignature} \mid \text{TimeStamp})$$
   
   **تعريفات الحمولة الكنسية (الإصدار 1.0):**
   
   - **EvidenceRootPayload:**
```
   file_sha512:{sha512}\nforensics:{canonicalForensics(forensics)}
```
   
   - **NotarySealPayload:**
```
   evidence_root:{evidence_root}\nsigner_sig:{signer_sig}\ntimestamp:{timestamp}
```
   
   > ملاحظة: القيمة المشار إليها كمخرج PFE هي **NotarySeal**. سيتم تفعيل آلية **SignerSignature** في المرحلة 2 (مع محول محفظة Solana)؛ في الإصدار الحالي 1.0، يتم استخدام توقيع الشهادة الخاص بالنظام. يتم نشر المفتاح العام للشهادة في السجل تحت حقل `issuer.attestation_pubkey`.

2. **الفهرسة (الأرشفة):**  
   يسجل أي محفظة، في أي تاريخ، قدمت **إثبات العمل** لأي عمل في طبقة سجل شفافة وقابلة للاستعلام.  
   *(يمكن أن تكون هذه الطبقة قاعدة بيانات؛ يتم تعريف تكامل السلسلة بشكل منفصل كـ "طبقة مرساة السلسلة".)*

3. **التحقق:**  
   عندما يتم التشكيك في أصالة عمل ما، يعيد PFE معالجة الأدلة الخام؛ يختبر رياضياً ما إذا كانت القيم المحسوبة لـ **EvidenceRoot / NotarySeal** تطابق سجلات الأرشيف.

### 🧮 نظرية قيمة PoArt (نظرية القيمة)

يربط بروتوكول [PoArt] قيمة ($V$) الأصل الرقمي ليس بالإدراك الذاتي للسوق، بل بـ **الواقع المادي لعملية الإنتاج**.

يدمر الذكاء الاصطناعي (AI) العملية من خلال تقديم النتيجة فوراً ($t \to 0$). ومع ذلك، يعامل [PoArt] القيمة كتراكم لمكونات **الوقت والعمل والإرادة**.

$$V_{\text{PoArt}} = \int_{t_{\text{start}}}^{t_{\text{end}}} \left(P_{\text{labor}}(t) \cdot I_{\text{agency}}(t)\right) dt + U_{\text{irreversible}}$$

#### تعريفات المتغيرات

- **$\int dt$ (تراكم العملية):**  
  القيمة ليست "ناتج" فوري؛ إنها **عملية** متراكمة بين $t_{\text{start}}$ و $t_{\text{end}}$. مع انخفاض المدة (إنتاج الذكاء الاصطناعي)، تقترب نتيجة التكامل من 0.

- **$P_{\text{labor}}(t)$ (قوة العمل اللحظية):**  
  يمثل شدة الجهد العقلي والجسدي المبذول في لحظة الإنتاج. مع زيادة الجهد القابل للإثبات، ينمو التكامل.  
  > ملاحظة: يمكن تطبيع هذا المصطلح عملياً من خلال "إشارات العمل القابلة للقياس/الإثبات".

- **$I_{\text{agency}}(t)$ (معامل الإرادة):**  
  قدرة المنتج على تحمل المخاطر واتخاذ القرارات. يأخذ قيمة بين $0$ و $1$.
  - **الذكاء الاصطناعي ($I \approx 0$):** ينفذ الأوامر، لا يتحمل المخاطر، لا يدفع التكاليف.
  - **الإنسان ($I \to 1$):** يغير القرارات، يتردد، يتحمل المخاطر.

- **$U_{\text{irreversible}}$ (التفرد غير القابل للعكس):**  
  بينما التراجع (`Ctrl+Z`) ممكن في الإنتاج الرقمي، في الإنتاج المادي (الطلاء المطبق على القماش، الرخام المنحوت، الإيماءة في البث المباشر) لا يوجد طريق للعودة. هذه **اللاعكسية** هي مصطلح إضافي يخلق "التفرد" (الطابع غير القابل للاستبدال) في العمل.

### 🔎 تحليل الحالة: الذكاء الاصطناعي "الناتج الفوري" مقابل الإنسان "العملية المثبتة"

يوضح السيناريو التالي كيف تعمل **نظرية قيمة PoArt** عملياً ولماذا تحصل إنتاجات الذكاء الاصطناعي على درجات منخفضة في معيار [PoArt].

#### السيناريو أ: إنتاج بصري في 10 ثوانٍ بالذكاء الاصطناعي

- **المدة ($\Delta t$):** $10$ ثوانٍ (عملية ضئيلة)
- **قوة العمل ($P_{\text{labor}}$):** $1$ وحدة (فقط كتابة الأوامر)
- **معامل الإرادة ($I_{\text{agency}}$):** $0.01$ (لا مخاطرة، لا تكلفة)
- **اللاعكسية ($U_{\text{irreversible}}$):** $0$ (قابل للعكس / قابل للنسخ)

**النتيجة:**

$$V_{\text{AI}} \approx \int_{0}^{10} (1 \cdot 0.01) \, dt + 0 = 0.1$$

> **تعليق:** حتى لو كان الناتج مثالياً؛ قيمة [PoArt] تقترب من $0$ لأنه لم يتم عيش أي عملية ولم تشارك أي إرادة/مخاطرة.

#### السيناريو ب: إنتاج مادي لمدة 6 ساعات في البث المباشر

- **المدة ($\Delta t$):** $6$ ساعات ($21{,}600$ ثانية)
- **قوة العمل ($P_{\text{labor}}$):** $0.5$ وحدة (استمرارية الجهد الجسدي والعقلي)
- **معامل الإرادة ($I_{\text{agency}}$):** $0.9$ (تغيير القرارات، تحمل المخاطر، اختيارات لا رجعة فيها)
- **اللاعكسية ($U_{\text{irreversible}}$):** $>0$ (الآثار المادية لا يمكن التراجع عنها)

**النتيجة:**

$$V_{\text{Human}} \approx \int_{0}^{21600} (0.5 \cdot 0.9) \, dt + U_{\text{irreversible}} \approx 9720 + U_{\text{irreversible}}$$

> **تعليق:** مع استطالة العملية وزيادة الإرادة (المخاطرة)، تتراكم القيمة تراكمياً. مصطلح $U_{\text{irreversible}}$ هو مساهمة إضافية تخلق "التفرد" (الطابع غير القابل للاستبدال) في العمل.

### ✅ الخلاصة: القيمة المرتبطة بالإثبات

تستخرج هذه النظرية ادعاء قيمة [PoArt] من كونه "إعجاب" أو "سرد سوق" وتربطه بـ **واقع إنتاج قابل للإثبات**.

1. **لا عملية، لا قيمة:**  
   يدمر الذكاء الاصطناعي العملية بناتج فوري ($t \to 0$). مع تضيق نافذة العملية، تتقلص نتيجة التكامل بالضرورة:
   
   $$\Delta t \downarrow \ \Rightarrow\ \int \left(P(t) \cdot I(t)\right) dt \to 0$$

2. **الإرادة والمخاطرة مضاعفات:**  
   لا يقيس [PoArt] فقط "الوقت المستغرق" بل أيضاً الطبقة الحقيقية للقرار والمخاطرة والتكلفة في ذلك الوقت. الإنتاج بدون تحمل المخاطر (الذكاء الاصطناعي) له قيمة منخفضة:
   
   $$V_{\text{PoArt}} \propto \int \left(P_{\text{labor}}(t) \cdot I_{\text{agency}}(t)\right) dt$$

3. **التفرد هو إثبات مادي، وليس تسويقاً:**  
   الآثار غير القابلة للعكس في الإنتاج المادي (ضربة القماش، شظية الرخام) هي خارج منطق `Ctrl+Z` للعالم الرقمي. هذه اللاعكسية ($U_{\text{irreversible}}$) تجعل العمل فريداً أنطولوجياً.

> **🔐 الملخص:** على الرغم من أن نظرية القيمة قد تبدو غير مؤكدة كقياس (حتى لو لم يكن نظيرها في العالم الحقيقي قابلاً للقياس بالكامل)، فإن الغرض من هذه الصيغة هو إظهار تكوين واتجاه المتغيرات. في عصر الذكاء الاصطناعي، ما هو نادر ليس "الصورة" بل **العمل القابل للإثبات والوقت والإرادة.** يقيس [PoArt] هذه الندرة ويسجلها بـ **حزمة الأدلة**.

## أ) ما هو [PoArt]؟ (التعريف الفلسفي والتقني)

**إثبات الفن [PoArt];** هو معيار تحقق مؤسسي يضمن أن القيمة وراء الأصل على البلوكشين تستند ليس على المضاربة، بل على **العمل البشري** و**الوقت** و**الطاقة المادية** القابلة للتحقق.

مثلما يولد البيتكوين القيمة بـ *"الكهرباء وقوة المعالج"* **(إثبات العمل)**، تولد المشاريع المتوافقة مع [PoArt] القيمة بـ *"المهارة الفنية والوقت البشري"*.

يزيل خطر *"باع المطور، انتهى المشروع"* على منصات Pump.fun و DEX؛ لأن القيمة هنا ليست في الكود، بل في **استمرارية الإنتاج**.

> **لا يقول [PoArt] للمشاركين "ثق بنا"؛ بل يقول "ها هي الأدلة، انظر بعينيك، تحقق بالرياضيات الخاصة بك."**

## ب) معيار الأعمدة الخمسة [PoArt] (الأعمدة الخمسة للحقيقة)

هذه العناصر الخمسة هي مرشحات غير قابلة للتلاعب يجب أن يمر بها المشروع لتلقي ختم [PoArt].

### 1) إثبات الهوية المباشر

- **المشكلة:** عالم التشفير مليء بالمؤسسين المجهولين (المطورين) ذوي الهويات غير الواضحة الذين يجمعون الأموال ويتركون المشاريع.
- **حل [PoArt]:** يثبت المنتج ليس فقط بطاقة الهوية، بل **الوجود في لحظة الإنتاج**. يشمل ذلك جلسات البث المباشر حيث يحدث التفاعل مع المجتمع وتُلبى طلبات فورية محددة، وليس مقاطع فيديو مسجلة مسبقاً.  
  (على سبيل المثال، *"اكتب تاريخ اليوم ورقم الكتلة الحالي في الزاوية اليمنى من القماش"*)
- **الشعار:** *"يمكن للروبوتات الرسم لكن الروبوتات لا تتعرق ولا يمكنها الارتجال."*

### 2) إثبات العمل والعملية

- **المشكلة:** الصور المرئية المنتجة بالذكاء الاصطناعي في ثانيتين تحصل على نفس معاملة "jpeg" مثل اللوحات الزيتية المصنوعة في شهرين في العالم الرقمي.
- **حل [PoArt]:** يتم تسجيل عملية "الحمل والولادة" للعمل. يتم توثيق مراحل الرسم، طبقات الطلاء، الساعات المتراكمة المستغرقة والعملية المادية التي عاشها الفنان أثناء إنشاء العمل. هذا يضيف **"تكلفة الوقت"** إلى الرمز. كلما كان إنتاج الأصل أصعب، كانت قيمته أقوى.

### 3) إثبات القيمة الجمالية

- **المشكلة:** ثقافة "الميمات" التي تركز فقط على الكوميديا الفورية بينما تتجاهل الجماليات والعمق الفني، مما يؤدي إلى مشاريع "الضجة" قصيرة الأجل.
- **حل [PoArt]:** يجب أن يحتوي المشروع على معايير فنية أكاديمية، ونظرية الألوان، وقواعد التكوين، ومعرفة المواد (Impasto، الملمس، إلخ). لا ينبغي للمحتوى أن يجعلك تضحك فقط؛ بل يجب أن يلهم الإعجاب لدى المشاهدين ويكون له **قيمة قابلة للجمع**.

### 4) الجدة المفاهيمية

- **المشكلة:** الآلاف من عملات الكلاب/القطط المنسوخة الخالية من الإبداع.
- **حل [PoArt]:** يجب أن يبني المشروع جسراً جديداً يجمع الفن والعلوم والفلسفة أو التكنولوجيا في بنية ذات مغزى.  
  (على سبيل المثال، الجمع بين تمثال داود الكلاسيكي وبيانات سوق العملات المشفرة؛ معالجة فكرة أن الإدراك البشري "يتحول إلى حجر" من خلال ذلك وتأسيسه بمصادر علمية.)  
  يجب ألا يكون العمل مجرد احتفال بصري بل أيضاً تحدياً فكرياً يثير التفكير حول **العلم أو الفلسفة أو التكنولوجيا**.

> [!IMPORTANT]
> **مثال مرجعي (تأثير لاس بالميتاس):** في حي لاس بالميتاس في المكسيك، المثقل بالجريمة، تم تحويل أكثر من 200 منزل إلى مشهد قوس قزح ضخم. نتيجة لهذا التدخل الجمالي، انخفضت معدلات الجريمة في الحي إلى حد ما، وبدأ الشباب في الانخراط في الفن بدلاً من العصابات. أعاد التغيير الجمالي ترميز احترام الناس لبيئتهم ولبعضهم البعض (التماسك الاجتماعي).
>
> **التوقع:** يجب أن يحتوي المشروع الداخل إلى قائمة [PoArt]، كما في المثال أعلاه، على علاقة سببية اجتماعية أو علمية أو فلسفية تتجاوز الجماليات البصرية النقية. نظراً لأن الوقت هو الأصل الوحيد الذي لا يمكن شراؤه بالمال، في هذا البروتوكول يجب إثبات الوقت من خلال وضعه كضمان. يجب أن تكون القاعدة المفاهيمية للمشروع قوية وعالمية لدرجة أنه حتى في سيناريو CTO (استيلاء المجتمع) محتمل بعد سنوات، يمكن للمجتمع الاستمرار بشكل مستقل في الإمكانات المبتكرة للمشروع من خلال وراثة هذا الإرث.

### 5) الإرادة غير الخوارزمية

- **المشكلة:** إنتاجات رقمية مثالية ولكن بلا روح تكرر بعضها البعض.
- **حل [PoArt]:** يجب أن تُشعر الإرادة الفريدة للإنسان الذي يمكنه ارتكاب الأخطاء وتحمل المخاطر وتجربة التقلبات العاطفية في العمل. عدم اليقين في ضربات الفرشاة، وردود الفعل غير المتوقعة للمواد، والقرارات الفورية للفنان هي **التوقيع البيولوجي** الذي يفصل العمل عن "الإنتاج الآلي".

## ج) آلية التحقق ومكافحة الاحتيال

يضمن هذا النظام أن المشروع يبقى موثوقاً وحياً ليس فقط "في البداية" بل "للأبد".

### 📦 حزمة الأدلة - التوأم الرقمي

وراء كل عمل معتمد من [PoArt] توجد حزمة بيانات مشفرة ومختومة بالوقت يمكن للمستثمرين تنزيلها:

- **تسجيلات الفيديو الخام:** لقطات خام غير منقطعة من لحظة الإنتاج.
- **تحليل البيانات الوصفية:** تاريخ إنشاء الملف، معلومات الجهاز المستخدم وبيانات الموقع.
- **المراجع المادية:** دليل على أن العمل موجود في العالم المادي  
  (على سبيل المثال، الصحيفة الحالية أو بيانات البلوكشين من تلك اللحظة بجانب العمل).

> *ملاحظة الاتساق:* يرتبط مصطلح "حزمة الأدلة" بسلسلة **حزمة الأدلة → EvidenceRoot → NotarySeal** في الأقسام السابقة؛ أي يتم تمثيل سلامة الحزمة بختم قابل للتحقق.

### 🔄 تجديد 365 يوماً (بروتوكول الاستدامة)

- **الميزة الثورية:** في مشاريع التشفير، يطلق "المطور" الرمز ويختفي عادة بعد 1-2 أشهر (سحب ناعم). [PoArt] يجعل ذلك مستحيلاً.
- **القاعدة:** حالة "الفنان المتحقق منه" ليست مدى الحياة. **سنة واحدة** فقط صالحة.
- **التشغيل:** يجب على الفنان/المطور تقديم **عمل جديد مهم وقابل للإثبات** للمجتمع كل 365 يوماً.
- **مثال السيناريو:** أطلقت المشروع في 2026. في يناير 2027، يعطي النظام تحذيراً "انتهت فترة الإثبات". إذا لم يقدم الفنان معرضاً جديداً أو عملاً مادياً جديداً أو تكاملاً تقنياً جديداً، تنخفض "شارة الثقة" للمشروع.
- **النتيجة:** يضمن هذا النظام أن **المحتوى لا يفقد أبداً صلته** وأن المستثمر لا يختبر أبداً خوف *"هل المطور لا يزال هنا؟"*. يصبح المشروع استوديو حي.

### 🚩 بروتوكول العلم الأحمر

**في حالة اكتشاف أي احتيال من قبل المجتمع أو الخوارزميات (استخدام الذكاء الاصطناعي، عمل مسروق، فيديو متلاعب به):**

1. يتم وضع علامة فورية على الشهادة كـ **"VOID" (باطلة)**.
2. يتم تصنيف حزم الأدلة علناً كـ **"مزيفة"**.
3. يوضع المشروع في القائمة السوداء لـ [PoArt]. يعزز هذا أنه في عالم لامركزي، **السمعة هي العملة الوحيدة**.

## 🗳️ 6) الحوكمة والسجل العام

**الغرض من هذا القسم هو: تحويل معيار [PoArt] من مستوى "الثقة بالأفراد" إلى بنية تحتية عامة مستدامة مع السجل + التحقق + إشراف المجتمع.**

### 6.1 السجل العام

- **السجل العام:** يتم تسجيل جميع البيانات المعتمدة على `ilhanart.org/registry` (أو GitHub Registry).

**منطق السجل (المعيار الموصى به - بتنسيق مسار JSON):**

كل إدخال يدخل السجل يحمل هذه الحقول الأساسية القابلة للتحقق الدنيا:

- **الهوية والحالة:**
  - `certificate_id` (مرجع قابل للقراءة)
  - `status` (active / void)
  - `void_reason` (إذا كان ذلك مناسباً)
  - `visibility` (private / masked / public)
  - `created_at` (الطابع الزمني)

- **المؤسسة المصدرة:**
  - `issuer.name`
  - `issuer.location`
  - `issuer.attestation_pubkey`

- **معلومات العمل:**
  - `asset.title`
  - `asset.creator`
  - `asset.creator_wallet` (إذا كان ذلك ممكناً؛ للهوية ذات البوابة الرمزية)
  - `asset.fingerprints.sha256`
  - `asset.fingerprints.sha512`

- **البيانات الجنائية:**
  - `forensics.ip_masked`
  - `forensics.location`
  - `forensics.device`
  - `forensics.timestamp`

- **الأدلة التشفيرية:**
  - `proof.evidence_root`
  - `proof.signer_sig`
  - `proof.notary_seal`

- **الحوكمة:**
  - `governance.decision`
  - `governance.veto_threshold`

يمكن أن يحتوي السجل على طبقتين:
- **1)** فهرس قابل للقراءة البشرية (قائمة الويب / البحث / الفلتر)
- **2)** بيان قابل للقراءة الآلية (سجلات JSON؛ للتحقق من PFE)

**يصبح هذا "الإدخال" قابلاً للتحقق من خلال سلسلة حزمة الأدلة → EvidenceRoot → NotarySeal لـ PFE. يقدم السجل أهداف التحقق، وليس "ادعاءات".**

### 6.2 حق النقض المجتمعي بنسبة 40% (الحوكمة ذات البوابة الرمزية)

- **حق النقض المجتمعي بنسبة 40%:** يبدأ التصويت قبل شهر من منح الحالة؛ اعتراض 40% من المجتمع **ذي البوابة الرمزية (المتحقق منه بـ Solana)** يبطل الطلب.

**تدفق التصويت (العملية الواضحة الموصى بها):**
- **نافذة الطلب:** يفتح المشروع المرشح "تسجيل مرشح PoArt" (تظهر سجلات المرشحين في حالة "معلق").
- **فترة المراجعة:** يفحص المجتمع الأدلة لمدة 30 يوماً (حزمة الأدلة + تسجيلات البث المباشر + البيانات الوصفية).
- **التحقق ذو البوابة الرمزية:** يتم التصويت بمحافظ Solana المتحقق منها (على سبيل المثال ملكية رمز/NFT محدد + توقيع المحفظة).
- **قاعدة النقض:** إذا كانت 40% من الأصوات **اعتراض (لا / نقض)**، يتم رفض الطلب.
- **الشفافية:** يتم تخزين نتيجة التصويت في السجل كـ "سجل قرار" (التاريخ، النسبة، معرف اللقطة).

---

### 6.3 مزامنة البيانات الوصفية (التوافق مع العالم المادي)

- **مزامنة البيانات الوصفية:** يجب أن تتطابق البيانات التقنية في السجل بنسبة 100% مع الكيان المادي.

**تحديد "التطابق بنسبة 100%" تقنياً (الوضوح الموصى به):**
- **التطابق الأدنى (إلزامي):**
  - يجب أن يكون `asset.fingerprints.sha256/sha512` في السجل **متطابقاً** مع تجزئة الملف المعني.
  - عندما يتم إعادة إنتاج `proof.notary_seal` في السجل (إذا كانت حزمة الأدلة موجودة)، يجب أن يكون **متطابقاً**.
- **تطابق المرجع المادي (نوع الإثبات):**
  - يجب أن يكون العمل المادي + مرجع التاريخ/الكتلة الموضح في البث المباشر والأدلة المماثلة متسقاً مع حزمة الأدلة.
- **الامتثال للخصوصية:**
  - يتم نشر الحقول مثل IP/الموقع في رؤية `masked` **وفقاً لمعايير الإخفاء**.

### 6.4 النزاع والإلغاء

السجل ليس مجرد آلية "موافقة"؛ إنها **آلية تدقيق حية ضد الاحتيال**.

- عند بدء نزاع، يمكن وضع الإدخال في وضع **"review" (المراجعة)**.
- إذا تم اكتشاف احتيال، يتم وضع علامة عليه كـ `status: void` مع إضافة السبب:
  - `void_reason` (استخدام الذكاء الاصطناعي / السرقة / التلاعب، إلخ)
  - `revoked_at` (وقت الإلغاء)
- مصدر قرار الإلغاء واضح في السجل:
  - تصويت المجتمع / لجنة مصرح بها / ملاحظة تحقيق جنائي (ما ينطبق)

> **هذا القسم هو النظير في السجل لمفهوم VOID في قسم "بروتوكول العلم الأحمر".**

## 🧩 لماذا "وحدات الرؤية" المتعددة?

هذا هو الجزء الأكثر أهمية من الكود (قائمة اختيار الرؤية). تسمح هذه الخيارات للمستخدمين بموازنة **"الخصوصية مقابل الشفافية"**:

### 🔒 خاص

- **السيناريو:** لا يريد الفنان نشر العمل بعد ولكنه يريد ختمه بالوقت لإثبات "لقد فعلت هذا في هذا التاريخ".
- **ما يفعله الكود:** يكتب البيانات في قاعدة البيانات لكن يختمها بـ `visibility: "private"`. لاحقاً عند كتابة سياسة "القراءة العامة"، يمكنك إخفاء هذه السجلات من العامة باستخدام `WHERE visibility = 'public'`.

### 🕶️ مقنع

- **السيناريو:** يريد الفنان الشفافية لكنه يخشى العثور على عنوان منزله (موقع IP).
- **ما يفعله الكود:** تعمل وظائف `maskIP` و `maskLoc` على جانب JavaScript. يحول عنوان IP إلى تنسيق `88.241.***.***`، الموقع إلى تنسيق `***/TR`، ويرسل الإصدار المراقب إلى قاعدة البيانات.
- **ملاحظة الخصوصية:** يتم الإخفاء في المتصفح، لا ترى Supabase الموقع الفعلي. **ومع ذلك:** إذا تم استخدام واجهات برمجة تطبيقات طرف ثالث مثل ipapi.co لبيانات الموقع، فإن هؤلاء المزودين يرون عنوان IP في وقت الطلب.
- **الختم في الوضع المقنع:** يتم حساب EvidenceRoot و NotarySeal ببيانات جنائية مقنعة؛ وبالتالي يبقى التحقق حتمياً.

### 🌍 عام

- **السيناريو:** شفافية كاملة. وفقاً لمعايير [PoArt]، يتم الإعلان بوضوح عن مكان وزمان وشبكة إنتاج العمل.

## 💡 الابتكار التقني

PoArt ليس مجرد نظام تحميل ملفات. إنه محرك **"سلسلة الحفظ الجنائية"** الذي يجلب معياراً جديداً من خلال دمج ثلاث طبقات تقنية مختلفة في وعاء واحد.

**الطبقة الموصوفة كـ "محرك" في هذا القسم تتوافق مع جوهر محرك PoArt الجنائي (PFE) في المصطلحات السابقة.**

### 1) التجزئة من جانب العميل (الخصوصية القصوى)

لا يتم تحميل ملفات أعمالك الفنية أبداً إلى الخادم. يحسب محركنا القائم على المتصفح (جانب العميل) تجزئة (الملخص الرقمي) للملف على جهاز الكمبيوتر الخاص بك. يتم إرسال هذه البصمة والبيانات الوصفية فقط إلى الخادم.

> **ملاحظة الخصوصية:** لا يتم تحميل ملف العمل إلى الخادم وهو محمي بهذه الطريقة. ومع ذلك، يتم مشاركة البيانات الجنائية (IP/الموقع) وفقاً لوضع الرؤية المحدد (خاص/مقنع/عام).

### 2) دمج البيانات الجنائية (القوة الجنائية)

أكثر بكثير من مجرد طابع زمني عادي. يجمع النظام هذه البيانات في "ختم التكوين" الواحد:

- **الملخص الرقمي (SHA-512):** بصمة رقمية باستخدام معيار الملخص التشفيري (SHA-512) الذي سينكسر إذا تغير حتى بكسل واحد من العمل.
- **الموقع والوقت:** تاريخ بدقة ميلي ثانية، بلد، مدينة وبيانات منطقة المعاملة.
- **هوية الجهاز:** نظام التشغيل، المتصفح ونوع الجهاز (تحليل User-Agent).

## 🗺️ خريطة الطريق: مستقبل "بلا ثقة"

الإصدار الحالي **(بيتا الإصدار 1.0)** محسّن لتوفير أقصى سرعة وواجهة سهلة ووصول مجاني للمستخدمين النهائيين. ومع ذلك، فإن رؤيتنا النهائية هي الانتقال إلى بنية لا يمكن حتى لمسؤول قاعدة البيانات (نحن) التدخل فيها.

### المرحلة 1: بيتا (مباشر حالياً)

- **البنية التحتية:** قاعدة بيانات سحابية (Supabase).
- **الغرض:** السرعة، إزالة حواجز تجربة المستخدم والتكيف. توفير أمان "بلا احتكاك".

### 🚀 المرحلة 2: (متطلبات الخلفية / وظيفة Edge)

تغطي هذه المرحلة الانتقال من البنية العاملة "جانب العميل" بالكامل إلى بنية "سلطة جانب الخادم" أكثر أماناً وقابلية للإدارة.

| العنصر | ماذا يقدم؟ | مجموعة التقنيات | الأولوية |
|-------|---------------|------------|---------|
| **`INSERT` → وظيفة Edge** | منع الرسائل غير المرغوبة + أمان مفتاح API | Supabase Edge (Deno) | 🔴 عالية |
| **توقيع المحفظة** | مصادقة تشفيرية | Solana Wallet Adapter | 🟡 متوسطة |
| **نسخ احتياطي IPFS/Arweave** | ثبات لامركزي | IPFS SDK + Pinata | 🟢 منخفضة |
| **آلية الإلغاء** | إلغاء شهادة مزيفة | تحديث مخطط قاعدة البيانات | 🔴 عالية |
| **سجل التدقيق** | سجل استعلام جنائي | جدول سجلات مخصص | 🟡 متوسطة |
| **OpenTimestamps** | مرساة البيتكوين | OTS JavaScript | 🟢 منخفضة |
| **تكامل DID** | الهوية اللامركزية | ION/Ceramic | 🟢 منخفضة |

## 🔬 العمق التقني: خوارزمية الختم

### وظائف التجزئة الحتمية
```javascript
// وظائف مساعدة: تحويل الملخص إلى سلسلة سداسية عشرية
async function digestToHex(algorithm, dataBytes) {
  const hashBuffer = await crypto.subtle.digest(algorithm, dataBytes);
  const hashArray = Array.from(new Uint8Array(hashBuffer));
  return hashArray.map(b => b.toString(16).padStart(2, '0')).join('');
}

// تحويل السلسلة إلى مصفوفة بايتات
function stringToBytes(text) {
  return new TextEncoder().encode(text);
}

// توليد سلسلة جنائية كنسية (الإصدار 1.0: ترتيب حقل ثابت + UTF-8 + فاصل \n)
// ملاحظة المرحلة 2: الانتقال إلى JSON كنسي مع RFC 8785 (JCS)
function canonicalForensics(forensicsData) {
  return JSON.stringify({
    ip_masked: forensicsData.ip_masked,
    location: forensicsData.location,
    device: forensicsData.device,
    timestamp: forensicsData.timestamp
  });
}
```

### عملية إنتاج NotarySeal (حتمية تماماً)
```javascript
// 1. حساب FileHash (جانب العميل)
async function computeFileHash(file) {
  const fileBuffer = await file.arrayBuffer();
  const fileBytes = new Uint8Array(fileBuffer);
  
  const sha256 = await digestToHex('SHA-256', fileBytes);
  const sha512 = await digestToHex('SHA-512', fileBytes);
  
  return { sha256, sha512 };
}

// 2. جمع البيانات الجنائية (استخدام طابع زمني واحد)
async function collectForensics(visibilityMode) {
  const timestamp = new Date().toISOString(); // توليد طابع زمني واحد
  const ipData = await fetch('https://ipapi.co/json/').then(r => r.json());
  
  let forensics = {
    ip_masked: visibilityMode === 'masked' ? maskIP(ipData.ip) : ipData.ip,
    location: visibilityMode === 'masked' 
      ? `***/${ipData.country}` 
      : `${ipData.city}, ${ipData.country_name || ipData.country}`,
    device: navigator.userAgent,
    timestamp: timestamp // نفس الطابع الزمني
  };
  
  return { forensics, timestamp };
}

// 3. إنشاء EvidenceRoot (مع الترميز الكنسي)
async function computeEvidenceRoot(fileHash512, forensicsData) {
  const canonicalPayload = `file_sha512:${fileHash512}\nforensics:${canonicalForensics(forensicsData)}`;
  return await digestToHex('SHA-512', stringToBytes(canonicalPayload));
}

// 4. توليد NotarySeal (استخدام نفس الطابع الزمني)
async function computeNotarySeal(evidenceRoot, signerSignature, timestamp) {
  const sealPayload = `evidence_root:${evidenceRoot}\nsigner_sig:${signerSignature}\ntimestamp:${timestamp}`;
  return await digestToHex('SHA-512', stringToBytes(sealPayload));
}

// وظائف مساعدة للإخفاء (دعم IPv4 و IPv6)
function maskIP(ip) {
  if (!ip) return "***";
  
  // فحص IPv4
  if (ip.includes(".")) {
    const parts = ip.split(".");
    if (parts.length === 4) {
      return `${parts[0]}.${parts[1]}.***.***`;
    }
  }
  
  // IPv6 أو تنسيق غير معروف
  return "***";
}
```

#### التحقق السريع
```javascript
// يتحقق فقط من تجزئة الملف (علم أحمر سريع)
async function verifyQuick(file, certificateId) {
  const { sha512: userFileHash } = await computeFileHash(file);
  
  // الحصول من السجل
  const cert = await fetchFromRegistry(certificateId);
  const { sha512: originalHash } = cert.asset.fingerprints;
  
  // مقارنة التجزئة
  if (userFileHash === originalHash) {
    return {
      valid: true,
      message: "✅ أصلي - تجزئة الملف تطابق"
    };
  } else {
    return {
      valid: false,
      message: "❌ مزيف - تم التلاعب بالملف"
    };
  }
}
```

#### التحقق الكامل
```javascript
// يعيد توليد ويتحقق من EvidenceRoot و NotarySeal
async function verifyFull(file, certificateId) {
  const { sha512: userFileHash } = await computeFileHash(file);

  // الحصول من السجل
  const cert = await fetchFromRegistry(certificateId);

  // 1) التحقق من FileHash (علم أحمر سريع)
  const originalHash = cert.asset.fingerprints.sha512;
  if (userFileHash !== originalHash) {
    return { valid: false, message: "❌ مزيف - تجزئة الملف لا تطابق" };
  }

  // 2) إعادة توليد EvidenceRoot (مع البيانات الجنائية المخزنة في السجل)
  const evidenceRoot = await computeEvidenceRoot(userFileHash, cert.forensics);
  if (evidenceRoot !== cert.proof.evidence_root) {
    return { valid: false, message: "❌ لا تطابق - EvidenceRoot لا يصمد" };
  }

  // 3) إعادة توليد NotarySeal (مع نفس الطابع الزمني + signer_sig)
  const seal = await computeNotarySeal(
    evidenceRoot,
    cert.proof.signer_sig,
    cert.forensics.timestamp
  );

  if (seal !== cert.proof.notary_seal) {
    return { valid: false, message: "❌ لا تطابق - NotarySeal لا يصمد" };
  }

  // اختياري: في المرحلة 2، تحقق أيضاً من signer_sig مع attestation_pubkey
  // const sigValid = await verifySig(cert.issuer.attestation_pubkey, cert.proof.signer_sig, evidenceRoot);
  // if (!sigValid) return { valid: false, message: "❌ توقيع غير صالح" };

  return { valid: true, message: "✅ أصلي - التحقق الكامل مرر" };
}
```

> **ملاحظات مهمة:**
> - **التحقق السريع:** يتحقق فقط من تجزئة الملف للاستخدام السريع.
> - **التحقق الكامل:** يتحقق من جميع طبقات البروتوكول (EvidenceRoot + NotarySeal).
> - يتم تنفيذ جميع عمليات التجزئة بشكل حتمي مع ترميز وفواصل ثابتة.
> - **معيار التوحيد الإصدار 1.0:** ترتيب حقل ثابت + ترميز UTF-8 + فاصل `\n`.
> - **خطة المرحلة 2:** الانتقال إلى JSON كنسي مع RFC 8785 (JCS - مخطط التوحيد JSON).
> - في الوضع المقنع، يتم إجراء حساب EvidenceRoot و NotarySeal ببيانات جنائية مقنعة؛ وبالتالي يبقى التحقق حتمياً.
> - يتم استخدام طابع زمني واحد في جميع أنحاء العملية (جنائي + NotarySeal)؛ الحتمية مضمونة.
> - **أسماء الحقول الجنائية:** `ip_masked`، `location`، `device`، `timestamp` (الكود والسجل متوافقان تماماً).
> - **مسار السجل:** `certificate.asset.fingerprints` (متوافق تماماً مع كود التحقق).
> - **signer_sig في السجل:** حقل `proof.signer_sig` ضروري للتحقق الكامل.
> - سيتم تفعيل آلية SignerSignature في المرحلة 2 مع محول محفظة Solana؛ في الإصدار 1.0، يمكن إجراء التحقق مع `attestation_pubkey`.
