# 📚 தொழில்நுட்ப சொற்கள் மற்றும் கருத்துகளின் சொற்களஞ்சியம்
> **"இந்த நெறிமுறையின் மொழியைப் புரிந்துகொள்வது அதன் பார்வையைப் புரிந்துகொள்வதாகும்."**

## ⚙️ PoArt தடயவியல் இயந்திரம் (PFE) v1.0: அடிப்படை உள்கட்டமைப்பு

**PoArt தடயவியல் இயந்திரம் (PFE)** என்பது [PoArt] நெறிமுறையின் பின்னணியில் உள்ள மைய தர்க்கம் மற்றும் தொழில்நுட்ப செயல்பாட்டை பிரதிநிதித்துவப்படுத்தும் முக்கிய அடுக்கு ஆகும். இது கலை உற்பத்தியின் மூல தரவை எடுத்து அதை **டிஜிட்டல் சான்றாக** மாற்றும் "தடயவியல் இயந்திரம்" ஆகும், இது சரிபார்க்கக்கூடியது மற்றும் மாற்ற முடியாதது.

### 🧩 ஏன் "PoArt Forensic"?

- **PoArt (கலையின் ஆதாரம்):** இயந்திரத்தின் நோக்கம் டிஜிட்டல் சொத்தின் மதிப்பை ஊகத்துடன் இணைக்காமல், **சரிபார்க்கக்கூடிய உற்பத்தி செயல்முறையுடன்** இணைப்பதாகும்.
- **Forensic (அறிவியல் சரிபார்ப்பு):**
  - **தொழில்நுட்ப வரையறை:** உற்பத்தி செயல்முறை தரவு (தூரிகை வீச்சு, நேர வீடியோ, பதிவுகள்) சிதைக்கப்படவில்லை என்பதை சரிபார்க்க வழிமுறை முறை மற்றும் பதிவு வரிசை.
  - **தத்துவ நிலை:** **மனித நேரம், முயற்சி மற்றும் முடிவு செலவுகளை** அளவிடக்கூடிய உண்மையாக மாற்றும் கூற்று, AI இன் "உடனடி முடிவு" உற்பத்திக்கு எதிராக.

> குறிப்பு: பிளாக்செயின் ஒருங்கிணைப்பு (உதாரணமாக, Solana) PFE இன் மையமல்ல; இது சரிபார்ப்பு/பதிவு நோக்கங்களுக்காக **சங்கிலி நங்கூர அடுக்காக** தனித்தனியாக விவரிக்கப்படும்.

### 🛠️ தொழில்நுட்ப நோக்கம் v1.0

**PoArt தடயவியல் இயந்திரம் (PFE) v1.0** சிக்கலான நிதி மாதிரிகளை விட பின்வரும் **3 முக்கிய தூண்களில்** கட்டமைக்கப்பட்டுள்ளது:

1. **Hashing & Sealing (முத்திரையிடுதல்):**  
   PFE ஆதாரப் பொதியில் உள்ள அனைத்து கூறுகளையும் (வேலைக் கோப்பு, வீடியோ, JSON/பதிவு, கையாளுதல், போன்றவை) தீர்மானிக்கக்கூடிய வழியில் செயலாக்குகிறது மற்றும் ஒரு தனித்துவமான **NotarySeal** மதிப்பை உருவாக்குகிறது.

   **முக்கிய கருத்துக்கள் (v1.0):**
   - **FileHash (வேலையின் கைரேகை):** வேலைக் கோப்பு பைட்டுகளிலிருந்து உருவாக்கப்பட்ட ஹாஷ்.
   - **EvidenceRoot (ஆதாரப் பொதியின் வேர்):** ஆதாரப் பொதியின் ஒருமைப்பாட்டை பிரதிநிதித்துவப்படுத்தும் வேர் சுருக்கம் (Merkle வேர் அல்லது நியமன பிரதிநிதித்துவத்தின் ஹாஷ்).
   - **NotarySeal (இறுதி முத்திரை / PFE வெளியீடு):** EvidenceRoot + நேரம் + கையாளுதல் கூட்டிலிருந்து உருவாக்கப்பட்ட இறுதி முத்திரை.

   **சூத்திரங்கள் (முதலீட்டாளர்களுக்கு தெளிவாக தெரியும்):**
   
   $$\text{FileHash}_{512} = \text{SHA-512}(\text{ArtworkFileBytes})$$
   
   $$\text{NotarySeal} = \text{SHA-512}(\text{EvidenceRoot} \mid \text{SignerSignature} \mid \text{TimeStamp})$$
   
   **நியமன பேலோட் வரையறைகள் (v1.0):**
   
   - **EvidenceRootPayload:**
```
   file_sha512:{sha512}\nforensics:{canonicalForensics(forensics)}
```
   
   - **NotarySealPayload:**
```
   evidence_root:{evidence_root}\nsigner_sig:{signer_sig}\ntimestamp:{timestamp}
```
   
   > குறிப்பு: PFE வெளியீடாக குறிப்பிடப்படும் மதிப்பு **NotarySeal** ஆகும். **SignerSignature** செயல்முறை நிலை 2 இல் (Solana Wallet Adapter உடன்) செயல்படுத்தப்படும்; தற்போதைய v1.0 இல், அமைப்பின் சான்றிதழ் கையாளுதல் பயன்படுத்தப்படுகிறது. சான்றிதழ் பொது விசை பதிவேட்டில் `issuer.attestation_pubkey` புலத்தின் கீழ் வெளியிடப்படுகிறது.

2. **Indexing (சேமிப்பு):**  
   எந்த பணப்பை, எந்த தேதியில், **வேலையின் ஆதாரத்தை** எந்த வேலைக்கு ஒரு தெளிவான மற்றும் கேள்விக்கு உட்படுத்தக்கூடிய பதிவு அடுக்குக்கு அனுப்பியது என்பதை எழுதுகிறது.  
   *(இந்த அடுக்கு ஒரு தரவுத்தளமாக இருக்கலாம்; சங்கிலி ஒருங்கிணைப்பு தனித்தனியாக "சங்கிலி நங்கூர அடுக்கு" என விவரிக்கப்படுகிறது.)*

3. **Verification (சரிபார்ப்பு):**  
   ஒரு வேலையின் செல்லுபடியாகும் தன்மை கேள்விக்குட்படுத்தப்படும் போது, PFE மூல ஆதாரங்களை மீண்டும் செயலாக்குகிறது; கணக்கிடப்பட்ட **EvidenceRoot / NotarySeal** மதிப்புகள் சேமிக்கப்பட்ட பதிவுகளுடன் பொருந்துகின்றனவா என்பதை கணித ரீதியாக சோதிக்கிறது.

### 🧮 PoArt மதிப்பு கோட்பாடு (The Value Theorem)

[PoArt] நெறிமுறை டிஜிட்டல் சொத்தின் மதிப்பை ($V$) தவிர்க்க முடியாத சந்தை உணர்விலிருந்து இணைக்கவில்லை, மாறாக **உற்பத்தி செயல்முறையின் உடல் யதார்த்தத்துடன்** இணைக்கிறது.

செயற்கை நுண்ணறிவு (AI) உடனடி முடிவுகளை வழங்குவதன் மூலம் செயல்முறையை அழிக்கிறது ($t \to 0$). [PoArt], இருப்பினும், மதிப்பை **நேரம், உழைப்பு மற்றும் முகவர்** கூறுகளின் குவிப்பாக கையாளுகிறது.

$$V_{\text{PoArt}} = \int_{t_{\text{start}}}^{t_{\text{end}}} \left(P_{\text{labor}}(t) \cdot I_{\text{agency}}(t)\right) dt + U_{\text{irreversible}}$$

#### மாறிகளின் வரையறைகள்

- **$\int dt$ (செயல்முறை குவிப்பு):**  
  மதிப்பு "உடனடி முடிவு" அல்ல; இது $t_{\text{start}}$ மற்றும் $t_{\text{end}}$ இடையே குவிக்கப்படும் **செயல்முறை** ஆகும். காலம் குறையும்போது (AI உற்பத்தி), ஒருங்கிணைப்பு முடிவு 0 நெருங்குகிறது.

- **$P_{\text{labor}}(t)$ (உடனடி உழைப்பு சக்தி):**  
  உற்பத்தியின் போது செலவிடப்பட்ட மன மற்றும் உடல் முயற்சியின் தீவிரத்தை பிரதிநிதித்துவப்படுத்துகிறது. சரிபார்க்கக்கூடிய முயற்சி அதிகரிக்கும்போது, இன்டிகிராண்ட் வளர்கிறது.  
  > குறிப்பு: இந்த சொல் நடைமுறையில் "அளவிடக்கூடிய/சரிபார்க்கக்கூடிய உழைப்பு அறிகுறிகள்" மூலம் இயல்பாக்கப்படலாம்.

- **$I_{\text{agency}}(t)$ (முகவர் காரணி):**  
  படைப்பாளியின் ஆபத்துகளை எடுக்கும் மற்றும் முடிவுகளை எடுக்கும் திறன். இது $0$ மற்றும் $1$ இடையே மதிப்புகளை எடுக்கிறது.
  - **AI ($I \approx 0$):** கட்டளைகளை செயல்படுத்துகிறது, எந்த ஆபத்தும் எடுக்கவில்லை, எந்த செலவும் செலுத்தவில்லை.
  - **மனிதன் ($I \to 1$):** முடிவுகளை மாற்றுகிறார், தயங்குகிறார், ஆபத்துகளை எடுக்கிறார்.

- **$U_{\text{irreversible}}$ (மீளமுடியாத தனித்தன்மை):**  
  டிஜிட்டல் உற்பத்தியில் செயல்தவிர்த்தல் (`Ctrl+Z`) சாத்தியமாக இருந்தாலும், உடல் உற்பத்தியில் (கேன்வாஸில் பயன்படுத்தப்பட்ட வண்ணம், செதுக்கப்பட்ட கல், நேரலை ஒளிபரப்பில் செயல்) திரும்பும் வழி இல்லை. இந்த **மீளமுடியாத தன்மை** வேலையில் "தனித்தன்மையை" (மாற்ற முடியாத பண்புகள்) உருவாக்கும் கூடுதல் சொல்.

### 🔎 வழக்கு பகுப்பாய்வு: AI "உடனடி முடிவு" vs. மனிதன் "சரிபார்க்கப்பட்ட செயல்முறை"

பின்வரும் சூழ்நிலை **PoArt மதிப்பு கோட்பாடு** நடைமுறையில் எவ்வாறு செயல்படுகிறது மற்றும் [PoArt] அளவுகோலில் AI உற்பத்தி ஏன் குறைவான மதிப்பெண்களைப் பெறுகிறது என்பதைக் காட்டுகிறது.

#### சூழ்நிலை A: AI உடன் 10-நொடி காட்சி உற்பத்தி

- **காலம் ($\Delta t$):** $10$ நொடிகள் (சிறிய செயல்முறை)
- **உழைப்பு சக்தி ($P_{\text{labor}}$):** $1$ அலகு (கட்டளை எழுதுவது மட்டும்)
- **முகவர் காரணி ($I_{\text{agency}}$):** $0.01$ (ஆபத்து இல்லை, செலவு இல்லை)
- **மீளமுடியாத தன்மை ($U_{\text{irreversible}}$):** $0$ (மீளக்கூடியது / நகலெடுக்கக்கூடியது)

**முடிவு:**

$$V_{\text{AI}} \approx \int_{0}^{10} (1 \cdot 0.01) \, dt + 0 = 0.1$$

> **கருத்து:** முடிவு முழுமையானதாக இருந்தாலும்; [PoArt] மதிப்பு $0$ க்கு நெருங்குகிறது ஏனெனில் எந்த செயல்முறையும் வாழப்படவில்லை மற்றும் எந்த முகவர்/ஆபத்தும் ஈடுபடவில்லை.

#### சூழ்நிலை B: நேரலை ஒளிபரப்பில் 6-மணி நேர உடல் உற்பத்தி

- **காலம் ($\Delta t$):** $6$ மணி நேரம் ($21{,}600$ நொடிகள்)
- **உழைப்பு சக்தி ($P_{\text{labor}}$):** $0.5$ அலகுகள் (தொடர்ச்சியான உடல் மற்றும் மன முயற்சி)
- **முகவர் காரணி ($I_{\text{agency}}$):** $0.9$ (முடிவுகளை மாற்றுதல், ஆபத்துகளை எடுத்தல், மீளமுடியாத தேர்வுகள்)
- **மீளமுடியாத தன்மை ($U_{\text{irreversible}}$):** $>0$ (உடல் அறிகுறிகள் செயல்தவிர்க்க முடியாது)

**முடிவு:**

$$V_{\text{Human}} \approx \int_{0}^{21600} (0.5 \cdot 0.9) \, dt + U_{\text{irreversible}} \approx 9720 + U_{\text{irreversible}}$$

> **கருத்து:** செயல்முறை நீட்டிக்கப்படும்போது மற்றும் முகவர் (ஆபத்து) அதிகரிக்கும்போது, மதிப்பு ஒட்டுமொத்தமாக குவிகிறது. $U_{\text{irreversible}}$ சொல் வேலையில் "தனித்தன்மையை" (மாற்ற முடியாத பண்புகள்) உருவாக்கும் கூடுதல் பங்களிப்பு.

### ✅ முடிவு: ஆதாரம்-கட்டுப்படுத்தப்பட்ட மதிப்பு (Proof-Bound Value)

இந்த கோட்பாடு [PoArt] இன் மதிப்பு கூற்றை "விருப்பம்" அல்லது "சந்தை கதை" என்பதிலிருந்து வெளியேற்றுகிறது மற்றும் அதை **சரிபார்க்கக்கூடிய உற்பத்தி யதார்த்தத்துடன்** இணைக்கிறது.

1. **செயல்முறை இல்லை, மதிப்பு இல்லை:**  
   AI உடனடி முடிவுகளுடன் செயல்முறையை அழிக்கிறது ($t \to 0$). செயல்முறை சாளரம் சுருங்கும்போது, ஒருங்கிணைப்பு முடிவு குறைய வேண்டும்:
   
   $$\Delta t \downarrow \ \Rightarrow\ \int \left(P(t) \cdot I(t)\right) dt \to 0$$

2. **முகவர் மற்றும் ஆபத்து பெருக்கிகள்:**  
   [PoArt] "செலவிடப்பட்ட நேரத்தை" மட்டும் அளவிடவில்லை ஆனால் அந்த நேரத்தில் உள்ள முடிவு, ஆபத்து மற்றும் செலவின் உண்மையான நிலையையும் அளவிடுகிறது. ஆபத்து இல்லாத உற்பத்தி (AI) குறைந்த மதிப்பைக் கொண்டுள்ளது:
   
   $$V_{\text{PoArt}} \propto \int \left(P_{\text{labor}}(t) \cdot I_{\text{agency}}(t)\right) dt$$

3. **தனித்தன்மை உடல் சான்று, சந்தைப்படுத்தல் அல்ல:**  
   உடல் உற்பத்தியில் மீளமுடியாத அறிகுறிகள் (கேன்வாஸ் வீச்சு, கல் துண்டு) டிஜிட்டலின் `Ctrl+Z` தர்க்கத்திற்கு வெளியே உள்ளன. இந்த மீளமுடியாத தன்மை ($U_{\text{irreversible}}$) வேலையை இயல்பியல் மூலம் தனித்துவமாக்குகிறது.

> **🔐 சுருக்கம்:** மதிப்பு கோட்பாடு அளவீடாக நிச்சயமற்ற தன்மையைப் போல தோன்றினாலும் (உண்மையான உலக சமமானவற்றை முழுமையாக அளவிட முடியாவிட்டாலும்), இந்த சூத்திரத்தின் நோக்கம் மாறிகளின் அமைப்பு மற்றும் திசையைக் காட்டுவதாகும். AI யுகத்தில், அரிதானது "படம்" அல்ல மாறாக **சரிபார்க்கக்கூடிய வேலை, நேரம் மற்றும் முகவர்** ஆகும். [PoArt] இந்த அரிதான தன்மையை அளவிடுகிறது மற்றும் அதை **ஆதாரப் பொதியுடன்** எழுதுகிறது.

## a) [PoArt] என்றால் என்ன? (தத்துவ மற்றும் தொழில்நுட்ப வரையறை)

**கலையின் ஆதாரம் [PoArt];** என்பது பிளாக்செயினில் சொத்தின் பின்னணியில் உள்ள மதிப்பு ஊகத்தின் அடிப்படையில் அல்ல, மாறாக **மனித உழைப்பு**, **நேரம்** மற்றும் **சரிபார்க்கக்கூடிய உடல் ஆற்றல்** அடிப்படையில் உள்ளது என்பதை உறுதிசெய்யும் நிறுவன சரிபார்ப்பு தரநிலை ஆகும்.

Bitcoin *"மின்சாரம் மற்றும் செயலி சக்தியுடன்"* **(வேலையின் ஆதாரம்)** மதிப்பை உருவாக்குவது போல, [PoArt] உடன் பொருந்தும் திட்டங்கள் *"கலை திறன் மற்றும் மனித நேரத்துடன்"* மதிப்பை உருவாக்குகின்றன.

இது Pump.fun மற்றும் DEX தளங்களில் *"டெவலப்பர் விற்றுவிட்டார், திட்டம் முடிந்தது"* ஆபத்தை நீக்குகிறது; ஏனெனில் இங்கே மதிப்பு குறியீட்டில் இல்லை, மாறாக **உற்பத்தியின் தொடர்ச்சியில்** உள்ளது.

## b) [PoArt] இன் 5-தூண் தரநிலை (உண்மையின் 5 தூண்கள்)

இந்த 5 உருப்படிகள் ஒரு திட்டம் [PoArt] முத்திரையைப் பெற கடந்து செல்ல வேண்டிய மீளமுடியாத வடிகட்டிகள்.

### 1) நேரடி அடையாள ஆதாரம்

- **பிரச்சனை:** கிரிப்டோ உலகம் தெளிவற்ற அடையாளங்கள் கொண்ட அறியப்படாத நிறுவனர்களால் (Devs) நிரப்பப்பட்டுள்ளது, அவர்கள் பணத்தை சேகரித்து திட்டங்களை கைவிடுகிறார்கள்.
- **[PoArt] தீர்வு:** படைப்பாளி அடையாளத்தை மட்டும் சரிபார்க்கவில்லை, மாறாக **உற்பத்தியின் போது இருப்பையும்** சரிபார்க்கிறார். இது நேரலை ஒளிபரப்பு அமர்வுகளை உள்ளடக்கியது, அங்கு சமூக தொடர்பு நிகழ்கிறது மற்றும் குறிப்பிட்ட கோரிக்கைகள் உடனடியாக செயல்படுத்தப்படுகின்றன, முன் பதிவு செய்யப்பட்ட வீடியோக்கள் அல்ல.  
  (உதாரணமாக, *"இன்றைய தேதி மற்றும் தற்போதைய தொகுதி எண்ணை கேன்வாஸின் வலது மூலையில் எழுதுங்கள்"*)
- **முழக்கம்:** *"போட்கள் வரைய முடியும் ஆனால் போட்கள் வியர்க்காது மற்றும் மேம்படுத்த முடியாது."*

### 2) வேலை மற்றும் செயல்முறை ஆதாரம்

- **பிரச்சனை:** 2 நொடிகளில் உருவாக்கப்பட்ட AI (செயற்கை நுண்ணறிவு) படங்கள் டிஜிட்டல் உலகில் 2 மாதங்களில் செய்யப்பட்ட எண்ணெய் ஓவியத்திற்கு சமமான "jpeg" சிகிச்சையைப் பெறுகின்றன.
- **[PoArt] தீர்வு:** வேலையின் "கர்ப்பம் மற்றும் பிறப்பு" செயல்முறை எழுதப்படுகிறது. ஸ்கெட்ச் நிலைகள், பெயிண்டிங் நிலைகள், சேமிக்கப்பட்ட செலவழித்த மணிநேரங்கள் மற்றும் கலைஞர் வேலையை உருவாக்கும்போது கடந்து சென்ற உடல் செயல்முறை எழுதப்படுகின்றன. இது டோக்கனுக்கு **"நேர செலவை"** சேர்க்கிறது. சொத்து உற்பத்தி கடினமானது, அதன் மதிப்பு வலுவானது.

### 3) அழகியல் மதிப்பின் ஆதாரம்

- **பிரச்சனை:** "மீம்" கலாச்சாரம் உடனடி நகைச்சுவையில் மட்டுமே கவனம் செலுத்துகிறது, அழகியல் மற்றும் கலை ஆழத்தை புறக்கணிக்கிறது, இது குறுகிய கால "Hype" திட்டங்களுக்கு வழிவகுக்கிறது.
- **[PoArt] தீர்வு:** திட்டத்திற்கு கல்வி கலை தரநிலைகள், வண்ண கோட்பாடு, கலவை விதிகள் மற்றும் பொருள் அறிவு (Impasto, Texture, போன்றவை) இருக்க வேண்டும். உள்ளடக்கம் உங்களை சிரிக்க வைக்க மட்டும் இருக்கக்கூடாது; இது பார்வையாளர்களில் ஆச்சரியத்தை ஏற்படுத்த வேண்டும் மற்றும் **சேகரிப்பு மதிப்பு** இருக்க வேண்டும்.

### 4) கருத்து புதுமை

- **பிரச்சனை:** படைப்பாற்றல் இல்லாத ஆயிரக்கணக்கான நாய்/பூனை டோக்கன் நகல்கள்.
- **[PoArt] தீர்வு:** திட்டம் கலை, அறிவியல், தத்துவம் அல்லது தொழில்நுட்பத்தை அர்த்தமுள்ள கட்டமைப்பில் இணைக்கும் புதிய பாலத்தை உருவாக்க வேண்டும்.  
  (உதாரணமாக, பண்டைய டேவிட் சிலையை கிரிப்டோ சந்தை தரவுடன் இணைத்தல்; மனித உணர்வு "கல்லாக மாறுகிறது" என்ற கருத்தை இதன் மூலம் செயலாக்குதல் மற்றும் அறிவியல் ஆதாரங்களுடன் அதை அடித்தளமாக்குதல்.)

- **1)** மனிதர்-படிக்கக்கூடிய குறியீடு (வலைப் பட்டியல் / தேடல் / வடிகட்டி)
- **2)** இயந்திரம்-படிக்கக்கூடிய பிரதிநிதித்துவம் (JSON பதிவுகள்; PFE சரிபார்ப்புக்கு)

**இந்த "பதிவு" ஆதாரப் பொதி → EvidenceRoot → NotarySeal இன் PFE சங்கிலியால் சரிபார்க்கக்கூடியதாகிறது. பதிவேடு சரிபார்ப்பு இலக்குகளை வழங்குகிறது, "கூற்றுகள்" அல்ல.**

### 6.2 40% சமூக வீட்டோ (டோக்கன்-கேட் செய்யப்பட்ட ஆட்சி)

- **40% சமூக வீட்டோ:** நிலையை வழங்குவதற்கு ஒரு மாதத்திற்கு முன்பு வாக்களிப்பு தொடங்குகிறது; **டோக்கன்-கேட் செய்யப்பட்ட (Solana உடன் சரிபார்க்கப்பட்ட)** சமூகத்தின் 40% வீட்டோ விண்ணப்பத்தை ரத்து செய்கிறது.

**வாக்களிப்பு ஓட்டம் (முன்மொழியப்பட்ட தெளிவான செயல்முறை):**
- **விண்ணப்ப சாளரம்:** வேட்பாளர் திட்டம் "PoArt வேட்பாளர் பதிவு" திறக்கிறது (வேட்பாளர் பதிவுகள் "நிலுவையில்" நிலையில் தெரியும்).
- **மதிப்பாய்வு காலம்:** சமூகம் 30 நாட்களுக்கு ஆதாரங்களை ஆராய்கிறது (ஆதாரப் பொதி + நேரலை ஒளிபரப்பு பதிவுகள் + மெட்டாடேட்டா).
- **டோக்கன்-கேட் சரிபார்ப்பு:** வாக்களிப்பு சரிபார்க்கப்பட்ட Solana வாலட்டுகளுடன் செய்யப்படுகிறது (உதாரணமாக குறிப்பிட்ட டோக்கன்/NFT உரிமை + வாலட் கையொப்பம்).
- **வீட்டோ விதி:** 40% வாக்குகள் **எதிர்ப்பு (இல்லை / வீட்டோ)** என்றால், விண்ணப்பம் நிராகரிக்கப்படுகிறது.
- **வெளிப்படைத்தன்மை:** வாக்களிப்பு முடிவுகள் பதிவேட்டில் "முடிவு பதிவு" (தேதி, விகிதம், படம் ஐடி) என சேமிக்கப்படுகின்றன.

### 6.3 மெட்டாடேட்டா ஒத்திசைவு (உடல் உலகத்துடன் சீரமைப்பு)

- **மெட்டாடேட்டா ஒத்திசைவு:** பதிவேட்டில் உள்ள தொழில்நுட்ப தரவு உடல் நிறுவனத்துடன் 100% பொருந்த வேண்டும்.

**"100% சீரமைப்பு" இன் தொழில்நுட்ப வரையறை (முன்மொழியப்பட்ட வெளிப்படைத்தன்மை):**
- **குறைந்தபட்ச சீரமைப்பு (கட்டாயம்):**
  - பதிவேட்டில் உள்ள `asset.fingerprints.sha256/sha512` விவாதிக்கப்பட்ட கோப்பின் ஹாஷுடன் **அதே** இருக்க வேண்டும்.
  - பதிவேட்டில் `proof.notary_seal` மீண்டும் உருவாக்கப்படும்போது (ஆதாரப் பொதி இருந்தால்), அது **அதே** இருக்க வேண்டும்.
- **உடல் குறிப்பு சீரமைப்பு (ஆதார வகை):**
  - உடல் வேலை + நேரலை ஒளிபரப்பில் காட்டப்பட்ட தேதி/தொகுதி குறிப்பு மற்றும் அதே ஆதாரம் ஆதாரப் பொதியுடன் பொருந்த வேண்டும்.
- **தனியுரிமை இணக்கம்:**
  - `masked` தெரிவுநிலையில் IP/இடம் போன்ற புலங்கள் **மறைக்கும் தரநிலைகளுக்கு ஏற்ப** வெளியிடப்படுகின்றன.

---

### 6.4 சர்ச்சை மற்றும் ரத்து

பதிவேடு "ஒப்புதல்" செயல்முறை மட்டும் அல்ல; இது மோசடிக்கு எதிரான **உயிருள்ள மதிப்பாய்வு செயல்முறை**.

- சர்ச்சை தொடங்கும்போது, பதிவை **"review" (மதிப்பாய்வு)** நிலையில் வைக்கலாம்.
- மோசடி கண்டுபிடிக்கப்பட்டால், அது `status: void` என குறிக்கப்பட்டு காரணம் சேர்க்கப்படுகிறது:
  - `void_reason` (AI பயன்பாடு / திருட்டு / கையாளுதல், போன்றவை)
  - `revoked_at` (ரத்து நேரம்)
- ரத்து முடிவின் ஆதாரம் பதிவேட்டில் தெளிவாக உள்ளது:
  - சமூக வாக்கு / அங்கீகரிக்கப்பட்ட குழு / அறிவியல் விசாரணை குறிப்பு (பொருந்தக்கூடியது)

> **இந்த பிரிவு "சிவப்பு கொடி நெறிமுறை" பிரிவில் VOID கருத்தின் பதிவேடு இரட்டை.**

## 7) 🔐 தொழில்நுட்ப முத்திரை (NOTARY SEAL)

**PoArt தடயவியல் இயந்திரம் (PFE) v1.0** ஆல் உருவாக்கப்பட்ட மாற்ற முடியாத முத்திரை வழிமுறை:

$$\text{NotarySeal} = \text{SHA-512}\left(\text{EvidenceRoot} \mid \text{SignerSignature} \mid \text{TimeStamp}\right)$$

---

# [PoArt] டிஜிட்டல் நோட்டரி மற்றும் அறிவியல் ஆதார நெறிமுறை (Beta v1.0)

> **"கலாச்சாரம் மூலதனத்தை விட பெரியது. உங்கள் வேலைகளை இன்று பாதுகாக்கவும், நாளை எடுத்துச் செல்லவும்."**

---

## ஏன் பொது?

உண்மையான பாதுகாப்பு வெளிப்படைத்தன்மையிலிருந்து வருகிறது. எங்கள் **பொது பதிவேடு** அமைப்பின் நன்றி, உலகில் எங்கும் யாரும் ஒரு கோப்பு உண்மையானது என்பதை நொடிகளில் சரிபார்க்கலாம், எந்த அதிகாரமும் தேவையில்லாமல்.

---

## 🧩 பல "தெரிவுநிலை தொகுதிகள்" ஏன்?

இது குறியீட்டின் மிக முக்கியமான பகுதி (தெரிவுநிலை தேர்வு பட்டியல்). இந்த தேர்வுகள் பயனர்களை **"தனியுரிமை vs. வெளிப்படைத்தன்மை"** சமநிலைப்படுத்த அனுமதிக்கின்றன:

### 🔒 தனிப்பட்ட

- **சூழ்நிலை:** கலைஞர் இன்னும் வேலையை வெளியிட விரும்பவில்லை, ஆனால் "நான் இதை இந்த தேதியில் செய்தேன்" என்பதை நிரூபிக்க நேர முத்திரை செய்ய விரும்புகிறார்.
- **குறியீடு என்ன செய்கிறது:** இது தரவுத்தளத்தில் தரவை எழுதுகிறது ஆனால் முத்திரையை `visibility: "private"` என குறிக்கிறது. பின்னர் நீங்கள் "பொது வாசிப்பு" கொள்கையை எழுதும்போது, இந்த பதிவுகளை `WHERE visibility = 'public'` உடன் பொதுமக்களிடமிருந்து மறைக்கலாம்.

### 🕶️ மறைக்கப்பட்ட

- **சூழ்நிலை:** கலைஞர் வெளிப்படைத்தன்மை விரும்புகிறார் ஆனால் அவரது வீட்டு முகவரி (IP இடம்) கண்டுபிடிக்கப்படும் என்று பயப்படுகிறார்.
- **குறியீடு என்ன செய்கிறது:** `maskIP` மற்றும் `maskLoc` செயல்பாடுகள் JavaScript பக்கத்தில் வேலை செய்கின்றன. இது IP முகவரியை `88.241.***.***` வடிவத்திற்கு, இடத்தை `***/TR` வடிவத்திற்கு மாற்றுகிறது, மற்றும் தணிக்கை செய்யப்பட்ட பதிப்பை தரவுத்தளத்திற்கு அனுப்புகிறது.
- **தனியுரிமை உண்மை:** மறைத்தல் உலாவியில் செய்யப்படுகிறது, Supabase உண்மையான இடத்தைக் காணவில்லை. **ஆனால்:** இட தரவுக்கு ipapi.co போன்ற மூன்றாம் தரப்பு API கள் பயன்படுத்தப்பட்டால், இந்த வழங்குநர்கள் கோரிக்கை நேரத்தில் IP முகவரியைப் பார்க்கிறார்கள்.
- **மறைத்த முறையில் முத்திரையிடுதல்:** EvidenceRoot மற்றும் NotarySeal கணக்கீடு மறைக்கப்பட்ட தடயவியல் தரவுடன் செய்யப்படுகிறது; எனவே சரிபார்ப்பு தீர்மானிக்கக்கூடியதாக உள்ளது.

### 🌍 பொது

- **சூழ்நிலை:** முழு வெளிப்படைத்தன்மை. [PoArt] தரநிலைகளின்படி, எங்கே, எப்போது, எந்த நெட்வொர்க்கிலிருந்து வேலை உருவாக்கப்பட்டது என்பது வெளிப்படையாக அறிவிக்கப்படுகிறது.

## 💡 தொழில்நுட்ப புதுமை

PoArt ஒரு கோப்பு பதிவேற்ற அமைப்பு மட்டும் அல்ல. இது ஒரு பானையில் மூன்று வெவ்வேறு தொழில்நுட்ப நிலைகளை ஒன்றிணைத்து புதிய தரத்தை கொண்டுவரும் **"அறிவியல் பராமரிப்பு சங்கிலி"** இயந்திரம்.

**இந்த பிரிவில் "இயந்திரமாக" விவரிக்கப்பட்ட அடுக்கு முந்தைய விதிமுறைகளில் PoArt தடயவியல் இயந்திரம் (PFE) இன் மையத்துடன் ஒத்துப்போகிறது.**

### 1) கிளையன்ட்-பக்க ஹாஷிங் (உயர்ந்த தனியுரிமை)

உங்கள் கலைப்படைப்பு கோப்புகள் சர்வருக்கு பதிவேற்றப்படவில்லை. எங்கள் உலாவி-அடிப்படையிலான (கிளையன்ட்-பக்க) இயந்திரம் உங்கள் சொந்த கணினியில் கோப்பின் ஹாஷை (டிஜிட்டல் சுருக்கம்) கணக்கிடுகிறது. இந்த கைரேகை மற்றும் மெட்டாடேட்டா மட்டுமே சர்வருக்கு அனுப்பப்படுகிறது.

> **தனியுரிமை உண்மை:** வேலைக் கோப்பு சர்வருக்கு பதிவேற்றப்படவில்லை மற்றும் இந்த வழியில் பாதுகாக்கப்படுகிறது. இருப்பினும், தடயவியல் தரவு (IP/இடம்) தேர்ந்தெடுக்கப்பட்ட தெரிவுநிலை முறையின்படி (தனிப்பட்ட/மறைக்கப்பட்ட/பொது) பகிரப்படுகிறது.

### 2) தடயவியல் தரவு இணைப்பு (அறிவியல் சக்தி)

சாதாரண நேர முத்திரையை விட அதிகம். அமைப்பு இந்த தரவை ஒரு "தோற்ற முத்திரையில்" இணைக்கிறது:

- **டிஜிட்டல் சுருக்கம் (SHA-512):** குறியாக்க சுருக்க தரநிலை (SHA-512) பயன்படுத்தி கைரேகை, இது வேலையின் ஒரு பிக்சல் கூட மாறினால் உடைந்துவிடும்.
- **இடம் மற்றும் நேரம்:** மில்லி விநாடி துல்லியத்துடன் தேதி, நாடு, நகரம் மற்றும் மாவட்ட தரவு பரிவர்த்தனை.
- **சாதன அடையாளம்:** இயக்க முறைமை, உலாவி மற்றும் சாதன வகை (User-Agent பகுப்பாய்வு).

## 🛡️ பயன்பாட்டு நிகழ்வுகள் மற்றும் நன்மைகள்

நீங்கள் ஒரு கலைஞர், எழுத்தாளர் அல்லது வடிவமைப்பாளராக இருந்தால், "நான் இதை முன்பு செய்தேன்" என்று சொல்வது போதாது; நீங்கள் நிரூபிக்க வேண்டும்.

**நீங்கள் PoArt உடன் முத்திரையிடும் வேலை:**

- **கணித ஆதாரம்:** உங்கள் கோப்பின் ஒரு பிக்சல் கூட மாறினால், அமைப்புக்கு தெரியும். கையாளுதல் சாத்தியமற்றது.
- **சட்ட அடிப்படை:** எந்த தேதி, எந்த நகரம், எந்த சாதனத்திலிருந்து வேலை முத்திரையிடப்பட்டது என்பது எழுதப்பட்டுள்ளது.
- **உடனடி சான்றிதழ்:** இது நொடிகளில் உங்களுக்கு ஒரு சிறப்பு **"சொத்து அடையாள சான்றிதழை"** உருவாக்குகிறது, QR குறியீடு மற்றும் முத்திரையிடப்பட்டது.

## 🔬 தொழில்நுட்ப ஆழம்: முத்திரை வழிமுறை

### தீர்மானிக்கக்கூடிய ஹாஷ் செயல்பாடுகள்
```javascript
// உதவி செயல்பாடுகள்: சுருக்கத்தை ஹெக்ஸாடெசிமல் சரமாக மாற்றவும்
async function digestToHex(algorithm, dataBytes) {
  const hashBuffer = await crypto.subtle.digest(algorithm, dataBytes);
  const hashArray = Array.from(new Uint8Array(hashBuffer));
  return hashArray.map(b => b.toString(16).padStart(2, '0')).join('');
}

// சரத்தை பைட் வரிசையாக மாற்றவும்
function stringToBytes(text) {
  return new TextEncoder().encode(text);
}

// நியமன தடயவியல் சர உருவாக்கம் (v1.0: நிலையான புல வரிசை + UTF-8 + பிரிப்பான் \n)
// நிலை 2 உண்மை: RFC 8785 (JCS) உடன் நியமன JSON க்கு மாறுதல்
function canonicalForensics(forensicsData) {
  return JSON.stringify({
    ip_masked: forensicsData.ip_masked,
    location: forensicsData.location,
    device: forensicsData.device,
    timestamp: forensicsData.timestamp
  });
}
```

### NotarySeal உருவாக்கம் செயல்முறை (முழுமையாக தீர்மானிக்கக்கூடியது)
```javascript
// 1. FileHash கணக்கீடு (கிளையன்ட்-பக்கம்)
async function computeFileHash(file) {
  const fileBuffer = await file.arrayBuffer();
  const fileBytes = new Uint8Array(fileBuffer);
  
  const sha256 = await digestToHex('SHA-256', fileBytes);
  const sha512 = await digestToHex('SHA-512', fileBytes);
  
  return { sha256, sha512 };
}

// 2. தடயவியல் தரவு சேகரிப்பு (ஒற்றை நேர முத்திரை பயன்பாடு)
async function collectForensics(visibilityMode) {
  const timestamp = new Date().toISOString(); // ஒற்றை நேர முத்திரை உருவாக்கம்
  const ipData = await fetch('https://ipapi.co/json/').then(r => r.json());
  
  let forensics = {
    ip_masked: visibilityMode === 'masked' ? maskIP(ipData.ip) : ipData.ip,
    location: visibilityMode === 'masked' 
      ? `***/${ipData.country}` 
      : `${ipData.city}, ${ipData.country_name || ipData.country}`,
    device: navigator.userAgent,
    timestamp: timestamp // அதே நேர முத்திரை
  };
  
  return { forensics, timestamp };
}

// 3. EvidenceRoot கட்டுமானம் (நியமன குறியாக்கத்துடன்)
async function computeEvidenceRoot(fileHash512, forensicsData) {
  const canonicalPayload = `file_sha512:${fileHash512}\nforensics:${canonicalForensics(forensicsData)}`;
  return await digestToHex('SHA-512', stringToBytes(canonicalPayload));
}

// 4. NotarySeal உருவாக்கம் (அதே நேர முத்திரை பயன்பாடு)
async function computeNotarySeal(evidenceRoot, signerSignature, timestamp) {
  const sealPayload = `evidence_root:${evidenceRoot}\nsigner_sig:${signerSignature}\ntimestamp:${timestamp}`;
  return await digestToHex('SHA-512', stringToBytes(sealPayload));
}

// மறைத்தல் உதவி செயல்பாடுகள் (IPv4 மற்றும் IPv6 ஆதரவு)
function maskIP(ip) {
  if (!ip) return "***";
  
  // IPv4 சரிபார்ப்பு
  if (ip.includes(".")) {
    const parts = ip.split(".");
    if (parts.length === 4) {
      return `${parts[0]}.${parts[1]}.***.***`;
    }
  }
  
  // IPv6 அல்லது அறியப்படாத வடிவம்
  return "***";
}
```

### சரிபார்ப்பு ஓட்டம் (இரண்டு நிலைகள்)

#### Quick Verify (விரைவான சரிபார்ப்பு)
```javascript
// கோப்பு ஹாஷை மட்டும் சரிபார்க்கவும் (விரைவான சிவப்பு கொடி)
async function verifyQuick(file, certificateId) {
  const { sha512: userFileHash } = await computeFileHash(file);
  
  // பதிவேட்டிலிருந்து பெறவும்
  const cert = await fetchFromRegistry(certificateId);
  const { sha512: originalHash } = cert.asset.fingerprints;
  
  // ஹாஷ் ஒப்பீடு
  if (userFileHash === originalHash) {
    return {
      valid: true,
      message: "✅ உண்மையானது - கோப்பு ஹாஷ் பொருந்துகிறது"
    };
  } else {
    return {
      valid: false,
      message: "❌ தவறானது - கோப்பு கையாளப்பட்டுள்ளது"
    };
  }
}
```

#### Full Verify (முழு சரிபார்ப்பு)
```javascript
// EvidenceRoot மற்றும் NotarySeal ஐ மீண்டும் உருவாக்கி சரிபார்க்கவும்
async function verifyFull(file, certificateId) {
  const { sha512: userFileHash } = await computeFileHash(file);

  // பதிவேட்டிலிருந்து பெறவும்
  const cert = await fetchFromRegistry(certificateId);

  // 1) FileHash சரிபார்ப்பு (விரைவான சிவப்பு கொடி)
  const originalHash = cert.asset.fingerprints.sha512;
  if (userFileHash !== originalHash) {
    return { valid: false, message: "❌ தவறானது - கோப்பு ஹாஷ் பொருந்தவில்லை" };
  }

  // 2) EvidenceRoot ஐ மீண்டும் உருவாக்கவும் (பதிவேட்டில் சேமிக்கப்பட்ட தடயவியல் தரவுடன்)
  const evidenceRoot = await computeEvidenceRoot(userFileHash, cert.forensics);
  if (evidenceRoot !== cert.proof.evidence_root) {
    return { valid: false, message: "❌ பொருந்தவில்லை - EvidenceRoot நிற்கவில்லை" };
  }

  // 3) NotarySeal ஐ மீண்டும் உருவாக்கவும் (அதே நேர முத்திரை + signer_sig உடன்)
  const seal = await computeNotarySeal(
    evidenceRoot,
    cert.proof.signer_sig,
    cert.forensics.timestamp
  );

  if (seal !== cert.proof.notary_seal) {
    return { valid: false, message: "❌ பொருந்தவில்லை - NotarySeal நிற்கவில்லை" };
  }

  // விருப்பமானது: நிலை 2 இல், signer_sig ஐ attestation_pubkey உடன் சரிபார்க்கவும்
  // const sigValid = await verifySig(cert.issuer.attestation_pubkey, cert.proof.signer_sig, evidenceRoot);
  // if (!sigValid) return { valid: false, message: "❌ தவறான கையொப்பம்" };

  return { valid: true, message: "✅ உண்மையானது - முழு சரிபார்ப்பு தேர்ச்சி" };
}
```

> **முக்கியமான உண்மைகள்:**
> - **Quick Verify:** விரைவான பயன்பாட்டிற்கு கோப்பு ஹாஷை மட்டும் சரிபார்க்கிறது.
> - **Full Verify:** அனைத்து நெறிமுறை நிலைகளையும் சரிபார்க்கிறது (EvidenceRoot + NotarySeal).
> - அனைத்து ஹாஷ் செயல்பாடுகளும் நிலையான குறியாக்கம் மற்றும் நிலையான பிரிப்பான்களுடன் தீர்மானிக்கக்கூடிய வழியில் செய்யப்படுகின்றன.
> - **தற்போதைய தரநிலை v1.0:** நிலையான புல வரிசை + UTF-8 குறியாக்கம் + பிரிப்பான் `\n`.
> - **நிலை 2 திட்டம்:** RFC 8785 (JCS - JSON Canonicalization Scheme) உடன் நியமன JSON க்கு மாறுதல்.
> - மறைத்த முறையில், EvidenceRoot மற்றும் NotarySeal கணக்கீடு மறைக்கப்பட்ட தடயவியல் தரவுடன் செய்யப்படுகிறது; எனவே சரிபார்ப்பு தீர்மானிக்கக்கூடியதாக உள்ளது.
> - செயல்முறை முழுவதும் ஒற்றை நேர முத்திரை பயன்படுத்தப்படுகிறது (தடயவியல் + NotarySeal); தீர்மானம் உறுதிப்படுத்தப்பட்டுள்ளது.
> - **தடயவியல் புல பெயர்கள்:** `ip_masked`, `location`, `device`, `timestamp` (குறியீடு மற்றும் பதிவேடு சரியாக பொருந்துகின்றன).
> - **பதிவேடு பாதை:** `certificate.asset.fingerprints` (சரிபார்ப்பு குறியீட்டுடன் சரியாக பொருந்துகிறது).
> - **பதிவேட்டில் signer_sig:** முழு சரிபார்ப்புக்கு `proof.signer_sig` புலம் தேவை.
> - SignerSignature செயல்முறை நிலை 2 இல் Solana Wallet Adapter உடன் செயல்படுத்தப்படும்; v1.0 இல், சரிபார்ப்பு `attestation_pubkey` உடன் செய்யப்படலாம்.
