# 📚 సాంకేతిక పదాలు మరియు భావనల పదకోశం
> **"ఈ ప్రోటోకాల్ భాషను అర్థం చేసుకోవడం అంటే దాని దృష్టిని అర్థం చేసుకోవడం."**

## ⚙️ PoArt ఫోరెన్సిక్ ఇంజిన్ (PFE) v1.0: మౌలిక మౌలిక సదుపాయం

**PoArt ఫోరెన్సిక్ ఇంజిన్ (PFE)** అనేది [PoArt] ప్రోటోకాల్ వెనుక ఉన్న కేంద్ర తర్కం మరియు సాంకేతిక ఆపరేషన్‌ను సూచించే ప్రధాన పొర. ఇది కళా ఉత్పత్తి యొక్క ముడి డేటాను తీసుకొని దానిను **డిజిటల్ సాక్ష్యంగా** మార్చే "ఫోరెన్సిక్ ఇంజిన్" - ఇది ధృవీకరించదగినది మరియు మార్చలేనిది.

### 🧩 "PoArt Forensic" ఎందుకు?

- **PoArt (కళ యొక్క రుజువు):** ఇంజిన్ యొక్క లక్ష్యం డిజిటల్ ఆస్తి విలువను ఊహాగానాలతో కాకుండా **ధృవీకరించదగిన ఉత్పత్తి ప్రక్రియతో** అనుసంధానించడం.
- **Forensic (శాస్త్రీయ ధృవీకరణ):**
  - **సాంకేతిక నిర్వచనం:** ఉత్పత్తి ప్రక్రియ డేటా (బ్రష్ స్ట్రోక్, సమయ వీడియో, రికార్డులు) తారుమారు చేయబడలేదని ధృవీకరించడానికి అల్గోరిథం పద్ధతి మరియు రికార్డు క్రమం.
  - **తాత్విక స్థాయి:** **మానవ సమయం, కృషి మరియు నిర్ణయ ఖర్చులను** కొలవగల సత్యంగా మార్చే వాదన, AI యొక్క "తక్షణ ఫలితం" ఉత్పత్తికి వ్యతిరేకంగా.

> గమనిక: బ్లాక్‌చైన్ ఏకీకరణ (ఉదాహరణకు, Solana) PFE యొక్క కోర్ కాదు; ఇది ధృవీకరణ/నమోదు ప్రయోజనాల కోసం **చైన్ యాంకర్ లేయర్‌గా** విడిగా వివరించబడుతుంది.

### 🛠️ సాంకేతిక పరిధి v1.0

**PoArt ఫోరెన్సిక్ ఇంజిన్ (PFE) v1.0** సంక్లిష్ట ఆర్థిక నమూనాల కంటే క్రింది **3 ముఖ్య స్తంభాలపై** నిర్మించబడింది:

1. **Hashing & Sealing (సీలింగ్):**  
   PFE సాక్ష్య ప్యాకేజీలోని అన్ని మూలకాలను (పని ఫైల్, వీడియో, JSON/రికార్డు, సంతకం, మొదలైనవి) నిర్ణయాత్మక పద్ధతిలో ప్రాసెస్ చేస్తుంది మరియు ఒక ప్రత్యేకమైన **NotarySeal** విలువను ఉత్పత్తి చేస్తుంది.

   **కీలక భావనలు (v1.0):**
   - **FileHash (పని వేలిముద్ర):** పని ఫైల్ బైట్‌ల నుండి ఉత్పత్తి చేయబడిన హాష్.
   - **EvidenceRoot (సాక్ష్య ప్యాకేజీ మూలం):** సాక్ష్య ప్యాక్ యొక్క సమగ్రతను సూచించే మూల సారాంశం (Merkle మూలం లేదా కానానికల్ ప్రాతినిధ్యం యొక్క హాష్).
   - **NotarySeal (చివరి ముద్ర / PFE అవుట్‌పుట్):** EvidenceRoot + సమయం + సంతకం కలయిక నుండి ఉత్పత్తి చేయబడిన చివరి ముద్ర.

   **సూత్రాలు (పెట్టుబడిదారులకు స్పష్టంగా కనిపిస్తాయి):**
   
   $$\text{FileHash}_{512} = \text{SHA-512}(\text{ArtworkFileBytes})$$
   
   $$\text{NotarySeal} = \text{SHA-512}(\text{EvidenceRoot} \mid \text{SignerSignature} \mid \text{TimeStamp})$$
   
   **కానానికల్ పేలోడ్ నిర్వచనాలు (v1.0):**
   
   - **EvidenceRootPayload:**
```
   file_sha512:{sha512}\nforensics:{canonicalForensics(forensics)}
```
   
   - **NotarySealPayload:**
```
   evidence_root:{evidence_root}\nsigner_sig:{signer_sig}\ntimestamp:{timestamp}
```
   
   > గమనిక: PFE అవుట్‌పుట్‌గా సూచించబడే విలువ **NotarySeal**. **SignerSignature** ప్రక్రియ దశ 2లో (Solana Wallet Adapter తో) సక్రియం చేయబడుతుంది; ప్రస్తుత v1.0లో, సిస్టమ్ యొక్క ధృవీకరణ సంతకం ఉపయోగించబడుతుంది. ధృవీకరణ పబ్లిక్ కీ రిజిస్టర్‌లో `issuer.attestation_pubkey` ఫీల్డ్ క్రింద ప్రచురించబడుతుంది.

2. **Indexing (నిల్వ):**  
   ఏ వాలెట్, ఏ తేదీన, **పని రుజువును** ఏ పనికి స్పష్టమైన మరియు ప్రశ్నించదగిన రిజిస్టర్ పొరకు పంపింది అని వ్రాస్తుంది.  
   *(ఈ పొర డేటాబేస్ కావచ్చు; చైన్ ఏకీకరణ విడిగా "చైన్ యాంకర్ లేయర్"గా వివరించబడింది.)*

3. **Verification (ధృవీకరణ):**  
   పని యొక్క చెల్లుబాటుపై ప్రశ్నించబడినప్పుడు, PFE ముడి సాక్ష్యాలను మళ్లీ ప్రాసెస్ చేస్తుంది; లెక్కించబడిన **EvidenceRoot / NotarySeal** విలువలు నిల్వ చేసిన రికార్డులతో సరిపోతాయా అని గణితపరంగా పరీక్షిస్తుంది.

### 🧮 PoArt విలువ సిద్ధాంతం (The Value Theorem)

[PoArt] ప్రోటోకాల్ డిజిటల్ ఆస్తి విలువను ($V$) అస్పష్టమైన మార్కెట్ అవగాహనతో కాకుండా, **ఉత్పత్తి ప్రక్రియ యొక్క భౌతిక వాస్తవికతతో** అనుసంధానిస్తుంది.

ఆర్టిఫిషియల్ ఇంటెలిజెన్స్ (AI) తక్షణ ఫలితాలను అందించడం ద్వారా ప్రక్రియను నాశనం చేస్తుంది ($t \to 0$). [PoArt], అయితే, విలువను **సమయం, శ్రమ మరియు ఏజెన్సీ** అంశాల సంచితంగా నిర్వహిస్తుంది.

$$V_{\text{PoArt}} = \int_{t_{\text{start}}}^{t_{\text{end}}} \left(P_{\text{labor}}(t) \cdot I_{\text{agency}}(t)\right) dt + U_{\text{irreversible}}$$

#### వేరియబుల్స్ నిర్వచనాలు

- **$\int dt$ (ప్రక్రియ సంచితం):**  
  విలువ "తక్షణ ఫలితం" కాదు; ఇది $t_{\text{start}}$ మరియు $t_{\text{end}}$ మధ్య సంచితమైన **ప్రక్రియ**. వ్యవధి తగ్గుతున్నప్పుడు (AI ఉత్పత్తి), సమగ్ర ఫలితం 0 కు చేరుకుంటుంది.

- **$P_{\text{labor}}(t)$ (తక్షణ శ్రమ శక్తి):**  
  ఉత్పత్తి సమయంలో ఖర్చు చేసిన మానసిక మరియు శారీరక కృషి యొక్క తీవ్రతను సూచిస్తుంది. ధృవీకరించదగిన కృషి పెరుగుతున్నప్పుడు, ఇంటిగ్రాండ్ పెరుగుతుంది.  
  > గమనిక: ఈ పదాన్ని ఆచరణలో "కొలవదగిన/ధృవీకరించదగిన శ్రమ సంకేతాల" ద్వారా సాధారణీకరించవచ్చు.

- **$I_{\text{agency}}(t)$ (ఏజెన్సీ కారకం):**  
  సృష్టికర్త యొక్క రిస్క్ తీసుకునే మరియు నిర్ణయాలు తీసుకునే సామర్థ్యం. ఇది $0$ మరియు $1$ మధ్య విలువలను తీసుకుంటుంది.
  - **AI ($I \approx 0$):** ఆదేశాలను అమలు చేస్తుంది, ఎటువంటి రిస్క్ తీసుకోదు, ఎటువంటి ఖర్చు చెల్లించదు.
  - **మానవుడు ($I \to 1$):** నిర్ణయాలను మార్చుతాడు, సందేహిస్తాడు, రిస్క్‌లు తీసుకుంటాడు.

- **$U_{\text{irreversible}}$ (తిరిగి మార్చలేని ప్రత్యేకత):**  
  డిజిటల్ ఉత్పత్తిలో అన్‌డూ చేయడం (`Ctrl+Z`) సాధ్యమైనప్పటికీ, భౌతిక ఉత్పత్తిలో (కాన్వాస్‌పై వర్తించిన పెయింట్, చెక్కబడిన రాయి, లైవ్ ప్రసారంలో చర్య) తిరిగి వచ్చే మార్గం లేదు. ఈ **తిరిగి మార్చలేని స్వభావం** పనిలో "ప్రత్యేకతను" (భర్తీ చేయలేని లక్షణాలు) సృష్టించే అదనపు పదం.

### 🔎 కేసు విశ్లేషణ: AI "తక్షణ ఫలితం" vs. మానవుడు "ధృవీకరించబడిన ప్రక్రియ"

క్రింది దృశ్యం **PoArt విలువ సిద్ధాంతం** ఆచరణలో ఎలా పనిచేస్తుందో మరియు [PoArt] స్కేల్‌లో AI ఉత్పత్తి ఎందుకు తక్కువ స్కోర్‌లు పొందుతుందో చూపిస్తుంది.

#### దృశ్యం A: AI తో 10-సెకన్ల విజువల్ ఉత్పత్తి

- **వ్యవధి ($\Delta t$):** $10$ సెకన్లు (చిన్న ప్రక్రియ)
- **శ్రమ శక్తి ($P_{\text{labor}}$):** $1$ యూనిట్ (ఆదేశం రాయడం మాత్రమే)
- **ఏజెన్సీ కారకం ($I_{\text{agency}}$):** $0.01$ (రిస్క్ లేదు, ఖర్చు లేదు)
- **తిరిగి మార్చలేని స్వభావం ($U_{\text{irreversible}}$):** $0$ (రివర్సిబుల్ / కాపీ చేయదగినది)

**ఫలితం:**

$$V_{\text{AI}} \approx \int_{0}^{10} (1 \cdot 0.01) \, dt + 0 = 0.1$$

> **వ్యాఖ్యానం:** ఫలితం పరిపూర్ణంగా ఉన్నప్పటికీ; [PoArt] విలువ $0$ కు చేరుకుంటుంది ఎందుకంటే ఎటువంటి ప్రక్రియ జీవించలేదు మరియు ఎటువంటి ఏజెన్సీ/రిస్క్ పాల్గొనలేదు.

#### దృశ్యం B: లైవ్ ప్రసారంలో 6-గంటల భౌతిక ఉత్పత్తి

- **వ్యవధి ($\Delta t$):** $6$ గంటలు ($21{,}600$ సెకన్లు)
- **శ్రమ శక్తి ($P_{\text{labor}}$):** $0.5$ యూనిట్లు (నిరంతర శారీరక మరియు మానసిక కృషి)
- **ఏజెన్సీ కారకం ($I_{\text{agency}}$):** $0.9$ (నిర్ణయాలను మార్చడం, రిస్క్‌లు తీసుకోడం, తిరిగి మార్చలేని ఎంపికలు)
- **తిరిగి మార్చలేని స్వభావం ($U_{\text{irreversible}}$):** $>0$ (భౌతిక సంకేతాలను అన్‌డూ చేయలేము)

**ఫలితం:**

$$V_{\text{Human}} \approx \int_{0}^{21600} (0.5 \cdot 0.9) \, dt + U_{\text{irreversible}} \approx 9720 + U_{\text{irreversible}}$$

> **వ్యాఖ్యానం:** ప్రక్రియ పొడిగించబడినప్పుడు మరియు ఏజెన్సీ (రిస్క్) పెరుగుతున్నప్పుడు, విలువ సంచిత రీతిలో పేరుకుపోతుంది. $U_{\text{irreversible}}$ పదం పనిలో "ప్రత్యేకతను" (భర్తీ చేయలేని లక్షణాలు) సృష్టించే అదనపు సహకారం.

### ✅ ముగింపు: రుజువు-బంధిత విలువ (Proof-Bound Value)

ఈ సిద్ధాంతం [PoArt] యొక్క విలువ వాదనను "ప్రాధాన్యత" లేదా "మార్కెట్ కథ" కావడం నుండి వెలికితీస్తుంది మరియు దానిని **ధృవీకరించదగిన ఉత్పత్తి వాస్తవికతతో** అనుసంధానిస్తుంది.

1. **ప్రక్రియ లేదు, విలువ లేదు:**  
   AI తక్షణ ఫలితాలతో ప్రక్రియను నాశనం చేస్తుంది ($t \to 0$). ప్రక్రియ విండో కుదించబడినప్పుడు, సమగ్ర ఫలితం తగ్గాలి:
   
   $$\Delta t \downarrow \ \Rightarrow\ \int \left(P(t) \cdot I(t)\right) dt \to 0$$

2. **ఏజెన్సీ మరియు రిస్క్ గుణకాలు:**  
   [PoArt] కేవలం "ఖర్చు చేసిన సమయాన్ని" మాత్రమే కొలవదు కానీ ఆ సమయంలో నిర్ణయం, రిస్క్ మరియు ఖర్చు యొక్క వాస్తవ స్థాయిని కూడా కొలుస్తుంది. రిస్క్ లేని ఉత్పత్తికి (AI) తక్కువ విలువ ఉంటుంది:
   
   $$V_{\text{PoArt}} \propto \int \left(P_{\text{labor}}(t) \cdot I_{\text{agency}}(t)\right) dt$$

3. **ప్రత్యేకత భౌతిక రుజువు, మార్కెటింగ్ కాదు:**  
   భౌతిక ఉత్పత్తిలో తిరిగి మార్చలేని సంకేతాలు (కాన్వాస్ స్ట్రోక్, రాయి ముక్క) డిజిటల్ యొక్క `Ctrl+Z` తర్కానికి వెలుపల ఉన్నాయి. ఈ తిరిగి మార్చలేని స్వభావం ($U_{\text{irreversible}}$) పనిని ఆంటాలజీ ద్వారా ప్రత్యేకమైనదిగా చేస్తుంది.

> **🔐 సారాంశం:** విలువ సిద్ధాంతం కొలతగా అనిశ్చితి వలె కనిపించినప్పటికీ (వాస్తవ ప్రపంచ సమానమైనది పూర్తిగా కొలవబడకపోయినా), ఈ ఫార్ములా యొక్క లక్ష్యం వేరియబుల్స్ యొక్క ఏర్పాటు మరియు దిశను చూపించడం. AI యుగంలో, అరుదైనది "చిత్రం" కాదు కానీ **ధృవీకరించదగిన పని, సమయం మరియు ఏజెన్సీ**. [PoArt] ఈ అరుదైన స్వభావాన్ని కొలుస్తుంది మరియు దానిని **సాక్ష్య ప్యాకేజీతో** వ్రాస్తుంది.

## b) [PoArt] యొక్క 5-స్తంభ ప్రమాణం (సత్యం యొక్క 5 స్తంభాలు)

ఈ 5 అంశాలు ఒక ప్రాజెక్ట్ [PoArt] ముద్రను పొందడానికి దాటవలసిన తిరిగి మార్చలేని ఫిల్టర్లు.

### 1) ప్రత్యక్ష గుర్తింపు రుజువు

- **సమస్య:** క్రిప్టో ప్రపంచం అస్పష్టమైన గుర్తింపులు ఉన్న తెలియని వ్యవస్థాపకులతో (Devs) నిండి ఉంది, వారు డబ్బు సేకరిస్తారు మరియు ప్రాజెక్టులను విడిచిపెడతారు.
- **[PoArt] పరిష్కారం:** సృష్టికర్త కేవలం గుర్తింపును మాత్రమే ధృవీకరించడు, కానీ **ఉత్పత్తి సమయంలో ఉనికిని** కూడా ధృవీకరిస్తాడు. ఇందులో లైవ్ ప్రసార సెషన్లు ఉన్నాయి, ఇక్కడ సమాజ పరస్పర చర్య జరుగుతుంది మరియు నిర్దిష్ట అభ్యర్థనలు వెంటనే అమలు చేయబడతాయి, ముందుగా రికార్డ్ చేసిన వీడియోలు కాదు.  
  (ఉదాహరణకు, *"ఈ రోజు తేదీ మరియు ప్రస్తుత బ్లాక్ సంఖ్యను కాన్వాస్ యొక్క కుడి మూలలో రాయండి"*)
- **నినాదం:** *"బాట్లు పెయింట్ చేయగలవు కానీ బాట్లు చెమట పట్టవు మరియు మెరుగుపరచలేవు."*

### 2) పని మరియు ప్రక్రియ రుజువు

- **సమస్య:** 2 సెకన్లలో సృష్టించిన AI (ఆర్టిఫిషియల్ ఇంటెలిజెన్స్) చిత్రాలు డిజిటల్ ప్రపంచంలో 2 నెలల్లో తయారు చేసిన ఆయిల్ పెయింటింగ్‌తో సమానమైన "jpeg" చికిత్సను పొందుతాయి.
- **[PoArt] పరిష్కారం:** పని యొక్క "గర్భధారణ మరియు జననం" ప్రక్రియ వ్రాయబడుతుంది. స్కెచ్ దశలు, పెయింటింగ్ దశలు, నిల్వ చేసిన ఖర్చు చేసిన గంటలు మరియు కళాకారుడు పనిని సృష్టించేటప్పుడు గడిపిన భౌతిక ప్రక్రియ వ్రాయబడతాయి. ఇది టోకెన్‌కు **"సమయ ఖర్చు"** జోడిస్తుంది. ఆస్తి ఉత్పత్తి కష్టతరం, దాని విలువ బలమైనది.

### 3) సౌందర్య విలువ రుజువు

- **సమస్య:** సౌందర్యశాస్త్రం మరియు కళాత్మక లోతును విస్మరిస్తూ కేవలం తక్షణ హాస్యంపై మాత్రమే దృష్టి సారించే "మీమ్" సంస్కృతి, ఇది స్వల్పకాలిక "Hype" ప్రాజెక్టులకు దారితీస్తుంది.
- **[PoArt] పరిష్కారం:** ప్రాజెక్ట్‌కు అకడమిక్ కళా ప్రమాణాలు, రంగు సిద్ధాంతం, కూర్పు నియమాలు మరియు పదార్థ జ్ఞానం (Impasto, Texture, మొదలైనవి) ఉండాలి. కంటెంట్ మిమ్మల్ని నవ్వించడం మాత్రమే కాకూడదు; ఇది వీక్షకులలో ఆశ్చర్యాన్ని రేకెత్తించాలి మరియు **సేకరణ విలువ** కలిగి ఉండాలి.

### 4) భావన కొత్తదనం

- **సమస్య:** సృజనాత్మకత లేని వేలాది కుక్క/పిల్లి టోకెన్ కాపీలు.
- **[PoArt] పరిష్కారం:** ప్రాజెక్ట్ కళ, సైన్స్, తత్వశాస్త్రం లేదా సాంకేతికతను అర్థవంతమైన నిర్మాణంలో కలిపే కొత్త వంతెనను నిర్మించాలి.  
  (ఉదాహరణకు, పురాతన డేవిడ్ విగ్రహాన్ని క్రిప్టో మార్కెట్ డేటాతో కలపడం; మానవ అవగాహన "రాయిగా మారుతోంది" అనే ఆలోచనను దీని ద్వారా ప్రాసెస్ చేయడం మరియు శాస్త్రీయ మూలాలతో దానికి పునాదులు వేయడం.)  
  పని కేవలం దృశ్య విందు మాత్రమే కాకూడదు కానీ **సైన్స్, తత్వశాస్త్రం లేదా టెక్నాలజీ** గురించి ఆలోచనలను రేకెత్తించే మేధో సవాలు కూడా కావాలి.

> **అంచనా:** [PoArt] జాబితాలోకి ప్రవేశించే ప్రాజెక్ట్, పైన ఉదాహరణ వలె, దృశ్య సౌందర్యానికి మించి సామాజిక, శాస్త్రీయ లేదా తాత్విక కారణ మరియు ప్రభావ సంబంధం కలిగి ఉండాలి. సమయం డబ్బుతో కొనలేని ఏకైక ఆస్తి కాబట్టి, ఈ ప్రోటోకాల్‌లో సమయాన్ని భద్రతగా ఉంచడం ద్వారా ధృవీకరించాలి. ప్రాజెక్ట్ యొక్క భావన పునాది చాలా బలంగా మరియు సార్వత్రికంగా ఉండాలి, సంవత్సరాల తర్వాత సాధ్యమైన CTO (కమ్యూనిటీ టేక్‌ఓవర్) పరిస్థితిలో కూడా, సమాజం ఈ వారసత్వాన్ని వారసత్వంగా పొందడం ద్వారా ప్రాజెక్ట్ యొక్క సృజనాత్మక సామర్థ్యాన్ని స్వతంత్రంగా కొనసాగించగలదు.

### 6.2 40% సమాజ వీటో (టోకెన్-గేటెడ్ పాలన)

- **40% సమాజ వీటో:** స్థితిని ఇవ్వడానికి ఒక నెల ముందు ఓటింగ్ ప్రారంభమవుతుంది; **టోకెన్-గేటెడ్ (Solana తో ధృవీకరించబడిన)** సమాజం యొక్క 40% వీటో దరఖాస్తును రద్దు చేస్తుంది.

**ఓటింగ్ ప్రవాహం (ప్రతిపాదిత స్పష్టమైన ప్రక్రియ):**
- **దరఖాస్తు విండో:** అభ్యర్థి ప్రాజెక్ట్ "PoArt అభ్యర్థి నమోదు" తెరుస్తుంది (అభ్యర్థి రికార్డులు "పెండింగ్ స్థితి"లో కనిపిస్తాయి).
- **సమీక్ష కాలం:** సమాజం 30 రోజులపాటు సాక్ష్యాలను పరిశీలిస్తుంది (సాక్ష్య ప్యాకేజీ + లైవ్ ప్రసార రికార్డులు + మెటాడేటా).
- **టోకెన్-గేటెడ్ ధృవీకరణ:** ఓటింగ్ ధృవీకరించబడిన Solana వాలెట్లతో చేయబడుతుంది (ఉదాహరణకు నిర్దిష్ట టోకెన్/NFT యాజమాన్యం + వాలెట్ సంతకం).
- **వీటో నియమం:** 40% ఓట్లు **వ్యతిరేకత (లేదు / వీటో)** అయితే, దరఖాస్తు తిరస్కరించబడుతుంది.
- **పారదర్శకత:** ఓటింగ్ ఫలితాలు రిజిస్టర్‌లో "నిర్ణయ రికార్డు" (తేదీ, నిష్పత్తి, చిత్ర ID) గా నిల్వ చేయబడతాయి.

### 6.3 మెటాడేటా సింక్రనైజేషన్ (భౌతిక ప్రపంచంతో సమలేఖనం)

- **మెటాడేటా సింక్రనైజేషన్:** రిజిస్టర్‌లోని సాంకేతిక డేటా భౌతిక సంస్థతో 100% సరిపోలాలి.

**"100% సమలేఖనం" యొక్క సాంకేతిక నిర్వచనం (ప్రతిపాదిత పారదర్శకత):**
- **కనిష్ట సమలేఖనం (తప్పనిసరి):**
  - రిజిస్టర్‌లోని `asset.fingerprints.sha256/sha512` చర్చించిన ఫైల్ యొక్క హాష్‌తో **అదే** ఉండాలి.
  - రిజిస్టర్‌లోని `proof.notary_seal` మళ్లీ ఉత్పత్తి చేయబడినప్పుడు (సాక్ష్య ప్యాకేజీ ఉంటే), అది **అదే** ఉండాలి.
- **భౌతిక సూచన సమలేఖనం (రుజువు రకం):**
  - భౌతిక పని + లైవ్ ప్రసారంలో చూపబడిన తేదీ/బ్లాక్ సూచన మరియు అదే రుజువు సాక్ష్య ప్యాకేజీతో సరిపోలాలి.
- **గోప్యత అనుకూలత:**
  - `masked` దృశ్యమానతలో IP/స్థానం వంటి ఫీల్డ్‌లు **మాస్కింగ్ ప్రమాణాల ప్రకారం** ప్రచురించబడతాయి.

### 6.4 వివాదం మరియు రద్దు

రిజిస్టర్ కేవలం "ఆమోదం" ప్రక్రియ కాదు; ఇది మోసానికి వ్యతిరేకంగా **సజీవ సమీక్ష ప్రక్రియ**.

- వివాదం ప్రారంభమైనప్పుడు, నమోదును **"review" (సమీక్ష)** స్థితిలో ఉంచవచ్చు.
- మోసం కనుగొనబడితే, అది `status: void` గా గుర్తించబడుతుంది మరియు కారణం జోడించబడుతుంది:
  - `void_reason` (AI వినియోగం / దొంగతనం / తారుమారు, మొదలైనవి)
  - `revoked_at` (రద్దు సమయం)
- రద్దు నిర్ణయం యొక్క మూలం రిజిస్టర్‌లో స్పష్టంగా ఉంటుంది:
  - సమాజ ఓటు / అధికారిక కమిటీ / శాస్త్రీయ విచారణ గమనిక (వర్తించేది)

> **ఈ విభాగం "ఎరుపు జెండా ప్రోటోకాల్" విభాగంలోని VOID భావన యొక్క రిజిస్టర్ ట్విన్.**

## 7) 🔐 సాంకేతిక ముద్ర (NOTARY SEAL)

**PoArt ఫోరెన్సిక్ ఇంజిన్ (PFE) v1.0** ద్వారా ఉత్పత్తి చేయబడిన మార్చలేని ముద్ర అల్గోరిథం:

$$\text{NotarySeal} = \text{SHA-512}\left(\text{EvidenceRoot} \mid \text{SignerSignature} \mid \text{TimeStamp}\right)$$

## ఎందుకు పబ్లిక్?

నిజమైన భద్రత పారదర్శకత నుండి వస్తుంది. మా **పబ్లిక్ రిజిస్టర్** వ్యవస్థకు ధన్యవాదాలు, ప్రపంచంలో ఎక్కడైనా ఎవరైనా ఒక ఫైల్ ప్రామాణికమైనదా అని సెకన్లలో ధృవీకరించవచ్చు, ఏ అధికారం అవసరం లేకుండా.

## 🧩 బహుళ "దృశ్యమానత మాడ్యూళ్లు" ఎందుకు?

ఇది కోడ్ యొక్క అత్యంత క్లిష్టమైన భాగం (దృశ్యమానత ఎంపిక మెను). ఈ ఎంపికలు వినియోగదారులు **"గోప్యత vs. పారదర్శకత"** సమతుల్యం చేయడానికి అనుమతిస్తాయి:

### 🔒 ప్రైవేట్

- **దృశ్యం:** కళాకారుడు ఇంకా పనిని ప్రచురించదలచుకోడు, కానీ "నేను దీన్ని ఈ తేదీన చేసాను" అని నిరూపించడానికి సమయ ముద్ర వేయాలనుకుంటాడు.
- **కోడ్ ఏమి చేస్తుంది:** ఇది డేటాబేస్‌లో డేటాను వ్రాస్తుంది కానీ ముద్రను `visibility: "private"` గా గుర్తిస్తుంది. తరువాత మీరు "పబ్లిక్ రీడ్" విధానాన్ని వ్రాసేటప్పుడు, మీరు ఈ రికార్డులను `WHERE visibility = 'public'` తో ప్రజల నుండి దాచవచ్చు.

### 🕶️ మాస్క్ చేయబడింది

- **దృశ్యం:** కళాకారుడు పారదర్శకత కోరుకుంటాడు కానీ అతని ఇంటి చిరునామా (IP స్థానం) కనుగొనబడుతుందని భయపడతాడు.
- **కోడ్ ఏమి చేస్తుంది:** `maskIP` మరియు `maskLoc` ఫంక్షన్లు JavaScript వైపు పనిచేస్తాయి. ఇది IP చిరునామాను `88.241.***.***` ఫార్మాట్‌కు, స్థానాన్ని `***/TR` ఫార్మాట్‌కు మారుస్తుంది, మరియు సెన్సార్ చేసిన వెర్షన్‌ను డేటాబేస్‌కు పంపుతుంది.
- **గోప్యత సత్యం:** మాస్కింగ్ బ్రౌజర్‌లో చేయబడుతుంది, Supabase నిజమైన స్థానాన్ని చూడదు. **కానీ:** స్థాన డేటా కోసం ipapi.co వంటి మూడవ-పార్టీ API లు ఉపయోగించబడితే, ఈ ప్రొవైడర్లు అభ్యర్థన సమయంలో IP చిరునామాను చూస్తారు.
- **మాస్క్ మోడ్‌లో సీలింగ్:** EvidenceRoot మరియు NotarySeal గణన మాస్క్ చేసిన ఫోరెన్సిక్ డేటాతో చేయబడుతుంది; కాబట్టి ధృవీకరణ నిర్ణయాత్మకంగా ఉంటుంది.

### 🌍 పబ్లిక్

- **దృశ్యం:** పూర్తి పారదర్శకత. [PoArt] ప్రమాణాల ప్రకారం, ఎక్కడ, ఎప్పుడు, ఏ నెట్‌వర్క్ నుండి పని సృష్టించబడింది అని బహిరంగంగా ప్రకటించబడుతుంది.

## 💡 సాంకేతిక ఆవిష్కరణ

PoArt కేవలం ఫైల్ అప్‌లోడ్ వ్యవస్థ కాదు. ఇది ఒక కుండలో మూడు వేర్వేరు సాంకేతిక స్థాయిలను కలిపి కొత్త ప్రమాణాన్ని తెచ్చే **"శాస్త్రీయ సంరక్షణ గొలుసు"** ఇంజిన్.

**ఈ విభాగంలో "ఇంజిన్"గా వర్ణించబడిన పొర మునుపటి నిబంధనలలో PoArt ఫోరెన్సిక్ ఇంజిన్ (PFE) యొక్క కోర్‌తో సరిపోలుతుంది.**

### 1) క్లయింట్-సైడ్ హాషింగ్ (అత్యధిక గోప్యత)

మీ కళాఖండాల ఫైళ్లు సర్వర్‌కు అప్‌లోడ్ చేయబడవు. మా బ్రౌజర్-ఆధారిత (క్లయింట్-సైడ్) ఇంజిన్ మీ స్వంత కంప్యూటర్‌లో ఫైల్ యొక్క హాష్ (డిజిటల్ సారాంశం) ను గణిస్తుంది. ఈ వేలిముద్ర మరియు మెటాడేటా మాత్రమే సర్వర్‌కు పంపబడుతుంది.

> **గోప్యత సత్యం:** పని ఫైల్ సర్వర్‌కు అప్‌లోడ్ చేయబడదు మరియు ఈ విధంగా రక్షించబడుతుంది. అయితే, ఫోరెన్సిక్ డేటా (IP/స్థానం) ఎంచుకున్న దృశ్యమానత మోడ్ (ప్రైవేట్/మాస్క్/పబ్లిక్) ప్రకారం భాగస్వామ్యం చేయబడుతుంది.

### 2) ఫోరెన్సిక్ డేటా ఫ్యూజన్ (శాస్త్రీయ శక్తి)

సాధారణ సమయ ముద్ర కంటే ఎక్కువ. వ్యవస్థ ఈ డేటాను ఒక "మూల ముద్రలో" కలుపుతుంది:

- **డిజిటల్ సారాంశం (SHA-512):** క్రిప్టోగ్రాఫిక్ సారాంశ ప్రమాణం (SHA-512) ఉపయోగించి వేలిముద్ర, ఇది పని యొక్క ఒక పిక్సెల్ కూడా మారితే విరిగిపోతుంది.
- **స్థానం మరియు సమయం:** మిల్లీసెకండ్ ఖచ్చితత్వంతో తేదీ, దేశం, నగరం మరియు జిల్లా డేటా లావాదేవీ.
- **పరికర గుర్తింపు:** ఆపరేటింగ్ సిస్టమ్, బ్రౌజర్ మరియు పరికర రకం (User-Agent విశ్లేషణ).

### నిర్ణయాత్మక హాష్ ఫంక్షన్లు
```javascript
// సహాయక ఫంక్షన్లు: సారాంశాన్ని హెక్సాడెసిమల్ స్ట్రింగ్‌గా మార్చండి
async function digestToHex(algorithm, dataBytes) {
  const hashBuffer = await crypto.subtle.digest(algorithm, dataBytes);
  const hashArray = Array.from(new Uint8Array(hashBuffer));
  return hashArray.map(b => b.toString(16).padStart(2, '0')).join('');
}

// స్ట్రింగ్‌ను బైట్ శ్రేణిగా మార్చండి
function stringToBytes(text) {
  return new TextEncoder().encode(text);
}

// కానానికల్ ఫోరెన్సిక్స్ స్ట్రింగ్ ఉత్పత్తి (v1.0: స్థిర ఫీల్డ్ క్రమం + UTF-8 + విభజకం \n)
// దశ 2 సత్యం: RFC 8785 (JCS) తో కానానికల్ JSON కు మారడం
function canonicalForensics(forensicsData) {
  return JSON.stringify({
    ip_masked: forensicsData.ip_masked,
    location: forensicsData.location,
    device: forensicsData.device,
    timestamp: forensicsData.timestamp
  });
}
```

### NotarySeal ఉత్పత్తి ప్రక్రియ (పూర్తిగా నిర్ణయాత్మకం)
```javascript
// 1. FileHash గణన (క్లయింట్-సైడ్)
async function computeFileHash(file) {
  const fileBuffer = await file.arrayBuffer();
  const fileBytes = new Uint8Array(fileBuffer);
  
  const sha256 = await digestToHex('SHA-256', fileBytes);
  const sha512 = await digestToHex('SHA-512', fileBytes);
  
  return { sha256, sha512 };
}

// 2. ఫోరెన్సిక్ డేటా సేకరణ (ఏకైక సమయ ముద్ర వినియోగం)
async function collectForensics(visibilityMode) {
  const timestamp = new Date().toISOString(); // ఏకైక సమయ ముద్ర ఉత్పత్తి
  const ipData = await fetch('https://ipapi.co/json/').then(r => r.json());
  
  let forensics = {
    ip_masked: visibilityMode === 'masked' ? maskIP(ipData.ip) : ipData.ip,
    location: visibilityMode === 'masked' 
      ? `***/${ipData.country}` 
      : `${ipData.city}, ${ipData.country_name || ipData.country}`,
    device: navigator.userAgent,
    timestamp: timestamp // అదే సమయ ముద్ర
  };
  
  return { forensics, timestamp };
}

// 3. EvidenceRoot నిర్మాణం (కానానికల్ ఎన్‌క్రిప్షన్‌తో)
async function computeEvidenceRoot(fileHash512, forensicsData) {
  const canonicalPayload = `file_sha512:${fileHash512}\nforensics:${canonicalForensics(forensicsData)}`;
  return await digestToHex('SHA-512', stringToBytes(canonicalPayload));
}

// 4. NotarySeal ఉత్పత్తి (అదే సమయ ముద్ర వినియోగం)
async function computeNotarySeal(evidenceRoot, signerSignature, timestamp) {
  const sealPayload = `evidence_root:${evidenceRoot}\nsigner_sig:${signerSignature}\ntimestamp:${timestamp}`;
  return await digestToHex('SHA-512', stringToBytes(sealPayload));
}

// మాస్కింగ్ సహాయక ఫంక్షన్లు (IPv4 మరియు IPv6 మద్దతు)
function maskIP(ip) {
  if (!ip) return "***";
  
  // IPv4 తనిఖీ
  if (ip.includes(".")) {
    const parts = ip.split(".");
    if (parts.length === 4) {
      return `${parts[0]}.${parts[1]}.***.***`;
    }
  }
  
  // IPv6 లేదా తెలియని ఫార్మాట్
  return "***";
}
```

### ధృవీకరణ ప్రవాహం (రెండు స్థాయిలు)

#### Quick Verify (వేగవంతమైన ధృవీకరణ)
```javascript
// ఫైల్ హాష్‌ను మాత్రమే ధృవీకరించండి (వేగవంతమైన ఎరుపు జెండా)
async function verifyQuick(file, certificateId) {
  const { sha512: userFileHash } = await computeFileHash(file);
  
  // రిజిస్టర్ నుండి పొందండి
  const cert = await fetchFromRegistry(certificateId);
  const { sha512: originalHash } = cert.asset.fingerprints;
  
  // హాష్ పోలిక
  if (userFileHash === originalHash) {
    return {
      valid: true,
      message: "✅ ప్రామాణికమైనది - ఫైల్ హాష్ సరిపోలుతుంది"
    };
  } else {
    return {
      valid: false,
      message: "❌ తప్పుడు - ఫైల్ తారుమారు చేయబడింది"
    };
  }
}
```

#### Full Verify (పూర్తి ధృవీకరణ)
```javascript
// EvidenceRoot మరియు NotarySeal ను మళ్లీ ఉత్పత్తి చేసి ధృవీకరించండి
async function verifyFull(file, certificateId) {
  const { sha512: userFileHash } = await computeFileHash(file);

  // రిజిస్టర్ నుండి పొందండి
  const cert = await fetchFromRegistry(certificateId);

  // 1) FileHash ధృవీకరణ (వేగవంతమైన ఎరుపు జెండా)
  const originalHash = cert.asset.fingerprints.sha512;
  if (userFileHash !== originalHash) {
    return { valid: false, message: "❌ తప్పుడు - ఫైల్ హాష్ సరిపోలడం లేదు" };
  }

  // 2) EvidenceRoot ను మళ్లీ ఉత్పత్తి చేయండి (రిజిస్టర్‌లో నిల్వ చేసిన ఫోరెన్సిక్ డేటాతో)
  const evidenceRoot = await computeEvidenceRoot(userFileHash, cert.forensics);
  if (evidenceRoot !== cert.proof.evidence_root) {
    return { valid: false, message: "❌ సరిపోలడం లేదు - EvidenceRoot నిలబడదు" };
  }

  // 3) NotarySeal ను మళ్లీ ఉత్పత్తి చేయండి (అదే సమయ ముద్ర + signer_sig తో)
  const seal = await computeNotarySeal(
    evidenceRoot,
    cert.proof.signer_sig,
    cert.forensics.timestamp
  );

  if (seal !== cert.proof.notary_seal) {
    return { valid: false, message: "❌ సరిపోలడం లేదు - NotarySeal నిలబడదు" };
  }

  // ఐచ్ఛికం: దశ 2లో, signer_sig ను attestation_pubkey తో కూడా ధృవీకరించండి
  // const sigValid = await verifySig(cert.issuer.attestation_pubkey, cert.proof.signer_sig, evidenceRoot);
  // if (!sigValid) return { valid: false, message: "❌ చెల్లని సంతకం" };

  return { valid: true, message: "✅ ప్రామాణికమైనది - పూర్తి ధృవీకరణ పాస్" };
}
```

> **క్లిష్టమైన సత్యాలు:**
> - **Quick Verify:** వేగవంతమైన వినియోగం కోసం ఫైల్ హాష్‌ను మాత్రమే ధృవీకరిస్తుంది.
> - **Full Verify:** అన్ని ప్రోటోకాల్ స్థాయిలను ధృవీకరిస్తుంది (EvidenceRoot + NotarySeal).
> - అన్ని హాష్ ఆపరేషన్లు స్థిర ఎన్‌క్రిప్షన్ మరియు స్థిర విభజకాలతో నిర్ణయాత్మక పద్ధతిలో చేయబడతాయి.
> - **ప్రస్తుత ప్రమాణం v1.0:** స్థిర ఫీల్డ్ క్రమం + UTF-8 ఎన్‌క్రిప్షన్ + విభజకం `\n`.
> - **దశ 2 ప్రణాళిక:** RFC 8785 (JCS - JSON Canonicalization Scheme) తో కానానికల్ JSON కు మారడం.
> - మాస్క్ మోడ్‌లో, EvidenceRoot మరియు NotarySeal గణన మాస్క్ చేసిన ఫోరెన్సిక్ డేటాతో చేయబడుతుంది; కాబట్టి ధృవీకరణ నిర్ణయాత్మకంగా ఉంటుంది.
> - ప్రక్రియ అంతటా ఏకైక సమయ ముద్ర ఉపయోగించబడుతుంది (ఫోరెన్సిక్స్ + NotarySeal); నిర్ణయం హామీ ఇవ్వబడింది.
> - **ఫోరెన్సిక్ ఫీల్డ్ పేర్లు:** `ip_masked`, `location`, `device`, `timestamp` (కోడ్ మరియు రిజిస్టర్ ఖచ్చితంగా సరిపోలుతాయి).
> - **రిజిస్టర్ పాత్:** `certificate.asset.fingerprints` (ధృవీకరణ కోడ్‌తో ఖచ్చితంగా సరిపోలుతుంది).
> - **రిజిస్టర్‌లో signer_sig:** పూర్తి ధృవీకరణ కోసం `proof.signer_sig` ఫీల్డ్ అవసరం.
> - SignerSignature ప్రక్రియ దశ 2లో Solana Wallet Adapter తో సక్రియం చేయబడుతుంది; v1.0లో, ధృవీకరణ `attestation_pubkey` తో చేయవచ్చు.
