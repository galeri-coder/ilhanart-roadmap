## ⚙️ PoArt Forensic Engine (PFE) v1.0: Основна Інфраструктура

**PoArt Forensic Engine (PFE)** — це основний шар, що представляє базову логіку та технічну роботу протоколу [PoArt]. Це "криміналістичний двигун", який бере необроблені дані виробництва мистецтва та перетворює їх на перевірений та незмінний **цифровий доказ**.

### 🧩 Чому "PoArt Forensic"?

- **PoArt (Proof of Art - Доказ Мистецтва):** Фокус двигуна полягає в прив'язці вартості цифрового активу не до спекуляції, а до **доказового процесу виробництва**.
- **Forensic (Криміналістична Перевірка):**
  - **Технічне Визначення:** Підхід алгоритму та ланцюга записів, спрямований на перевірку того, що дані процесу виробництва (мазки пензля, таймлапси, логи) не були маніпульовані.
  - **Філософський Шар:** Проти "миттєвого виводу" штучного інтелекту; твердження про перетворення виробництва людини, що містить час, зусилля та ціну рішень, у вимірювану реальність.

> Примітка: Інтеграція блокчейну (наприклад, Solana) не є ядром PFE; вона визначена як окремий **Chain Anchor Layer** для перевірки/реєстрації.

### 🛠️ Технічний Обсяг v1.0

**PoArt Forensic Engine (PFE) v1.0** побудований на наступних **3 основних стовпах**, а не на складних фінансових моделях:

1. **Hashing & Sealing (Хешування та Запечатування):**  
   PFE детерміністично обробляє всі елементи в Evidence Pack (файл роботи, відео, JSON/лог, підпис тощо) та генерує унікальне значення **NotarySeal**.

   **Основні концепції (v1.0):**
   - **FileHash (відбиток твору):** Хеш, згенерований з байтів файлу твору.
   - **EvidenceRoot (корінь пакета доказів):** Кореневий дайджест, що представляє цілісність Evidence Pack (Merkle root або канонічний маніфест хеш).
   - **NotarySeal (остаточна печатка / вихід PFE):** Остаточна печатка, згенерована з комбінації EvidenceRoot + час + підпис.

   **Формули (чітко видимі для інвесторів):**
   
   $$\text{FileHash}_{512} = \text{SHA-512}(\text{ArtworkFileBytes})$$
   
   $$\text{NotarySeal} = \text{SHA-512}(\text{EvidenceRoot} \mid \text{SignerSignature} \mid \text{TimeStamp})$$
   
   **Визначення Canonical Payload (v1.0):**
   
   - **EvidenceRootPayload:**
```
   file_sha512:{sha512}\nforensics:{canonicalForensics(forensics)}
```
   
   - **NotarySealPayload:**
```
   evidence_root:{evidence_root}\nsigner_sig:{signer_sig}\ntimestamp:{timestamp}
```
   
   > Примітка: Значення, яке мається на увазі як вихід PFE, — це **NotarySeal**. Механізм **SignerSignature** буде активовано у Фазі 2 (з Solana Wallet Adapter); у поточній версії v1.0 використовується власний підпис атестації системи. Публічний ключ атестації публікується в реєстрі в полі `issuer.attestation_pubkey`.

2. **Indexing (Архівування):**  
   Записує в прозорий та запитуваний шар записів, який гаманець, в яку дату, для якого твору подав **Labor Proof (Доказ Праці)**.  
   *(Цей шар може бути базою даних; інтеграція ланцюга визначається окремо як "Chain Anchor Layer".)*

3. **Verification (Перевірка):**  
   Коли оригінальність твору ставиться під сумнів, PFE повторно обробляє необроблені докази; математично точно перевіряє, чи збігаються обчислені значення **EvidenceRoot / NotarySeal** із записами в архіві.

### 🧮 Теорема Вартості PoArt (The Value Theorem)

Протокол [PoArt] пов'язує вартість ($V$) цифрового активу не з суб'єктивним сприйняттям ринку, а з **фізичною реальністю процесу виробництва**.

Штучний Інтелект (AI) знищує процес, даючи результат миттєво ($t \to 0$). [PoArt] розглядає вартість як накопичення компонентів **часу, праці та волі**.

$$V_{\text{PoArt}} = \int_{t_{\text{start}}}^{t_{\text{end}}} \left(P_{\text{labor}}(t) \cdot I_{\text{agency}}(t)\right) dt + U_{\text{irreversible}}$$

#### Визначення Змінних

- **$\int dt$ (Накопичення Процесу):**  
  Вартість — це не миттєвий "вивід" (output); це **процес**, що накопичується між $t_{\text{start}}$ та $t_{\text{end}}$. Коли тривалість зменшується (виробництво AI), результат інтеграла прямує до 0.

- **$P_{\text{labor}}(t)$ (Миттєва Потужність Праці):**  
  Представляє інтенсивність розумових та фізичних зусиль, витрачених у момент виробництва. Коли доказові зусилля зростають, інтегранд збільшується.  
  > Примітка: На практиці цей термін може бути нормалізований через "вимірювані/доказові сигнали праці".

- **$I_{\text{agency}}(t)$ (Коефіцієнт Волі):**  
  Це здатність виробника йти на ризик та приймати рішення. Має значення від $0$ до $1$.
  - **AI ($I \approx 0$):** Виконує команди, не йде на ризик, не платить ціни.
  - **Людина ($I \to 1$):** Змінює рішення, вагається, йде на ризик.

- **$U_{\text{irreversible}}$ (Незворотна Унікальність):**  
  У той час як у цифровому виробництві можливе скасування (`Ctrl+Z`); у фізичному виробництві (фарба, нанесена на полотно, вирізаний мармур, жест у прямому ефірі) немає зворотності. Ця **незворотність** є додатковим терміном, що створює "унікальність" (non-fungible характер) у творі.

### 🔎 Аналіз Кейсів: AI "Миттєвий Вивід" проти Людина "Доказовий Процес"

Наступний сценарій показує, як працює **Теорема Вартості PoArt** на практиці та чому виробництво AI отримує низькі оцінки за стандартом [PoArt].

#### Сценарій A: Виробництво Візуального Контенту за 10 Секунд з AI

- **Тривалість ($\Delta t$):** $10$ секунд (майже відсутній процес)
- **Потужність Праці ($P_{\text{labor}}$):** $1$ одиниця (лише написання команди)
- **Коефіцієнт Волі ($I_{\text{agency}}$):** $0.01$ (немає ризику, немає ціни)
- **Незворотність ($U_{\text{irreversible}}$):** $0$ (можна скасувати / скопіювати)

**Результат:**

$$V_{\text{AI}} \approx \int_{0}^{10} (1 \cdot 0.01) \, dt + 0 = 0.1$$

> **Коментар:** Навіть якщо вихід бездоганний; оскільки процес не був прожитий і не містить волі/ризику, вартість [PoArt] прямує до $0$.

#### Сценарій B: 6-Годинне Фізичне Виробництво в Прямому Ефірі

- **Тривалість ($\Delta t$):** $6$ годин ($21{,}600$ секунд)
- **Потужність Праці ($P_{\text{labor}}$):** $0.5$ одиниць (безперервність фізичних та розумових зусиль)
- **Коефіцієнт Волі ($I_{\text{agency}}$):** $0.9$ (зміна рішень, прийняття ризику, незворотні вибори)
- **Незворотність ($U_{\text{irreversible}}$):** $>0$ (фізичні сліди незворотні)

**Результат:**

$$V_{\text{Human}} \approx \int_{0}^{21600} (0.5 \cdot 0.9) \, dt + U_{\text{irreversible}} \approx 9720 + U_{\text{irreversible}}$$

> **Коментар:** Коли процес подовжується і воля (ризик) зростає, вартість накопичується кумулятивно. Термін $U_{\text{irreversible}}$ є додатковим внеском, що створює "унікальність" (non-fungible характер) у творі.

### ✅ Висновок: Закріплення Вартості Доказом (Proof-Bound Value)

Ця теорема виводить претензію на вартість [PoArt] з площини "вподобання" або "ринкового наративу" і пов'язує її з **доказовою реальністю виробництва**.

1. **Без Процесу Не Створюється Вартість:**  
   AI знищує процес у миттєвому виводі ($t \to 0$). Коли вікно процесу звужується, результат інтеграла математично зменшується:
   
   $$\Delta t \downarrow \ \Rightarrow\ \int \left(P(t) \cdot I(t)\right) dt \to 0$$

2. **Воля та Ризик є Множниками:**  
   [PoArt] вимірює не лише "витрачений час", але й шар справжніх рішень, ризику та ціни в цей час. Вартість виробництва без ризику (AI) низька:
   
   $$V_{\text{PoArt}} \propto \int \left(P_{\text{labor}}(t) \cdot I_{\text{agency}}(t)\right) dt$$

3. **Унікальність — Не Маркетинг, а Фізичний Доказ:**  
   У фізичному виробництві незворотні сліди (мазок на полотні, скол мармуру) знаходяться за межами логіки `Ctrl+Z` у цифровій сфері. Ця незворотність ($U_{\text{irreversible}}$) онтологічно робить твір унікальним.

> **🔐 РЕЗЮМЕ:** Хоча теорема вартості може здаватися невизначеною як вимірювання (навіть якщо її не можна виміряти на 100% у реальному житті), мета цієї формули — показати конструкцію та напрямок змінних. У епоху AI рідкісним є не "зображення", а **доказова праця, час і воля.** [PoArt] вимірює цю рідкісність і реєструє її через **Evidence Pack**.

## a) Що таке [PoArt]? (Філософське та Технічне Визначення)

**Proof of Art [PoArt];** це інституційний стандарт перевірки, що гарантує, що вартість активу на блокчейні базується не на спекуляції, а на перевірюваній **людській праці**, **часі** та **фізичній енергії**.

Так само, як Bitcoin створює вартість через *"Електрику та Процесорну Потужність"* **(Proof of Work)**; проекти, сумісні з [PoArt], створюють вартість через *"Художній Талант та Людський Час"*.

Це усуває ризик *"Розробник (Dev) продав, проект закінчився"* на Pump.fun та DEX платформах; тому що тут вартість зберігається не в коді, а у **безперервності виробництва**.

> **[PoArt] не каже учасникам "Довіртеся нам"; він каже "Ось докази, подивіться своїми очима, перевірте своєю математикою".**

## b) 5 Стандартів [PoArt] (The 5 Pillars of Truth)

Ці 5 пунктів є фільтрами, що не піддаються маніпуляції, через які повинен пройти проект, щоб отримати печатку [PoArt].

### 1) Доказ Живої Ідентичності (Live Identity Proof)

- **Проблема:** Криптовалютний світ повний анонімних засновників (Dev'ів) з невизначеною ідентичністю, які збирають гроші та залишають проект.
- **Рішення [PoArt]:** Виробник доводить не лише паспорт, а **свою присутність під час виробництва**. Це включає сесії прямих трансляцій, де відбувається взаємодія зі спільнотою та виконуються конкретні миттєві запити, а не попередньо записані відео.  
  (Наприклад: *"Напишіть сьогоднішню дату та поточний номер блоку в правому куті полотна"*)
- **Девіз:** *"Боти можуть малювати картини, але боти не потіють і не можуть імпровізувати."*

### 2) Доказ Праці та Процесу (Labor & Process Proof)

- **Проблема:** Зображення AI (Штучного Інтелекту), створене за 2 секунди, отримує таке ж ставлення "jpeg" у цифровому світі, як картина маслом, створена за 2 місяці.
- **Рішення [PoArt]:** Процес "вагітності та народження" твору записується. Документуються етапи ескізів, шари фарби, накопичені години та фізичний процес, який пережив художник під час створення цього твору. Це додає **"Вартість Часу" (Time Cost)** до токена. Чим важче виробництво активу, тим міцніша його вартість.

### 3) Доказ Естетичної Цінності (Aesthetic Value Proof)

- **Проблема:** Культура "Мемів" ігнорує естетику та художню глибину, зосереджуючись лише на миттєвій комедії, що призводить до короткострокових "Hype" проектів.
- **Рішення [PoArt]:** Проект повинен відповідати академічним художнім стандартам, теорії кольору, правилам композиції та знанню матеріалів (Імпасто, Текстура тощо). Контент повинен не просто розсмішити; він повинен викликати захоплення у глядача та мати **колекційну цінність**.

### 4) Концептуальна Новизна (Conceptual Novelty)

- **Проблема:** Тисячі собачих/котячих монет, що копіюють одна одну, без творчості.
- **Рішення [PoArt]:** Проект повинен створити новий міст, що значущим чином поєднує мистецтво, науку, філософію або технологію.  
  (Наприклад: Поєднання класичної статуї Давида з криптовалютними ринковими даними; обробка ідеї "перетворення на камінь" людського сприйняття та можливість обґрунтувати це науковими джерелами.)  
  Твір повинен бути не лише візуальним бенкетом, але й інтелектуальним викликом, що змушує замислитися про **Науку, Філософію або Технологію**.

> [!IMPORTANT]
> **Референсний Приклад (Ефект Лас Палмітас):**

В результаті цього естетичного втручання рівень злочинності в районі певною мірою знизився, молодь почала цікавитися мистецтвом замість банд. Естетична зміна перекодувала повагу людей до свого оточення та один до одного (Social Cohesion).
>
> **Очікування:** Проект, що увійде до списку [PoArt], повинен, як у прикладі вище, містити соціологічний, науковий або філософський причинно-наслідковий зв'язок, що виходить за межі простої візуальної естетики. Оскільки єдиним активом, який не можна купити за гроші, є "Час", у цьому протоколі час повинен бути доведений шляхом стейкінгу як застава. Концептуальна основа проекту повинна бути настільки міцною та універсальною, що навіть через роки, у можливому сценарії CTO (Community Take Over), спільнота може автономно продовжувати інноваційний потенціал проекту, успадковуючи цю спадщину.

### 5) Неалгоритмічна Воля (Non-Algorithmic Agency)

- **Проблема:** Бездоганні, але бездушні, повторювані цифрові виробництва.
- **Рішення [PoArt]:** Унікальна воля людини, здатної помилятися, йти на ризик та переживати емоційні коливання, повинна відчуватися у творі. Невизначеність у мазках пензля, несподівані реакції матеріалу та миттєві рішення художника є **Біологічним Підписом**, що відрізняє твір від "Машинного Виробництва".

### 📦 Пакет Доказів (Evidence Pack - The Digital Twin)

За кожним твором, сертифікованим [PoArt], знаходиться зашифрований та позначений часовою міткою пакет даних, який можуть завантажити інвестори:

- **RAW Відеозаписи:** Безперервні необроблені кадри моменту виробництва.
- **Аналіз Метаданих:** Дата створення файлу, інформація про використаний пристрій та дані про місцезнаходження.
- **Фізичні Референси:** Докази існування твору у фізичному світі  
  (Наприклад: Поточна газета або дані блокчейну того моменту поруч з твором).

## 🧩 Чому Існує Кілька "Модулів Видимості"?

Найкритичніша частина коду знаходиться тут (меню вибору видимості). Ці опції дозволяють користувачам встановити баланс між **"Конфіденційність проти Прозорість"**:

### 🔒 Приватний (Private)

- **Сценарій:** Художник ще не хоче публікувати твір, але хоче поставити часову мітку та довести "Я зробив це в цю дату".
- **Що робить код:** Записує дані в базу даних, але ставить мітку `visibility: "private"`. Пізніше, коли ви пишете політику "Public Read", ви можете приховати ці записи від публіки, сказавши `WHERE visibility = 'public'`.

### 🕶️ Маскований (Masked)

- **Сценарій:** Художник хоче прозорості, але боїться, що буде знайдена його домашня адреса (IP-локація).
- **Що робить код:** На стороні JavaScript працюють функції `maskIP` та `maskLoc`. Вони перетворюють IP-адресу у форму `88.241.***.***`, а місцезнаходження у форму `***/TR` і відправляють цензуровану версію в базу даних.
- **Примітка про конфіденційність:** Маскування відбувається в браузері, Supabase не бачить справжнє місцезнаходження. **Однак:** Якщо використовуються сторонні API, такі як ipapi.co для даних про місцезнаходження, ці постачальники бачать IP-адресу під час запиту.
- **Запечатування в Маскованому Режимі:** Обчислення EvidenceRoot та NotarySeal виконується з маскованими криміналістичними даними; таким чином перевірка залишається детерміністичною.

### 🌍 Публічний (Public)

- **Сценарій:** Повна прозорість. Відповідно до стандарту [PoArt], чітко заявляється, де, коли та з якої мережі був створений твір.

## 💡 Технологічна Інновація

PoArt — це не просто система завантаження файлів. Це двигун **"Криміналістичного Ланцюга Зберігання" (Forensic Chain of Custody)**, що об'єднує три різні технологічні шари в одному котлі, створюючи новий стандарт.

**Шар, описаний тут як "двигун", відповідає ядру PoArt Forensic Engine (PFE) у попередній термінології.**

### 1) Client-Side Hashing (Максимальна Конфіденційність)

Ваші файли творів ніколи не завантажуються на сервер. Наш двигун, що працює на стороні браузера (Client-side), обчислює хеш (цифровий дайджест) файлу на вашому власному комп'ютері. На сервер надсилаються лише цей відбиток та метадані.

> **Примітка про конфіденційність:** Файл твору не завантажується на сервер і таким чином захищений. Однак криміналістичні дані (IP/місцезнаходження) поширюються відповідно до обраного режиму видимості (private/masked/public).

### 2) Forensic Data Fusion (Криміналістична Сила)

Це набагато більше, ніж звичайна часова мітка (Timestamp). Система об'єднує наступні дані в єдину "Genesis Печатку":

- **Цифровий Дайджест (SHA-512):** Цифровий відбиток, що буде зламаний, навіть якщо один піксель твору зміниться, використовуючи криптографічний стандарт дайджесту (SHA-512).
- **Місцезнаходження та Час:** Дата з точністю до мілісекунди, країна, місто та район, де була виконана операція.
- **Ідентичність Пристрою:** Операційна система, браузер та тип пристрою (аналіз User-Agent).

## 🔬 Технічна Глибина: Алгоритм Печатки

### Детерміністичні Хеш-Функції
```javascript
// Допоміжні Функції: Перетворення digest у hex string
async function digestToHex(algorithm, dataBytes) {
  const hashBuffer = await crypto.subtle.digest(algorithm, dataBytes);
  const hashArray = Array.from(new Uint8Array(hashBuffer));
  return hashArray.map(b => b.toString(16).padStart(2, '0')).join('');
}

// Перетворення string у byte array
function stringToBytes(text) {
  return new TextEncoder().encode(text);
}

// Генерація canonical forensics string (v1.0: фіксований порядок полів + UTF-8 + \n delimiter)
// Примітка Фази 2: перехід на canonical JSON з RFC 8785 (JCS)
function canonicalForensics(forensicsData) {
  return JSON.stringify({
    ip_masked: forensicsData.ip_masked,
    location: forensicsData.location,
    device: forensicsData.device,
    timestamp: forensicsData.timestamp
  });
}
```

### Процес Генерації NotarySeal (Повністю Детерміністичний)
```javascript
// 1. Обчислення FileHash (client-side)
async function computeFileHash(file) {
  const fileBuffer = await file.arrayBuffer();
  const fileBytes = new Uint8Array(fileBuffer);
  
  const sha256 = await digestToHex('SHA-256', fileBytes);
  const sha512 = await digestToHex('SHA-512', fileBytes);
  
  return { sha256, sha512 };
}

// 2. Збір forensic data (використання єдиного timestamp)
async function collectForensics(visibilityMode) {
  const timestamp = new Date().toISOString(); // Генерація єдиного timestamp
  const ipData = await fetch('https://ipapi.co/json/').then(r => r.json());
  
  let forensics = {
    ip_masked: visibilityMode === 'masked' ? maskIP(ipData.ip) : ipData.ip,
    location: visibilityMode === 'masked' 
      ? `***/${ipData.country}` 
      : `${ipData.city}, ${ipData.country_name || ipData.country}`,
    device: navigator.userAgent,
    timestamp: timestamp // Той самий timestamp
  };
  
  return { forensics, timestamp };
}

// 3. Створення EvidenceRoot (з canonical encoding)
async function computeEvidenceRoot(fileHash512, forensicsData) {
  const canonicalPayload = `file_sha512:${fileHash512}\nforensics:${canonicalForensics(forensicsData)}`;
  return await digestToHex('SHA-512', stringToBytes(canonicalPayload));
}

// 4. Генерація NotarySeal (використання того ж timestamp)
async function computeNotarySeal(evidenceRoot, signerSignature, timestamp) {
  const sealPayload = `evidence_root:${evidenceRoot}\nsigner_sig:${signerSignature}\ntimestamp:${timestamp}`;
  return await digestToHex('SHA-512', stringToBytes(sealPayload));
}

// Допоміжні функції маскування (підтримка IPv4 та IPv6)
function maskIP(ip) {
  if (!ip) return "***";
  
  // Перевірка IPv4
  if (ip.includes(".")) {
    const parts = ip.split(".");
    if (parts.length === 4) {
      return `${parts[0]}.${parts[1]}.***.***`;
    }
  }
  
  // IPv6 або невідомий формат
  return "***";
}
```

### Потік Перевірки (Два Рівні)

#### Quick Verify (Швидка Перевірка)
```javascript
// Перевіряє лише хеш файлу (швидкий червоний прапор)
async function verifyQuick(file, certificateId) {
  const { sha512: userFileHash } = await computeFileHash(file);
  
  // Отримання з Registry
  const cert = await fetchFromRegistry(certificateId);
  const { sha512: originalHash } = cert.asset.fingerprints;
  
  // Порівняння хешів
  if (userFileHash === originalHash) {
    return {
      valid: true,
      message: "✅ Оригінал - Хеш файлу збігається"
    };
  } else {
    return {
      valid: false,
      message: "❌ Підробка - Файл маніпульований"
    };
  }
}
```

#### Full Verify (Повна Перевірка)
```javascript
// Регенерує та перевіряє EvidenceRoot та NotarySeal
async function verifyFull(file, certificateId) {
  const { sha512: userFileHash } = await computeFileHash(file);

  // Отримання з Registry
  const cert = await fetchFromRegistry(certificateId);

  // 1) Перевірка FileHash (швидкий червоний прапор)
  const originalHash = cert.asset.fingerprints.sha512;
  if (userFileHash !== originalHash) {
    return { valid: false, message: "❌ Підробка - Хеш файлу не збігається" };
  }

  // 2) Регенерація EvidenceRoot (з forensics, збереженими в registry)
  const evidenceRoot = await computeEvidenceRoot(userFileHash, cert.forensics);
  if (evidenceRoot !== cert.proof.evidence_root) {
    return { valid: false, message: "❌ Не збігається - EvidenceRoot не підходить" };
  }

  // 3) Регенерація NotarySeal (з тим самим timestamp + signer_sig)
  const seal = await computeNotarySeal(
    evidenceRoot,
    cert.proof.signer_sig,
    cert.forensics.timestamp
  );

  if (seal !== cert.proof.notary_seal) {
    return { valid: false, message: "❌ Не збігається - NotarySeal не підходить" };
  }

  // Опціонально: У Фазі 2 також перевірте signer_sig з attestation_pubkey
  // const sigValid = await verifySig(cert.issuer.attestation_pubkey, cert.proof.signer_sig, evidenceRoot);
  // if (!sigValid) return { valid: false, message: "❌ Підпис недійсний" };

  return { valid: true, message: "✅ Оригінал - Full Verify пройдено" };
}
```

> **Важливі Примітки:**
> - **Quick Verify:** Перевіряє лише хеш файлу для швидкого використання.
> - **Full Verify:** Перевіряє всі шари протоколу (EvidenceRoot + NotarySeal).
> - Всі операції хешування виконуються детерміністично з фіксованим кодуванням та роздільниками.
> - **Стандарт канонізації v1.0:** Фіксований порядок полів + кодування UTF-8 + роздільник `\n`.
> - **План Фази 2:** Перехід на canonical JSON з RFC 8785 (JCS - JSON Canonicalization Scheme).
> - У маскованому режимі обчислення EvidenceRoot та NotarySeal виконується з маскованими forensics.
> - Єдиний timestamp використовується протягом усього процесу (forensics + NotarySeal); детерміністичність гарантована.
> - **Назви полів Forensics:** `ip_masked`, `location`, `device`, `timestamp` (код та реєстр повністю узгоджені).
> - **Шлях Registry:** `certificate.asset.fingerprints` (повна узгодженість з кодом verify).
> - **signer_sig у Registry:** Поле `proof.signer_sig` необхідне для Full Verify.
> - Механізм SignerSignature буде активовано у Фазі 2 з Solana Wallet Adapter; у v1.0 можна виконати перевірку з `attestation_pubkey`.

- Governance: Лише консультативна (кураторське остаточне рішення)
- Token utility: Доступ до галереї + реєстр + пріоритет NFT

**Бачення v2.0+ (2027+):**
- Registry: On-chain (Solana)
- Signatures: На основі гаманця (децентралізовані)
- Governance: Гібридна (community advisory + кураторська якість)
- Token utility: Розширені функції + розширений доступ

Ця структура забезпечує **операційну ефективність** та **контроль якості** на ранніх стадіях, залишаючи відкритим шлях для **підвищення участі спільноти** у майбутньому.
