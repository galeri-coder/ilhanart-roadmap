## ⚙️ PoArt Forensic Engine (PFE) v1.0: Базова Інфраструктура

**PoArt Forensic Engine (PFE)** є основним рівнем, що представляє фундаментальну логіку та технічне функціонування протоколу [PoArt]. Це "криміналістичний двигун", який перетворює сирі дані виробництва твору мистецтва у верифікований та незмінний **цифровий доказ**.

### 🧩 Чому "PoArt Forensic"?

- **PoArt (Proof of Art):** Фокус двигуна полягає у прив'язці вартості цифрового активу не до спекуляції, а до **верифікованого процесу виробництва**.
- **Forensic (Криміналістична Верифікація):**
  - **Технічне Визначення:** Алгоритмічний підхід та ланцюг доказів для верифікації того, що дані процесу виробництва (мазки пензлем, таймлапс, логи) не були маніпульовані.
  - **Філософський Рівень:** Проти "миттєвого виробництва" штучного інтелекту; твердження про перетворення людського виробництва, що містить **час, зусилля та вартість рішень** у вимірювану реальність.

> Примітка: Інтеграція блокчейн (наприклад, Solana) не є ядром PFE; буде визначена окремо як **Chain Anchor Layer** для верифікації/реєстру.

### 🛠️ Технічний Обсяг v1.0

**PoArt Forensic Engine (PFE) v1.0** побудований на **3 основних стовпах** замість складних фінансових моделей:

1. **Hashing & Sealing (Запечатування):**  
   PFE детерміністично обробляє всі елементи в Evidence Pack (файл твору, відео, JSON/log, підпис тощо) і генерує унікальне значення **NotarySeal**.

   **Основні концепції (v1.0):**
   - **FileHash (відбиток твору):** Хеш, згенерований з байтів файлу твору.
   - **EvidenceRoot (корінь пакету доказів):** Кореневий дайджест, що представляє цілісність Evidence Pack (Merkle root або хеш канонічного маніфесту).
   - **NotarySeal (остаточна печатка / Вихід PFE):** Остаточна печатка, згенерована з комбінації EvidenceRoot + час + підпис.

   **Формули (у форматі, зрозумілому для інвесторів):**
   
   $$\text{FileHash}_{512} = \text{SHA-512}(\text{ArtworkFileBytes})$$
   
   $$\text{NotarySeal} = \text{SHA-512}(\text{EvidenceRoot} \mid \text{SignerSignature} \mid \text{TimeStamp})$$
   
   **Визначення Canonical Payload (v1.0):**
   
   - **EvidenceRootPayload:**
```
   file_sha512:{sha512}\nforensics:{canonicalForensics(forensics)}
```
   
   - **NotarySealPayload:**
```
   evidence_root:{evidence_root}\nsigner_sig:{signer_sig}\ntimestamp:{timestamp}
```
   
   > Примітка: Значення, призначене як вихід PFE, це **NotarySeal**. Механізм **SignerSignature** буде активовано у Фазі 2 (з Solana Wallet Adapter); у поточній v1.0 використовується власний підпис атестації системи. Публічний ключ атестації публікується у реєстрі в полі `issuer.attestation_pubkey`.

2. **Indexing (Архівування):**  
   Реєструє, який гаманець, в яку дату, представив **Labor Proof (Доказ Праці)** для якого твору; у прозорому та запитуваному шарі реєстру.  
   *(Цей шар може бути базою даних; інтеграція блокчейн натомість визначена окремо як "Chain Anchor Layer".)*

3. **Verification (Верифікація):**  
   Коли оригінальність твору ставиться під сумнів, PFE повторно обробляє сирі докази; тестує з математичною впевненістю, чи відповідають обчислені значення **EvidenceRoot / NotarySeal** записам в архіві.

### 🧮 Теорема Вартості PoArt (The Value Theorem)

Протокол [PoArt] пов'язує вартість ($V$) цифрового активу не із суб'єктивним сприйняттям ринку, а з **фізичною реальністю процесу виробництва**.

Штучний Інтелект (AI) анулює процес, надаючи миттєві результати ($t \to 0$). [PoArt] натомість розглядає вартість як акумуляцію компонентів **часу, праці та волі**.

$$V_{\text{PoArt}} = \int_{t_{\text{start}}}^{t_{\text{end}}} \left(P_{\text{labor}}(t) \cdot I_{\text{agency}}(t)\right) dt + U_{\text{irreversible}}$$

#### Визначення Змінних

- **$\int dt$ (Акумуляція Процесу):**  
  Вартість не є миттєвим "виходом"; це **процес**, що акумулюється між $t_{\text{start}}$ та $t_{\text{end}}$. У міру того, як час зменшується (виробництво AI), результат інтегралу наближається до 0.

- **$P_{\text{labor}}(t)$ (Миттєва Інтенсивність Праці):**  
  Представляє інтенсивність розумових та фізичних зусиль, витрачених в момент виробництва. У міру того, як верифіковані зусилля зростають, інтегранд збільшується.  
  > Примітка: Цей термін може бути на практиці нормалізований на "вимірюваних/верифікованих сигналах праці".

- **$I_{\text{agency}}(t)$ (Коефіцієнт Волі):**  
  Це здатність виробника приймати ризики та приймати рішення. Приймає значення між $0$ та $1$.
  - **AI ($I \approx 0$):** Виконує команди, не приймає ризиків, не несе витрат.
  - **Людина ($I \to 1$):** Змінює рішення, вагається, приймає ризики.

- **$U_{\text{irreversible}}$ (Незворотна Унікальність):**  
  У той час як у цифровому виробництві можна скасувати (`Ctrl+Z`); у фізичному виробництві (фарба, нанесена на полотно, висічений мармур, жест під час прямого ефіру) немає повернення. Ця **незворотність** є додатковим терміном, що створює "унікальність" (non-fungible характер) у творі.

### 🔎 Аналіз Випадку: AI "Миттєвий Вихід" проти Людина "Доведений Процес"

Наступний сценарій показує, як працює **Теорема Вартості PoArt** на практиці та чому AI-виробництва отримують низькі бали в стандарті [PoArt].

#### Сценарій A: Візуальне Виробництво з AI за 10 Секунд

- **Тривалість ($\Delta t$):** $10$ секунд (процес майже неіснуючий)
- **Інтенсивність Праці ($P_{\text{labor}}$):** $1$ одиниця (тільки написання команди)
- **Коефіцієнт Волі ($I_{\text{agency}}$):** $0.01$ (без ризику, без витрат)
- **Незворотність ($U_{\text{irreversible}}$):** $0$ (зворотне / копійоване)

**Результат:**

$$V_{\text{AI}} \approx \int_{0}^{10} (1 \cdot 0.01) \, dt + 0 = 0.1$$

> **Коментар:** Навіть якщо вихід досконалий; оскільки процес не був пережитий і не містить волі/ризику, вартість [PoArt] наближається до $0$.

#### Сценарій B: Фізичне Виробництво в Прямому Ефірі Протягом 6 Годин

- **Тривалість ($\Delta t$):** $6$ годин ($21{,}600$ секунд)
- **Інтенсивність Праці ($P_{\text{labor}}$):** $0.5$ одиниці (безперервність фізичних та розумових зусиль)
- **Коефіцієнт Волі ($I_{\text{agency}}$):** $0.9$ (зміна рішень, прийняття ризиків, незворотні вибори)
- **Незворотність ($U_{\text{irreversible}}$):** $>0$ (фізичні сліди не можуть бути скасовані)

**Результат:**

$$V_{\text{Human}} \approx \int_{0}^{21600} (0.5 \cdot 0.9) \, dt + U_{\text{irreversible}} \approx 9720 + U_{\text{irreversible}}$$

> **Коментар:** У міру того, як процес подовжується і воля (ризик) зростає, вартість акумулюється кумулятивно. Термін $U_{\text{irreversible}}$ є додатковим внеском, що створює "унікальність" (non-fungible характер) у творі.

### ✅ Висновок: Вартість, Прив'язана до Доказу (Proof-Bound Value)

Ця теорема видаляє твердження про вартість [PoArt] з буття "лайком" або "ринковою розповіддю" і прив'язує його до **верифікованої реальності виробництва**.

1. **Без Процесу Не Створюється Вартість:**  
   AI анулює процес у миттєвому виході ($t \to 0$). У міру того, як вікно процесу звужується, результат інтегралу зменшується з математичної необхідності:
   
   $$\Delta t \downarrow \ \Rightarrow\ \int \left(P(t) \cdot I(t)\right) dt \to 0$$

2. **Воля та Ризик є Множниками:**  
   [PoArt] вимірює не тільки "витрачений час", але й реальний рівень рішень, ризику та витрат протягом цього часу. Вартість виробництва, що не приймає ризиків (AI), є низькою:
   
   $$V_{\text{PoArt}} \propto \int \left(P_{\text{labor}}(t) \cdot I_{\text{agency}}(t)\right) dt$$

3. **Унікальність є Фізичним Доказом, Не Маркетингом:**  
   У фізичному виробництві незворотні сліди (мазок пензлем на полотні, зламаний мармур) знаходяться поза логікою `Ctrl+Z` цифрового. Ця незворотність ($U_{\text{irreversible}}$) робить твір онтологічно унікальним.

> **🔐 РЕЗЮМЕ:** Хоча теорема вартості може здаватися невизначеною як вимірювання (навіть якщо її не можна виміряти на 100% у реальному житті), метою цієї формули є показати структуру та напрямок змінних. Те, що є рідкісним в еру AI, це не "зображення", а **верифікована праця, час та воля.** [PoArt] вимірює цей дефіцит та реєструє його за допомогою **Evidence Pack**.

## a) Що Таке [PoArt]? (Філософське та Технічне Визначення)

**Proof of Art [PoArt];** це інституційний стандарт верифікації, який гарантує, що вартість, що стоїть за активом на блокчейні, базується не на спекуляції, а на верифікованій **людській праці**, **часі** та **фізичній енергії**.

Так само, як Bitcoin виробляє вартість за допомогою *"Електрики та Обчислювальної Потужності"* **(Proof of Work)**; проекти, сумісні з [PoArt], виробляють вартість за допомогою *"Мистецьких Навичок та Людського Часу"*.

Усуває ризик *"Розробник (Dev) продав, проект закінчився"*, присутній на Pump.fun та платформах DEX; тому що тут вартість не в коді, а в **безперервності виробництва**.

> **[PoArt] не говорить учаснику "Довіряй нам"; говорить "Ось докази, подивись власними очима, перевір своєю математикою".**

## b) 5-Стовповий Стандарт [PoArt] (The 5 Pillars of Truth)

Ці 5 пунктів є неманіпульованими фільтрами, які проект повинен пройти, щоб отримати печатку [PoArt].

### 1) Доказ Особи в Прямому Ефірі (Live Identity Proof)

- **Проблема:** Світ криптовалют повний анонімних засновників (Dev) з невизначеною ідентичністю, які збирають гроші та залишають проект.
- **Рішення [PoArt]:** Виробник доводить не лише посвідчення особи, а **свою присутність під час виробництва**. Це включає сесії прямого ефіру, де взаємодіють зі спільнотою та виконують конкретні миттєві вимоги, а не з попередньо записаними відео.  
  (Наприклад: *"Напиши сьогоднішню дату та поточний номер блоку в правому куті полотна"*)
- **Девіз:** *"Боти можуть малювати, але боти не потіють і не імпровізують."*

### 2) Доказ Праці та Процесу (Labor & Process Proof)

- **Проблема:** AI-зображення, вироблені за 2 секунди, та олійні картини, зроблені за 2 місяці, розглядаються як один і той же "jpeg" у цифровому світі.
- **Рішення [PoArt]:** Процес "вагітності та народження" твору реєструється. Етапи ескізу, шари фарби, накопичені витрачені години та фізичний процес, пережитий художником під час створення твору, документуються. Це додає **"Часову Вартість" (Time Cost)** до токена. Чим важче виробити актив, тим міцніша його вартість.

### 3) Доказ Естетичної Вартості (Aesthetic Value Proof)

- **Проблема:** Естетика та художня глибина культури "Meme", яка ігнорує все та зосереджується лише на миттєвій комедії, та короткострокові проекти "Hype", що з цього випливають.
- **Рішення [PoArt]:** Проект повинен мати академічні мистецькі стандарти, теорію кольору, правила композиції та знання матеріалів (Impasto, Текстура тощо). Зміст не повинен лише смішити; повинен викликати захоплення у глядача та мати **колекційну вартість**.

### 4) Концептуальна Інновація (Conceptual Novelty)

- **Проблема:** Тисячі ідентичних dog/cat coin, далеких від креативності.
- **Рішення [PoArt]:** Проект повинен побудувати новий міст, який значущо поєднує мистецтво, науку, філософію або технологію.  
  (Наприклад: Поєднання класичної статуї Давида з даними ринку криптовалют; опрацювання через це ідеї "кам'яніння" людського сприйняття та можливість обґрунтувати це науковими джерелами.)  
  Твір повинен бути не лише візуальним святом, а й інтелектуальним викликом, що спонукає до роздумів про **Науку, Філософію або Технологію**.

> [!IMPORTANT]
> **Приклад Посилання (Ефект Las Palmitas):** У районі Las Palmitas в Мексиці, що бореться зі злочинністю, понад 200 будинків були перетворені на гігантське веселкове свято. В результаті цього >естетичного втручання показники злочинності в районі знизилися до певної міри, молодь почала цікавитися мистецтвом замість банд. Естетична зміна >перекодувала повагу людей до навколишнього середовища та один до одного (Соціальна Згуртованість).
>
> **Очікування:** Проект, що увійде до списку [PoArt]; так само, як у наведеному вище прикладі, повинен містити соціологічний, науковий або філософський причинно->наслідковий зв'язок поза візуальною естетикою. Оскільки єдиною річчю, яку не можна купити за гроші, є "Час", у цьому протоколі час повинен бути доведений як >гарантія через стейкінг. Концептуальна основа проекту повинна бути настільки сильною та універсальною, що; навіть у сценарії можливого CTO (Community Take Over) >років потому, спільнота може автономно підтримувати інноваційний потенціал проекту, успадковуючи цю спадщину.

### 5) Неалгоритмічна Воля (Non-Algorithmic Agency)

- **Проблема:** Досконалі, але бездушні цифрові вироби, що повторюються.
- **Рішення [PoArt]:** Оригінальна воля людської істоти, яка може помилятися, брати на себе ризики та відчувати емоційні коливання, повинна відчуватися у творі. Невизначеність у мазках пензля, неочікувані реакції матеріалу та миттєві рішення художника - це **Біологічний Підпис**, що відрізняє твір від "Механічного Виробництва".

## c) Механізм Верифікації та Анти-Підробки

Ця система забезпечує, щоб проект залишався надійним та живим не лише "на початку", але "назавжди".

### 📦 Пакет Доказів (Evidence Pack - The Digital Twin)

За кожним твором, сертифікованим [PoArt], знаходиться зашифрований та позначений часовою міткою пакет даних, який інвестори можуть завантажити:

- **Записи Відео RAW:** Безперервні сирі записи моменту виробництва.
- **Аналіз Метаданих:** Дата створення файлу, інформація про використаний пристрій та дані про місцезнаходження.

## 🧩 Чому Існує Більше "Модулів Видимості"?

Найбільш критична частина коду - тут (меню вибору видимості). Ці опції дозволяють користувачам збалансувати **"Конфіденційність проти Прозорості"**:

### 🔒 Приватний (Private)

- **Сценарій:** Художник ще не хоче публікувати твір, але хоче позначити часовою міткою та довести "я зробив це в цю дату".
- **Що Робить Код:** Записує дані в базу даних, але застосовує тег `visibility: "private"`. У майбутньому, при написанні політики "Public Read", можна приховати ці записи від публіки, кажучи `WHERE visibility = 'public'`.

### 🕶️ Замаскований (Masked)

- **Сценарій:** Художник хоче прозорості, але боїться, що буде знайдено адресу будинку (місцезнаходження IP).
- **Що Робить Код:** На стороні JavaScript працюють функції `maskIP` та `maskLoc`. Конвертує IP-адресу в формат `88.241.***.***` і місцезнаходження в формат `***/TR` і відправляє цензуровану версію в базу даних.
- **Примітка щодо Конфіденційності:** Маскування відбувається в браузері, Supabase не бачить реального місцезнаходження. **Однак:** Якщо використовуються API третіх сторін, такі як ipapi.co для даних про місцезнаходження, ці постачальники бачать IP-адресу в момент запиту.
- **Запечатування в Режимі Masked:** Обчислення EvidenceRoot та NotarySeal здійснюється із замаскованими даними forensics; таким чином верифікація залишається детерміністичною.

### 🌍 Публічний (Public)

- **Сценарій:** Повна прозорість. Відповідно до стандарту [PoArt], де, коли та з якої мережі було вироблено твір, явно декларується.

## 💡 Технологічна Інновація

PoArt - це не просто система завантаження файлів. Це двигун **"Forensic Chain of Custody"**, який зливає три різні технологічні шари в один тигель та приносить новий стандарт.

**Шар, описаний у цьому розділі як "двигун", відповідає ядру PoArt Forensic Engine (PFE) у попередній термінології.**

### 1) Client-Side Hashing (Максимальна Конфіденційність)

Файли ваших творів ніколи не завантажуються на сервер. Наш двигун на основі браузера (Client-side) обчислює хеш (цифровий дайджест) файлу на вашому комп'ютері. Тільки цей відбиток та метадані відправляються на сервер.

> **Примітка щодо Конфіденційності:** Файл твору не завантажується на сервер і таким чином захищений. Однак дані forensics (IP/місцезнаходження) надаються відповідно до обраного режиму видимості (private/masked/public).

### 2) Forensic Data Fusion (Криміналістична Потужність)

Це набагато більше, ніж просто часова мітка. Система поєднує наступні дані в одну "Genesis Seal":

- **Цифровий Дайджест (SHA-512):** Використовуючи стандарт криптографічного дайджесту (SHA-512), цифровий відбиток, який зламається, навіть якщо зміниться один піксель твору.
- **Місцезнаходження та Час:** Дата з точністю до мілісекунди, країна, місто та район, де була здійснена транзакція.
- **Ідентичність Пристрою:** Операційна система, браузер та тип пристрою (аналіз User-Agent).

## 🔬 Технічна Глибина: Алгоритм Запечатування

### Детерміністичні Хеш-Функції
```javascript
// Допоміжні Функції: Конвертувати дайджест у hex рядок
async function digestToHex(algorithm, dataBytes) {
  const hashBuffer = await crypto.subtle.digest(algorithm, dataBytes);
  const hashArray = Array.from(new Uint8Array(hashBuffer));
  return hashArray.map(b => b.toString(16).padStart(2, '0')).join('');
}

// Конвертувати рядок у масив байтів
function stringToBytes(text) {
  return new TextEncoder().encode(text);
}

// Генерація канонічного рядка forensics (v1.0: фіксований порядок полів + UTF-8 + роздільник \n)
// Примітка Фаза 2: Перехід до канонічного JSON з RFC 8785 (JCS)
function canonicalForensics(forensicsData) {
  return JSON.stringify({
    ip_masked: forensicsData.ip_masked,
    location: forensicsData.location,
    device: forensicsData.device,
    timestamp: forensicsData.timestamp
  });
}
```

### Процес Виробництва NotarySeal (Повністю Детерміністичний)
```javascript
// 1. Обчислення FileHash (client-side)
async function computeFileHash(file) {
  const fileBuffer = await file.arrayBuffer();
  const fileBytes = new Uint8Array(fileBuffer);
  
  const sha256 = await digestToHex('SHA-256', fileBytes);
  const sha512 = await digestToHex('SHA-512', fileBytes);
  
  return { sha256, sha512 };
}

// 2. Збирання криміналістичних даних (використання одного часового штампу)
async function collectForensics(visibilityMode) {
  const timestamp = new Date().toISOString(); // Генерація одного часового штампу
  const ipData = await fetch('https://ipapi.co/json/').then(r => r.json());
  
  let forensics = {
    ip_masked: visibilityMode === 'masked' ? maskIP(ipData.ip) : ipData.ip,
    location: visibilityMode === 'masked' 
      ? `***/${ipData.country}` 
      : `${ipData.city}, ${ipData.country_name || ipData.country}`,
    device: navigator.userAgent,
    timestamp: timestamp // Той самий часовий штамп
  };
  
  return { forensics, timestamp };
}

// 3. Створення EvidenceRoot (з канонічним кодуванням)
async function computeEvidenceRoot(fileHash512, forensicsData) {
  const canonicalPayload = `file_sha512:${fileHash512}\nforensics:${canonicalForensics(forensicsData)}`;
  return await digestToHex('SHA-512', stringToBytes(canonicalPayload));
}

// 4. Виробництво NotarySeal (використання того ж часового штампу)
async function computeNotarySeal(evidenceRoot, signerSignature, timestamp) {
  const sealPayload = `evidence_root:${evidenceRoot}\nsigner_sig:${signerSignature}\ntimestamp:${timestamp}`;
  return await digestToHex('SHA-512', stringToBytes(sealPayload));
}

// Допоміжні функції маскування (підтримка IPv4 та IPv6)
function maskIP(ip) {
  if (!ip) return "***";
  
  // Контроль IPv4
  if (ip.includes(".")) {
    const parts = ip.split(".");
    if (parts.length === 4) {
      return `${parts[0]}.${parts[1]}.***.***`;
    }
  }
  
  // IPv6 або невідомий формат
  return "***";
}
```

### Потік Верифікації (Два Рівні)

#### Quick Verify (Швидка Верифікація)
```javascript
// Перевіряє тільки хеш файлу (швидкий червоний прапор)
async function verifyQuick(file, certificateId) {
  const { sha512: userFileHash } = await computeFileHash(file);
  
  // Отримати з Реєстру
  const cert = await fetchFromRegistry(certificateId);
  const { sha512: originalHash } = cert.asset.fingerprints;
  
  // Порівняння хешу
  if (userFileHash === originalHash) {
    return {
      valid: true,
      message: "✅ Оригінал - Хеш файлу збігається"
    };
  } else {
    return {
      valid: false,
      message: "❌ Фальшивий - Файл маніпульований"
    };
  }
}
```

#### Full Verify (Повна Верифікація)
```javascript
// Відтворює та верифікує EvidenceRoot та NotarySeal
async function verifyFull(file, certificateId) {
  const { sha512: userFileHash } = await computeFileHash(file);

  // Отримати з Реєстру
  const cert = await fetchFromRegistry(certificateId);

  // 1) Контроль FileHash (швидкий червоний прапор)
  const originalHash = cert.asset.fingerprints.sha512;
  if (userFileHash !== originalHash) {
    return { valid: false, message: "❌ Фальшивий - Хеш файлу не збігається" };
  }

  // 2) Відтворити EvidenceRoot (з даними forensics, збереженими в реєстрі)
  const evidenceRoot = await computeEvidenceRoot(userFileHash, cert.forensics);
  if (evidenceRoot !== cert.proof.evidence_root) {
    return { valid: false, message: "❌ Не збігається - EvidenceRoot недійсний" };
  }

  // 3) Відтворити NotarySeal (з тим самим часовим штампом + signer_sig)
  const seal = await computeNotarySeal(
    evidenceRoot,
    cert.proof.signer_sig,
    cert.forensics.timestamp
  );

  if (seal !== cert.proof.notary_seal) {
    return { valid: false, message: "❌ Не збігається - NotarySeal недійсний" };
  }

  // Опціонально: У Фазі 2 верифікувати також signer_sig з attestation_pubkey
  // const sigValid = await verifySig(cert.issuer.attestation_pubkey, cert.proof.signer_sig, evidenceRoot);
  // if (!sigValid) return { valid: false, message: "❌ Підпис недійсний" };

  return { valid: true, message: "✅ Оригінал - Full Verify пройдено" };
}
```

> **Важливі Примітки:**
> - **Quick Verify:** Перевіряє тільки хеш файлу для швидкого використання.
> - **Full Verify:** Верифікує всі шари протоколу (EvidenceRoot + NotarySeal).
> - Усі операції хешування виконуються детерміністично, з фіксованим кодуванням та роздільниками.
> - **Стандарт канонізації v1.0:** Фіксований порядок полів + кодування UTF-8 + роздільник `\n`.
> - **План Фази 2:** Перехід до канонічного JSON з RFC 8785 (JCS - JSON Canonicalization Scheme).
> - У режимі Masked обчислення EvidenceRoot та NotarySeal здійснюється із замаскованими forensics.
> - Використовується один часовий штамп у всьому процесі (forensics + NotarySeal); детермінізм гарантований.
> - **Назви полів Forensics:** `ip_masked`, `location`, `device`, `timestamp` (код та реєстр повністю сумісні).
> - **Шлях Реєстру:** `certificate.asset.fingerprints` (повністю сумісний з кодом верифікації).
> - **signer_sig у Реєстрі:** Поле `proof.signer_sig` необхідне для Full Verify.
> - Механізм SignerSignature буде активовано у Фазі 2 з Solana Wallet Adapter; у v1.0 можна провести верифікацію з `attestation_pubkey`.
